# 教学管理演示场景设计

`education` 是 MuYunSpring 用于验证“动静一体”的单一学校业务演示应用。它不是两套静态/动态示例的并排陈列：稳定主数据与可配置评价业务共同服务于一条学年教务流程，并复用同一套模块身份、权限、租户、审计、引用和页面交付语义。

## 目标与边界

本场景首先验证以下能力在一个真实业务链中成立：

1. 静态主数据的树、引用、主子表和引用完整性。
2. 动态业务对象的元数据、主子表、页面配置与发布预览。
3. 动态业务对静态主数据的真实引用，而不是复制学号、姓名等展示字段。

它不在一期承担工作流、导入导出、编码规则、生成回写、复杂多级子表或多端页面运行时的综合演示。新增能力只有在能服务这条业务链时才进入场景。

## 业务主线

```text
维护学科分类、学生、教师
  -> 创建教学班并维护班级成员
  -> 创建考试/测评，选择班级与学科
  -> 从学生主数据选择参考学生并录入成绩
  -> 按已发布页面配置查询、查看和编辑测评记录
```

教学管理菜单按业务职责组织为“基础资料、教学组织、学业评价”。静态或动态来源是实现事实，不在面向普通业务人员的菜单中拆成两套产品；来源与接入差异只在模块治理、演示导览和开发文档中展示。

## 业务对象与来源划分

| 业务域   | 模块/对象     | 来源     | 聚合与关系               | 主要能力                             |
| -------- | ------------- | -------- | ------------------------ | ------------------------------------ |
| 基础资料 | 学科分类      | 静态     | 分类树                   | 树、同级排序、启停、租户唯一性       |
| 基础资料 | 学生          | 静态     | 独立主数据               | 标题、启停、引用目标、唯一约束       |
| 基础资料 | 教师          | 静态     | 独立主数据               | 标题、启停、引用目标                 |
| 教学组织 | 教学班        | 静态主表 | 引用班主任；拥有班级成员 | 主子表、引用投影、排序分区           |
| 教学组织 | 班级成员      | 静态子表 | 归属教学班；引用学生     | 子表所有权、引用完整性、反向读取     |
| 学业评价 | 考试/测评     | 动态主表 | 引用教学班、学科分类     | 元数据字段、查询、页面编排、修订发布 |
| 学业评价 | 参考学生/成绩 | 动态子表 | 归属考试；引用学生       | 动态主子表、子表编辑、字段投影       |

静态对象承载长期稳定的组织和主数据语义：Java 模型、领域约束、引用完整性与聚合所有权应可直接阅读。动态对象承载易变的评价字段与页面表达：测评类型、附加指标、查询项、表单布局和展示字段可由元数据与页面配置治理。不能因为来源不同重复实现 CRUD、权限或审计流程。

## 关系设计

```text
学科分类（树）
       ↑
       └──────── 考试/测评（动态主表）

教师（静态） ── 班主任 ──> 教学班（静态主表）
学生（静态） ────────────> 班级成员（静态子表） ──归属──> 教学班
学生（静态） ────────────> 参考学生/成绩（动态子表） ──归属──> 考试/测评
教学班（静态） ──────────> 考试/测评（动态主表）
```

关系必须表达真实业务事实：

- 教学班删除时，班级成员按子表所有权处理；学生删除受班级成员引用完整性约束。
- 考试子表只持久化学生引用 ID、参考状态、成绩等考试事实；学生姓名、学号等应由引用标题或只读投影提供，不能由 bootstrap 或前端复制维护。
- 动态测评对教学班、学科分类和学生的引用必须走平台 `ReferenceTarget`、候选查询、标题解析和数据范围链路。

## 能力验收矩阵

| 能力         | 主展示场景                       | 验收事实                                                 |
| ------------ | -------------------------------- | -------------------------------------------------------- |
| Tree         | 学科分类                         | 可维护层级、同级排序、启停；下游引用只允许选择有效节点   |
| 静态主子表   | 教学班—班级成员                  | 保存聚合时自动维护子表归属；成员排序仅在所属班级内生效   |
| 静态引用     | 班主任、成员学生                 | 候选、标题投影、删除约束和反向读取均由平台能力执行       |
| 动态主子表   | 考试—参考学生/成绩               | 元数据关系生成动态子表，页面保存使用标准 `children` 语义 |
| 动态页面治理 | 考试模块                         | 页面定义、变体、修订、草稿预览与发布使用同源 descriptor  |
| 动静引用     | 动态测评引用静态班级、学科、学生 | 选择、展示、读投影、数据范围与删除约束均复用统一引用契约 |

每项能力只指定一个主场景，避免为了展示平台而复制多组语义相同的样例。动态树不是本场景一期的必要重复样例；树先由学科分类承担，动态侧优先收口跨来源引用与动态主子表。

## 已收口前置能力

动态字段引用已通过来源无关的 `MetadataFieldReferenceConfig` 接入统一 `ReferenceTarget` 契约：动态目标继续以模块主元数据声明，静态目标以完整平台模块别名和实体段声明。两类目标均通过同一引用能力完成候选、标题、读投影、数据范围和引用完整性。

因此，动态测评可直接引用静态学生、教学班和学科分类；不得以冗余 `studentNo`、`studentName` 等字段代替该能力。页面定义、变体、修订和真实 descriptor 渲染仍是本场景下一步需要完成的交付闭环。

## 现有教育演示的迁移口径

| 当前对象             | 目标处理                     | 原因                                           |
| -------------------- | ---------------------------- | ---------------------------------------------- |
| 学生、教师           | 保留为静态主数据             | 已适合承载稳定身份和引用目标                   |
| 班级、班级成员       | 保留并收敛为教学班聚合       | 已覆盖静态主子表、引用与排序分区               |
| 爱好分类树           | 替换为或重构为学科分类       | 让树直接进入教学评价主线，不保留孤立能力样例   |
| 考试、参考学生       | 保留为动态测评聚合并重建引用 | 保留动态主子表和页面治理价值，去除复制字段方案 |
| 通知触发器等专项样例 | 保持独立，不纳入核心业务主线 | 避免扩大一期场景范围                           |

仓库尚未上线，不保留历史示例的兼容迁移负担；但每一步替换仍应以运行态、Web 契约与演示验收测试锁定行为。

## 推进顺序

1. 为动态字段补齐静态目标引用的来源无关门面、验证与契约测试。
2. 按本设计重塑教育静态主数据、教学班聚合和动态测评元数据；删除复制字段。
3. 为动态测评建立页面定义、变体和修订，并以真实 descriptor 渲染列表、查询、详情和编辑。
4. 添加以业务主线为单位的演示验收：从主数据维护到考试子表录入、引用展示和页面发布。

在第 1 步完成前，不开始对现有 `education.exam` 做表面改名或页面重排。
