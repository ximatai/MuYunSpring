# MuYun Web 主题颜色体系

本文定义 MuYun Web 的颜色设计语言。它将原始调色板、稳定视觉语义和具体组件实现分离，使工作台、平台管理页、动态页面运行器与 UI adapter 使用同一套颜色规则。

本文不引入暗色主题，也不承诺当前阶段支持用户自行选择主题；它先固定默认主题和未来可替换的边界。

## 设计目标

1. 页面不再用某个颜色表达多个无关含义。
2. 当前导航、主要操作和焦点属于主题表达；成功、风险和失败属于业务状态表达。
3. 一个主题不是一个单独色值，而是一组有状态层级的颜色。
4. 业务页面消费语义 token 和 MuYun 组件，不直接消费 Ant Design Vue 的主题 token 或原始十六进制色值。

## 颜色角色

| 角色       | 英文 token 前缀 | 解决的问题                             | 典型使用                                     |
| ---------- | --------------- | -------------------------------------- | -------------------------------------------- |
| 主题色     | `theme`         | 品牌识别与当前交互焦点                 | 主操作、当前导航、链接、开关开启、键盘焦点   |
| 品牌点缀色 | `brand-accent`  | 品牌识别中的次级强调，不承载业务状态   | 品牌标志细节、极少量宣传或引导装饰           |
| 陪衬色     | `support`       | 保持页面秩序而不抢占注意力             | 画布、表面、普通 hover、边框、次级文字与图标 |
| 友好高亮色 | `positive`      | 表达已完成、健康、已启用等正向业务事实 | 成功回执、健康状态、已启用状态、正向趋势     |
| 警告高亮色 | `warning`       | 表达待处理、临界或潜在风险             | 风险提示、待确认、受限操作                   |
| 危险高亮色 | `danger`        | 表达错误、破坏性或不可逆动作           | 删除、失败、校验错误                         |
| 信息高亮色 | `info`          | 表达说明、进行中或中性通知             | 帮助说明、处理中、非紧急提醒                 |

“陪衬色”不是第二个品牌色。它以低饱和中性色和表面层级为主，负责让主题色和状态高亮只在有必要时出现。

## 默认主题的取舍

默认主题使用现有视觉基线的工程蓝：`palette_brand_base #0052D9`。它是唯一用于当前导航、主按钮、焦点和链接的主题入口。

绿色不作为当前主题色。现有成功绿 `palette_success_base #00A870` 映射为友好高亮色，保留给“启用、完成、健康、成功”等业务事实。工作台菜单中用于选中或 hover 的青绿色应逐步迁移到主题色 token，避免“当前位置”被误读为“已成功”。

### 徐工色彩参考

复查徐工公开品牌资料后，能够确认其企业标志以蓝、白为基调；公开资料没有给出可直接复用的官方十六进制标准色，也没有将黄色定义为企业标志主色。因此本系统不将未经授权的近似色宣称为“徐工官方标准色”。

本实现吸收其工程制造的蓝色识别，并增加暖黄 `brand-accent`（默认 `#F5B700`）作为可替换的品牌点缀输入：工作台标志保持纯主题蓝，菜单层级切换器使用黄色作为受控的品牌强调，但黄色不进入 `warning`。这样既保留未来替换为正式 VI 色值的单点入口，也不会把品牌装饰误解为风险提示。

## 色阶契约

`theme`、`brand-accent` 与所有状态色都提供以下 token；组件不得自行从 `base` 推算透明度或临时生成浅色。

| 色阶                         | 用途                               |
| ---------------------------- | ---------------------------------- |
| `base`                       | 常规强调、图标、状态点、主按钮底色 |
| `hover`                      | 指针悬停                           |
| `active`                     | 按下或持续激活                     |
| `soft`                       | 轻量选中背景、提示背景、弱强调面   |
| `soft-text`                  | 在 `soft` 表面上的可读文字         |
| `border`                     | 该角色对应的结构或提示边界         |
| `focus`                      | 焦点环、键盘可达提示               |
| `disabled` / `disabled-text` | 禁用态                             |

`support` 采用表面与文本层级，而非强行套用 `base`：`page`、`canvas`、`surface`、`elevated`、`hover`、`border`、`border-subtle`、`text`、`text-muted`、`icon`。这些值由视觉基线中的 surface、border、text palette 映射。

## 三层映射

```text
原始调色板
  -> 主题与状态语义 token
    -> MuYun 组件 token / Ant Design Vue adapter token
```

原始调色板允许主题包替换；语义 token 是应用代码的稳定消费面；组件 token 只存在于 adapter 内部。

例如默认主题中：

```text
palette_brand_base       -> --muyun-theme-base       -> Ant colorPrimary
palette_brand_light      -> --muyun-theme-soft       -> 菜单选中背景、表格选中行
palette_brand_accent     -> --muyun-brand-accent-base -> 标志与品牌装饰
palette_success_base     -> --muyun-positive-base    -> 成功通知、健康状态
palette_surface_subtle   -> --muyun-support-hover    -> 普通 hover 和弱分区
```

业务页面和 `platform-workbench` 只使用 `--muyun-theme-*`、`--muyun-support-*`、`--muyun-positive-*` 等语义变量。`vue-ui-antdv` 负责把同一主题映射到 Ant Design Vue 的 `ConfigProvider` 与必要的组件级 token；业务层不得直接引用 `--ant-*` 或 `colorPrimary`。

`UiThemeProvider` 是语义颜色和 Ant 主题的同一作用域边界：CSS variables 写在 Provider 根节点而不是 `document.documentElement`，因此嵌套、卸载或临时预览主题不会污染应用其他区域。Provider 使用 `display: contents`，不额外介入业务页面的 flex/grid 布局。应用根 Provider 覆盖整个工作台；需要局部预览时，必须同时由该 Provider 包住 CSS 消费者与 Ant 组件，不能只改其中一侧。

## 组件使用口径

| 场景                                         | 颜色角色       | 禁止用法                                     |
| -------------------------------------------- | -------------- | -------------------------------------------- |
| 当前菜单、页签、主操作、链接、开关开启、焦点 | `theme`        | 使用 `positive` 只因颜色更醒目               |
| 文字兜底头像、系统身份标记                   | `theme`        | 将用户上传的真实头像强行染成主题色           |
| 品牌标志、菜单层级切换器等受控品牌强调       | `brand-accent` | 作为警告、失败、通用导航选中态或普通主操作色 |
| 普通悬停、面板分区、弱化边框、次级图标       | `support`      | 为每个 hover 使用主题浅色                    |
| 完成、健康、启用、成功反馈                   | `positive`     | 作为当前导航或默认主操作色                   |
| 待处理、风险、受限                           | `warning`      | 作为普通信息提示或主操作色                   |
| 删除、失败、阻断性错误                       | `danger`       | 用于普通取消或弱操作                         |
| 帮助、说明、进行中                           | `info`         | 与主题当前态混用                             |

主题色可以在未来替换为青绿、靛蓝或其他品牌调色板，但上述组件语义不改变。主题切换不会让成功状态、危险操作或警告提示跟着变成主题色。

## 实施边界

当前要做：

1. 在 `vue-ui-antdv` 建立单一默认主题定义，并生成 CSS semantic variables。
2. 用该定义配置 Ant Design Vue，补齐主要操作、焦点、输入、开关、表格选中与反馈的 adapter 映射。
3. 迁移 `platform-workbench` 的硬编码青绿色和全局样式中的零散默认蓝，优先修正导航与状态语义。
4. 为主题映射、导航选中、成功反馈和危险操作补测试；以工作台颜色契约检查防止平台层继续引入未经声明的十六进制颜色常量。

后续预留：

- 以相同角色契约新增主题包，例如 `teal`、`violet`；它们只替换 palette 与派生的 `theme` token。
- 在完整暗色表面、边框、文本和状态色得到设计验证后，再增加暗色主题。

当前明确不做：

- 让每个用户任意输入品牌色后在运行时猜测整套色阶。
- 向业务页面透传 Ant Design Vue 的完整主题配置。
- 仅替换 `colorPrimary` 就宣称已支持完整主题。
