# 统一树与平铺拖拽组件专项治理

本文记录 MuYun 前端统一树/平铺展示组件的目标能力、交互契约、异步加载、结构动效和仓库治理边界。它先固定长期方向，不等同于当前实现已经全部完成。

设计以完整业务体验和公共能力复用为依据。实现缺口由实现与验证补齐，不能反向降低需求；阶段交付可以分步完成，但专项验收仍覆盖本文全部目标。内部机制可以调整，已有合理能力不因 renderer 或实现成本而静默降级。

## 治理目标

MuYun 当前同时存在树、平铺列表和页面编排三类节点交互：

| 场景         | 当前承载                                                   | 主要问题                       |
| ------------ | ---------------------------------------------------------- | ------------------------------ |
| 标准树资源   | `UiTree` / `TreeRecordExplorer`                            | 统一树展示，领域层保留排序规则 |
| 标准平铺资源 | `UiTree` / `RecordListExplorer` / `CrudRecordListExplorer` | 统一平铺展示与拖拽协议         |
| 页面配置编排 | `PageCompositionTree` -> `UiTree`                          | 领域层仍需解释嵌套容器移动语义 |

这些组件的视觉表达相近，但选择、拖拽、跨组件投放、异步节点和状态变化没有统一公共契约。专项目标是形成一个可复用的基础交互能力，同时保留业务组件对领域规则和持久化的所有权。

## 核心原则

1. 公共组件统一节点身份、选择、复选、拖拽、异步状态和动效协议，不承载 CRUD 查询、业务权限、页面草稿或后端保存。
2. `tree` 和 `flat` 是同一套节点模型的两种展示适配器，不是两套互不兼容的组件 API。
3. 拖拽分为同实例排序、跨实例复制、跨实例移动和嵌套容器移动，不能用一个模糊的 `drop` 语义掩盖差异。
4. 异步数据既支持组件托管，也支持父页面受控；默认使用组件托管，复杂页面可以接管节点数据和缓存。
5. 动效主要跟踪节点结构变化；选中、展开、复选和加载状态使用各自的状态反馈，不冒充结构移动。
6. 业务事实在业务层产生，组件只发出规范化意图。排序、字段归属、页面草稿和发布仍由对应业务状态或平台 client 处理。
7. 所有节点必须有稳定且唯一的 `key`。节点的展示标题、标签和位置都不能替代身份。
8. 不以减少依赖数量或绝对去 vendor 为独立目标。只要底层库能显著提高可访问性、交互稳定性、动效质量或维护效率，且版本、许可证、性能和升级成本可接受，绑定底层库就是合理方案；是否做 adapter 按实际收益决定。

## 统一节点模型

公共组件继续使用来源无关的节点模型：

```ts
interface UiTreeNode {
  key: string;
  title: string;
  secondary?: string;
  tag?: string;
  muted?: boolean;
  disabled?: boolean;
  isLeaf?: boolean;
  children?: UiTreeNode[];
}
```

业务扩展字段不进入基础节点的固定语义；需要参与拖拽或投放时，通过拖拽 payload 或业务侧节点映射表达。

### 身份、结构与容器能力

节点 key 在同一实例内全树唯一且非空，跨实例使用实例身份与节点 key 共同定位。输入和异步合并应校验重复身份；复制产生的新业务身份由数据所有者分配，基础组件不生成领域 ID。

`children` 表达已知结构，分支加载状态表达是否尚未加载、正在加载或仍有下一页，投放策略表达是否允许接收某个来源。三者不能互相替代。`isLeaf` 只参与结构展示，不能决定是否允许移入子级；空节点也可以是合法容器，无需伪装成未加载分支。

根容器具有独立身份与投放区域。空树、空列表及非树预览区应能接收合法投放，不依赖虚构业务节点。Flat 的节点只有前后插入位置，Flat 根容器可以接收内部插入。

## 展示模式

### Tree 模式

Tree 模式支持：

- 多级父子结构；
- 展开/收起；
- 异步子节点加载；
- 同父级排序；
- 可选树形复选级联；
- 节点动作、选中和禁用状态。

标准记录树由 `TreeRecordExplorer` 对接后端树移动协议：节点中部表示移入子级，前后横线表示在目标同级插入，根层显式传 `parentId: "root"`。父级可改变，运行态声明的其他排序分区仍须一致；自身、后代和搜索过滤状态不接受结构移动。

树内拖拽是否允许改变父子关系由业务 `canDrop` 决定。默认不因为“拖到节点上”就隐式改变父子关系；需要结构移动的页面必须显式声明目标区域和规则。

### Flat 模式

Flat 模式消费有序的一维节点集合，保留与 Tree 模式一致的 item 视觉、选择、动作、复选和拖拽事件。

Flat 模式支持：

- 纵向排序；
- 跨组件复制或移动；
- 关键字过滤后的只读展示；
- 与 Tree 模式一致的节点 descriptor。

Flat 模式不解释 `children`，也不自行推导父子关系。需要树形语义时必须使用 Tree 模式。

## 选择与复选

复选框默认隐藏，由 `checkable` 显式开启。

### Tree 模式

支持两种复选语义：

- 级联模式：父节点、子节点和半选状态由树关系计算；
- 严格模式：节点之间独立选中，不因为父子关系联动。

复选值通过受控的 `checkedKeys` / `update:checkedKeys` 契约同步，组件同时发出包含当前节点、选中 key 和半选 key 的规范化 `check` 事件。

### Flat 模式

Flat 模式只有独立复选，不产生半选状态。复选框不应阻断节点选择、行内动作或拖拽手柄之外的正常点击语义。

节点 `disabled` 时，选择、复选和拖拽都必须遵守禁用规则；业务可以通过 `canDrag` 和 `canCheck` 做更细的权限限制。

选中、展开和复选各有唯一状态所有者：受控时以输入为准，组件托管时使用明确初值与更新事件。拖动、点击复选框和行内动作不应顺带改变节点选择；动作可用性由动作契约表达，不从视觉弱化状态推断权限。

懒加载树的级联复选必须区分已加载节点集合与服务端范围选择。组件维护已加载节点的选中和半选一致性，新增子节点按已声明的级联规则重新计算；“包括尚未读取的全部后代”属于业务范围契约，不能仅凭一个父 key 静默解释。

Tree 与 Flat 均须有可聚焦的选择入口、键盘操作和清晰焦点反馈。排序、跨容器移动及复制应支持键盘拖拽或等价的可访问命令，复用同一投放策略和业务命令；提供替代操作不意味着鼠标拖拽可以缺少完整反馈。

## 拖拽协议

### 拖拽来源

组件提供统一的拖拽来源能力：

- `canDrag(node)` 判断节点是否可作为来源；
- `dragPayloadOf(node)` 生成来源无关 payload；
- `dragPayloadType` 标识 payload 类型；
- `drag-start` 暴露规范化来源身份与节点，原生事件仅作可选观测信息；
- 原生 `DataTransfer` 只承载可序列化的跨组件数据，不承载 Vue 实例或业务状态引用。

没有声明跨组件来源时，组件仍可以只提供同实例排序，不强制产生外部 payload。

### 投放类型

统一区分以下投放语义：

| 语义       | 典型场景                     | 组件输出                                     |
| ---------- | ---------------------------- | -------------------------------------------- |
| 同实例排序 | 同一树的同级节点、平铺列表   | `dragNode`、`dropNode`、相对位置             |
| 跨实例复制 | 可用字段 → 页面字段          | payload + 目标区域，来源保留                 |
| 跨实例移动 | 工作区之间转移同一节点       | payload + 目标区域，来源移除由业务决定       |
| 嵌套移动   | 表单字段 → 分组、分组 → 表单 | source container、target container、目标下标 |

`canDrop` 只负责判断投放是否成立；真正的复制、移动、排序和持久化由业务层执行。组件不根据节点标题或 DOM 位置猜测业务关系。

### 规范化目标与操作语义

公共协议使用 `before`、`after`、`inside` 表达位置，目标明确区分节点与根容器；不让调用方组合 `dropPosition` 与 `dropToGap` 猜测有效含义。前后位置相对于目标节点，内部位置表示容器末尾；容器中已有节点时可以通过其前后位置精确插入。嵌套移动继续保留来源容器、目标容器及目标下标语义，由业务 adapter 基于规范化位置解析。

来源上下文包含实例身份、节点身份和可选的类型化 payload，操作明确表达 `copy` 或 `move`。来源声明允许的操作，目标策略只能在其中选择；同实例排序无需额外序列化业务数据。跨实例 key 相同不表示同一节点，也不能仅凭 payload 类型相同就接受投放，接收方还须校验数据结构和领域归属。

悬停反馈、键盘替代操作和释放提交使用同一目标解析与准入规则。数据或权限状态变化后需重新校验；没有显式目标策略时不接受投放。对不完整的同级数据，业务 adapter 不猜测不可见邻居，应取得足够的排序事实或拒绝该位置。

`copy` 保留来源；`move` 由拥有业务操作的协调者在成功后转移数据，失败时保留来源，组件不抢先删除节点。涉及多个数据所有者时由业务协调一致性，基础组件只提供完整意图与会话结束反馈。字段目录投放后目录保持不变，页面已有字段的重新定位由草稿唯一归属规则处理。

### 公共 API 接入

组件的投放策略 prop 为 `allowDrop(event)`；本文的 `canDrop` 指同一准入职责。`UiTreeDropEvent` 包含 `source`、`target`、`operation` 和可选观测事件，不携带第三方树事件。`drag-start` 直接提供 `UiDragSource`，`drag-end` 提供 `cancelled`，业务不需要再查询全局拖拽状态。

| API                              | 契约                                                                                   |
| -------------------------------- | -------------------------------------------------------------------------------------- |
| `source`                         | `instanceId`、`node`、允许的 `operations`、可选 `payloadType` / `payload`              |
| `target`                         | `instanceId`，以及 `kind: 'node'` 的节点和相对位置，或 `kind: 'root'` 的 `inside` 位置 |
| `dragOperations`                 | 来源允许的 `copy` / `move` 集合，默认 `['move']`；字段目录显式声明 `['copy']`          |
| `dropOperation(source)`          | 接收方从来源允许的操作中选择一种，默认采用来源首选操作                                 |
| `useUiDropTarget(root, options)` | 非树目标复用公共会话；解析目标、准入、操作选择和领域命令由适配器提供                   |
| `changeReason`                   | `interaction`、`filter`、`reset`；数据所有者在更新数据时同步表达原因                   |

复制与移动事件都不直接修改 `nodes`；同实例身份检查及树环保护在公共层兜底，领域策略仍负责排序分区与合法容器。结构更新和自动打开目标路径同时发生时，关闭 Ant 的旧展开快照过渡，避免同一身份短暂渲染两次；单纯展开/收起继续使用展开动效。

### 输入与业务协议边界

Tree、Flat 和非树目标（如页面预览区）消费同一规范化投放上下文。业务处理只依赖 payload、操作和目标，不读取 `DataTransfer` 或第三方节点对象；原生事件的缺失不得影响命令执行。

HTML5 拖拽的编码、解码和原生事件适配留在 UI adapter，页面内指针会话可以直接传递公共上下文。不得通过模拟 `DataTransfer` 让业务继续依赖浏览器传输细节，也不要求业务用 `nativeDragSource` 等实现方式开关补救跨组件行为。更换输入 adapter 不改变业务命令。

### 交互与视觉

拖拽过程至少需要统一：

- 来源节点拖拽态；
- 目标区域高亮；
- 上方/下方或容器内的投放指示；
- 不可投放时的反馈；
- 空容器可见的投放区域；
- 拖拽取消后的视觉恢复。

原生拖拽、指针拖拽和 Sortable adapter 可以是不同实现，但必须输出同一份平台事件，不能让业务页面分别理解 Ant Tree、HTML5 DragEvent 和 SortableEvent。

Tree/Flat 的拖拽会话、投放判定和反馈由公共交互层统一管理。采用该层时，Ant Tree 仅承载树展示、展开与复选，不同时启用其拖拽引擎。跨组件悬停、离开与投放共享同一 payload；取消、失焦和组件卸载必须清理来源与目标反馈。业务 adapter 继续负责排序分区、字段归属和持久化。

一个手势只有一个所有者，区分待启动、拖动、提交与取消，达到阈值后才启动。按钮、输入框和复选框不启动拖拽；释放时重算目标，一次手势最多提交一次，结束后不误触发选择或双击。来源移除、目标失效、Esc、失焦、输入取消和卸载均有明确清理路径。

长树和长列表应支持拖动期间滚动到目标，嵌套滚动区域的命中与插入反馈保持一致。缩进、标题、辅助文本等同一行区域应解析为一致节点；跨层级目标须能通过展开后投放到达，不因 renderer 命中差异遗漏合法位置。浏览器和输入设备支持范围以真实验证为准，不能由 jsdom 模拟事件推断。

## 异步加载与懒加载

异步加载只对 Tree 模式有结构意义，Flat 模式不通过 `children` 做隐式懒加载。组件需要支持以下策略：

### 组件托管模式（默认）

组件在节点展开时调用 loader，loader 返回显式加载结果；组件管理该节点的请求生命周期、最小 loading 时长、空分支处理和加载缓存。适合普通树资源和标准动态页面。

```text
expand -> loading -> replace/append children -> expanded
                 -> empty
                 -> error/retry
```

### 外部受控模式

组件只发出加载请求，父页面负责请求、缓存和更新 `nodes`。组件根据传入数据变化更新展示和动效，不直接拥有业务节点状态。适合页面编排、复杂权限或已有状态中心的场景。

### 数据与请求所有权

完整数据展示无需启用异步加载。启用后，托管与受控是互斥的数据所有权，不以 loader 返回 `void` 或函数参数个数判断模式。

| 责任                                | 组件托管                           | 外部受控                                 |
| ----------------------------------- | ---------------------------------- | ---------------------------------------- |
| 权威子树、游标、节点状态            | 组件持有，loader 返回结果          | 父级持有并显式传入                       |
| 请求去重、完成、取消和旧响应隔离    | 组件管理 loader Promise 与取消信号 | 父级管理请求作用域，组件只发出意图       |
| 展开、loading、空态、错误和重试入口 | 组件根据内部状态呈现               | 组件根据父级状态呈现，能力与托管模式一致 |
| 新快照或作用域切换                  | 同步失效相关缓存和请求             | 父级同步替换数据与状态并取消旧请求       |

托管模式以明确的数据版本或重置入口接收新权威快照；本地子树、loaded 标记、游标和错误同步失效。不能在丢弃子节点后保留“已加载”标记，也不能因无关节点的展示属性变化取消全部分支请求。普通节点刷新仅影响相应分支，新结果返回前保留可用数据。

受控模式必须显式接入节点 loading、error、empty 和分页状态。组件不能在发出事件或等待最小展示时长后自行认定请求完成；取消信号由实际请求所有者维护，直至请求结束或作用域释放。父级复用平台请求治理能力处理并发，避免每个业务页面复制同一套状态机。

分支的展开状态与加载状态独立。成功空结果有明确空态，不冒充未加载或失败；空分支折叠、折叠后释放缓存和重新展开加载均由显式策略控制。释放缓存须同步失效 loaded 状态；最小 loading 展示时长不改变真实请求生命周期。

公共托管 loader 签名为 `(node, request) => Promise<UiTreeLoadResult>`。结果必须包含 `mode`、`nodes`、`hasMore`，有下一页时提供 `nextCursor`；请求包含 `reason`、可选 `cursor`、`requestId` 与 `signal`。调用方应将取消信号传入支持取消的 client，或在修改业务映射之前检查信号。

受控组件通过 `branchStates` 接收每个 key 的 `status`（`idle/loading/loaded/error`）、游标、是否有下一页、错误和失败请求；`load-request` 只携带 `UiTreeLoadIntent`，不伪造父级请求的取消信号。父级可以复用导出的 `useTreeData({ nodes, loader, version })` 管理真实请求；这些配置使用 getter 读取响应式值。`request`、`retry`、`release` 与 `reset` 统一管理父级数据和状态，`retryNode(key)` 是组件对应的重试命令。

托管刷新替换该节点的整个子树，同时失效旧后代缓存和未完成请求；新结果校验成功前保留旧子树。这样父节点的新结果不会被同 key 后代的旧缓存再次覆盖。分页追加保留其他已加载分支，重复的非终页游标作为错误处理。

### 数据合并模式

加载结果明确区分：

- `replace`：刷新或首次加载，替换当前子节点集合；
- `append`：分页、游标或“加载更多”，追加子节点。

加载协议还必须支持节点级刷新、请求去重、旧请求隔离、空结果和取消后的安全回收。`refreshNode(key)` 表达重新读取该分支；重试表达重新执行失败的操作，不能把失败的分页追加误当成整分支重置。旧请求不得覆盖新的节点快照。

`UiTree` 对外提供 `refreshNode(key)` 与 `loadMore(key)` 命令，分别对应 `refresh` 和 `load-more` 请求原因；游标和 `replace` / `append` 的合并仍由组件协议统一处理，业务 loader 只负责返回节点结果或在受控模式下更新上游数据。

分页结果明确是否还有下一页；有下一页时给出可用游标，终页清除旧游标并关闭加载更多入口，再次调用也不产生重复请求。相同分支与游标的并发请求合并；刷新替代旧分页请求，节点移除、快照切换或卸载取消相关请求，即使 loader 忽略取消，旧响应也不得生效。

追加按稳定 key 合并：同一父级已存在的节点更新内容并保留顺序，新节点按返回顺序追加；同一批重复 key 或与其他分支冲突的身份应作为数据错误处理，不能生成重复节点。刷新与追加都应校验合并后的身份和结构。

首次加载失败显示节点错误和重试入口，不显示为“没有数据”。刷新或分页失败保留已有内容，重试保留失败操作所需的游标；刷新、追加与重试均有节点级 busy 反馈，不能只在展开时显示 spinner。

## 结构动效

动效以节点结构前后快照为基础，不依赖某一种拖拽库事件。组件或其 adapter 识别以下变化：

```text
enter     新增节点
leave     删除节点
move      同容器位置变化
reparent  父节点或目标容器变化
update    标题、标签等展示信息变化
```

默认动效策略：

1. 首次加载和整树刷新不播放移动动画。
2. 普通新增、删除、排序、跨容器移动和懒加载插入播放结构过渡。
3. 展开、收起、选择、复选和 loading 使用独立状态动画。
4. 搜索过滤和批量替换默认关闭位置移动动画，避免全列表跳动。
5. 默认时长保持在约 160～240ms，允许主题统一调整。
6. 遵守 `prefers-reduced-motion`，系统要求减少动效时降级为无位移动画。

Flat 模式可以使用标准 FLIP/TransitionGroup 实现同容器移动。Tree 模式按每个同级容器计算位置；跨父节点移动默认表现为旧位置离开、新位置进入，只有在渲染层具备稳定 FLIP 信息时才做连续位移动画。

### 变化识别与生命周期

`enter`、`leave`、`move`、`reparent`、`update` 均是必须识别和覆盖的变化语义。结构快照至少能确定节点 key、父容器和同级顺序；只比较 DOM 矩形不足以区分排序、展开和过滤。标题/标签等 `update` 使用适合内容变化的反馈，不把未移动节点播放为重排。

数据所有者提供变化原因，公共层结合前后快照判定反馈。交互引起的排序或跨父级移动，即使随后重新查询数据，也应保留该操作的变化语义；后台全量刷新、搜索过滤和批量替换则按抑制策略处理。展开产生的可见节点变化不应误报为业务新增。

Tree/Flat 共用动效时长和减少动效策略。结构更新尽量保留 renderer 实例与稳定 key，不能先卸载组件再要求其识别前后位置。离开动画需保留必要的离场节点；跨父级的离开与进入须可关联，同容器移动避免重复播放。快速连续更新、动画中取消、减少动效设置变化和卸载都要安全终止或更新动画任务。

结构反馈不得破坏选择、焦点和展开路径。标准树移动成功后保留有效展开状态并打开目标路径，刷新不重新覆盖为首次加载的默认层级；即使关闭动画，用户也应能定位移动结果。领域写入成功与后续刷新失败分别呈现，不把读取失败误报为移动未执行。

## 分层边界

```text
UiTreeCore / UiTree
  -> 节点展示、选择、复选、展开、拖拽、异步状态、动效

TreeRecordExplorer / RecordListExplorer / PageCompositionTree
  -> 数据加载适配、过滤、领域规则、容器语义、页面状态

web-core / 业务状态 / service
  -> 权限、CRUD、排序、草稿、发布和持久化
```

`UiTree` 不应演变成带 CRUD 查询、HTTP、领域权限和保存按钮的业务容器。`TreeRecordExplorer`、`CrudRecordListExplorer` 和 `PageCompositionTree` 可以继续存在，但应逐步消费统一的基础交互协议。

内部优先按节点索引/结构快照、拖拽会话、异步分支状态和动效调度分离职责，Tree/Flat renderer 处理各自的 DOM、焦点与展示。公共行为独立验证，组件保留清晰装配入口；拆分以消除重复状态和降低变更耦合为依据，不以新增文件或另建框架为目标。

公共投放能力还须服务非树目标，不在 `PageCompositionWorkspace` 或预览组件中重新维护拖拽会话。领域 adapter 只转换字段归属、分组和合法下标；公共事件中保留足够的来源与目标事实，避免页面回到 DOM 或第三方事件中补找信息。

## 实现依赖策略

依赖策略的目标是用可接受的维护成本获得稳定能力，而不是机械地删除依赖包或追求形式上的完全解耦。底层库绑定本身不是问题，无法控制业务语义、升级风险或测试成本时才是问题。

### 依赖决策规则

引入或保留底层库时，按以下顺序判断：

1. 能否直接满足 Tree/Flat、拖拽、复选、懒加载和动效等真实需求；
2. 复用它是否明显低于 MuYun 自己实现和长期维护的成本；
3. 版本稳定性、许可证、性能、浏览器兼容和升级风险是否可接受；
4. 底层 API 是否会迫使业务页面理解第三方内部事件或数据结构；
5. 是否需要 adapter，以及 adapter 的复杂度是否真的换来了稳定边界。

如果前 3 项收益明显、后 2 项风险可控，即使组件直接绑定 `ant-design-vue` 或 Sortable，也可以接受。adapter 不是必须存在的架构装饰；它只有在统一多个底层实现、隔离高频变化或显著降低业务接入成本时才值得保留。

### 允许保留和引入的依赖

以下依赖可以根据真实收益纳入实现：

- `ant-design-vue`：继续作为 MuYun 整体 UI 体系和部分基础控件的实现来源；
- `Ant Tree`：在过渡阶段作为 Tree renderer 或兼容 adapter，复用其成熟的展开、键盘、ARIA 和级联复选能力；
- `vue-draggable-plus` / Sortable：在需要可靠处理复杂嵌套容器时作为局部拖拽 adapter；
- Vue 原生 `TransitionGroup`、PointerEvent、DragEvent：用于 MuYun 自有的 Flat renderer、拖拽协议和结构动效。

是否使用某个依赖，以它是否减少重复实现、降低交互风险和提供可验证的浏览器行为为判断依据。不能为了追求“零依赖”而重新实现已经成熟且容易出错的可访问性或拖拽细节。

### 优先保持稳定的 MuYun 契约

无论底层使用 Ant Tree、Sortable 还是原生 DOM，以下内容属于 MuYun 的稳定交互语义，优先由 MuYun 定义。它们可以委托底层库实现，不要求全部重新实现：

- `UiTreeNode` 和节点身份规则；
- Tree/Flat 统一的选择、复选、异步和动效状态；
- 同实例排序、跨实例复制/移动和嵌套移动的拖拽语义；
- `canDrag`、`canDrop`、payload 类型和 drop zone 契约；
- loading、empty、error、retry、replace、append 的异步状态；
- `enter`、`leave`、`move`、`reparent`、`update` 的结构变化分类；
- 业务层接收的事件和值类型，以及必要时对第三方事件的归一化。

业务页面默认不直接消费 `AntTreeNode`、`SortableEvent` 或某个第三方组件的半选值结构。若直接绑定能显著降低复杂度，可以把绑定收敛在 `vue-ui-antdv` 公共组件内，并记录其版本和升级边界；不应让同一套第三方细节散落到多个业务页面。

### 推荐的演进方式

```text
MuYun public contract
  -> UiTreeCore / composables
  -> Tree renderer adapter
       -> Ant Tree
       -> 按综合收益评估的 MuYun renderer
  -> Flat renderer adapter
       -> Vue/native DOM
       -> 必要时局部 Sortable
```

目标不是立即移除 `ant-design-vue`，也不承诺未来一定替换底层 renderer。只要 Ant Tree 在目标场景下的能力、稳定性和维护成本仍然优于自有实现，就可以继续使用；只有在自有 renderer 的综合收益明确超过它时，才评估替换或减少 Ant Tree 的使用范围。

## 迁移路线

### 第一阶段：固定公共契约

- 在 `vue-ui-antdv` 统一节点、拖拽、复选和异步状态类型；
- `UiTree` 完整支持 Tree/Flat 展示能力，内部调用随契约同步迁移，对已明确发布的外部契约维护必要兼容；
- 先建立 renderer/adapter 边界，不因追求减少依赖而提前重写成熟的 Tree 基础行为；
- 提供组件托管 loader 和外部受控 loader 两种入口；
- 增加结构变化动效的默认策略和减少动效降级；
- 用组件测试锁住同树排序、跨组件 payload、懒加载并发隔离和复选语义。

### 第二阶段：迁移现有使用方

- `RecordListExplorer` 的平铺拖拽改为消费统一 flat adapter；
- `TreeRecordExplorer` 的树排序改为消费统一 Tree adapter；
- `PageCompositionTree` 已迁移为单一 `UiTree` 实例，保留页面领域命令，但消费统一跨容器 drop 事件；
- 左侧“可用字段”和右侧“页面结构”都消费 `UiTree`，前者作为拖拽源，后者作为领域投放目标。
- 页面编排的元数据源只暴露运行时可编译字段；平台保留字段（如 `id`、租户和审计字段）仍由元数据治理展示，但不作为页面拖拽源，`enabled`、`sortOrder` 等能力字段按运行时契约保留。

### 第三阶段：完善平台体验

- 补齐键盘拖拽或可访问替代操作；
- 补齐浏览器级拖拽回归测试；
- 评估大数据量树的虚拟化，但不在基础组件尚未稳定前提前绑定虚拟化实现。

## GitHub 仓库治理判断

### 当前结论：跟随 MuYun 项目治理

现阶段不建议立即拆成独立 GitHub 项目，原因是组件仍与 MuYun 的以下平台契约紧密相关：

- `UiRecordExplorerItem` 和 MuYun 主题体系；
- `UiTreeNode`、平台动作和页面 explorer 视觉契约；
- 动态/静态统一页面运行器；
- `web-core` 的模块上下文和排序语义；
- MuYun 当前的构建、测试、发布和 consumer 校验链路。

现在拆仓库会提前引入独立版本、文档、CI、发布和兼容性成本，同时容易把平台组件做成与 MuYun 脱节的通用 UI 库。更合适的做法是在 MuYun 内部先把公共边界治理干净，让它成为一个清晰的可发布 package 边界，而不是复制出第二套实现。

### 未来可以独立拆分的条件

满足以下条件后再评估独立 GitHub 项目或独立 npm package：

1. 组件不再依赖 MuYun 业务类型、模块上下文和页面状态；
2. 主题、item renderer、拖拽 payload 和异步 loader 都有来源无关的公共契约；
3. 至少有两个非 MuYun 消费方或明确的外部使用需求；
4. 已具备独立的单元测试、浏览器拖拽测试、可访问性测试和视觉回归；
5. 有独立维护者、版本策略、变更日志和发布流程；
6. 拆分后 MuYun 仍可以通过稳定 adapter 消费，而不是直接反向依赖 MuYun 内部实现。

在此之前，建议采用“MuYun 单仓库内的平台 package 边界”治理：公共类型和组件保持在 `vue-ui-antdv`，业务适配器留在 `platform-components` / `views`，通过测试和文档维护边界。

仓库治理与依赖治理分开处理：即使未来保留 `ant-design-vue` 或局部 Sortable 依赖，仍然可以先把公共协议、adapter 和业务边界治理好；是否拆成独立项目不以依赖数量作为前置条件。

## 当前不纳入

- 不在基础组件中内置 CRUD、HTTP、权限和后端排序；
- 不把页面编排领域规则抽象成通用节点规则；
- 不强制所有树都支持改变父子关系；
- 不提前建设虚拟滚动、多人协作冲突合并或远程实时同步；
- 不为了独立开源而牺牲 MuYun 当前动静一体的平台契约。

## 验收口径

专项完成时，至少应满足：

1. 同一套节点和事件类型可以驱动 Tree 与 Flat 两种展示；
2. 普通同实例排序、跨组件复制、跨组件移动和嵌套移动可以明确区分；
3. 复选框默认隐藏，Tree 支持级联/严格模式，Flat 支持独立多选；
4. 懒加载支持组件托管、外部受控、replace、append、失败重试和旧请求隔离；
5. 节点结构变化可按 enter、leave、move、reparent、update 分类并触发动效；
6. 初次加载、批量刷新和减少动效环境不会出现不必要的位移动画；
7. 业务页面不需要理解 Ant Tree、原生 DragEvent 或 SortableEvent 的内部差异；
8. 现有应用管理、树管理和页面编排场景可以渐进迁移，不要求一次性重写。

### 验证证据

验收应逐项证明功能、异常路径和实际交互，不能把组件挂载成功或仅向 stub 发射事件视为能力完成：

| 能力             | 必须覆盖的证据                                                                                     |
| ---------------- | -------------------------------------------------------------------------------------------------- |
| Tree/Flat 与复选 | 共用身份和事件、独立/级联/半选、禁用、异步子节点到达后的复选一致性、选择与动作互不误触             |
| 四类拖拽         | 同实例排序、跨实例复制与移动、嵌套容器移动均验证来源/目标及结果；复制保留来源，移动失败不丢数据    |
| 投放与会话       | 精确前后插入、空节点与空根、非树预览区、拒绝反馈、释放前状态变化、取消/失焦/卸载、一次手势一次提交 |
| 托管与受控加载   | 两种模式有等价反馈；请求去重、不同分支并发、快照替换、节点移除、卸载与旧响应隔离                   |
| 分页与重试       | replace/append、身份冲突、终页再次调用、首次失败、追加失败与原游标重试、已有数据保留               |
| 完整结构动效     | 五类变化分别验证；展开不冒充新增；过滤/刷新抑制、连续更新、减少动效及卸载回收                      |
| 业务闭环         | 标准树跨父级移动、根层插入、分区与环保护、移动后定位；页面编排精确插入、分组归属和删除语义         |
| 可访问性与浏览器 | 键盘操作或等价命令、焦点保持、长列表滚动、真实浏览器下完整拖拽生命周期                             |

状态与协议使用 Vitest 单元测试，Vue/DOM 使用组件测试。关键手势须有浏览器级回归，并以真实服务验证标准树移动与刷新链路；动效验收同时覆盖变化分类的逻辑证据和视觉行为。人工验证可以补充自动化难以覆盖的体验，但不能替代专项承诺的浏览器回归。测试失败应修复实现或澄清有依据的契约问题，不通过降低验收要求消除失败。

浏览器回归入口为 `npm run test:browser`，使用 Vitest 的 Playwright provider；首次运行先执行 `npx playwright install chromium`。CI 安装 Chromium 后执行同一个 Vitest 测试入口。当前自动化覆盖 Chromium 桌面鼠标与键盘，其他浏览器及触摸输入需要补充实际验证后再声明支持。

真实服务用例位于 `tests/platform-components/TreeRecordExplorer.browser.test.ts`。仅在配置 `MUYUN_TREE_SERVICE_URL` 和 `MUYUN_TREE_SERVICE_TOKEN` 时运行；必须指向独立、可回收的开发数据库，并使用已完成初始密码设置的测试管理员会话。用例通过正式 HTTP client 与模块上下文创建测试租户和节点，验证跨父级移动、根层移动、服务端读取、renderer 保持及展开路径。普通浏览器测试不依赖后端，服务用例的跳过不构成服务链路已通过的证据。
