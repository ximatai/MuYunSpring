# 后台任务与异步批次边界

本文用于约束后台任务、批处理、异步导入、补偿任务和长耗时执行的建设边界：哪些执行应保持同步，哪些进入平台标准后台作业机制，以及作业运行与专题业务事实、平台运行审计如何分工。后台作业机制本身的设计见 [后台作业与定时调度设计](BACKGROUND_JOB_SCHEDULING.md)。

同步动作仍优先复用现有平台能力：模块动作、动态记录服务、权限、数据范围、租户、校验、生命周期、事务和运行审计。只有当执行需要脱离请求完成，或者需要按计划触发、进度查询、重试、取消、补偿和运行留痕时，才进入后台作业。

## 当前已有事实

| 能力         | 当前口径                                                                                      |
| ------------ | --------------------------------------------------------------------------------------------- |
| 动态批量动作 | `/{moduleAlias}/{actionCode}/batch` 是同步动作宿主，复用动作权限、数据范围和运行事件链路。    |
| 批量删除     | 标准 `batchDelete` 是同步批量动作，不单独建设批次流水。                                       |
| 导入导出     | 当前导入执行返回结果、错误文件名和错误文件 token；暂不持久化异步批次。                        |
| 记录联动     | 生单返回 `batchId`，来源影响关系可按 batch 查询；这是记录联动专题事实，不是后台作业运行。     |
| 编码规则     | 取号重试写入编码 issue log；这是编码专题诊断事实，不是作业运行记录。                          |
| 工作流       | 任务、事件、历史和 after-commit 插件归工作流专题；超期扫描是周期触发，计划迁入后台作业。      |
| 业务内容翻译 | 受权记录入口创建专题生成任务，持久化租约、有限重试与恢复；执行迁为排队作业，译文与生成证据仍归专题。 |
| 配置治理     | 归档、指针切换、dry-run 和导入草稿归配置治理事实；多实体 DDL 补偿仍是触发型技术债。           |
| 日志留存     | 由运行期业务策略驱动日志专题内的有界、幂等、跨实例互斥清理；调度计划迁入后台作业。           |

迁移完成前，上述专题自建的调度保持现状。

## 归属判断

| 执行形态                                                       | 归属                                                         |
| -------------------------------------------------------------- | ------------------------------------------------------------ |
| 请求内可完成的单条或批量动作                                   | 同步动作链路和运行审计，不进入后台作业                       |
| 需要集群内只执行一次的周期工作                                 | 平台后台作业的定时作业                                       |
| 由业务入口发起、脱离请求执行、需要重试或进度的一次性工作       | 平台后台作业的排队作业                                       |
| 低代码侧按计划调用模块动作                                     | 平台后台作业的动态配置作业                                   |
| 只依赖本节点内存状态的周期工作（如本机实时连接扫描）           | 节点本地调度，继续使用 Spring 定时注解                       |
| 启动期幂等初始化                                               | 平台启动任务，不进入后台作业                                 |

触发以下任一条件时，执行应进入后台作业，不再由专题自建调度：

1. 单次执行可能明显超过同步请求可接受时间。
2. 用户需要查询进度、取消或重新执行。
3. 执行需要自动重试、租约接管或幂等入队。
4. 执行按计划触发，且多节点部署时只能执行一次。
5. 执行必须在无登录请求上下文中运行，需要明确执行身份和系统原因。
6. 运维需要查看执行历史或在失败时得到提醒。

## 作业运行与专题事实

后台作业只记录执行过程：触发方式、执行身份、状态、尝试、进度、统计摘要、错误摘要与追踪编号。专题业务事实仍由专题建模，并以作业运行标识关联：

| 专题           | 专题自身保留的事实                                                     |
| -------------- | ---------------------------------------------------------------------- |
| 通讯录同步     | 范围版本、游标、失败页、部门映射与本轮变更统计。                       |
| 业务内容翻译   | 原文修订、译文版本与生成证据，以及面向记录的生成状态查询。             |
| 日志留存       | 留存策略与清理上限；清理结果写入程序日志。                             |
| 导入异步化     | 导入批次、逐行错误与错误文件（触发后建设）。                           |
| 外部写入       | 幂等键、外部回执与报文摘要，按 [外部写入接入边界](EXTERNAL_WRITE_BOUNDARY.md) 建设。 |

逐行数据、外部报文全文、业务字段快照和复杂恢复步骤不进入作业运行记录，由专题按安全、保留期和查询场景单独设计。专题批次或流水的留存独立于作业运行留存。

## 不建设的能力

1. 外部调度框架、独立 worker 集群或跨应用的调度中心。
2. 把所有批量动作都包装成后台作业。
3. 在 `RuntimeAuditRecord` 中保存批次进度、逐条错误、重试明细或补偿过程。
4. 用作业运行记录替代导入、回写、工作流、配置发布等专题的业务事实。
5. 作业之间的依赖编排与任意脚本作业；需要多步编排的业务归工作流或专题自身。

## 与运行审计的关系

运行审计只记录“谁触发了什么动作、以什么身份、授权如何、系统态原因是什么、结果摘要是什么”。作业运行记录“这次执行后来怎么跑、进度如何、是否重试、能否恢复”。两者通过追踪编号、作业类型、计划与运行标识互相定位，不互相替代。
