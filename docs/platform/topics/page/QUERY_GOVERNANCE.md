# 标准列表查询治理

状态：实施中。统一递归条件契约、常驻字段查询、已应用条件反馈和复杂度门禁已完成首轮交付；查询模板参数、条件摘要标签与旧入口退役仍按下列阶段推进。当前 Web 请求与页面声明契约见 [页面交付概览](delivery/OVERVIEW.md) 和 [页面交付 Web API](delivery/WEB_API.md)。

## 目标

标准列表查询采用“常驻查询覆盖日常筛选，高级编排覆盖复杂组合”的交互。静态 Java 模块与动态元数据模块共享查询字段契约、值编辑能力、条件模型和执行语义，业务只声明查询事实和页面表达。

本专项完成以下能力：

1. 时间、字典、业务引用等字段可声明为常驻条件，条件之间固定 AND，单个条件使用符合字段语义的操作符。
2. 高级查询支持递归条件组，以组边界表达括号，每组选择 AND 或 OR；普通使用不要求理解表达式语言。
3. 常驻条件、高级条件和查询模板参数复用查询值编辑器，避免分别实现日期、选项、引用和多值输入。
4. 查询字段与列表展示列解耦，列表、总数和汇总使用同一有效查询，用户始终能够识别当前已应用的筛选。
5. 动静两侧收敛条件校验和编译，页面声明在启动、发布或刷新时编译，请求期只消费已安装计划。

## 能力边界

### 查询能力、页面表达与强制范围

查询字段契约拥有字段身份、值类型、合法操作符、排序资格、选项与引用来源。页面查询声明只拥有常驻字段选择、顺序、标题、默认值和受控展示方式，不创造新的数据库过滤语义。

静态声明与动态配置进入同一编译模型。静态模块应能通过轻量 DSL 指定常驻字段，复用已有模型事实；动态模块以稳定元数据字段身份配置，编译到相同运行态字段引用。普通业务不重复声明字典、引用来源和字段类型。

普通字段查询与业务条件分开建模：部门、状态、日期直接使用字段契约；“仅在线”等非普通字段条件由所属 Service 声明业务过滤，经平台查询契约暴露。不得为每个字段生成自定义 resolver，也不得把业务过滤实现留在 Controller 或前端。

完整查询按以下逻辑组合，AND 表达约束关系，不规定数据库执行顺序：

```text
服务端强制范围（权限、租户、领域约束、记录可见性）
AND 页面及导航范围
AND 常驻条件
AND 高级条件组
AND 快捷搜索条件组
AND 已选择的查询模板条件
```

高级组中的 OR 只作用于该组，不能放宽外层范围。页面默认值和查询模板不是授权机制；必需的领域范围必须独立在服务端施加。SESSION 来源由服务端解析，客户端传入的导航选择仍须校验。

### 字段与数据读取

- 可查询、可展示、可排序是不同资格；常驻与高级查询都不要求字段已经成为列表列。
- 查询目录仅暴露当前模块允许查询的字段，字段保护和可执行性仍在服务端检查。虚拟展示字段不因能够渲染就自动成为可查询字段。
- 引用条件提交记录 ID，展示标题；候选与标题解析复用现有引用契约，不新增裸数据读取入口。
- 不因查询需要某个字段，就自动把该字段加入对外响应。内部执行依赖与输出投影分别治理。
- 查询面以 `NONE`、`FLAT_AND`、`TREE` 声明可用条件编排。`FLAT_AND` 的字段条件仍可自由选择，但只允许根 AND 叶子条件；例如三类日志使用该模式，常驻时间和操作用户与“更多筛选”的日志字段共同收窄结果。
- 特殊查询模块可以声明更窄能力，例如仅平铺 AND、固定排序；标准 UI 必须按真实能力收窄，不能承诺所有查询后端支持完整条件树。

## 前端目标交互

### 常驻查询

列表上方提供独立、可换行的查询区，与业务操作栏分开。较多条件允许折叠，并保留已应用条件摘要。首期支持以下字段语义：

| 字段         | 条件与输入方式                                 |
| ------------ | ---------------------------------------------- |
| 字典、枚举   | 单选 EQ；允许多选时 IN，使用选项名称展示       |
| 业务引用     | 单选 ID 等值或多选 ID 集合，复用引用选择能力   |
| 日期、时间戳 | 日期或时间范围，支持单端范围及受控快捷日期选择 |
| 布尔         | 全部、是、否三态，区别于业务开关的开关语义     |
| 数值         | 等值或数值范围                                 |
| 文本         | 明确声明等于或字面包含                         |

常驻条件之间固定 AND，不向用户展示关系编排。普通字段先编辑，点击查询或回车后统一应用；独立业务开关可声明即时应用。提交任一查询入口时不得隐式应用其他区域未确认的草稿。字段自身可在 `QuerySchema` 中声明默认常驻控件；标准列表据此直接渲染，既有静态或动态页面不应为时间、字典或引用条件增加业务专用前端代码。页面 DSL 只在需要调整顺序、标题、默认值或额外外部业务条件时覆盖这一默认表达。

查询值编辑器由“字段语义 × 操作符”决定：单选与多选、时间点与区间、单值与集合按契约切换。复用已有输入、选项和引用组件，但不继承记录编辑表单的保存、必填、只读和联动副作用。

### 高级条件组

高级查询默认收起，在列表查询区展开草稿编辑。根节点为一个条件组，每个组有统一的“满足全部（AND）”或“满足任一（OR）”关系，子节点可以是条件或条件组。

```text
满足全部 AND
  状态 等于 启用
  满足任一 OR
    部门 等于 研发部
    负责人 等于 张三
  创建日期 在指定范围内
```

组边界直接表达括号，不提供手写括号或隐式优先级规则。支持添加、删除条件与组，以及将条件移入或移出组；首期不依赖拖拽操作。字段选择提供搜索和业务标题，不要求普通用户理解物理表名。

高级编辑器使用同一查询值编辑器，只额外提供合法操作符选择。应用前校验全部有效编辑节点；不完整条件提示到对应行，不能静默丢弃后执行。取消保留原已应用条件，单独清空高级条件不影响其他筛选。

设置统一的嵌套深度、节点数量和集合值数量上限；前端提示、后端强制检查。具体限值在第一阶段随契约冻结，不建设不受限的任意查询语言。

### 查询状态与结果一致性

前端显式区分查询草稿、已应用查询和产生当前响应的查询快照。摘要只描述已应用查询，并且与当前显示结果对应；有未应用修改时给出轻量提示。保留查询状态来源，不从合并后的条件树反推常驻控件状态。

- 标签展示字典名称、引用标题和明确的时间范围，允许移除用户条件并重查。
- 高级摘要保留组关系，不把 OR 组展开成含义不清的平铺标签。
- `TREE` 查询面中同一字段可以同时出现在常驻与高级查询，按 AND 叠加，不静默覆盖；冲突条件可以正常得到空集。`FLAT_AND` 的专用查询面将已常驻的字段留在常驻区，更多筛选只展示其余字段，避免页面提交后端不接受的同字段重复条件。
- 页面重置恢复声明的初始常驻值，清除高级条件与关键词；不清除导航和服务端强制范围。模板参数恢复该模板声明的默认值。
- 筛选变化回到第一页；普通刷新保留已应用条件。范围、计划或模块切换时使旧请求失效，旧响应不能恢复已经失效的结果。
- 列表记录、总数、汇总以及消费当前查询的既有导出入口必须复用同一有效查询语义；不在浏览器对当前页统计完整结果。

## 后端与协议治理

### 统一条件模型

采用有序、类型化的递归节点，分别表示条件组和叶子条件。概念结构如下，具体 DTO 命名由第一阶段确定：

```text
Group     { operator: AND | OR, children: Node[] }
Condition { fieldName, operator, values, timeZone? }
```

有序 children 保留条件与子组交错的编辑顺序。前端以明确联合类型替代 unknown；UI 临时节点 ID 留在前端，服务端错误以节点路径关联输入位置。配置持久化实体、已编译计划与请求 DTO 各司其职，不直接复用同一个实体类。

常驻字段条件与高级树最终归一到同一执行模型，模板也使用该模型编译。externalQueryValues 继续承载明确声明的业务条件或上下文参数，不作为任意扩展 map。现有 conditions、queryForm 等重复入口以合并和退役为方向，不长期维持多套相似解释器。

静态与动态保留各自的声明适配，共享结构校验、叶子操作符、值归一和布尔组合执行。统一入口位于现有分层允许的能力与平台契约中，不由基础模块反向依赖动态 Web 或平台 Web 实现。

### 值、空值与错误

- JSON 保留数值、布尔、数组和范围结构，不将数组或范围序列化成字符串再猜测解析。
- 常驻控件未填写表示不参与查询；false 和 0 是有效值。查询 NULL、空集合必须使用显式操作符。
- 显式条件的空数组、不完整范围和类型错误按操作符契约处理，不能一律当作“没有条件”。前后端同步集合操作符与无值操作符语义。
- 无用户筛选使用缺省根条件表达；已提交树中的空组或未完成叶子不得靠删除节点来隐式修复。条件删除后的结构归一与空根清除由编辑器明确完成。
- 快捷搜索采用字面包含并转义通配字符；原始 LIKE 模式如继续公开，须使用不混淆的操作符语义和文案。
- 未知字段、越界操作符、缺失计划、过期配置和无效参数必须明确失败，不降级为更宽查询。缺失计划和版本冲突沿用平台已有错误分类。

### 时间语义

业务日期与绝对时间分别处理。日期筛选时间戳时，后端根据有效业务时区生成半开区间；单端范围保留端点角色，不通过删除空值把结束端点误作开始端点。

快捷日期选择包括今天、本周、本月及最近若干天。相对时间应保留业务意图，由服务端在执行时解析，不保存成过期的固定日期。最近若干自然日与滚动小时数分别定义；周起点、有效时区来源及结束边界在第一阶段明确，并由固定时钟测试锁定。

同一查询执行中的列表、计数和汇总使用一致时间基准。固定日期与相对时间在摘要及后续个人方案中明确区分。记录本身存储区间的相交、包含点等能力，不因新增范围查询控件而自动进入本次范围。

### 查询模板参数

已发布模板可以将部分值声明为参数，页面只呈现可填写参数，复杂逻辑保留在模板中。参数具有独立稳定 key、类型、默认值与必填语义，同一个参数可以被多个条件引用，不以数据库查询项 ID 作为业务参数身份。

参数编辑复用同一查询值编辑器。未提供、使用默认值、必填缺失和显式空值必须可区分。可选参数缺失时必须声明其条件停用策略；涉及 OR 或整个组的策略若不能明确表达，编译阶段拒绝配置，不能在运行时默默删项。

普通用户高级查询只开放字段、操作符、值和组；平台模板配置才按能力开放受控参数与上下文来源。本次不开放任意公式、客户端系统变量或跨记录动态求值。

## 阶段规划与验收

各阶段围绕完整能力交付；前一阶段的公共契约冻结后，再展开依赖实现。状态标识当前完成度，验收项仍是阶段收口条件。

| 阶段 | 状态 | 交付范围 | 主要验收 |
| --- | --- | --- |
| 一：统一查询契约与执行 | 已完成首轮 | 查询字段目录、有序条件树、动静适配与共享编译、操作符和值语义、能力限制、时间语义、模板参数契约 | 同一条件在静态/动态真实数据路径得到一致结果；嵌套 OR 不扩大强制范围；非法输入明确失败；前后端类型一致 |
| 二：常驻字段查询闭环 | 正在收口 | 静态 DSL、动态配置与发布计划、共享值编辑器、常驻查询区、草稿/应用状态、标签和重置 | 时间、字典、业务引用各有代表性场景；动态页面编排器能编辑并保留 `persistentQueries`；非展示字段可筛选；单端范围正确；引用候选受控；列表、总数、汇总一致；受影响平铺列表不再仅过滤 200 条 |
| 三：递归高级编排 | 正在收口 | 条件组编辑器、组关系切换、节点移动、摘要、节点级错误及复杂度门禁 | A AND (B OR C) 与 (A AND B) OR C 正确区分；多层组往返不失真；取消不生效；空节点不静默丢失；常驻与高级叠加正确 |
| 四：模板参数交付与收口 | 未开始 | 参数配置校验、运行时参数输入、共享值编辑器接入、旧查询入口退役与契约文档更新 | 一个参数可绑定多个条件；默认值及缺失策略正确；过期模板明确失败；业务无需重复编排复杂条件；迁移范围内不留并行解释链 |

个人查询方案作为后续独立阶段：在前四阶段稳定后，复用页面偏好保存个人常驻值、高级树及相对时间意图，不保存权限、租户或已解析的导航范围。方案恢复须按当前契约重新校验，失效字段不能静默忽略。个人方案与平台发布模板分开治理；个人收藏、共享、方案授权和发布不是本次核心阶段的验收条件。

### 验证要求

后端默认运行 `./gradlew verifyAll`。基础查询边界优先补真实数据库 contract 测试，覆盖动静一致性、分页排序、字段映射、时间边界、租户与数据范围；结构归一、参数规则和错误路径以单元测试为主。

前端运行 `npm run check --prefix muyun-web`。查询状态与序列化采用单元测试，控件切换、分组编辑、应用/取消、条件摘要、导航切换与过期响应采用组件测试，并以代表性页面进行布局和交互验证。UI 验收包含窄宽度、多条件、长引用标题及多层分组，不仅验证 JSON 输出。

## 迁移与非目标

当前项目未上线，本专项不以旧协议兼容为默认目标，可以调整 DTO、页面配置与前端结构；实施时仍需盘点仓库内调用方、公开包消费者样例、OpenAPI、mock 和配置 fixture，并同步迁移。不得仅删除旧入口而留下内部调用，也不得为本机历史演示数据长期保留模糊 fallback。

范围限定在当前仓库及既有模块，不预设新增 Gradle 子项目、查询框架或外部依赖。参考实现仅用于提炼能力，不引入外部项目源码依赖或私有环境信息。

以下能力明确不纳入本次核心治理：

- SQL/脚本编辑器、任意表达式语言、AI 查询生成、自由查询设计器。
- 任意关联路径、跨模块联表、聚合 HAVING 和完整区间代数。
- 通用公式值来源与跨记录求值；后续须另行约束来源、权限和执行边界。
- 查询方案共享、发布和授权体系，以及独立搜索引擎。
- 将树导航的本地节点定位全部替换为列表查询，或借本专项重写表单保存及页面内核。
