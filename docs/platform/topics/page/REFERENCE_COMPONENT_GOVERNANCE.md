# 模块引用与前端组件专项治理

状态：阶段一公共内核与代表入口已落地，阶段二已交付列表与详情的共同只读展示及引用目标浏览；下拉／弹窗展示配置与私有业务公开接入已纳入本阶段；树入口统一和完整入口迁移尚未完成，不将首批接入等同于本专项全部交付。

本文规定模块引用从元数据到页面组件的关系、平台封装边界与可执行阶段。字典保留独立业务契约和组件入口，不以字典接入作为本专项验收条件。

## 问题与目标

平台已具备模块引用定义、来源字段解析、标题投影、下拉与树选择。首批治理已将用户选择弹窗与普通来源字段下拉接入 `ReferencePicker`；其余目标导航与树选择入口仍有独立的数据和状态管理。`UserPicker` 保留账号列、机构部门导航和用户类型等领域语义，作为公共内核的轻量包装。

建设目标是让普通业务只声明引用目标、来源约束和展示偏好，由平台完成候选读取、值与标题管理、选择交互及只读展示。静态 Java 声明与动态元数据应进入同一已编译契约，标准表单、详情和查询共用引用基础能力，并保留各自的保存、读取与条件编排职责。

本专项在已有链路上收敛，不新增平行引用运行时、通用 CRUD 查询协议或独立 Gradle 子项目，也不把所有界面逻辑集中到一个带大量开关的组件。

## 概念与关系

### 从模块引用到页面组件

模块引用表达来源字段与目标业务记录的关系。动态字段在具体模块—元数据关系下配置引用；静态模型以模型契约和引用声明接入。动态目标限定为目标模块的 MAIN 元数据，静态目标须具备可用的引用能力。

```text
静态模型引用声明 / 动态元数据引用配置
    → 统一运行态引用定义、校验与读投影
    → 已编译的页面描述符与执行计划
    → 前端来源适配、引用值和展示状态
    → 下拉 / 树 / 搜索弹窗 / 只读展示
    → 表单宿主、详情宿主或查询宿主消费结果
```

组件外观不决定引用身份，字段命名中的 `ref…Id` 也不是运行态能力判断依据。配置中的目标匹配键用于搜索、匹配或导入解析；标准模块引用始终保存目标记录 ID，展示字段和业务唯一键不替代持久化身份。

| 要素 | 语义与责任 |
| --- | --- |
| 引用值 | 实际参与保存或查询的 ID；单值、多值及空值形态由字段或查询契约决定 |
| 展示内容 | 标题、辅助摘要、受控投影和不可用状态；不作为身份或授权依据 |
| 引用目标 | 模块身份和已声明的目标实体；不能只凭前端目标模块名构造任意读取 |
| 来源用途 | 来源模块与字段，或服务端授权的专用业务用途；决定候选资格与解析方式 |
| 有效上下文 | 当前记录、表单依赖和业务范围；服务端校验，客户端只能在合法范围内收窄 |
| 展示策略 | 可用渲染方式、候选列和导航表达；不改变存储身份和授权范围 |

同样引用 `iam.user`，单据负责人、历史日志操作用户和职员绑定账号的候选资格不同。目标相同不表示候选提供者、回显规则或权限相同。

### 与字典的关系

| 维度 | 模块引用 | 字典 |
| --- | --- | --- |
| 业务含义 | 与目标业务记录的关系 | 字段所属分类或值域 |
| 持久化值 | 目标记录 ID | 字典项目 code |
| 来源身份 | 目标模块及来源字段／业务用途 | 应用与字典类别 |
| 候选约束 | 引用权限、来源规则、上下文与记录状态 | 字典类别、租户覆盖与项目状态 |
| 关联行为 | 引用投影、显式回填、目标删除约束 | 值域校验、标题与样式展示 |

模块引用、字典和枚举继续保留各自的元数据、解析、保存校验和组件入口。不得把字典改为保存字典项目记录 ID，也不得为复用选择控件而要求所有值域提供目标模块。

下拉、标签、加载提示等沿用现有 UI adapter；确有重复且语义一致的状态逻辑可以提取小型公共实现。是否进一步共享组件内核，应以实际调用与测试为依据另行评估，不预建统一选项框架，不要求全链路合并。

## 当前基础与治理缺口

| 当前基础 | 可沿用能力 | 本专项需要收敛的部分 |
| --- | --- | --- |
| 引用元数据与 `EntityReferenceDefinition` | 目标、基数、展示与完整性规则 | 保持字段事实唯一，避免页面重复声明或覆盖引用身份 |
| `ResolvedReferenceFieldDescriptor` | 目标模块、标题字段、选择模式、候选交付、依赖与投影 | 扩充必要的来源无关交互事实，校验可用展示能力 |
| 来源字段 `references/{field}/resolve` | 查询、回显、树及受控上下文解析 | 由前端适配层接入共同候选契约，保留分页和错误信息 |
| `RecordPicker` / `RecordMultiPicker` | 下拉、树、单多选与回显基础 | 收敛数据和状态管理，补齐大候选集交付，逐项核验迁移调用点 |
| `UserPicker` | 搜索弹窗、分页、选择草稿和身份导航 | 公共交互不硬编码账号列或租户、机构、部门；身份摘要留在领域适配 |
| `QueryValueEditor` / 表单与详情字段组件 | 已有标准宿主分派与标题渲染 | 统一引用基础能力，减少查询面专属用户选择分支 |

现有 `TARGET_NAVIGATOR` 与 `SOURCE_FIELD` 交付分别核验。已注册的目标引用入口可保留其合法用途；声明了来源字段或专用业务候选的入口必须使用相应规则，不得失败后回退普通 CRUD 或更宽的目标查询。

## 平台封装边界

### 后端声明与前端适配

后端负责目标身份、单多值、来源规则、字段依赖、允许披露的摘要、候选范围及最终业务校验。页面表达在启动、发布或刷新阶段编译，请求期不重新解释配置；动态页面只消费已发布契约。

前端引用能力接收已编译描述和来源适配，统一值、回显、搜索、分页、选择草稿与响应失效管理。适配层负责将已有字段解析或专用日志接口映射为共同交互所需的数据，不改变后端的授权语义，也不要求所有来源合并为一个端点。

候选列与导航通过类型化的描述和受控扩展表达。通用内核不判断目标是否为用户，不内置机构、部门层级，不接收任意脚本或未经声明的查询字段。导航父子关系与筛选范围仍由服务端确认，不因通用化开放任意模块读取。

用户、职员等领域封装可以保留，用于类型、标题和摘要表达；它们应组合平台引用能力，不再复制分页、回显、确认和并发状态机。静态业务通过已有模型和轻量 Web 声明接入，普通字段不逐个编写 resolver 或复制前端配置。

### 展示形式

| 形式 | 适用条件 | 必须满足的行为 |
| --- | --- | --- |
| 搜索下拉 | 普通记录选择 | 远程搜索与按值回显；详细选择入口收在同一控件内，不额外拼接“查看更多”按钮，不把第一页当全部 |
| 树选择 | 目标有树语义且来源允许树读取 | 大树按需加载；父节点默认只代表自身；不隐式扩大到下级范围 |
| 文本入口＋搜索弹窗 | 需要分页、详细过滤或范围导航 | 输入仅为搜索草稿；单选失焦唯一命中可补全，多条命中进入弹窗；显式确认或双击完成，多选确认后一次交付；取消不改变外部值 |
| 只读展示 | 列表、详情及已应用查询摘要 | 优先消费已授权读投影；缺少标题保留 ID，不为只读展示加载候选或逐字段查询标题 |

模块引用提供下拉与文本弹窗两种展示偏好，不提供单选组；树表示目标候选的组织语义，沿用已有受控树读取。字典的少量完整值域仍可独立使用单选组，不将其约束带入模块引用。

展示偏好必须与候选能力兼容。静态启动或动态发布时拒绝不可执行组合；权限或上下文在运行时变化则呈现明确状态，不静默切换到更宽的来源。未配置展示偏好时由平台提供稳定默认值，不依赖某次搜索结果数量猜测。

文本入口的已关联内容使用主题色，自由输入使用正文色。Tab 将焦点移到下一个字段，搜索按钮不单独参与 Tab 顺序；Enter 与鼠标点击仍可打开详细选择。修改后的非空搜索草稿在失焦时复用同一来源查询：单选仅在返回总数为一且记录可选时自动交付 ID 与摘要；多条命中打开弹窗，不以第一页条数判断唯一性。零条命中保留草稿，以警告色和删除线标记输入文字，不增加下方提示，多选仍由弹窗确认。空白和未修改的已选内容不触发自动搜索，确认原值也必须恢复回显。新的编辑、选择、来源或上下文变化以及组件卸载使旧请求失效；失焦补全不直接保存单据或应用列表查询。

引用组件通过 `validity-change` 交付 `ReferencePickerValidity`，区分可提交、编辑中、匹配中、未匹配和读取失败。编辑草稿可以暂时保留原 ID，但宿主不得在输入尚未确认时提交该 ID；标准表单将该状态汇总到表单校验，常驻与递归高级查询在应用条件前检查，私有业务手动接入也须消费此契约。已有查询结果的翻页继续使用已应用条件，不受未应用草稿影响。允许清除时，用户删空输入明确清除引用；必填由表单宿主检查。校验反馈不得重建字段组件、丢弃未确认草稿。历史引用解析失败与新输入尚未确认分别处理，不仅因历史标题暂时无法读取就判定记录不可保存。

### 表单、详情与查询

| 宿主 | 共享内容 | 保留职责 |
| --- | --- | --- |
| 单据填报 | 选择、回显、值与摘要、候选依赖 | 草稿、必填校验、显式回填、保存和生命周期 |
| 列表与详情 | 标题、摘要、不可用状态、只读投影 | 记录读取权限和数据投影；引用目标浏览独立校验 VIEW 与数据范围 |
| 常驻／高级查询 | 候选与标题解析、单多选交互 | 合法操作符、条件草稿、应用查询和结果刷新 |

引用字段的存储基数与查询输入数量分别解析：单值引用字段在允许 `IN` 时可以选择多个 ID；不因此把表单存储升级为集合。当前日志仍按其 `EQ` 契约单选，不借组件迁移扩展查询能力。

展示投影留在只读选择上下文，不混入可保存草稿；只有显式回填规则才能修改业务字段。查询选择不触发表单回填、保存或字段生命周期。空值、清除、多值排序与去重遵守既有字段和宿主协议，由适配层归一，不能通过标题反推 ID。

### 引用目标浏览契约

浏览文本由后端标准读投影提供，UI 展示偏好不改变翻译责任。已持久化 ID 与引用描述符确定目标；标题、别名和自由输入不能决定跳转身份。无需增加一套浏览展示配置，也不为引用目标复制完整管理页。

目标详情按目标模块 `VIEW` 权限及记录数据范围读取，不要求目标菜单权限。来源字段或专用业务的候选资格、来源记录可读以及已获得标题均不等于目标详情可读；不得用 `REFERENCE` 候选接口代替标准详情接口。目标拒绝访问、记录已不可用或上下文变化时，必须避免展示旧详情；多值引用按各自 ID 独立浏览。目标读取保留当前租户和认证边界，不继承来源页面专属过滤范围。平台现有 `REFERENCE` 动作的权限键继承 `VIEW`，本专项不改变该授权模型；来源专用候选可采用自身查询权限，不应与目标 `REFERENCE` 动作混为一谈。

引用入口使用目标模块的标准单据详情与动作流程。`VIEW` 只决定能否打开详情；编辑、删除、启停和配置动作仍按目标模块权限、记录级可用性及业务规则决定，菜单权限不是前置条件。只读是动作授权后的结果，不是引用入口强制隐藏全部动作。启停开关仅在模块声明启停能力、记录返回明确布尔状态且配置驱动页面提供当前状态对应动作时显示；记录级动作可用性加载前保持禁用，拒绝执行时展示原因，不将缺失状态推断为启用。表单校验、版本、读投影过滤、业务扩展及保存流程复用标准宿主，不复制引用专用 CRUD。标准宿主同时负责抽屉布局：状态进入标题区，业务动作进入固定操作区，浏览与编辑共用标准模式切换；引用入口只提供目标身份、授权上下文和关闭／变更通知，不另建内容区按钮栏或嵌套第二层单据布局。

目标详情不加载目标管理列表或来源导航。打开、编辑和关闭目标时保留来源单据现场；目标变更后刷新受影响的展示，不能覆盖来源未保存的业务草稿。删除或失去浏览资格后不保留旧目标详情，也不能继续把旧引用呈现为可用记录。来源的引用 ID 不因目标改名或刷新被重写。动作提交失败与提交成功后的回读失败分开处理：提交拒绝不等于目标不可见；成功后回读 403／404 才清理旧详情并通知来源刷新，临时读取故障不标记为永久不可用。嵌套引用沿用当前抽屉的承载方式，工作区内联与独立视口入口不在第二层切换宿主。

### 首批受控展示配置

引用展示沿用字段控件目录，使用 `rendererType=RECORD_PICKER` 和可选的 `properties.presentation=DROPDOWN|DIALOG`。标准预设为 `record_picker_dropdown` 与 `record_picker_dialog`；未配置时，公共引用入口默认使用文本框与框内搜索动作，打开详细选择弹窗；普通来源字段树在公共弹框中展示层级，复杂范围树及目标导航树保留原有入口。引用目标、基数、依赖和权限仍来自引用描述符，控件属性不重复保存这些事实。

静态字段通过既有 `uiType` 声明预设。新版动态管理页在表单字段节点的 `props.fieldUiControlAlias` 声明控件别名，修订适配器将其转换为同一字段声明。 页面编排的主表直接引用字段提供“引用选择形式”入口，可选平台默认、下拉或弹窗；已有自定义别名保留，移入列表时移除仅适用于表单的配置。例如：

```json
{ "field": "customerId", "props": { "fieldUiControlAlias": "record_picker_dialog" } }
```

发布编译只解析页面实际引用的目录项；目录项缺失、禁用或不可执行时拒绝发布。显式下拉／弹窗仅允许非树 `SOURCE_FIELD` 引用；非引用字段、未知展示形式、树或目标导航组合不能静默替换来源。已发布页面消费安装的执行计划；控件目录属性变更需重新发布或刷新计划后生效。

本次目录预设为单值引用，动态多值限制保持不变。前端内核和既有静态多值契约支持多选，不代表动态目录已开放集合引用。旧 `PlatformUiConfigField` 不自动归并进新版页面修订；旧配置迁移、自定义控件目录的完整可视化选择与树入口统一仍属后续范围。

### 私有业务手动接入

对外包 `@ximatai/muyun-web-app` 公开 `ReferencePicker`、`ReferencePickerProvider` 与候选／来源类型，以及 `ReferencePickerReadError`。业务 App 无需导入仓库内部路径或标准表单运行器，可以直接组合组件与自己的授权来源。

手动接入仍需声明 `identity.targetModuleAlias`、`identity.source`，提供 `searchPage` 与 `resolve`。同一目标的表单用途和查询用途应使用独立来源身份；服务端负责实际授权，身份字符串本身不授予权限。表单将组件输出的 ID 写入保存字段，标题和摘要另行保留；查询宿主将选择作为条件草稿，只有显式应用才刷新结果。

普通树来源可额外提供 `loadTree({ scope })`，返回 `ReferencePickerTreeNode[]`，节点由 `record` 与可选 `children` 组成。它声明的是完整授权树交付能力，不是新的字段展示枚举。弹框在空关键词下展示层级树，搜索仍走 `searchPage`，回显仍走 `resolve`；父子记录独立选择，多值选择不联动。来源字段适配只使用其声明的 `TREE`、`QUERY`、`TRANSLATE` 接口，保持当前草稿依赖、来源记录、标题投影和业务回填。

`loadTree` 不表示懒加载树能力，不得用分页结果拼装或冒充完整树。带范围和子节点懒加载的 `ScopedTreePicker` 继续使用已有契约；普通树首批以弹框交付，不放开后端对树字段显式下拉／弹窗控件预设的编译限制。

[业务 App 消费者示例](../../../../muyun-web/examples/business-web/README.md)展示直接从公开包入口接入、自有候选分页、历史 ID 回显、表单值与标题分离，以及非动态表单查询的草稿／应用边界。示例数据是确定性的本地候选，不构成业务服务端保存或权限验收。

只读手动接入可从同一公开包导入 `ReferenceRecordDetailBrowser` 与 `ReadonlyReferenceValue`，由页面级浏览器承载一个共享抽屉。浏览器的 `http` 使用当前认证、租户会话的基础客户端，不传入叠加了来源菜单或页面范围的客户端；切换会话或租户时重建宿主。字段只传引用描述、持久化值和标准读投影，不能传自由输入草稿充当已选值。例如：

```vue
<ReferenceRecordDetailBrowser :http="sessionHttp">
  <ReadonlyReferenceValue
    :reference="supplierReference"
    :value="record.supplierId"
    :summary="record.supplierTitle"
  />
</ReferenceRecordDetailBrowser>
```

私有业务需要完整单据动作时，直接使用公开的 `ModuleReferenceRecordDetailBrowser` 替换示例外层浏览器，字段写法保持不变。该运行时包装提供目标标准详情、编辑与授权动作；业务通过 `record-change` 更新自己的来源读投影，不覆盖尚未保存的字段值。轻量 `ReferenceRecordDetailBrowser` 默认只读，保留给只需要展示的消费者；它的详情插槽是组件层与标准运行时的组合边界，普通业务无需自行实现。

首次点击才读取目标浏览配置，不为每个列表单元格预加载。已确认的模块或记录权限拒绝在当前宿主内降级为文字；标准详情接口每次重新裁决数据范围。轻量浏览器默认消费目标 `detail.display` 字段；缺少详情字段配置时展示明确空态，不直接展开原始记录。标准模块和工作台由运行时提供标准单据详情，编辑、删除及配置动作复用标准宿主；组件层不反向依赖页面运行时。未提供的字典投影不通过菜单选项接口补查。

### 范围、历史与状态

1. 已选值不在当前候选页时按 ID 解析；不能因翻页、搜索或浏览导航变化而丢失。
2. 来源业务依赖变化时使旧请求失效，并按业务规则清除或重验原值；浏览导航只是寻找候选，不能等同于改变业务约束。
3. 权限不足、缺少依赖、空候选、读取失败及目标不可用分别表达。解析失败保留原 ID，不把失败结果视为用户清除。
4. 标题读取与候选资格不是同一权限：来源记录已授权的展示遵守现有读投影规则；允许显示历史引用不代表仍可新选或提交该目标。
5. 日志保持事件时机构、部门及身份快照语义，不以当前人员关系替换授权事实。登录失败的账号文本条件保持独立；现有登录审计缺少部门快照的限制不由组件补造。
6. 候选是否联动宿主时间等条件须由来源明确声明。现有日志候选不联动列表时间、结果条件，弹窗导航也不自动转成日志查询条件；迁移保持该行为。
7. 搜索、分页、关闭重开、来源切换和依赖变化均隔离过期响应。缓存如有必要，必须隔离目标、来源用途、授权上下文与范围。
8. 业务保存或查询时服务端重新执行所属规则；前端选中过、已经回显或曾经授权都不能成为绕过校验的依据。

## 可执行阶段

阶段顺序为一 → 二 → 三。依赖已稳定的跨阶段基础能力可以先行交付，但不能据此跳过本阶段的剩余验收。每个能力单元完成实现、自检、主 agent 复核、相应真实路径验证及文档状态更新后再扩大迁移。各阶段以状态及已交付范围区分实现与计划。

后续按以下依赖顺序收口：

1. 公共读取错误分类和代表性权限、分页契约已落地；继续补齐仅查询权限账号的浏览器验收与大候选集性能，不以少量跨页样本代表性能结论。
2. 普通查询按已有查询描述符接入公共内核，同时保留目标引用与来源字段的不同权限和依赖语义；继续补齐静态声明、动态配置及发布后的真实接入闭环。
3. 在首批分页下拉／弹窗展示契约之上，明确树读取能力，再收敛对应展示与启动／发布校验；不凭第一页数量推断可用形态。
4. 按实际调用者迁移旧入口并回收重复状态机，以普通业务接入成本和旧实现减少作为最终验收依据。

### 阶段一：标准引用选择与日志候选共用闭环

状态：公共内核、来源适配和代表入口已交付；代表页面的跨页搜索与保存重读、真实 HTTP 权限分页及 PostgreSQL 回归通过，仅查询权限账号的浏览器验收与大候选集性能待补齐。

已交付范围：

- `ReferencePickerProvider` 显式区分目标模块、来源用途和上下文版本，提供分页搜索与按 ID 回显；`ReferencePicker` 交付单多选、搜索下拉和详细弹窗。分页、关键词与浏览导航不丢失选择草稿，取消不写值；来源或依赖变更隔离请求与缓存。
- 来源字段适配继续调用 `QUERY` / `TRANSLATE`，保留总数、来源记录、依赖、投影和显式回填。标准主表、导航管理表单和 inline 子资源中的非树 `SOURCE_FIELD` 引用共用该适配。来源失败没有目标 CRUD 兜底。
- `BusinessLogListDrawer` 通过通用 `referencePickerOf` 向常驻／高级查询交付专用日志候选。三个日志复用该宿主；`UserPicker`、`EmployeePicker` 组合公共内核，身份列和导航留在领域适配层，已有职员绑定账号入口继续使用自己的来源函数。
- `select` 表示用户确认，可由表单消费显式回填；`selection-resolved` 仅更新展示投影。查询只消费 ID 值，不回放表单副作用。候选失败、回显失败与不可用值分别呈现并保留原 ID。回显加载中或读取失败仅展示中性 ID，不误标不可用；成功解析确认缺失后才标记不可用。中性占位不赋予新的选择资格，切换来源立即清除旧标题。
- 普通非树查询按 `QuerySchemaField.reference` 与目标引用运行态自动接入公共选择器，常驻与递归高级查询复用同一分派；分页搜索与按 ID 分批回显固定使用目标 `navigator/reference/query`，不读取普通 CRUD。日志等显式业务 provider 优先，树目标继续使用原有树链路。`EQ` / `IN` 决定单多选，不引入额外业务数量上限。这是已有目标引用查询的交互统一，不将查询条件解释为表单依赖，也不代表来源字段查询配置已完整交付。
- 公共读取错误沿用平台 `AppError` 的状态与错误码区分权限拒绝、配置不支持和暂时失败，只有可重试错误提供重试。来源字段适配依据已编译的必填依赖和当次表单值提示缺少依赖；不从异常消息猜测原因。401 继续交给全局认证流程，但候选读取失败仍禁止确认旧草稿。服务端尚无独立的缺依赖响应码，此分类仅限拥有明确依赖描述的来源。
- 全局字段目录内部的七个引用显式声明 `GLOBAL`，修复无租户配置记录编辑时的来源解析失败；普通 `SAME_TENANT` 来源校验保持不变。

验收边界：已在真实登录日志验证用户选择、查询、重开、取消与重置；已在字段 UI 控件主表和子表验证普通来源引用的回显、搜索与选择；重新选择原值并保存、整页重载后标题仍正确，原始数据保持引用 ID。跨页、多选、依赖变化、失败和并发失效由组件契约测试覆盖；全局来源 `QUERY` / `TRANSLATE` 与原有事件时范围契约由后端测试覆盖。真实 HTTP/PostgreSQL 测试以仅有登录日志查询权限的租户角色验证 24 个候选的分页、默认前 20 条外关键词命中、跨页已选值及跨租户隔离，同时拒绝普通用户查询、目标引用、日志详情与无授权账号候选访问。真实 PostgreSQL 测试验证字段目录引用保存后标准读取补齐标题、原始记录不持久化标题。浏览器以 24 条临时本地日志样本验证第二页选择、默认前 20 条外关键词命中、按选中 ID 查询、重开回显和取消保留原条件，样本已清理。仅查询权限账号目前由真实 HTTP 测试覆盖，其浏览器操作及大候选集性能仍待补齐。

交付内容：

- 在现有 descriptor、Web client 和平台组件边界内建立共同引用值、摘要、候选读取与选择状态契约，落实分页、按值解析和类型化错误。
- 交付搜索下拉与文本入口搜索弹窗，共用选择状态；抽出当前用户弹窗的公共部分，身份列和导航由来源适配提供。
- 选择一个已有非 IAM 普通模块引用表单和登录日志操作用户查询作为代表入口，分别接入来源字段解析与日志专用候选，不新增演示业务体系。
- 选定入口前核实其已有保存和查询契约；前后端若缺少完成共同交互必需的字段，在原有契约上补齐。

验收标准：两个真实入口共享内核且没有目标模块特判；关键词带入、跨页搜索、按 ID 回显、清除、取消、重开和过期响应隔离正确；日志仅有查询权限的账号与无租户平台管理员仍可使用；表单仍保存 ID，日志仍提交 `operatorId EQ`；通用内核不包含用户列或固定 IAM 导航。

### 阶段二：动静统一的多形态与多宿主交付

状态：只读展示、目标浏览、保存边界、首批下拉／弹窗展示及普通来源字段树契约已交付；复杂范围树、目标导航树入口统一和跨动静多形态完整验收待实施。

首批展示配置由静态编译测试、真实 JSON 页面修订到发布协调器／执行计划的契约测试、前端属性保存与渲染组件测试覆盖。非法展示形式不能安装计划，已发布描述符不随目录编辑漂移，缺计划不在请求期重编译；运行时界面规则只叠加一次，移除后不残留。标准列表和单据详情通过同一记录宿主打开引用目标，复用编辑、删除及配置动作，目标变更后刷新来源展示。代表性动态采购链路已验收；跨动静完整矩阵仍待验收。

已交付范围：标准列表和详情共用只读引用展示函数，优先消费 descriptor 指定的标题字段；结构化多值摘要按 ID 对齐，保持原顺序和未解析 ID，清空引用后不展示旧摘要。完整的旧式标题数组继续支持，不完整且无 ID 的数组不猜测标题归属。只有来源显式返回不可用标记时才显示不可用状态，缺少标题不推断目标删除或越权。

字段 UI 控件及其属性、绑定模型以 `@ReferenceLoad` 声明所需标题，编译到已有 descriptor；浏览器已验证主表和子表详情显示标题。只读展示不发候选或翻译请求、不触发表单事件。标准主表、导航管理和 inline 子表的保存出口过滤 descriptor 声明的读投影输出，保留引用 ID 与显式业务回填；真实 PostgreSQL 回归覆盖原始读取不持久化标题、标准读取补齐标题及更新后重新读取。

交付内容：

- 在静态声明与动态配置中提供受控展示偏好，编译到同一描述符；复用已有引用事实，不要求业务重复声明目标、标题和来源规则。
- 统一现有树选择入口，补齐能力匹配校验；大树沿用来源范围下的懒加载与搜索。
- 标准表单、列表／详情、常驻／高级查询共用引用值和展示基础能力；以已有支持集合的契约验证多选，不开放尚未支持的动态多值引用配置。
- 用静态与动态模块、固定范围树与分页候选集验证完整交付；至少覆盖动态来源引用静态目标及静态来源引用动态目标的合法路径。

验收标准：切换合法展示形式不改变保存值、候选范围和回显；不可执行的展示组合在启动／发布时被拒绝；依赖变化正确重验，展示投影不进入保存；详情不读取候选页；查询不触发表单副作用；已有动态单选限制和字典行为保持不变。动态配置、发布、真实选择、保存与重新读取形成闭环。

目标浏览权限由真实 HTTP/IAM 集成测试覆盖：静态目标和通过标准元数据编排、页面发布安装的动态目标，均允许拥有目标 `VIEW` 而没有 `MENU` 的用户读取运行态描述与范围内详情；动态目标同时验证 `OWNER` 范围，范围外及跨租户记录拒绝。静态与动态标准详情对不存在或不可见记录统一返回 404，不返回 200 空响应；仅有来源日志候选查询权限时不能读取目标浏览配置。组件测试覆盖逐 ID 展示、拒绝降级、关闭和切换的过期响应、失败后重试、标准工作区内联抽屉与独立消费者视口抽屉。

### 阶段三：入口迁移与重复实现回收

状态：主体待实施，依赖阶段二验收。三个日志已随公共宿主接入，用户／职员包装已复用内核；不据此标记全部入口迁移完成。

交付内容：

- 核验 `RecordPicker`、`RecordMultiPicker`、`UserPicker`、查询专用分支及各来源适配的实际调用，逐项迁移已覆盖能力的入口。
- 将活动、异常日志和职员绑定账号等已有用户选择入口接入共同内核，分别保持日志范围与绑定资格；有价值的领域包装保留为轻量组合。
- 回收已无调用的旧状态管理与候选实现；需要保留的兼容入口必须记录调用者、限制和移除条件，不无限期维持两套内核。
- 更新配置、页面、查询和身份选择文档的最终边界，修正过期的阶段限制；复核普通业务接入代码和重复逻辑是否减少。

验收标准：三个日志、职员绑定和代表性模块引用页面均通过真实操作验证；不同来源不会共享错误范围或缓存；迁移路径没有普通 CRUD 兜底；被替代实现有删除或保留依据，不能仅新增组件而保留全部旧链路。无需通过角色范围选择键等非记录 ID 场景证明模块引用能力。

## 验证与交付标准

- 前端契约与组件测试覆盖值／标题分离、单多值、草稿确认、依赖与导航区别、不可用回显和并发响应隔离。
- 后端契约测试覆盖来源身份、导航与按值回显的越权拒绝、展示偏好校验、动态发布和最终保存／查询规则。数据范围、搜索分页和字段解析优先使用真实路径 contract 测试，不仅验证 mock 请求形状。
- 浏览器验证包括搜索命中第一页之外的数据、取消不生效、重新打开与重新读取、静态／动态跨来源引用及日志历史身份；不能仅凭组件截图或测试通过宣布完成。
- 涉及后端变更运行 `./gradlew verifyAll`，涉及前端变更运行 `npm run check --prefix muyun-web`；阶段交付说明真实验证范围、未验证项和剩余风险。
- 本专项文档阶段状态随实际验收更新；区分代码接入、自动化契约和真实业务验收，不将首批组件交付标为整个专项完成。

## 当前保留链路与回收条件

`RecordPicker` / `RecordMultiPicker` 仍服务 `TARGET_NAVIGATOR`、复杂范围树的紧凑入口及未声明公共 provider 的调用者。公共内核已接管普通来源字段树：完整树读取、关键词分页、按值回显和业务回填共用来源 provider，运行态不再为普通树装配旧加载器。`ScopedTreePicker` 及其紧凑入口仍承担带范围和懒加载的树契约，不改变授权范围或读取接口。

| 保留入口                                                  | 当前职责                                                     | 回收前必须具备的替代契约                                                                                     |
| --------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| `RecordFormFields` → `RecordPicker` / `RecordMultiPicker` | 复杂范围树、目标导航树及未提供公共 provider 的表单选择                       | 单多值回显、禁选约束与业务回填；来源树继续使用 `SOURCE_FIELD` 的 `TREE` / `TRANSLATE`，不能退回目标普通 CRUD |
| `RecordFormFields` → `ScopedTreePicker`                   | 带范围的树弹窗、子节点读取及按 ID 回显                       | 保留范围选择和懒加载；不能把分页候选拼成不完整的全量树                                                       |
| `QueryValueEditor` → `RecordPicker` / `RecordMultiPicker` | 目标具有树能力时的查询选择，以及目标运行态加载失败的显式错误 | 继续使用目标 `REFERENCE` 上下文；查询值保持条件草稿，不引入表单依赖或回填副作用                              |

树入口迁移须先补齐这些契约，再切换宿主并删除旧实现；仅将旧组件改名或包进公共组件不视为完成迁移。来源页面导航范围与目标浏览范围的隔离由真实宿主组件测试覆盖：来源查询携带页面范围，目标浏览请求仅保留认证和当前租户上下文。

剩余复杂范围树和目标导航树的替代契约完成后，再按实际调用迁移并删除旧状态机。`UserPicker`、`EmployeePicker` 的领域类型和来源注入入口有独立价值，可继续保留轻量包装；无生产调用的旧身份查询配置类型及归一函数已回收，普通业务统一消费公共引用契约。字典不进入该回收清单。

## 范围与后续事项

当前要做：扩展引用目标标准详情与授权动作的跨动静、多宿主验收，保持下拉／弹窗展示契约；按真实调用收敛候选来源适配及重复实现。

后续按实际需求评估：字典可共享的局部实现、动态多值引用配置、任意查询结果全量选择。它们不阻塞本专项，也不通过预留大量可选字段提前承诺实现。

明确不做：模块引用单选组、独立编辑／浏览展示配置、字典与模块引用全链路合并、任意对象混选、流程选人规则引擎、通用授权范围表达式、自由脚本渲染器、以弹窗能力扩展目标管理权限，以及完整目标模块管理页的复制。
