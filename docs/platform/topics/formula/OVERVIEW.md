# 计算公式使用说明

计算公式用于声明可重复、可审计的业务判断和计算；它不是浏览器脚本、表达式注入入口或通用流程编排器。公式由平台解析、校验并编译为受限程序，浏览器只执行平台下发的受限程序，保存和业务事实仍由服务端负责。

## 先判断使用哪一类公式

| 场景 | 选择 | 真相源与执行位置 |
| --- | --- | --- |
| 字段可见、必填、只读等交互判断 | `WEB_UI` 谓词 | 服务端编译并随页面 descriptor 下发；浏览器仅即时渲染 |
| 表单内的即时派生值 | `FORM_COMPUTE` | 服务端编译并下发计算程序；浏览器可预览，服务端保存前仍复算 |
| 动态记录的默认值、保存校验、保存前计算、动作前校验、导入校验 | 动态元数据公式规则 | 动态运行态服务端执行；`formula/preview` 只提供当前草稿试算 |
| 聚合子表中由一个变更行影响同一直接子表其他行 | 受限子表 `FORM_COMPUTE` | 前端即时预览，父记录保存时服务端再次调和 |

不要用 `WEB_UI` 隐藏字段代替服务端授权、数据范围、保存校验或状态流转；也不要把公式用于跨模块写入、异步任务、流程编排或任意 JavaScript。

## 表单交互公式

静态模块通过 `UiFormula` 声明 `visible`、`required`、`readOnly` 等规则。例如：

```java
.field("pageMode", field -> field.visible(
        UiFormula.booleanExpression("{moduleAlias.entryType} == 'module'")))
```

`{fieldName}` 读取当前草稿字段。公式程序只能由服务端生成；浏览器不接收、解析或执行原始表达式，也不能补充未被 descriptor 声明的字段。

### 读取引用目标字段

当规则依赖已选择的 ONE 引用目标时，在引用字段上显式声明 `selectionProjections`，再使用相对目标的点路径：

```java
@ReferenceTo(target = SupplierService.class,
        selectionProjections = {"organizationId.regionCode"})
private String supplierId;

.field("taxPolicy", field -> field.visible(
        UiFormula.booleanExpression("{supplierId.organizationId.regionCode} == 'CN'")))
```

该声明不是对象导航语法糖，而是一次受控的引用读取授权：

1. 第一段必须是当前表单已声明的 ONE 引用；后续引用跳也必须是已声明的 ONE 引用。
2. 末端字段以及每一跳均按 `REFERENCE` 数据范围和字段保护读取；不可见或不存在时公式只获得空值。
3. 投影只存在于浏览器的临时选择上下文，不写入业务草稿、保存请求或记录持久化字段。
4. 静态、动态与混合引用目标使用同一条路径契约；实现方不得通过前端候选对象绕过声明。

投影路径应只取规则真正需要的最小字段。不要为“以后可能用到”而暴露整段目标记录，也不要用 MANY 引用驱动标量表单规则。

## 动态记录公式规则

动态模块的公式规则由元数据关系维护，并在模块刷新后编译为运行态定义。规则必须明确 `ruleKind`、`rulePhase`、目标字段和启用状态；保存、动作或导入入口只执行与自身阶段匹配的规则。

表单即时计算使用 descriptor 中的 `FORM_COMPUTE` 程序。`/{moduleAlias}/formula/preview` 提供需要服务端能力时的业务记录试算，沿用新建或更新权限；结果不能替代实际保存。保存前服务端会在同一业务能力、权限、租户、数据范围和事务边界内重新执行适用规则。

同一实体的 `BEFORE_SAVE` 主表计算会编译为一个确定性执行计划：每个计算字段只能有一个写入规则，输入和目标必须是已声明字段，计算目标必须可写；平台按字段依赖执行全部计算，再执行保存校验。因此客户端提交的派生字段值只作为草稿输入，服务端计算结果才是保存事实。默认值仍属于记录初始化，子表写入和其他 phase 保留各自既有执行边界；子表计算依赖新的主表计算结果属于尚未开放的混合依赖，会在配置校验时拒绝，避免静默改变执行顺序。

## 低代码治理入口

模块的“业务规则”维护主记录字段计算与保存校验；字段可见、必填、只读等交互规则仍在页面配置中维护。

- 字段计算选择目标字段并填写取值表达式，服务端生成赋值语句。计算按字段依赖排序；循环依赖和同一目标的多个计算规则会拒绝应用。
- 业务校验填写条件、失败提示和可选定位字段，在计算全部完成后执行。
- 编辑会话提供“试算”和“应用更改”；应用时自动检查完整规则集，检查通过后才生效，失败时保留输入并定位问题。未应用更改只保留在当前页面会话，不构成服务端草稿版本。
- 样例试算使用用户输入的主记录值；声明了引用路径时，服务端按根引用 ID 读取真实目标字段，沿用保存时的引用范围、字段保护和租户约束，不接受调用者提供的点路径值。系统管理员需选择试算租户。试算不写入业务记录。应用时校验包含保留规则的完整定义，并检查配置基线，事务提交后激活运行态。
- 首期编辑限主表、保存前、可配置业务字段。默认值、子表、其他阶段和不能无损映射到此入口的既有规则保留为只读。固定默认值仍由字段元数据管理，上下文初值仍由初始化链路提供。

可移植计算会自动投射到表单。缺少声明字段或依赖不可移植计算时，对应依赖链保留服务端计算，不向浏览器补充隐藏字段。新建表单会首次计算，之后按输入变化传播；保存始终重新计算并校验。

治理主页面按“字段计算 / 业务校验”管理规则列表，工具栏提供整组试算，存在未应用更改时展示放弃与应用操作。规则列表复用平台标准列表展示与单元格渲染；搜索和分页仅影响当前会话的展示，检查及应用始终使用完整规则集，不触发逐条持久化。新增或编辑规则打开宽抽屉，左侧元数据树、右侧编排区域；完成编辑或关闭抽屉会保留当前会话输入，只有主页面应用更改才激活规则，未完善规则会阻止检查和应用。元数据树按需展开引用字段；可读字段可双击或拖入表达式的光标位置。引用目标字段仅作为只读输入，计算目标仍限当前主记录的可写字段。函数目录由服务端提供名称、分类、参数、返回类型与示例，界面提供搜索、说明和插入，不以函数目录扩展引擎语法。

保存规则可读取多个连续 ONE 引用的标量字段，例如 `{supplierId.organizationId.regionCode}`，沿用平台引用路径深度上限。每一跳都必须是可读、以 `id` 为目标键的声明引用；MANY 引用、受保护字段和对象字段不属于该标量输入能力。引用为空或不可见时得到空值，引用结果不作为持久化字段写回。此类规则及其依赖计算保留在服务端执行；治理试算可以验证结果，浏览器表单尚不即时执行这类保存规则。

`FORM_COMPUTE` 的可用表达式以编译器契约为准，目前支持基本算术、比较、逻辑以及 `PRESENT`、`ISNULL`、`IN`，不提供任意脚本或外部调用。数值计算不作为高精度结算引擎承诺。

## 静态服务接入

静态服务实现 `MainRecordFormulaAbility<T>` 并返回 `mainRecordFormulaRules()`。平台在业务保存预处理后、通用字段与引用校验前执行同一 `FormulaRuleExecutionPlan`，成功后将类型转换后的计算值写回实体。

同一份 Java 规则列表可通过表单 DSL 的 `.businessRules(rules)` 生成前端计算定义，无需手工重复表达式和触发字段。该入口不是新的页面业务规则存储。静态接入限主记录 `BEFORE_SAVE` 的计算和校验；标准系统字段不参与计算写入。

## 设计与治理边界

- 公式负责确定性判断和字段计算；外部 I/O、跨聚合写入、通知、任务调度和流程推进应进入各自的平台能力。
- `WEB_UI` 只影响交互，不构成安全边界；所有引用、查询、详情与变更仍由后端执行授权和范围约束。
- 公式修改属于配置变更：动态规则通过运行态刷新生效，页面只消费已编译 descriptor，不依赖浏览器私有解释器。
- 新增公式 profile、字段路径能力或语义时，必须同时更新本说明、页面 DSL 指南和对应契约测试。
