# 审批与业务接入

审批能力以业务记录为宿主，静态 Java 服务和动态元数据复用同一套定义、实例、参与人、任务检查、权限和通知能力。审批完成里程碑与整个业务流程完成是两件事：例如采购审批通过后，仍须完成到货验收任务。

## 静态模块

1. 模型使用 `StandardApprovalEntity`，或实现 `ApprovalCapable` 并遵守标准五字段。
2. 普通 service 沿用 `StandardBusinessService` 等现有基类，实现 `ApprovalAbility<T>`；无需继承工作流专用 service。
3. Web 模块显式声明 `EntityCapability.APPROVAL`，平台自动补充 WORKFLOW，前端业务详情显示审批面板。
4. 在模块的“审批流程”入口配置并发布流程。

可参考教学采购模块 `education.purchase_request`。普通 service 插入、更新、数据权限、版本、生命周期、加密字段和保存事件继续由平台能力负责。

## 动态模块

MAIN 元数据声明 APPROVAL；模块的 MAIN 能力意图可用于创建元数据，已有模型通过元数据变更集启用。审批五字段由平台生成并管理，子元数据不能声明模块审批能力。声明、物理建表、发布编译和运行态发现使用同一能力契约，不通过普通业务字段伪造启用。

字段及语义：

| 字段 | 含义 |
| --- | --- |
| `approvalInstanceId` | 当前有效审批绑定 |
| `approvalStatus` | 业务审批态 |
| `approvalSubmittedBy` | 发起人 |
| `approvalSubmittedAt` | 提交时间 |
| `approvalCompletedAt` | 审批完成时间 |

普通 CRUD 不能覆盖摘要。processing、approved 状态禁止普通更新；被驳回业务可修改后重提。标准动作可用性和实际执行共同表达该审批更新限制，前端编辑入口消费记录动作可用性及受限原因；受信任务办理仍由独立命令授权。摘要写入走 `ApprovalAbility.writeApprovalState` 或动态记录服务对应门面，继续执行正常数据权限、乐观锁和保存生命周期。

## 流程与业务任务

流程为有向无环语义图。配置 START、APPROVAL、TASK、BRANCH、CONVERGE、MILESTONE、END；APPROVAL 的 NOTICE 模式生成知会任务；审批治理流程必须有 APPROVAL_COMPLETED 里程碑。发布检查唯一起止、可达性、节点和路径合法性、分支配对、人员来源和任务完成策略。已发布快照不可修改，业务实例保留启动版本。

审批参与人来源包括明确账号、角色、部门、组织、主管链、提交人本人和业务字段，合并去重后只保留当前租户或合法全局的有效账号。角色授权范围与启用状态参与解析；主管链检测循环。参与人会随任务创建冻结，转办不会重新匹配委托。

TASK 可配置公式、查询模板、关联视图和生成业务计数。公式只允许返回布尔值的只读表达式；所有必要检查必须通过。办理指引可以打开当前业务表单、执行已注册业务动作或提供只读说明。写入指引必须绑定当前业务模块，只读指引可跳转其他模块。OPEN_FORM 和 update 动作必须声明 `guideConfigText.editableFields`，禁止写入 ID、租户、版本、生命周期、审批摘要等平台保留字段。

“保存业务并完成任务”先锁定并核验当前任务、实际办理人和冻结指引，再通过 `ModuleRecordActionExecutor.executeApprovalBusiness` 执行平台标准写入，读取更新后的业务事实重新检查，最后完成任务与流转。所有步骤共用事务。写入任务后如需先按条件自动分流、再由人工选择路径，应增加独立后继审批或任务节点承载选路；发布拒绝依赖保存前候选而在保存后改变可达人工分支的配置。直接手工分支及自动分流进入后续阻塞节点仍支持。这个受信命令只供已授权的任务编排调用；公共 `execute` 保持普通业务编辑规则，不能借此更新审批中或已批准记录。 动态 SERVICE/GENERATE 动作沿用 `DynamicActionOperations.update`，运行器只对本次绑定的主记录、租户和实体快照开放审批业务写入；权限、数据范围、生命周期和乐观锁仍由标准链路执行，动作返回后授权失效。

静态业务需要自定义办理动作时实现 `StaticModuleActionExecutor`，动态侧沿用已注册 action；具体业务规则仍在领域服务。动作参数来自发布指引，客户端不能替换配置参数。无需在 workflow 核心引入 Controller、页面 URL 或具体业务类型。

## 扩展与边界

`ModuleRecordFacts` 为静态和动态记录提供统一事实读取，任务检查复用 `ModuleCompletionCheckService`。复杂领域约束优先保留在领域 service，不写成前端判断。

工作流插件在稳定动作前后消费事实，包括业务任务 complete。同步插件失败阻断事务；AFTER_COMMIT 用于通知等副作用。站内通知 adapter 独立于核心流程，面向任务实际接收人，提醒故障不改变已提交结果。离线办理以持久工作台任务为准。

撤销同意须满足当前任务和未办理后继的恢复约束，不越过审批完成里程碑。管理员强制处理、终止和重置使用独立管理模块权限。自然时间超期不自动审批；工作日历 SLA、持久离线收件箱和外部消息渠道保持后续边界。
