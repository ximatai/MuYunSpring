# 工作流与任务专题概览

工作流与任务专题把审批节点和任务节点统一到同一套 workflow 能力中，形成定义、发布、运行、任务、待办、历史、委托和插件挂点的业务闭环。

本文只梳理业务能力线索和稳定边界，不展开 Java 底层设计。Web 入口见 [WEB_API.md](WEB_API.md)，工作台能力见 [workbench/OVERVIEW.md](workbench/OVERVIEW.md)，业务接入见 [INTEGRATION.md](INTEGRATION.md)。

## 能力定位

工作流不是只有状态字段和待办入口的简化能力。它负责把业务记录、审批治理、任务办理、分支汇聚、历史归档和动作权限串到同一条运行链路。

核心定位：

1. 统一使用 HYBRID 工作流模型，不拆成审批流和任务流两套实现。
2. 流程通过 `approvalEnabled` 声明是否治理业务记录主审批态。
3. 审批治理流程在同一模块、租户、业务记录上当前有效实例独占。
4. 审批完成节点 `APPROVAL_COMPLETED` 回写业务记录审批通过，但不等于整条流程结束。
5. 任务节点是可独立配置、判定和引导动作的业务对象，不展示审批动作。
6. 分支、汇聚和 route 运行对象共同表达流程实际路径。
7. 运行时动作、任务动作和管理动作接入平台动作权限、数据权限、事件和审计上下文。
8. 历史归档冻结实例快照、任务、事件和画布回显信息。

## 主要对象

| 对象       | 说明                                                             |
| ---------- | ---------------------------------------------------------------- |
| 工作流定义 | 流程配置入口，绑定模块、审批治理开关、版本和当前发布态。         |
| 定义版本   | 发布后的冻结版本，保存节点、连线、语义图和布局图 JSON。          |
| 节点定义   | 表达审批（含知会模式）、任务、分支、汇聚和里程碑等流程节点。     |
| 连线定义   | 表达节点间 route、默认线、手工选择和条件选择。                   |
| 流程实例   | 业务记录上的当前运行对象，保存定义版本快照、实例状态和审批态。   |
| 节点实例   | 运行态节点状态，承载活动、完成、跳过、超期等事实。               |
| route 实例 | 运行态路径事实，是分支有效路径的真相源。                         |
| 工作流任务 | 用户办理对象，覆盖审批、知会、业务任务、委托和转办后的处理事实。 |
| 历史实例   | 撤回、重置或驳回后重新发起时保存的冻结归档。                     |
| 委托配置   | 用户或管理端维护的任务分派规则，只在正式 TODO 任务生成时匹配。   |

## 核心业务链路

### 定义与发布

1. 模块管理的“审批流程”入口以标准列表抽屉管理流程定义、匹配规则和顺序，新建和流程设置使用独立的标准表单抽屉，保留后方列表与查询状态；单条流程的“编排”进入独立页签，维护版本、参与人、节点、连线和业务完成检查。
2. 草稿按语义图整体保存和校验；发布冻结节点、连线、业务任务完成策略、办理指引和布局。
3. 发布后的定义可向目标模块贡献稳定 runtime 动作目录。
4. 运行实例只读发布快照；运行态加签只更新实例级画布快照，不反向修改定义版本。

流程以记录 ID 作为内部身份，配置界面不要求填写或生成编码；`alias` 仅保留为可选的兼容接入键，显式提供时仍校验格式与模块、租户内唯一性。非审批流程的动作编码 `actionCode` 与流程别名独立，创建时必须显式提供，遵循模块动作命名与唯一性约束；审批流程不需要此编码。未发布草稿可修复或修改动作编码，首次发布后不可修改，Java 接入与 Web 配置共用领域校验。静态接入可使用 `WorkflowModuleSubmitService.submitWorkflowById` 或 `WorkflowSubmitRequest.workflowById`；既有按别名的入口继续兼容。动作贡献以定义 ID 绑定，执行不能由请求体覆盖该绑定；直接按 ID 提交仍校验模块、租户、启用与发布状态、适用组织和匹配条件。

新建定义不隐式创建编排版本；首次进入编排时创建或复用草稿版本。页签以模块与流程 ID 标识，名称变化不改变页签身份。返回模块后刷新流程列表，未保存的定义设置不被后台刷新覆盖。编排页重新激活或收到定义变更时只刷新名称、匹配设置和定义版本，保留当前编排版本、未保存节点及画布状态；保存中的定义变更延后同步。同一身份与范围下，保存、创建版本及发布的成功回执跨页签停用保留；发布成功与随后定义读取失败分别反馈，读取失败不恢复待发布确认。

节点属性以平铺卡片选择审批、知会、业务任务或里程碑。知会只配置参与人，任务可标记已阅且不阻塞流程；存储和运行契约仍兼容 `approval + notice`，不增加第二套知会执行链路。

画布按结构化路径编辑：在已有路径插入节点或添加成对的分支与汇聚，通过“增加分支路径”自动连接对应汇聚；普通配置不提供自由创建、删除连线或改写连线端点，已有连线用于配置条件与默认出口。

画布聚焦时支持 Ctrl/⌘+Z 撤销、Ctrl/⌘+Shift+Z 或 Ctrl+Y 重做、Ctrl/⌘+A 全选、Ctrl/⌘+C/V 复制粘贴，Delete/Backspace 按既有删除规则删除单个选中节点（整个分支仍需确认），Shift/Ctrl/⌘ 点击多选。历史以语义配置及布局为单位、限定于当前编排版本，保存后仍可撤销，是否未保存由最近成功保存的内容判定。输入框继续使用原生编辑快捷键，只读版本不执行撤销、重做或粘贴。

异步编辑只作用于发起时的草稿修订；等待期间发生编辑、撤销重做或版本重置后，过期结果不覆盖新状态，并提示重新操作。节点和路径选择随图变化清理失效引用，不恢复已失效的属性面板；平移、缩放和选择变化不改变草稿修订。

复制选中的连续片段，选择分支时包含整个分支与配对汇聚，全选复制时排除开始和结束节点。粘贴到选中路径、节点之后或结束节点之前，自动接线并重建节点、路径与内部引用标识，不携带数据库 ID 或运行状态；片段外的人工选路节点引用需重新配置，粘贴后明确提示相关分支名称并定位首个待配置分支。剪贴板只接受有大小限制、无环、单入口单出口且分支配对完整的流程片段，不改变既有流程版本。

匹配条件、分支条件和任务公式复用公共公式编辑器的字段插入、函数说明与服务端语法校验；条件须返回布尔值，语法校验不代替提交时对真实业务记录的判断。

存量数据库启用无编码定义前，应执行 `scripts/migrations/workflow-definition-optional-alias-postgresql.sql`，解除 `alias` 非空约束；迁移保留既有值且可重复执行。

已有数据库升级到列表顺序选择前，应停止应用并执行 `scripts/migrations/workflow-selection-order-postgresql.sql`。迁移在各租户、模块分区内将原优先级降序与原排序转换为列表顺序，全局模板与租户流程不跨分区比较排序数值；日常排序命令仍按租户、模块隔离。原同优先级歧义按原排序、alias 和 ID 确定顺序，升级后应复核这些流程。脚本在事务中完成并删除旧优先级列，重复执行不会覆盖后续人工排序；当前脚本适用于 PostgreSQL 的 `public` schema。

定义和版本配置按模块聚合在 `/platform.module/{moduleAlias}/workflow-definitions` 下。普通维护只面向草稿；发布、停用和归档通过发布门面同步定义状态和模块动作贡献。运行态审批、任务办理和管理动作仍归属 `/workflow/runtime` 等运行入口。

### 人机共享编排草稿

人工画布与当前配置页助手共享语义图、布局和撤销重做历史。助手写入须同时满足活动页、已加载草稿版本、未忙及真实 `editWorkflowDesign` 记录动作权限；已发布与归档版本只读。身份、执行范围、版本、选择或草稿修订变化后，旧调用失效。

结构化批量操作完整校验后一次应用、一次撤销，拒绝整图 JSON、路径端点、持久标识和冻结状态覆盖；批内新建对象通过命名引用供后续操作使用。支持审批、知会、审批完成里程碑、成对分支汇聚、路径和条件；参与人写入限提交人、相对主管链与合法人员字段。指定账号、角色、部门和组织，以及业务任务复杂指引与完成检查继续人工维护，其他修改保留这些配置。

有界读取明确标记截断和未保存状态。真实变化摘要与本地草稿诊断不代表服务端正式发布校验、保存或生效；助手不执行持久写入，人工继续使用现有保存、校验和发布链路。

工作流编辑会话持有身份作用域、活动状态及保存恢复状态，人工入口与助手共同消费。草稿保存响应未知或版本冲突后暂停编辑与后续写入，保留本地草稿；所有未保存草稿均可主动读取当前版本，明确拒绝不会被误标为结果未知。核对时可查看服务端节点、路径、参与人和任务的完整只读配置，再采用服务端内容，或以当前版本为基线保留本地草稿并重新核对。主动核对可取消，结果未知或版本冲突的写入保护不可取消。当前版本读取不作为原请求成功回执；服务端版本已冻结时只能采用当前版本。流程保存可携带原请求标识，回执与设计变更在同一事务提交，按认证用户和租户隔离；同标识、同内容重试不重复写入，读取回执仍校验当前定义与版本权限。保存前在当前浏览器标签保留最小查询引用，刷新只恢复查询保护，不恢复草稿、授权或自动重发。查到回执证明原请求已提交，但当前版本可能已有后续修改；查不到回执不等于失败。持续未知时可显式终止原请求：服务端在同一锁下确认已提交，或持久化拒绝迟到请求的标记，不撤销已提交内容。只有回执确认提交、原请求已终止，或服务端乐观锁版本已推进、原请求无法再覆盖时，才允许人工采用当前版本或核对后保留仍在本页的草稿。关闭浏览器标签及跨设备恢复不在当前契约内。


### 提交与实例

1. 业务记录可读取提交状态和提交预览。
2. 提交审批时按当前租户、发起人组织和条件选择已发布流程；最近组织优先于全局，同一组织范围内先匹配普通流程，再使用兜底流程；各类候选中先当前租户、后全局模板，各分区内按列表从上到下选择首个命中项。租户普通流程未命中时仍可使用全局普通流程，全局普通流程优先于租户兜底流程。列表排序统一由标准排序能力维护，调整影响后续提交，不改写已有实例。
3. `approvalEnabled=true` 时，当前有效审批治理实例在同一业务记录上独占。
4. 实例启动后生成节点、route 和任务快照，并按流程推进。全局模板可被租户业务复用，实例及其子对象归属发起业务的租户。
5. 到达 `APPROVAL_COMPLETED` 后回写业务审批通过；后续节点仍可继续运行。

审批提交的预览、手动分支候选与实际提交共用已发布动作的有效授权策略，包含治理覆盖；业务摘要回写沿用本次策略。动作授权与数据范围独立校验，关闭数据权限不会跳过动作授权。

### 审批与任务

审批节点支持同意、驳回后重启或回到驳回人、重提、撤回、撤销本人同意、线性回退、分支域回退、转办、加签、强制同意和任务失效/取消等动作。撤销同意只允许尚可恢复的当前会签或未办理的线性后继；不跨越审批完成里程碑、知会和分支。知会任务不承载审批动作，提供已读入口。

任务节点支持业务字段公式、查询模板计数、动态关联视图计数和已生成业务计数。检查使用当前可见业务数据；人工确认不能绕过未通过的业务检查。办理指引支持填写表单、执行业务动作、查看列表、查看字段和阅读说明。填写表单或执行业务动作时，业务写入、重新检查和任务推进在同一事务中完成，失败全部回滚。已批准记录只能通过任务声明的字段白名单更新。

### 分支与汇聚

分支通过 route 表达实际有效路径。自动分支按规则和默认线推进；手工分支要求在本轮可达候选出线中显式选择，可携带选择原因。汇聚节点按已选路径判定是否继续推进。

自动分支启用所有命中的非默认出口；空条件表示始终命中，可用于并行路径。只有非默认出口全部未命中时才启用默认出口；无可用出口时拒绝推进。每个分支最多一个默认出口，默认出口不能配置条件；条件和默认标记仅用于分支直接出线。客户端手工选路不能覆盖自动判定。条件公式必须返回布尔值；文本和数字不能隐式当作真假值。自动条件错误阻断流转，手工条件错误仅标为未知建议。静态与动态业务事实均包含标准标识、版本、租户、软删和审计字段。

手工分支每次只选一个出口，指定开始节点的提交人，或前序审批/业务任务的实际办理人拥有选择权。决策必须跟随该来源节点的本次办理：发布校验所有最近可能触发分支的阻塞节点均为该来源，不能依赖跨并行路径的完成顺序或配置账号相同；跨路径汇聚后需要手工决策时，应增加独立审批或业务任务作为选择人来源。条件命中、默认出口和系统建议是参考信息，不限制人工选择。汇聚的分母只包含本轮有效路径，不包含条件未命中或人工未选择的出口。配置端成组插入分支与配对汇聚，并支持追加出口、嵌套配置及整体删除；发布前同时确认选路与汇聚规则。

连续自动或手工分支按当前业务事实逐步读取实际可达候选，改选后清除不可达的下级选择；未完成的审批、业务任务和汇聚保持阻塞。

当前覆盖默认线、多 MANUAL 分支选择、嵌套分支与配对汇聚、路径裁剪、有效分支域内回退和 route 原因回显。ANY 或比例汇聚结束后取消其未完成分支任务，避免留下失去办理意义的待办。

### 委托、转办与加签

委托只在正式 TODO 任务生成时匹配，不改变定义和实例图，不追链。任务会冻结原处理人、委托人、被委托人、策略和处理权解释。转办不会重新匹配委托，并切断原委托人额外处理权。

加签按运行态图编辑插入局部单出口收敛段，可包含加签段内部审批、分支和汇聚节点。同一来源节点已有未生效加签段时允许替换；已生效或已生成任务的加签段冻结后拒绝修改。创建和替换均在写入前校验修改后的有效图，保留既有手工分支的选择来源与本次办理职责；不能在选择来源和待决分支之间插入阻塞审批。校验失败时，原任务、加签段、路径及实例版本保持不变。

### 终止、重置与历史

撤回和重置会归档当前实例并释放审批绑定。正常结束和终止保留当前实例及其办理事实。历史实例提供列表、渲染包、任务、事件和解释视图；管理端可查询和删除历史实例。事件的 `reason` 保留操作者原文意见，与系统 `message` 分开持久化及归档；提交和驳回后重新发起的意见同样进入此契约，保留作者及明确填写的来源语言。办理时间线按意见事实展示，不根据系统说明的文字推断意见。

驳回的 `RESTART` 模式允许原发起人重新提交：完成旧轮次的重提待办、取消残留待办、归档旧实例，并按当前有效配置创建新实例，在同一事务中回写业务摘要。新实例关联上一轮实例；新版本只影响新一轮，旧轮次仍按冻结快照回显。`RETURN_TO_ME` 则在原实例内重提并回到驳回节点，保留原版本。

### 超期与预警

超期能力只扫描活动审批节点，只更新节点超期状态并写入预警或超期事件。不自动审批，不自动流转。周期扫描由平台级作业 `platform.workflow-overtime` 在 `default` 通道承担，使用系统上下文与受租约保护的事务；原始 DAO 查询仍覆盖全部租户分区，事件保留系统操作者，不新增提醒。`muyun.workflow.overtime-scan-delay-ms`（默认 300000）与 `muyun.workflow.overtime-scan-initial-delay-ms`（默认 60000）分别用于首次登记计划的 fixed-delay 间隔与首次延迟；已登记计划由管理员维护，受平台全局调度开关控制。运行统计记录扫描、预警、超期和更新节点数。

当前超期配置是自然时间分钟数，从节点激活时刻按绝对 elapsed time 计算；它不是工作日历 SLA，也不排除节假日或非工作时间。平台已提供默认自然日历门面 `BusinessCalendarService`，当前默认实现只表达自然 elapsed time。后续如进入工作时间 SLA，应在工作流节点定义上显式区分自然时间和业务日历时间，再通过该门面接入工作日历实现。

### 插件挂点

工作流运行插件面向稳定动作前后切点。当前支持 `submit`、`approve`、`forceApprove`、`transfer`、`reject`、`rollback`、`revoke`、`reset`、`terminate`、`forceTerminate` 、业务任务 `complete` 的 before/after 事件。

插件可同步执行或 after-commit 执行；默认同步异常会阻断主流程。改写实例图的 `addSign` 不开放普通插件，异步分发、插件配置管理和动态脚本后续再展开。

## 边界说明

1. 前端提供流程配置、业务详情审批面板、个人工作台和实例管理页；配置以语义节点和连线为中心，结构编辑受流程语义约束，不提供任意脚本编辑器。
2. 语义图参与编译和发布校验；布局 JSON 仅用于回显，不参与流程判定。
   前端以 AntV X6 承载配置、预览和运行图，Dagre 提供从上到下的自动布局；第三方 cell 格式不进入业务契约。画布支持平移、缩放、节点定位及全屏，草稿可直接选择节点和路径、拖动节点并保存布局。布局只记录业务节点坐标及结构签名，结构变化重新整理，已发布版本和运行实例使用冻结布局；浏览视口变化不产生草稿修改。
3. 工作流动作复用平台动作、事件、审计上下文和身份权限，不另起一套权限体系。
4. 模块任务不是工作流审批待办；它不保存处理人、办理状态、委托或加签。
5. 参与人支持账号、角色、部门、组织、主管链、提交人和业务字段。任务创建时解析并冻结有效账号；解析不到人员时失败，不退回给操作者。同人自动审批须由节点明确启用，委托和手工分支仍保留人工办理。
6. workflow 发布贡献的 runtime 动作目录保持模块级稳定可授权，不随单个定义停用自动回收。
7. 管理端强制终止、强行代办、管理查询和历史删除归属 `platform.workflow_admin` 管理模块动作。

## 关联专题

| 专题         | 关系                                                               |
| ------------ | ------------------------------------------------------------------ |
| 动静一体核心 | 工作流状态字段、实例字段和任务字段要兼顾静态模型与动态元数据模型。 |
| 平台执行底座 | 工作流动作复用动作上下文、规则引擎、事件和审计上下文。             |
| 身份与权限   | 工作流运行、工作台和管理动作复用当前用户、动作权限和数据权限。     |
| 动态运行态   | 动态记录通过模块动作目录提交审批、执行工作流动作和读取运行详情。   |
| 页面交付     | 流程画布、工作台卡片和表单任务面板属于前端编排面。                 |
| 业务自动化   | 回写、生成、导入导出等专题可通过工作流挂点进入业务编排。           |

## 提醒与数据边界

工作流事实提交后由通知 adapter 向实际待办人、允许共同办理的委托人和发起人发送平台站内提醒。提醒失败不改变已提交业务结果；离线用户以工作台持久任务为准，当前不承诺离线消息收件箱或邮件、短信渠道。

静态和动态审批记录共享五个摘要字段、版本与生命周期规则。普通 CRUD 不能伪造摘要；审批中和已批准记录拒绝普通更新。工作流查询默认只读取当前租户分区，系统用户跨租户管理也须明确选择上下文；直接读取实例、任务和历史 ID 同样受此边界约束。

模块的审批流程抽屉复用平台标准表格，展示流程状态、当前发布版本、匹配条件与启用状态，支持搜索、拖拽排序和行操作。停用流程可直接恢复当前冻结发布版本；草稿仍须进入独立编排页发布，归档流程不提供直接启用。
