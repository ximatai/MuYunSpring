# 工作流工作台概览

工作流工作台承接办理人日常视角：我的待办、已办、知会、发起跟踪和委托责任。它是工作流运行闭环的读侧与轻量操作入口，不替代流程定义、实例管理或业务表单页面。

## 能力定位

工作台面向当前用户聚合任务卡片和统计：

1. 待办展示当前用户需要处理的审批或业务任务。
2. 已办展示当前用户已经处理过的任务。
3. 知会展示当前用户收到的通知任务，并支持已读状态。
4. 发起跟踪展示当前用户发起的流程实例。
5. 委托视角展示当前用户因委托关系承担的任务责任。
6. 统计接口按 board 返回工作台计数。

## 卡片信息

页面使用平台标准查询表格与详情抽屉，按业务事项标题组织任务，可按模块、发起人、接收日期和时效筛选。分页返回筛选后的精确总数，并以实例与任务唯一标识兜底排序。个人委托明确选择全部或指定业务模块，可编辑已有规则，模块候选独立于本人当前任务。

工作台卡片围绕流程实例、业务记录和任务责任组织信息。服务端卡片透出：

| 信息           | 说明                                                       |
| -------------- | ---------------------------------------------------------- |
| 模块与记录     | 用于定位业务记录和运行实例。                               |
| 定义与版本     | 用于识别流程来源。                                         |
| 实例状态       | 表达运行中、结束、终止等实例状态。                         |
| 任务类型与状态 | 区分审批、知会、业务任务以及待办、完成、取消、失效等状态。 |
| 分派解释       | 表达直接分派、委托分派、转办后处理权等事实。               |
| 加签来源       | 可透出 `addedByAddSign`、加签来源节点、操作者和加签时间。  |
| 超期状态       | 用于展示审批节点预警或超期标记。                           |
| 知会已读       | 知会列表支持未读、已读和全部筛选。                         |

## 筛选与排序

工作台查询使用白名单请求字段，不开放任意数据库字段。当前可按模块、记录、定义、版本、实例状态、节点、任务类型、任务状态、分派类型、超期状态、知会已读状态、发起时间、接收时间、完成时间、最后操作时间、到期时间、加签来源和发起人等维度筛选。

排序由 `WorkflowWorkbenchSort` 表达，具体可用字段以运行时服务白名单为准。

## 典型使用

1. 用户打开工作台，前端按 board 拉取统计。
2. 进入待办、已办、知会、发起跟踪或委托页签，按当前用户查询卡片。
3. 用户从待办卡片进入业务详情与流程面板，查看冻结版本、路径状态、任务记录和事件。
4. 审批任务通过任务动作处理；业务任务先准备处理 bundle，再检查并继续推进。
5. 知会任务可在阅读后调用已读入口。

## 边界说明

1. 工作台只做当前用户视角聚合，不绕过任务归属和动作权限。
2. 工作台卡片不是流程实例的完整详情；完整节点、route、任务和事件仍从实例渲染包或历史入口读取。
3. 工作台提供个人委托配置，流程定义和管理端强制处理仍有独立入口。
4. 跨模块业务标题由 `WorkflowRecordSummaryResolver` 聚合：先检查业务记录读取权限，再通过 `ModuleRecordFacts.displayTitle` 应用 LIST 字段输出保护。受限标题不返回，也不参与搜索；自定义 facts 默认不暴露标题。

## 前端入口

个人工作台为 IAM 应用的 `iam.workflow_workbench`，页面 `/workflow/workbench`，包含待办、已办、知会、发起跟踪、委托任务和个人委托配置。其菜单与本人查询使用 `LOGIN_REQUIRED`，租户须开通并启用 IAM 应用，无需流程配置或实例管理权限；数据仍按当前租户与本人参与关系筛选。实例管理保留在平台应用，页面 `/workflow/admin`，提供当前实例和历史查询、强制同意、终止与重置。业务详情面板使用同一套办理组件，静态与动态模块一致。系统管理员切换租户后只查询所选分区。
