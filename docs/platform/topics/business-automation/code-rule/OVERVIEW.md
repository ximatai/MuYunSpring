# 编码规则

编码规则用于为业务记录生成稳定编码，并维护编码占用、序列状态和可回收编码。静态声明、动态记录与显式领域 API 共用生成和占用执行，配置治理、标准表单和无页面静态 API 已接入同一能力。

动静统一编码能力的目标、静态显式 API 与声明式接入边界、生命周期及分阶段验收见 [业务编码能力契约](DESIGN.md)。本文说明当前交付范围，配置、业务接入与运维边界分别由契约及真实数据库、HTTP 验收覆盖。

## 能力范围

- 规则以 `moduleAlias/entityAlias/fieldName` 定位目标字段。
- 支持规则树保存、查看、预览和正式生成。
- 支持序列状态、编码台账和回收池。
- 动态记录新增、更新、删除生命周期可接入编码占用、释放和复用。
- 静态 Service 通过 `CodeAbility` 和模型 `@BusinessCode` 声明接入，不要求动态元数据或管理页面；字段可以声明 `SAVE` 或 `EXPLICIT` 触发。
- 静态业务通过 `CodeRuntimeFacade.preview/generateOnly/issueAndBind` 预览、正式取号或取号并绑定自己的业务目标。显式赋码后的标准保存认可精确匹配的已有占用。

## 运行边界

编码台账是当前占用事实表，不是流水日志。同一租户、模块、实体、字段和编码值只有一条当前事实，跨规则共享占用约束，状态在 `ACTIVE`、`AVAILABLE`、`DISCARDED` 间流转。

软删除保留编码占用，恢复校验原占用归属；最终清理和硬删除才按实际发号时保存的策略释放。旧号的规则、计数范围和周期以原台账为准，不随当前规则与日期重算。回收只消费真正释放的号码，不通过软删除绕过业务唯一约束。

标准保存与显式绑定在业务事务内执行，台账通过宿主数据库事务锁串行化同一目标的占用变化；序列分配和回收池消费已在 PostgreSQL 路径验证并发边界；非 PostgreSQL 数据库不宣称具备同等原子语义。

编码规则中的日期段、周期键和系统时间预览使用平台业务时间服务解析当前业务本地时间。组织时区解析已通过平台时间底座接入；如果没有匹配的组织时区解析器，则回退到平台默认时区。后续租户、组织主数据时区应继续接入同一时间服务，不在编码规则内另建时区规则。

## 业务使用口径

- 动态业务先在模块关系下声明编码字段，再配置租户规则；动态记录保存链路只执行已声明的字段。
- 标准动静表单从字段 descriptor 读取编码角色和触发方式，再通过统一只读入口读取当前租户、业务机构、生效时间下的模式和候选编号。自动字段只读，手工模式保留模型必填约束；显式字段等待领域动作。候选单独展示，不写进提交草稿。
- 标准聚合的子表使用最终主表字段和编码作为限定来源；静态 Service 通过已声明的 `ChildrenAbility` 关系自动传递主表当前值与更新前值。静态主表来源使用其 `codeEntityAlias()` 限定名；子表同名字段不被覆盖。
- 预览读取当前流水和可用回收候选，不分配、不消费、不写占用；候选不构成预留，并发或生效时间变化后以正式保存结果为准。
- Excel 导入沿用标准保存的编码模式与占用校验；自动模式拒绝文件伪造编号，事务失败同步回滚流水与台账。审批状态写回保留编码，审批中及通过后的普通编辑仍遵守审批保护。
- 运维人员可通过规则运维入口查看规则快照、定位序列桶、调整序列基线、调整回收池状态、检查或释放台账；也可从序列状态行直接发起基线调整。

## 配置治理

动态模块的低代码治理提供“业务编码”页签；模块详情的“业务编码”入口同时支持静态与动态业务。编码规则菜单可进入独立编码工作台，不要求目标业务有页面。

动态字段角色与触发方式保存在 `ModuleMetadataField`，编译为 `EntityDefinition.businessCodes`，并推导 `BUSINESS_CODE` 能力。静态字段事实来自 Java 声明，配置页面只读其角色与触发方式。规则中的角色由字段绑定校准，不允许页面另设主编码开关；每个实体最多一个主编码字段。

字段绑定随模块定义归属；规则、流水与占用按业务租户隔离。系统管理员在工作台选择规则所属租户。组织“全局默认”表示该租户内全部组织，不表示系统规则自动向所有租户继承。共享绑定仍被任何租户的启用规则使用时，不允许移除或更换角色、生成时机；该约束在标准保存链生效，普通元数据治理入口也须遵守。

工作台维护完整规则树：编号模式、组织及生效区间、七类顺序片段、流水策略与映射。保存前编译目标身份、来源、公式只读性、循环依赖及编码长度；正式启用仍遵守有效范围不能重叠的约束。编码长度同时受目标列与平台 256 字符占用上限约束。无法推导长度上限的公式或外部上下文片段须显式声明长度和截取策略。

草稿试算使用后端同一渲染逻辑和业务时间，不推进流水、不创建占用。动作上下文中的外部名称只用于 `EXPLICIT` 字段，由领域动作提供；普通 `SAVE` 规则不得依赖未声明的外部输入。字段绑定变更沿既有模块运行态激活机制生效；编号规则按事务提交后的配置执行。

## 静态业务接入

模型在未保护的持久化 `VARCHAR` 字段上声明 `@BusinessCode`，Service 实现 `CodeAbility<T>`。默认实体别名是模块 alias 的最后一段，可通过 `codeEntityAlias()` 显式指定。`primary` 与 `trigger` 属于字段声明；规则维护入口从静态声明校验目标，不伪造动态字段 ID。

`SAVE` 字段在标准保存中自动处理；`@BusinessCode(trigger = CodeTrigger.EXPLICIT)` 字段可在草稿中为空，由已授权领域动作显式调用：

```java
// 在领域动作的业务事务内；调用前完成动作授权、记录范围、审批和版本校验。
var command = CodeRuntimeCommand.builder(moduleAlias, entityAlias, "confirmationNo")
        .sourceRecordId(record.getId())
        .organizationId(organizationId)
        .context(context)
        .build();
record.setConfirmationNo(codeRuntime.issueAndBind(command).value());
service.update(record);
```

`preview` 不分配流水；`generateOnly` 正式分配但不建立记录占用；`issueAndBind` 对目标与记录幂等绑定。独立取号与后续独立保存不构成一个事务。无事务宿主的手工装配不承诺数据库原子性，标准静态自动赋码要求有效业务事务。

`school-demo` 提供两种业务样例：`education.purchase_request` 为有标准表单的采购审批，`education.receipt` 只有静态模型、Service 和 HTTP API，不声明页面、菜单或动态元数据。使用前在编码工作台配置所属租户规则：采购的 `documentNo`；回执的 `documentNo` 和 `confirmationNo`。回执先通过 `/insert` 创建，再通过 `/{id}/confirm` 携带 `expectedVersion` 确认；该专用动作要求记录授权、版本一致，并在同一事务内赋码和保存。生产调用方应按实际领域规则增加自己的状态检查。

接口摘要见 [WEB_API.md](WEB_API.md)。

## 运维与保守纠偏

运维入口提供规则快照、序列桶定位与基线调整、台账检查与陈旧占用释放、回收状态调整。规则记录快照使用规则 ID 的记录查询授权；台账和回收条目操作使用 `opsQuery/opsManage` 管理动作，条目 ID 不冒充规则记录 ID。所有写操作以条目或规则真实租户执行，并与发号使用相同的目标事务锁；基线调整不会取消已有占用约束。

台账诊断按台账保存的目标和原发号事实执行，不依赖当前规则仍启用或存在。软删除记录仍是持号者；目标已卸载、字段不可确认、其他保留记录仍持有该号时，只报告问题并保留占用。只有确认原记录已不存在、字段为空或已改号，且没有其他保留记录持号时，才允许释放。释放同步更新台账与原规则的回收池，记录操作原因；不自动绑定当前业务值、不改业务单据、不自动回填历史流水。

回收状态调整同时校准对应台账；禁止重开已消费或正被业务占用的号码，禁止把原本不允许回收的作废号码重新开放。规则目标身份创建后不可迁移，避免把历史流水和回收池转给另一个字段；需要新目标时创建新规则。映射行继承所属规则的组织范围，不接受未参与执行的独立组织声明。手工改号与联动生成分别记录释放原因。

配置包沿既有通用快照归档与交换能力运行；该能力不自动采集编码配置，也不应用或恢复编号运行态。后续将规则与字段绑定接入配置包时，只能携带配置事实，不能携带序列状态、台账、回收池或执行日志；归档成功不表示规则已经应用或模块已激活。
