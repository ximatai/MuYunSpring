# 业务编码能力契约

本文规定业务编码的建设目标、公共边界和验收口径。当前已交付范围见 [专题概览](OVERVIEW.md)，不能把本文中的目标视为已经开放的 API。

## 能力与接入

业务编码为单据、主数据及其直接子表提供可配置的业务标识。静态 Java 声明、领域 Service 显式 API 和动态元数据是三种接入入口，共享规则解析、预览、生成、占用、释放与治理实现。

静态业务可以只有 Service 和 HTTP API，不要求管理页面、动态记录或动态元数据。静态声明使用平台已有的 Service 注册和模型字段事实；动态声明使用模块关系下的字段事实。两种来源在配置和执行前归一为相同的业务目标。普通业务不实现流水分配、台账同步或回收编排。

业务目标由模块、实体和字段确定；租户决定数据隔离。规则 ID 表示编号方案，不能作为业务编码唯一性的唯一分区。不同机构规则、不同生效期间及规则替换不应让同一目标内出现重复占用。

模块能力、字段绑定与编码规则各自承担不同事实：模块表达接入能力，字段绑定表达目标及角色，规则表达生成策略。只有一份有效字段绑定，页面和 API 从同一声明推导能力；不能维护互相矛盾的多组启用开关。

一个实体可以有多个编码字段，最多一个主编码字段。主编码是业务对象上下文中的角色，不是物理字段的永久属性。记录 `id` 仍是持久化及引用身份；主编码不替代标题字段。业务可绑定已有字符串字段，不强制为所有模型增加单据编号列。

## 编号规则

规则整体维护规则头、顺序片段、流水策略与值映射。保留常量、字段值、上下文变量、系统时间、流水、值映射及公式七种片段；公式复用平台公式引擎。片段声明长度、补位、截断、空值策略及是否参与计数范围。

流水支持起点、步长、长度、上限、溢出策略，以及不重置、按日、月、年重置。计数范围和计数周期是业务可解释的概念，不向普通用户暴露内部拼接键。

同一目标按当前机构、祖先机构、全局默认顺序命中规则，并校验生效区间。同范围规则冲突在配置阶段拒绝，不能依靠排序静默选择。业务机构来自显式目标上下文；局部更新使用最终有效业务记录，不因 patch 缺少机构而切换为操作者机构。

主表和子表字段来源必须明确；同名字段不能互相兜底。子表允许读取主表上下文及已生成的主编码。依赖与目标字段、字段类型、输出长度及公式可执行性在配置编译时校验。

## 生成与保存

| 模式 | 新增 | 更新 |
| --- | --- | --- |
| `AUTO` | 标准保存时自动生成，拒绝非空人工编码 | 默认保留；开启联动且实际依赖变化时重新生成 |
| `MANUAL` | 用户提供，平台检查最终值与占用 | 允许按声明修改，仍检查占用 |
| `AUTO_WITH_MANUAL_EDIT` | 缺省自动生成，也可显式提供人工编码 | 显式人工修改优先，否则按联动规则处理 |

字段绑定统一声明生成触发方式：`SAVE` 默认在首次保存时生成；`EXPLICIT` 仅由领域动作调用门面触发，例如确认订单，普通保存不提前发号。模式描述编号方式，触发方式描述何时执行，两者职责独立，不在规则和页面重复维护开关。显式触发字段允许业务草稿尚无编号，因此不可声明数据库非空或普通保存必填；该冲突在声明和绑定校验阶段拒绝，最终业务动作自行要求编号已产生。

显式 API 已绑定的编码在同一业务事务内写回时，标准保存以目标、租户、记录 ID 与编码值全部匹配的有效占用证明认可该值，不当成人工输入拒绝或再次生成。未绑定的候选或仅取号结果不能冒充此证明。空值、未提交字段、原值回传与人工变更必须区分，不能仅凭请求包含字段就误判人工改号。编码字段的必填约束检查最终值，不能要求自动模式的调用者事先提供编码。

预览、正式取号与取号并绑定是不同操作。预览不推进流水、不占用号码，结果仅为候选。正式取号推进流水；取号并绑定还维护业务记录占用。稳定门面覆盖这些操作，业务不直接操作底层状态表。重复绑定同一目标与记录应幂等；并发保证落在数据库，不能依赖单进程锁。

标准保存与显式 API 参与调用方的业务事务，主子表、业务值及编码占用失败整体回滚。独立取号必须明确自身事务边界，不承诺与尚未发生的业务保存原子一致。允许断号，不提供无断号开关或通过回收承诺连续性。

一次执行冻结有效规则、业务上下文和业务时间，预览与正式生成遵循同一时区语义。保存后的台账保留实际命中的规则、计数范围及周期；后续释放按原占用事实处理，不能按当前日期或新规则重算旧号码归属。

## 编码生命周期与组合能力

改号后释放旧号码并建立新占用，事务中任一步失败均回滚。是否允许旧号码复用由规则策略决定：可回收为 `AVAILABLE`，不可回收为 `DISCARDED`；重新发号只消费允许使用且仍无业务占用的号码。

软删除默认保留编码占用，恢复时仍须校验归属；最终清理或直接硬删除才按原占用策略释放。这与平台保留记录仍参与唯一性检查的语义一致。本轮不开放软删即回收的策略开关。恢复冲突应返回明确业务错误，不得静默改号；最终清理不得释放已由另一记录取得的号码。父子聚合沿既有删除链、恢复和清理边界执行，不另建整套删除协调器。

规则停用、失效或调整不取消历史占用，也不阻止按历史事实释放和诊断。正常改号、新增与人工编码接受仍须满足业务目标内的唯一性；规则变更不主动批量修改业务记录。

审批对普通业务写入的限制继续复用审批能力。编码能力不能绕过审批锁定、数据权限、租户、版本或事务。导入、生单草稿和正常录入使用同一保存链路；接受人工编码后的流水接续遵循显式模式与规则，不要求为历史导入数据自动补建全部台账。

显式门面是可信领域原语，不是授权完备的业务入口。领域 Service 在调用前负责业务动作授权、目标记录范围、审批状态和版本条件；编码内核负责声明目标合法性、租户隔离、占用唯一性、幂等与事务。HTTP 通过所属业务动作调用，不直接投影为可指定任意模块及记录的跨模块写接口。独立取号同样只供已授权领域动作或受治理的内部任务使用，不能从客户端任意选择目标绕过业务授权。

## 页面与治理

静态与动态页面从统一 descriptor 获取编码角色、模式、输入要求、可编辑性与预览能力。页面不解析规则表达式，不把候选预览值当成用户输入提交；最终编码以服务端保存结果为准。纯静态 API 的可用性不依赖这些页面投影。

模块治理提供字段绑定和规则配置入口；规则编辑支持格式示意、后端草稿试算及生效反馈。运维提供运行概览、流水、台账、回收池和日志。检查、释放陈旧占用、基线调整、回收状态调整各有明确动作授权、并发校验和留痕。

台账表达当前占用事实，不替代流水日志。业务事务失败后需要保留的诊断应遵循平台日志与事务边界，不把回滚掉的成功记录宣传为独立失败日志保障。编码配置接入配置包时，只能包含规则与绑定等配置事实，不携带目标环境的流水、台账、回收池及执行日志；通用快照归档不等同于编码配置的自动采集、应用或运行态恢复。

## 交付阶段与验收

| 阶段 | 完成能力 | 验收边界 |
| --- | --- | --- |
| 一：业务契约 | 动静声明、显式 API、目标身份及业务行为 | 公共事实归属和组合规则明确 |
| 二：共用运行能力 | 目标解析、统一门面、声明式保存与占用生命周期 | 真实静态业务不依赖动态元数据；数据库验证事务、并发和恢复冲突 |
| 三：配置治理 | 模块接入、动静目标选择、规则树编辑、试算与生效 | 可通过治理页面完成配置，无需直接操作数据库 |
| 四：业务交付 | 标准表单、主子聚合、静态 API、审批与导入组合 | 真实页面及无页面静态 API 均完成业务闭环 |
| 五：运维验收 | 运行诊断、保守纠偏、跨规则历史占用和整体验证 | 场景回归、前后端检查及完整后端验证通过 |

每阶段包含对应测试和必要文档；源码、配置定义和页面投影保持单一事实来源。新项目不为旧编号配置保留兼容分支。

本轮不建设编码外部服务中心、任意对象 SPI、批量自动修复、回收池重建、自动补绑历史业务或无断号机制。
