# 导入导出

开启 `EXCHANGE` 的静态 Java 模块与动态元数据模块复用 `RecordExchangeService`。标准页面提供业务填写、人工译文维护和阅读导出三种文件；普通业务只声明能力与字段策略，平台负责文件身份、预览、引用解析、事务及失败重传。

## 文件用途

- `DATA`：交换真实业务原值。来源语言随原文字段保存，修改形成正常业务修订；展示译文不会回写原字段。
- `TRANSLATIONS`：按原文身份、原文版本、目标语言和译文维护版本交换人工草稿。导入不确认译文质量，不修改业务原值；原文或译文已变化时要求重新导出复核。
- `READING`：指定语言的阅读副本，带原文、语言与译文状态。服务器验证用途身份，不能直接回导为业务原文。

文件使用技术字段名与展示标题两行表头。技术字段、sheet 实体身份和 `relateId` 定位业务，展示标题不参与匹配。文件声明的名称解析语言独立于界面语言和本次原文填写语言，导入时可显式调整解析语言并重新预览。

系统生成的文件携带可验证的文档与行身份。服务器只持久化身份、版本、基线摘要、引用身份和导入回执，不复制业务原文到回执；有效期为 30 天，过期回执分批清理。身份不授予访问权：每次操作重新校验租户、当前用户、业务范围、字段与状态。授权同事可以共同处理同一文件。

## 填写与引用

主表每行填写唯一 `relateId`，子表使用对应主行的标识。预览选择各表匹配字段和重复策略，展示当前值、拟修改值、来源语言、错误及待确认引用对象。服务端可从对象声明的单字段租户唯一约束推荐匹配字段；多字段联合唯一不会被拆成单字段推荐。对象核对使用正常受权引用说明（如声明的编码），不可见时保留稳定身份用于区分。文件、匹配策略、语言或对象选择变化后，必须重新核对才能导入。

引用名称只在正常候选范围内解析：唯一的原名或当前人工确认译名可以直接关联；重名需选择实际对象，未知名称提示修正，不自动新建基础资料。仅匹配未经确认机器译名时，须明确确认业务对象后重新核对；此操作不确认译文质量。

系统文件保留引用身份及单元格基线。分类后来改名，用户只改数量时仍保留原关联；主动改分类单元格时重新解析。原文、人工确认译名与机器译名的候选并集按实际对象去重，不能因某一种名称先匹配就忽略歧义。

更新时空白或缺列表示不修改；清空在 `__clearFields` 中显式列出技术字段名，不能同时填写新值。`0` 和 `false` 为实际值。新建执行正常必填、默认值及业务校验。文本保留实际空格和换行；超出 Excel 精确数字范围的长整数、小数以文本承载，导入仍按字段类型解析。

普通数字单元格按真实数值读取，不能以 Excel 显示格式的舍入结果修改业务值；日期仍按声明的时间契约处理。

## 事务与失败重传

独立业务单元分别提交。100 条独立记录中 90 条正确、10 条错误时，90 条先成功，错误文件只保留 10 条待修正记录，直接修改重传即可。错误文件保留本次修改字段的原文语言及有效名称解析语言，直接重传不要求再次选择；未修改原文仍保留原来的语言。服务器回执防止同一已提交文件行再次写入；已经成功的行若需继续修改，应重新导出当前业务。

一层主子表按完整业务聚合作为事务和重试单元，通过正常主表聚合保存执行子表生命周期、汇总公式及业务状态约束。某单失败时整单回滚，其他独立业务单元可以成功。错误文件包含未成功的可写行，以及必要的只读关联上下文；上下文只携带已验证身份，不重放旧业务值，不重复插入已成功记录。正常子表修改引起的主表派生汇总仍按原有语义更新。

并发修改依据预览或导出时的记录版本、原文版本检查。手工文件匹配到的对象同样冻结身份和版本；预览后新出现的同名对象不能悄悄把新建改为覆盖。可收集错误返回到失败文件，未识别的系统异常仍传播并回滚当前业务单元。

## 权限与查询

标准入口按 `IMPORT`、`EXPORT` 动作权限开放。读写复用当前已发布执行计划、正常字段保护、引用候选约束、租户与业务数据范围。主子记录重开读取，不能由文件指定服务、租户或可执行动作。导出复用当前查询的条件、快速搜索、引用范围与服务端语言排序；选中记录与查询同时提供时取交集。

单次文件限制为 8 MiB、1000 行、50 张业务 sheet、每张 200 列；导出应缩小查询或选择范围，不能静默截断。结果即时返回失败文件；旧下载 token 另受实际操作人、租户、模块、30 分钟有效期及下载时最新业务读取范围保护。回执用于文件幂等与恢复，不是通用任务中心。

同步业务文件导出按当前授权重开记录、读取来源并建立可核实的回执基线。1000 行是协议上限，不是交互延迟承诺；千行导出仍较慢，受控试用先以约 50 行的完整业务单元小批次评测，再按实际等待和代理超时选择范围。后续批量读取及基线构建优化必须保持逐记录权限、字段保护、原文与引用身份、事务及回执语义，不能直接绕过业务读取链路提速。

## 时间交换

工作簿 meta 的 `timeZone` 必须为 IANA `ZoneId`，如 `Asia/Shanghai`，不接受 fixed-offset 写法。

- `DATE` 交换业务日期，不换算时区。
- `TIMESTAMP` 接受 UTC instant，或按工作簿时区解释本地日期时间。
- `ZONED_TIMESTAMP` 同时交换 owner 与 companion timeZone，按 companion IANA 时区转换为 UTC instant。未改动的两列保持原值；明确清空 owner 时一并清空 companion。

## 兼容边界

标准页面与新的静态、动态 Web 入口使用同一文件引擎。旧动态 HTTP 解析、执行和导出路径作为兼容适配保留，写入与文件基线复用公共引擎；旧客户端不能明确确认机器译名时会得到待修正结果。旧模板仍接受协议 1，公共导出使用协议 2。

旧 `DynamicImportFacade`、`DynamicExportFacade` Java API 已标记废弃，仅保留既有调用兼容；新业务使用公共能力契约，不能据旧 API 的测试推断新文件能力。更深子表层级、广泛业务推广与跨环境配置译文交付不属于本轮范围。
