# 外部身份联邦设计

本文固化外部身份源接入登录体系的目标设计，首个身份源为 WeLink 扫码登录与通讯录同步。当前已实现“安全前置”、机构类型字段，以及基于模拟身份源的外部登录与绑定闭环（身份源、租户接入策略、外部身份绑定、登录事务）；通讯录同步已交付阶段 A/B（模拟通讯录、预览、作业接入、缺失与离职处理、调岗回收、范围变更确认及来源新鲜度）；`AUTO`/`REVIEW` 开户尚未实现；WeLink 插件已交付扫码登录与只读通讯录适配，本地模拟 HTTP/真实平台链路已覆盖，真实厂商联调待完成。实现按本文收口，未上线阶段不保留旧模型兼容路线。

## 定位

外部身份源只负责证明“这个人在外部系统中是谁”。本地账号、租户准入、角色授权、数据范围与会话始终由平台决定。外部身份不是平台身份根，也不替代 `tenantId` 隔离、动作授权或数据权限。

外部身份联邦是 IAM 的可选能力：平台提供与厂商无关的身份绑定、登录事务、开户策略和通讯录同步框架；具体厂商协议以独立插件交付。项目不启用（`muyun.iam.federation.enabled` 默认 `false`）时不装配联邦服务、HTTP 入口与管理模块；数据表随仓库扫描建立但保持为空。

## 核心取舍

| 议题           | 决定                                                                                                                         |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 账号模型       | 保持租户内账号。同一自然人参与多个租户时拥有多个账号；外部身份绑定按租户唯一。不引入全局账号与租户成员表。                   |
| 组织映射       | 同步根对应本地手工维护的机构，根以下外部部门同步为该机构下的部门树。映射结构预留“指定节点同步为机构”的扩展。               |
| 机构类型       | `Organization` 增加通用的机构类型字段，取值来自字典；具体业务类型（如主机厂）只是项目取值，不进入平台代码。                 |
| 跨机构服务     | 通过手工兼岗加任职角色表达。任岗区分同步来源与手工维护，同步只维护同步来源的任岗。不新增“指定机构”数据范围。               |
| 模块边界       | 厂商无关能力位于 `muyun-iam` 的 `federation` 包与 `muyun-iam-web`，由开关启用；厂商协议位于独立插件。会话签发不对外公开。 |
| 默认角色       | 授给同步来源的主岗（任职角色），数据范围按其所在机构解释；管理类角色不能作为默认角色。                                       |
| 登录入口       | 首期只支持锁定租户的登录地址；“需要选择租户”状态预留。                                                                       |
| 同步开户用户名 | 工号可信且在租户内唯一时使用工号，否则由外部用户标识派生。                                                                   |

### 账号模型

账号属于租户与平台“租户是身份根”的定位一致：租户管理员可以完整治理本租户账号，禁用、重置或删除不影响其他租户。全局账号会改变 `UserAccount`、`CurrentUser.tenantId`、账号角色授权和 `iam.user` 的租户语义，收益主要来自大量用户频繁跨租户的场景，当前不采用。

“租户成员资格”即本租户存在对应账号且账号启用；待审核加入以独立的加入申请表达，不以禁用账号占位。同一外部身份在多个租户分别绑定各自账号。跨租户切换按 [技术债 TD-008](../../../TECHNICAL_DEBT.md) 的租户切换治理推进，可基于同一已验证外部身份签发目标租户会话，不改变账号模型。

### 组织映射

平台机构与部门分两层：职员必须同时归属机构与部门，数据范围也分机构与部门两套。外部通讯录通常只有一棵部门树，因此：

1. 同步根映射到本地已存在的机构；该机构由管理员维护，同步不修改其名称、层级和状态。
2. 根以下的外部部门同步为该机构下的部门树，`本部门及下级` 对应外部子树，`本机构及下级` 对应整个同步根范围。
3. 同步配置以“外部部门编码 → 本地机构”的映射列表表达。后续需要把分公司等节点同步为机构时，在列表中增加条目，不推翻既有结构。
4. 外部部门编码不作为本地主键；映射唯一键至少包含租户、身份源与外部部门编码。

### 跨机构服务

员工在外部通讯录中归属甲机构、业务上被授权服务乙机构时，由管理员为其在乙机构增加手工兼岗，并为该任岗授予任职角色。用户权限按全部任岗聚合，乙机构数据范围按兼岗所在机构解释。

该方式不修改平台数据范围能力。代价是兼岗同时承载了“授权服务”语义；当跨机构授权大量出现，或汇报关系、组织图等能力开始依赖任岗事实时，再将“指定机构（及下级）”数据范围作为独立平台能力建设。

## 模块与扩展点

```text
muyun-iam（federation 包，muyun.iam.federation.enabled 默认关闭）
  身份源、租户接入策略、外部身份绑定、登录事务、加入申请、同步运行与映射
  登录事务编排、准入判定、开户与同步写入、会话签发
muyun-iam-web
  通用外部登录与绑定入口、管理端标准模块入口
muyun-iam-<vendor>（厂商插件，例如 muyun-iam-welink）
  实现身份源协议接口；HTTP 客户端、厂商字段解析与应用 Token 缓存只存在于插件内
```

厂商协议按能力拆为两个接口，身份源可以只实现其一：

| 接口         | 职责                                                                             |
| ------------ | -------------------------------------------------------------------------------- |
| 登录协议     | 生成授权跳转或受认可的二维码展示信息；用授权结果换取经后端校验的外部身份。       |
| 通讯录读取   | 部门详情、分页读取部门树和部门人员资料；可选员工详情与状态查询。                         |

插件只收到只读的身份源描述对象（`IdentityProviderDescriptor`）：身份源编码、外部企业标识、身份命名空间、Client ID、由平台按环境变量解析的密钥，以及协议配置。协议配置以字符串键值的 JSON 对象保存在身份源上，由协议在管理员保存时校验，用于承载端点、scope 等厂商参数。插件返回的外部身份必须包含外部用户标识和认证时间。企业标识应由协议返回；仅当登录协议通过 `singleEnterpriseApplication` 明确声明企业内部单企业应用时，平台允许用身份源配置的 `externalEnterpriseId` 补齐缺失值。协议未声明、配置缺失或返回企业与配置不符，均以 `enterpriseMismatch` 拒绝；浏览器参数不能补齐企业。前端提交的用户标识、部门或手机号不构成可信身份。

state、浏览器绑定、防重放、准入、账号关联、开户、同步写入和会话签发都由平台完成，插件不创建账号、不写 IAM 数据、不签发会话。会话签发入口 `UserSessionService.loginWithVerifiedIdentity` 只允许 `federation` 包调用，由契约测试约束。插件以自身自动装配与开关接入，进入 BOM，不进入 Starter 默认依赖。

模拟身份源（协议类型 `mock`）需同时开启 `muyun.iam.federation.mock.enabled`，只在开发运行模式下可用，生产运行模式下启动即失败。它提供一个开发用授权页，由开发者填写外部用户 ID 后按真实流程回到工作台，前后端链路与真实身份源一致。

## WeLink 插件

消费应用在 BOM 管理下显式依赖 `net.ximatai.muyun.spring:muyun-iam-welink`；Starter 不默认携带插件。插件仅证明外部身份与读取通讯录，不创建账号、不维护 state、不签发会话。部署开关默认均关闭：

```yaml
muyun:
  iam:
    federation:
      enabled: true
      welink:
        enabled: true
      workbench-url: https://workbench.example.com/app/
      api-base-url: https://platform.example.com/api/
```

由系统管理员创建类型为 `welink` 的身份源，填写 Client ID、`clientSecretEnvironmentVariable`（仅填写环境变量名；密钥由部署环境注入）、`externalEnterpriseId` 和包含应用范围的 `identityNamespace`。无企业标识返回值，协议声明内部单企业应用，企业仅由平台按已配置值补齐；不能用浏览器参数补齐。已有绑定后，端点基址属于锁定的身份范围配置。租户管理员建立接入策略，配置同步根到本地机构的映射、默认岗位和周期；先预览后正式同步，再开放已有账号扫码登录/主动绑定。同步更新既有来源部门、职员与账号时，在已确认的来源映射/绑定、`SYNC` 模式与租约事务内建立私有来源写入命令作用域，继续调用标准 service 的更新入口；不为普通后台作业或通用定时动作授予宽泛权限。该内部作用域不作为对外公开的记录授权凭证，同模块嵌套 hook 仍须遵守来源写入边界。插件不支持按 userId 查询详情，来源状态最大年龄必须覆盖同步周期、分页、调度和重试余量；超龄未同步时拒绝登录。

身份源 `configuration` 为字符串键值 JSON，例如：

```json
{
  "scope": "snsapi_login",
  "tokenParameterMode": "query",
  "pageSize": "100",
  "timeoutMillis": "10000",
  "minRequestIntervalMillis": "100",
  "activeStatuses": "3",
  "departedStatuses": "",
  "authenticationFailureCodes": "401,403",
  "rateLimitCodes": ""
}
```

| 配置键 | 默认值及边界 |
| --- | --- |
| `apiBaseUrl` | `https://open.welink.huaweicloud.com`；只接受无路径、查询、片段或用户凭据的 HTTPS origin；HTTP 仅允许 loopback 模拟服务 |
| `loginBaseUrl` | `https://login.welink.huaweicloud.com`；网页只信任这一官方 origin。HTTP loopback 覆盖仅用于后端协议测试，不能用于浏览器扫码；其他登录域名暂不支持 |
| `scope` | 仅接受 `snsapi_login`，不使用管理后台 scope |
| `tokenParameterMode` | `query` 或 `form`；默认沿用已对接项目的查询参数、空正文；`form` 使用标准表单正文。不会失败后换模式重兑同一码。真实环境确认表单兼容后优先使用 `form`，默认查询模式须对出站代理日志脱敏 |
| `timeoutMillis` | 每次 HTTP 请求 10000ms，范围 1–120000；连接另有 10s 上限，整体仍受请求超时约束 |
| `pageSize` / `maxPages` | 100 / 10000；范围分别为 1–200 / 1–100000；达到页数上限后失败，不能视为完整通讯录 |
| `refreshAheadSeconds` | 应用 Token 提前 300s 刷新，范围 0–3600；提前量最多为实际有效期的一半 |
| `minRequestIntervalMillis` | 同身份源及凭据配置内请求最小间隔 0ms，范围 0–60000；本地进程内限速 |
| `backoffMillis` / `rateLimitRetries` | 1000ms / 2，范围 0–60000 / 0–5；HTTP 429 或配置的业务限流码指数退避，最多等待 60s，数值型 Retry-After 在上限内被尊重 |
| `rateLimitCodes` / `authenticationFailureCodes` | 空 / `401,403`；逗号分隔业务码，不允许成功码 `0`、空项或重复。HTTP 401/403 及配置鉴权码清除应用 Token 后仅重试一次；应用票据获取失败不递归重试鉴权 |
| `rootParentCodes` | 空；逗号分隔且经厂商确认的根父节点哨兵（如部署返回的 `0`），映射为无父节点；空值本身已视为无父节点，不预设某个真实部门编码是哨兵 |
| `noMoreValue` | `0`；明确代表无更多的非布尔 hasMore 值。布尔 false 或返回条数小于请求 pageSize 也结束；满页的数字 1 默认继续，不能据存量代码直接判断结束 |
| `activeStatuses` / `disabledStatuses` / `departedStatuses` | `3` / 空 / 空；逗号分隔且互不重叠；只有 `3` 默认映射 active，其余（含 `6`）、缺失状态均为 unknown。停用与离职值仅在厂商确认后配置 |

HTTP 使用项目已有 JDK HttpClient 与 Jackson，不引入新库。应用 Token 缓存仅在插件进程内，按身份源、Client ID、密钥及协议配置摘要隔离，最多 256 项，并发刷新合并；重启自然丢弃，不记录请求、响应、授权码、Token、密钥或手机号。网络及解析异常不携带可能包含敏感内容的底层 cause；上游 message 用于判断登录兑换成功，但不向平台/日志透传。授权码兑换与登录身份读取不自动重试，避免一次性授权结果重复消费。状态限流退避只应用于应用票据和通讯录。

部门列表用 `recursiveflag=1` 收齐有界树、校验重复/缺失父节点/环并按父先子后返回（列表不含同步根时读取详情补入根，保证平台先建立根映射）。平台续页使用绑定身份源、凭据配置和同步根的随机快照游标，5 分钟有效；最多 64 个快照、合计 100000 部门行，读取单树同样不超过 100000 行。续页不重读变动后的树，重放游标结果相同。快照失效、淘汰或进程重启均明确失败，须新建整轮同步；不能跨节点恢复旧快照。快照只稳定插件续页，厂商本身分页期间的增删仍需真实联调确认。人员列表保留 mainDeptCode 主部门、deptCodes 全部部门与当前列表观察到的部门，手机号和邮箱只作为资料，不参与身份关联。

### 扫码交互与登记项

后端通过可选 `qrCode` 展示描述返回非敏感的脚本地址、Client ID、redirect_uri、state、scope、授权地址和消息 origin；原有授权 URL 及回调完成流程保持统一。登录和主动绑定入口均支持该展示方式。工作台只认可官方脚本与 origin，并校验消息 source 必须是当前二维码 iframe；消息重复、格式不符或事务过期时忽略。脚本失败显示网络/其他登录方式提示，可关闭后重新发起；不会自行伪造“已扫码”状态。

核对的公开资源：[wlQrcodeLogin.js](https://login.welink.huaweicloud.com/sso-proxy-front/public/qrcode/0.0.1/wlQrcodeLogin.js) 暴露 `window.wlQrcodeLogin(options)`，支持 id、client_id、redirect_uri、response_type、scope、state、self_redirect、lang、width/height；它只创建 iframe。[qrcode.html](https://login.welink.huaweicloud.com/sso-proxy-front/public/qrcode/0.0.1/qrcode.html) 在获得 login_code 后向 parent 发送字符串消息（目标为 `*`，因此接收方必须校验 origin/source）。组件收到字符串后以固定参数构造 `/sso/oauth2/sns_authorize`，将该值作为 code；最终 code/state 回到已登记工作台，再由原有浏览器凭证完成事务。以上是当前公开脚本观察结果，不替代厂商协议保证。

开放平台需登记：普通员工内部应用的 Client ID/密钥、工作台精确回调 URL（与兑换 redirect_uri 一致）、扫码可信域名、服务器出站 IP 白名单、通讯录权限和应用可见人员范围。部署 CSP 需允许官方 login origin 的 script-src/frame-src；工作台声明 no-referrer，并在入口访问日志及出站代理日志中移除授权参数。公网 API 与工作台地址分别填写，不能把 API 回调当成工作台。

### 已确认与待厂商确认

已按提供的运行事实及本地 HTTP 契约实现：应用票据 JSON 请求、提前缓存刷新、业务 code=0；登录 query/form 参数模式、message=success、x-wlk-Authorization 身份读取；页码从 1；内部单企业配置补齐；无员工详情接口。这里的“已确认”指提供的对接证据，不表示本插件已经真实厂商联调。

待厂商确认：

- userStatus 各值含义，特别是 `3`/`6`、禁用与离职区分；离职是否仍出现在列表，以及何时从列表消失。
- hasMore 的数字语义（存量代码按 1 结束存在疑点）、递归部门页的顺序/稳定性、根部门 parentCode 的空值语义、deptCodes 的数组或逗号分隔形态。
- 限流配额、业务限流/鉴权失败错误码、Retry-After 行为；当前限速/缓存为进程本地，多节点配额需部署侧统一控制。
- PKCE 或其他把授权码绑定到发起事务的厂商机制、授权码有效期/一次兑换保证、表单兑换支持。
- 内部单企业应用约束、配置的企业标识权威来源、不同应用间 userId 稳定性与普通员工 scope 可用范围。

授权请求不发送未经证实支持的 PKCE 参数。目前采用 state 一次性事务、浏览器绑定、服务端 client_secret 兑换及厂商授权码一次兑换作为补偿约束；它们**尚不能证明授权码绑定当前事务**，不宣称通过下文验收第 10 条的授权码移植防护。启用真实环境前必须让厂商确认等价绑定机制；本地模拟成功不能替代该安全确认。单企业能力只允许平台配置补齐，不接受浏览器提供企业字段。

## 领域模型

| 对象         | 职责                                                                                                                       |
| ------------ | -------------------------------------------------------------------------------------------------------------------------- |
| 身份源       | 平台级配置，由系统管理员维护：类型、外部企业标识、身份命名空间、应用凭据引用、端点与启停。可被多个租户引用。               |
| 租户接入策略 | 租户级配置，由有权限的租户管理员维护：引用身份源，登录与绑定开关、开户策略、默认角色、准入范围、同步根映射与同步计划。     |
| 外部身份绑定 | 外部身份与本地账号的关联：身份命名空间、外部企业标识、外部用户标识、租户、账号、关联来源、来源状态与时间。                 |
| 登录事务     | 一次扫码的服务端状态：随机 state、PKCE 校验串、目的（登录或绑定）、目标租户与身份源、绑定发起账号与会话、浏览器关联、过期与消费状态。         |
| 加入申请     | 首次扫码、无本地账号且开户策略为审核时产生的待审事实；审批前不签发业务会话。                                               |
| 同步运行     | 一次同步的专题事实：范围版本、游标、统计、失败页与完成标记，以作业运行标识关联平台后台作业的执行状态与进度。               |
| 部门映射     | 外部部门与本地部门的对应关系、所属同步根与最近同步信息。                                                                   |

约束：

1. 外部身份绑定唯一键为身份命名空间、外部企业标识、外部用户标识与租户；同一租户内一个外部身份只能绑定一个账号，一个账号对同一身份源最多一个有效绑定。唯一性由数据库约束兜底，软删除不能绕过。
2. 身份命名空间表达外部用户标识的真实唯一范围。未确认外部用户标识跨应用稳定前，命名空间包含应用范围，不合并不同应用的同名标识。身份源已有绑定时，协议类型、Client ID、身份命名空间、外部企业标识以及协议声明的身份范围配置（如 issuer）均锁定；更换身份权威须新建身份源。
3. 外部用户标识是唯一的主关联键。姓名、手机号、邮箱不用于自动合并；工号只在企业范围明确、唯一且可信时作为辅助依据。用户名相同不构成接管已有账号的依据。
4. 应用凭据只保存安全引用，不在前端、URL、普通日志与接口回显中出现。

### 与现有模型的对应

| 外部事实           | 平台落点                                                                                       |
| ------------------ | ---------------------------------------------------------------------------------------------- |
| 外部员工           | `Employee`，主机构为同步根映射的机构，主部门为外部主部门对应的本地部门。                       |
| 外部多部门任职     | `EmployeePosition`：一个主岗加若干兼岗，不以最后遍历的部门覆盖全部归属。                       |
| 登录账号           | `UserAccount`，允许无本地密码；通过 `EmployeeAccount` 与职员一对一绑定。                       |
| 默认角色           | `EmploymentRoleGrant`，授给同步来源的主岗。                                                    |
| 业务数据归属       | 沿用标准权限字段 `authOrganizationId` 等，不新增业务专属归属字段。                             |

`EmployeePosition.positionId` 必填，而外部通讯录通常不提供岗位标准项，因此租户接入策略需指定同步任岗使用的默认岗位。`Employee.employeeNo` 只在机构内唯一，工号作为用户名前需校验其在租户内唯一。

### 来源状态与本地状态

`UserAccount.enabled`、`Employee.enabled` 和任岗启停是本地管理状态；外部在职、停用或离职状态记录为来源状态，存放于外部身份绑定与同步来源事实上。

1. 登录要求本地状态与来源状态同时允许。
2. 同步与开户只能更新来源状态，不能恢复管理员禁用的账号、职员或任岗。
3. `unknown` 表示来源状态未确认：不新开户、不改变已有账号或任岗来源状态及核验时间、不撤销会话、不调岗、不按缺失回收该人员。预览与正式同步按去重人员计入 `unknownStatus`，在运行详情的统计摘要与作业结果中可见，并以告警结果提示管理员核实映射。未知观测不延长既有来源状态的新鲜度。
3. 同步只维护自身来源的数据：来源职员资料、同步部门、同步任岗与默认角色授权；手工任岗、手工授权和本地角色不被覆盖或回收。

## 登录与绑定流程

### 登录事务

```text
浏览器建立事务 → 平台返回授权地址、state 与 browserProof；state 和 browserProof 只保存在发起浏览器
  → 浏览器打开身份源授权页
  → 身份源把浏览器送回工作台地址，并附带 state 与授权结果参数
  → 工作台用 state 匹配本浏览器保存的事务，带 state、browserProof 与全部回传参数提交平台
  → 平台核对 state 与 browserProof 后原子领取事务，由协议插件在服务端校验并解析外部身份
  → 校验身份源、外部企业、租户接入策略，在租户内解析绑定
  → 登录成功时直接签发平台会话，绑定成功时返回绑定摘要；结果只交给提交请求的浏览器
```

1. 目标租户来自锁定租户的登录入口；未确定身份源时不生成授权地址。
2. 身份源的回调地址登记为工作台地址（`muyun.iam.federation.workbench-url`），而不是平台 API。这样授权结果只会回到完成授权的浏览器，只有发起该事务、持有 browserProof 的浏览器才能完成它：把授权链接发给他人，对方完成授权后也无法让发起者拿到会话，对方的工作台会因找不到对应事务而丢弃回传参数。
3. state 与 browserProof 均为服务端随机生成的一次性值，库中只存哈希，比较采用常量时间；state 不以租户编码充当。回传参数中的 state 须与提交的 state 一致。事务过期、state 未知、凭证不符或重复提交均拒绝，失败后重新建立事务。平台不使用 Cookie，与 Bearer token 会话模型一致。
4. 每个事务另有只存于服务端的 PKCE 校验串（S256），经授权上下文交给协议：授权请求携带其摘要，兑换授权结果时携带原值，使授权结果只能由请求它的事务兑换，泄露的授权码不能移植到他人建立的事务。校验串在事务完成时清除。不支持 PKCE 的身份源，协议须以厂商提供的等价机制把授权结果绑定到事务，接入前单独评估。
5. 工作台在提交前从地址栏移除回传参数，地址中最多保留锁定租户标记；授权码、state、凭证与任何 Token 都不留在地址或浏览历史中。工作台页面声明不发送 Referer，回传地址不会经后续请求带出。
6. 外部 Token 不作为平台 Token。外部身份解析成功后经 IAM 内部会话签发入口登录，复用租户启用、账号启用、登录审计与会话生命周期；会话登录方式记为 `external:<身份源编码>`。
7. 强制改密只约束以密码建立的会话；密码登录锁定只防护本地密码，不阻止也不解除外部登录。
8. 完成结果状态为 `succeeded`、`denied`、`expired`，拒绝原因以稳定码表达（`identityNotBound`、`identityConflict`、`alreadyBound`、`enterpriseMismatch`、`policyDisabled`、`accountUnavailable`、`sessionEnded`、`providerRejected`、`providerUnavailable`，平台自身故障为 `internalError`）。需要绑定、开户确认、审核和选择租户的状态随对应能力加入。
9. 以 POST 把授权结果送回回调地址的身份源（如 OIDC `form_post`、SAML）以及“手机授权、桌面登录”的桥接流程不在本流程内：它们的结果不经过发起浏览器，需要单独设计浏览器绑定或手机端确认后再接入。
10. 厂商不提供扫码状态时，不展示虚构的“已扫码”中间状态。

### 主动绑定

已登录用户在个人设置中发起绑定：

1. 需要近期认证：当前会话须在 5 分钟内建立，否则提示重新登录后再操作。该规则对有无本地密码的账号一致。
2. 绑定事务在建立时固化账号、租户、身份源与发起会话，回调侧不能替换目标账号；完成时发起会话须仍然有效，注销、改密或管理员下线该会话后，未完成的绑定以 `sessionEnded` 拒绝。
3. 外部身份已绑定本租户其他账号时返回冲突，不自动解绑、合并或接管。
4. 绑定不产生其他租户的账号，也不增加数据范围。
5. 解绑需近期认证并保留可用的登录方式：没有本地密码，且解除后不再有身份源可用、租户策略允许登录的绑定时拒绝解绑。解绑物理删除绑定，不删除账号。同步会自动建立绑定时，解绑需记录禁止自动重绑的标记。
6. 管理员在“外部身份绑定”模块查看绑定，通过标准删除动作解除并撤销该账号本租户的会话，沿用标准动作权限、唯一约束与审计。解绑事实阻止该来源自动重新开户或重绑；用户仍可通过显式主动绑定流程重建绑定。显式绑定成功时，在同一事务内清除该租户、身份源与外部用户的自动重绑阻断，允许后续同步继续管理；绑定失败不解除阻断，再次解绑会重新建立阻断。当前不提供管理员直接创建绑定的入口，绑定只能由经过校验的联邦流程创建。

### 开户策略

| 策略       | 无本地账号时的行为                                                                       |
| ---------- | ---------------------------------------------------------------------------------------- |
| `DISABLED` | 拒绝登录并提示联系管理员或使用已有账号登录后绑定。默认值。                               |
| `AUTO`     | 校验准入后展示确认信息，原子建立职员、任岗、账号、绑定与默认角色，提交成功后签发会话。   |
| `REVIEW`   | 校验准入后建立加入申请，审批前不签发业务会话。                                           |

`AUTO` 与 `REVIEW` 均需查询权威员工资料：外部企业、在职状态与准入范围均满足才可开户或申请；取不到可信归属时不自动开户。用户选择的租户或机构只表达意图，不作为准入证据；企业、外部用户标识、工号与组织归属不可由用户编辑。

## 通讯录同步

### 范围与语义

1. 同步根可配置多个互不相邻的外部部门子树；重叠根合并去重。空范围或全企业根需要显式确认，不默认拉取整个企业。
2. 准入范围独立于同步范围。“已同步”不等于“可加入租户”。
3. 同步先提供无数据变更的预览，统计组织数、人员数、重复身份与冲突；预览与正式同步一样后台运行，返回运行标识与进度。
4. 逐页读取并幂等写入，不一次装载整个通讯录；遵守厂商限流，可安全重试的读取采用退避重试，授权码不重试。
5. 只有某一范围整轮拉取成功且范围版本一致时，才判定“本轮缺失”；接口失败、权限不足或范围缩小不能按离职批量处理。
6. 可信的停用或离职状态使对应来源状态失效并撤销相关会话，不影响其他租户中的合法账号。调岗回收旧的同步任岗及其派生授权，保留手工任岗与手工授权。
7. 同步根范围变更先产出影响报告，由有权限的管理员确认执行；清理只作用于本来源管理的数据，不物理删除历史账号。
8. 首期无变更事件订阅时，以定时同步为主，并定义来源状态最大年龄。新鲜度门禁只适用于通讯录管理的身份：`DIRECTORY_SYNC` 绑定始终适用；其他绑定仅在身份源具备通讯录读取能力、租户策略已启用同步且存在生效范围、绑定已有来源状态时适用。仅登录身份源及未启用同步策略下的自助绑定不受最大年龄限制。受门禁约束的身份超龄时，登录前查询权威资料，查询失败拒绝登录及自动开户。

### 作业接入

通讯录同步是平台[后台作业](../../BACKGROUND_JOB_SCHEDULING.md)的首个租户级、专题托管业务作业，平台负责触发、租约、互斥、重试、运行记录与失败提醒，专题只负责读取通讯录与写入 IAM 事实：

| 事项       | 约定                                                                                                                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 作业类型   | 租户级类型，使用独立执行通道，外部拉取不占用平台维护作业线程。定时触发失败不自动重试、等待下一周期；允许管理员人工重试；采用标准失败提醒。                                                   |
| 计划       | 每个“租户 + 身份源”一条计划，专题键为租户接入策略。计划表达式与启停随租户接入策略维护，在策略保存事务中经 `JobService.registerManaged` 登记，策略删除时 `deleteManaged`；作业管理页只做运维。 |
| 执行身份   | 租户内系统执行主体（`SYSTEM` 模式），不以发起人身份执行。专题页的“立即同步”只记录触发人，不改变执行身份。                                                                                 |
| 互斥       | 同一租户与身份源的预览、正式同步共用同一互斥范围，串行执行；不同租户之间互不串行。                                                                                                           |
| 写入       | 外部读取在事务外进行；每页写入经 `JobContext.transaction(businessLocks, writes)` 提交，先取同步专题业务锁再校验租约，事务内不调用外部接口。分页边界检查取消请求；进入人员阶段与整轮处理结束时分别上报 50% 与 100%，接管不回退进度。                 |
| 专题事实   | 同步运行以作业运行标识关联，保存范围版本、游标、统计与失败页；`lockBusiness` 与 `stateChanged` 在平台运行状态变化的同一事务内镜像终态。作业运行不承载同步状态机。                          |
| 结果       | 返回稳定结果码与统计摘要：全部完成为成功；存在失败页为部分成功，不触发“本轮缺失”判定；缺失只在整轮成功且生效范围版本一致、无待确认范围时分批收尾；本轮可信停用或离职立即失效并撤销会话。                                                     |
| 幂等与续跑 | 执行语义为至少一次：写入以外部标识为键幂等；自动重试与接管复用原运行，按同步运行游标继续。                                                                                                   |
| 留存       | 每个租户与身份源保留最近一次整轮完成的正式同步及其后运行事实；更早且超过 30 天的终态运行、见到集合与部门事实由专题有界分批清理，不随作业运行清理一并删除。                                                                                                                                   |

过期登录事务已由 `iam.external-login-retention` 平台级作业清理，使用 `default` 通道，每小时 fixed-delay、首次延迟一分钟，每轮最多 10 批、每批 200 条，物理清理所有租户中已过期的已消费与未消费事务。结果码为 `LOGIN_TRANSACTIONS_CLEANED`，达到批次上限为 `BATCH_LIMIT_REACHED`。

### 阶段 A/B 接入契约

- 读取插件实现 `ExternalDirectoryProtocol`，仅消费 `IdentityProviderDescriptor`。部门分页为包含所选根的父先子后序列，部门只要求 `id/parentId/title`，无祖先路径。部门人员分页直接返回基本资料与来源状态，每项表示当前部门的一条任职观测，可选携带厂商主部门与完整任职集合；平台不逐人查询详情。`supportsPersonLookup` 默认关闭，仅声明支持时才使用 `person` 核验超龄登录身份。状态由插件将已确认的厂商取值映射为 `active/disabled/departed/unknown`，未确认状态不得默认为在职。分页 token 不透明，单页最多 100 条；只读拉取发生暂时失败时最多读取三次，50／100 毫秒退避，插件须遵守厂商限流。身份源可以只实现登录或读取能力，两类协议声明的身份范围配置键共同受绑定后的权威锁定约束；每页提交前在数据库事务内复核身份源权威，读取期间发生权威变化时以 `DIRECTORY_CONFIGURATION_CHANGED` 失败，不提交该页。
- `mock` 读取与模拟登录使用相同开发模式及开关门禁。身份源协议配置的字符串键 `directory` 保存 JSON 字符串，其对象包含 `departments`、`people`、`failPages`。不增加第二套可编辑文件或服务，现有身份源管理页即可维护，fixture 可由测试直接构造。部门按父先子后排列，字段为 `id/parentId/title`；人员字段为 `id/title/employeeNo/primaryDepartmentId/departmentIds/status/mobile/email`，主部门可空，状态为 `active/disabled/departed/unknown`。配置字符串键 `directorySingleDepartmentView=true` 使人员分页省略主部门和全部部门；`people.departmentIds` 仍决定 fixture 中各部门能观测到哪些人。`directoryPersonLookup=false` 关闭员工详情（默认支持）；可组合模拟 WeLink 形态。`failPages` 可填写 `departments:<root>:<offset>` 或 `people:<department>:<offset>`，用于模拟确定性失败。
- 策略的 `syncRoots` 是 `[{"externalDepartmentId":"部门 ID","organizationId":"本地机构 ID"}]`。保存前在持锁事务之外按部门详情的 `parentId` 逐级回溯、合并重复及被祖先覆盖的根；无父节点识别为全企业根。回溯最多 256 层并检测环与返回 ID 不符；同步分页的范围校验复用同一回溯，在事务外核对详情与分页父节点一致。选择父链回溯以避免依赖厂商祖先字段或尚未读完的分页树；代价是每个部门至多一次父链的读取，插件需遵守限流。同一根映射多个机构拒绝。空范围或全企业根要求 `syncScopeConfirmed=true`。空范围表示不读取任何人员，不自动解释为全企业。范围、默认岗位或角色变化产生不可变 `DirectorySyncScope`，队列仅冻结其引用，不保存通讯录全文或凭据。`syncPositionId` 必填，`syncRoleId` 可选，仅接受非管理用途的普通任职角色。
- `syncExpression` 默认每天零点（`0 0 0 * * *`），使用秒位为 0 的 cron，`syncZoneId` 指定合法 IANA 时区，为空时由平台默认时区解析，`syncEnabled` 与策略启停共同控制托管计划。关闭或删除策略时删除托管计划，保留执行历史。动作 `preview`、`synchronize` 按策略、模式与范围版本 `scopeId` 去重，同一未结束运行直接返回其 ID；终态后可再次发起。动作返回平台作业运行 ID，执行身份始终是租户内 SYSTEM。
- 租户类型为 `iam.directory-sync`，自动装配独立 `directory-sync` 通道；部署可通过 `muyun.platform.job.channels.directory-sync.threads/claim-interval` 调整资源，默认 2 个线程、1 秒领取间隔。同一租户和身份源的预览、正式同步共用互斥键，其他租户独立。运行租约五分钟、单次最长一小时、最多三次领取（支持失联执行者接管）；处理器失败不自动重试，保留标准失败提醒和人工重试。
- 游标分部门、任职观测收集、按人员写入与缺失收尾四阶段：保存根序号及外部分页 token，再按本轮部门事实的稳定 ID 遍历人员分页。人员收集按“运行 + 外部用户”唯一键合并到 `DirectorySyncSeen`，保存首条人员资料、按观测顺序去重的部门集合、来源状态和可选厂商主部门；不同部门观测到相互矛盾的状态或主部门，按失败页处理，避免任意覆盖。每页事实、统计与游标同事务提交。收集结束后按人员事实 ID 做 keyset 分页，每人一次性写入主岗与兼岗，和人员游标同事务提交；不在 JVM 装载整轮人员。人员页有失败时不根据不完整任职更新在职人员及回收其任岗，可信停用、离职仍使来源失效；缺失收尾仍要求整轮成功。租约接管沿用原运行；人工重试按平台契约创建新的作业运行，但通过受租户与范围版本校验的引用沿用原同步专题运行和游标。`lockBusiness/stateChanged` 在同一事务镜像终态。
- 主部门优先采用厂商给定值；厂商未提供时，已有本来源同步主岗所在外部部门仍在本轮范围内任职集合中则保留，否则取本轮最先观测的范围内部门。范围外任职不扩大权限；厂商主部门在范围外时采用首个范围内任职。主部门来源 `primaryDepartmentSource=vendor/inferred` 保存在本轮人员事实和同步主岗上，兼岗为空，回收主岗时清除。预览使用相同聚合及主部门决策，不修改 IAM；调岗回收以完整聚合结果为准。
- 所选外部根及其子树形成映射机构下的部门树，根机构本身不被修改；保留根节点对应的部门，以承接直接任职在根节点的人员。`EmployeePosition.source=manual/directory`，`sourceProviderId` 定义维护方，手工与同步任岗可在同一位置共存。同步仅维护其来源任岗，确保同步主岗存在默认角色授权，不重新启用管理员停用的账号、职员、任岗或既有授权。用户名仅在工号通过租户内现存职员与账号唯一性检查时使用工号，否则由身份源与外部用户 ID 摘要派生；不自动合并已有账号。
- 预览只持久化专题统计和逐轮见到事实，不写部门映射、职员、任岗、账号、绑定或授权。全部完成为 `DIRECTORY_COMPLETED`；失败页或冲突为 `DIRECTORY_PARTIAL`，不标记整轮完成。失败页仅保存阶段、部门或人员 ID 与游标，最多保留 100 条定位，失败总数独立统计，不保存厂商异常报文。
- 正式同步读取全部成功、无冲突、`completed=true` 后进入缺失收尾。每次受租约保护事务按绑定 ID 稳定游标选择一个本租户本来源的同步绑定，最多回收 100 条同步任岗；任岗子游标与变更同事务提交。该轮未见到的绑定来源标为 `missing` 并撤销本租户账号会话。预览、失败页、冲突、过期版本及待确认范围均不推断缺失；每次正式提交复核生效版本，已被替代的排队或续跑作业以 `DIRECTORY_SCOPE_CHANGED` 拒绝写入。重复收尾不会重复撤销已经撤销的会话。
- `disabled/departed/missing` 使绑定和本来源任岗来源失效，不改账号、职员或任岗的本地 `enabled`，不物理删除历史账号。来源任岗失效后不参与有效授权解析。主部门或任职变化将旧来源任岗标为 `retired`（清除主岗标记），保留历史；新任职复用或建立来源任岗。`EmploymentRoleGrant.source/sourceProviderId` 独立表达默认角色授权归属，只删除过时的来源授权，同一任岗同一角色的手工授权也保留。恢复来源在职不恢复本地禁用；管理员已设置手工主岗时记录同步冲突，不覆盖手工主岗。
- 同步根新增、移除或机构映射变化只产生 `pendingSyncScopeId`，定时计划与正式同步继续使用 `syncScopeId`。对待确认方案执行 `preview` 复用同一读取、互斥和租约机制，以 `SCOPE_PREVIEW` 模式保存部门及人员见到事实，完成后聚合报告受影响部门、人员、将回收任岗及来源授权数；同机构内的根归属及树重挂也计入部门和人员影响，不写 IAM 业务数据。管理员通过策略模块的 `scopeImpact` 查看，提交 `confirmScope`（附报告中的候选 `scopeId` 和 `runId`）确认；后端校验所审成功报告、基线版本及当前来源事实计数后原子切换计划，并立即排队正式同步（空范围同样排队回收）。正式同步逐页应用，跨机构映射建立替换部门并保留旧部门历史。复用预览使运行与失败诊断只有一条链路；影响报告属于冻结范围版本，不新增平行作业类型。
- 租户策略 `sourceStatusMaxAgeSeconds` 默认 259200 秒（72 小时），允许 60–2592000 秒。已同步绑定外部登录只允许来源 `active`，同时复核本地账号及关联职员启用；来源年龄以 `sourceCheckedAt` 计算，缺少时间时以绑定时间计算。超龄先在事务外通过可选员工详情协议读取权威状态；未声明支持详情、无协议、读取失败或无可信状态均拒绝登录。无详情能力时，来源最大年龄应大于同步周期，并预留调度、分页与重试余量；自动开户仍未开放。短登录事务重新锁定配置、绑定及账号，版本变化不覆盖较新的同步事实。查询到停用或离职时持久化来源失效、回收派生授权并撤销本租户会话。新鲜度门禁适用范围见“范围与语义”第 8 条；主动绑定尚无通讯录来源状态时不适用最大年龄限制。
- `iam.directory-sync-retention` 使用平台级 `default` 通道，每小时 fixed-delay、首次延迟一分钟；保留每个租户与身份源按终态完成顺序选择最近一次整轮完成的正式同步，保留该轮及其启动后的全部运行（跨范围版本，人工续跑旧轮不按创建顺序误删基线），无完成轮时仅按 30 天留存。更早且最后更新超过 30 天的终态运行可清理，预览与部分成功不推进保留基线；未结束运行及排队中的人工续跑引用始终保留。每轮最多 10 批，每批最多删除 200 条人员见到事实、200 条部门事实，开始清理即拒绝该旧轮的人工续跑（`DIRECTORY_CONTINUATION_EXPIRED`），可重新发起完整同步；子事实删完才删除所属运行；先取专题业务锁再取清理作业运行锁，并在锁内复核。结果为 `DIRECTORY_FACTS_CLEANED`／`BATCH_LIMIT_REACHED`。部门映射与不可变范围版本独立保留，不参与此清理。

## 安全前置

以下内核能力是外部登录的前提，已先于联邦能力交付，现状见 [身份与权限专题概览](OVERVIEW.md) 的“登录与上下文”：

1. IAM 内部统一会话签发入口：写入 session 前以最新账号记录原子复核启用状态（密码登录另复核锁定），再统一写入登录状态、审计与生命周期事件。联邦通过 `UserSessionService.loginWithVerifiedIdentity` 进入同一入口；该方法标记为内部协作者（`@hidden`），不作为业务接入 API，也没有对应的 HTTP 入口。
2. 登录失败锁定，锁定期内不校验凭据。按 IP 的登录限流依赖可信代理策略，在此之前由网关承担。
3. 无本地密码的账号，密码登录对其直接拒绝。
4. 会话与登录审计记录登录方式。
5. 未声明平台动作的 HTTP 入口默认要求登录，匿名访问须显式声明（平台动作用 `ANONYMOUS_ALLOWED`，其他方法用 `@AnonymousEndpoint`）；外部登录的匿名入口同样遵循该规则。

## Web 入口

外部登录入口位于 `/iam.auth/external` 下，按身份源路由：匿名入口只有建立登录事务与由发起浏览器完成事务（开发模式另有模拟授权页），均以 `@AnonymousEndpoint` 显式声明；绑定、解绑与查询本人绑定要求登录。锁定租户的登录上下文（`/iam.auth/login-context`）返回该租户提供的外部登录方式。管理端的身份源、租户接入策略与外部身份绑定以标准静态模块交付，同步运行提供标准只读列表与详情，加入申请随后续能力加入。URL 明细见 [Web API](WEB_API.md)。

部署需配置 `muyun.iam.federation.workbench-url`（工作台对外地址，即向身份源登记的回调地址）与 `muyun.iam.federation.api-base-url`（平台 API 对外地址，供需要自带页面的协议使用，如模拟身份源），二者只接受不带查询参数的绝对 http(s) 地址；事务有效期由 `muyun.iam.federation.transaction-ttl` 配置，默认 3 分钟。身份源编码最长 48 个字符，以便写入会话登录方式。

身份源回到工作台的那次页面请求本身携带授权码与 state，这是授权跳转固有的；部署时须对工作台地址的访问日志做查询参数脱敏。

匿名错误提示只给出必要信息，不暴露他人账号是否存在。稳定业务错误码见 [错误码目录](ERROR_CODE_DIRECTORY.md)。匿名建立事务当前没有频率限制，由网关限流承担；过期事务由平台后台作业有界清理。

## 首期范围与验收

首期包含：安全前置改造；外部身份绑定与登录事务；已有账号扫码登录；已登录账号主动绑定与解绑；按同步根预同步开户，含预览、后台运行与离职、调岗回收；开户策略 `DISABLED`；WeLink 插件与模拟身份源。

验收以 contract 与 IT 覆盖以下边界，并区分模拟通过与真实联调通过：

1. 预同步员工扫码进入锁定租户，账号与绑定唯一。
2. 多同步根、重叠根与多部门员工不重复开户、不丢任岗、不扩大数据范围。
3. 已有账号绑定后扫码进入同一账号，已绑定他人的身份返回冲突。
4. 无本地账号且策略为 `DISABLED` 时拒绝，不创建任何数据。
5. 本地禁用、来源停用均无法登录，同步不恢复本地禁用。
6. 调岗、移出范围、部分拉取失败按规则回收或保持，不误判离职。
7. 重复回调与并发同步不产生重复账号或绑定。
8. 伪造 state、过期事务、串用目的或替换绑定账号均被拒绝，不产生会话。
9. 前端、URL 与平台日志不出现外部 Token、授权码、密钥或平台 Token；回调页面请求的访问日志按部署要求脱敏。
10. 泄露的授权码提交到他人建立的事务时被拒绝。

## 外部前置条件

真实联调前需由身份源管理方确认，在此之前只以模拟身份源推进：

1. 部署环境、授权与 API 主机及网络可达性。
2. 外部企业标识及其返回与校验方式。
3. 适用于普通员工的应用类型、应用凭据与可用人员范围。
4. 普通员工网页扫码协议：授权地址或组件、scope、回调参数、授权码有效期、换取 Token 与身份查询格式。
5. 回调白名单、可信域名与 IP 白名单。
6. 通讯录权限、字段语义（含员工状态取值）与限流规则。
7. 试点同步根部门编码。
8. 外部用户标识在企业与不同应用间的稳定性，用于确定身份命名空间。
9. 普通在职、范围外、停用或离职测试账号。
10. 是否提供部门与用户变更事件订阅。

## 不做事项

1. 不引入全局账号模型与租户成员表。
2. 不新增“指定机构”数据范围类型。
3. 不让厂商插件直接写 IAM 数据或签发会话。
4. 不按姓名、手机号、邮箱或用户名自动合并账号。
5. 不引入外部调度框架；同步建在平台后台作业之上，不另建专题调度。
6. 首期不实现 `AUTO`、`REVIEW` 开户、公共登录入口选租户、跨租户切换与 H5 免登桥接。
7. 不迁移外部消息、机器人或短信通道。
