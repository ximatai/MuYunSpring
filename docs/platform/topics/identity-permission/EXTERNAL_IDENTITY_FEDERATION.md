# 外部身份联邦设计

本文固化外部身份源接入登录体系的目标设计，首个身份源为 WeLink 扫码登录与通讯录同步。当前已实现“安全前置”、机构类型字段，以及基于模拟身份源的外部登录与绑定闭环（身份源、租户接入策略、外部身份绑定、登录事务）；通讯录同步已交付阶段 A（模拟通讯录、预览、新增与更新及作业接入）；缺失与离职处理、调岗回收、`AUTO`/`REVIEW` 开户与 WeLink 协议插件尚未实现。实现按本文收口，未上线阶段不保留旧模型兼容路线。

## 定位

外部身份源只负责证明“这个人在外部系统中是谁”。本地账号、租户准入、角色授权、数据范围与会话始终由平台决定。外部身份不是平台身份根，也不替代 `tenantId` 隔离、动作授权或数据权限。

外部身份联邦是 IAM 的可选能力：平台提供与厂商无关的身份绑定、登录事务、开户策略和通讯录同步框架；具体厂商协议以独立插件交付。项目不启用（`muyun.iam.federation.enabled` 默认 `false`）时不装配联邦服务、HTTP 入口与管理模块；数据表随仓库扫描建立但保持为空。

## 核心取舍

| 议题           | 决定                                                                                                                         |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 账号模型       | 保持租户内账号。同一自然人参与多个租户时拥有多个账号；外部身份绑定按租户唯一。不引入全局账号与租户成员表。                   |
| 组织映射       | 同步根对应本地手工维护的机构，根以下外部部门同步为该机构下的部门树。映射结构预留“指定节点同步为机构”的扩展。               |
| 机构类型       | `Organization` 增加通用的机构类型字段，取值来自字典；具体业务类型（如主机厂）只是项目取值，不进入平台代码。                 |
| 跨机构服务     | 通过手工兼岗加任职角色表达。任岗区分同步来源与手工维护，同步只维护同步来源的任岗。不新增“指定机构”数据范围。               |
| 模块边界       | 厂商无关能力位于 `muyun-iam` 的 `federation` 包与 `muyun-iam-web`，由开关启用；厂商协议位于独立插件。会话签发不对外公开。 |
| 默认角色       | 授给同步来源的主岗（任职角色），数据范围按其所在机构解释；管理类角色不能作为默认角色。                                       |
| 登录入口       | 首期只支持锁定租户的登录地址；“需要选择租户”状态预留。                                                                       |
| 同步开户用户名 | 工号可信且在租户内唯一时使用工号，否则由外部用户标识派生。                                                                   |

### 账号模型

账号属于租户与平台“租户是身份根”的定位一致：租户管理员可以完整治理本租户账号，禁用、重置或删除不影响其他租户。全局账号会改变 `UserAccount`、`CurrentUser.tenantId`、账号角色授权和 `iam.user` 的租户语义，收益主要来自大量用户频繁跨租户的场景，当前不采用。

“租户成员资格”即本租户存在对应账号且账号启用；待审核加入以独立的加入申请表达，不以禁用账号占位。同一外部身份在多个租户分别绑定各自账号。跨租户切换按 [技术债 TD-008](../../../TECHNICAL_DEBT.md) 的租户切换治理推进，可基于同一已验证外部身份签发目标租户会话，不改变账号模型。

### 组织映射

平台机构与部门分两层：职员必须同时归属机构与部门，数据范围也分机构与部门两套。外部通讯录通常只有一棵部门树，因此：

1. 同步根映射到本地已存在的机构；该机构由管理员维护，同步不修改其名称、层级和状态。
2. 根以下的外部部门同步为该机构下的部门树，`本部门及下级` 对应外部子树，`本机构及下级` 对应整个同步根范围。
3. 同步配置以“外部部门编码 → 本地机构”的映射列表表达。后续需要把分公司等节点同步为机构时，在列表中增加条目，不推翻既有结构。
4. 外部部门编码不作为本地主键；映射唯一键至少包含租户、身份源与外部部门编码。

### 跨机构服务

员工在外部通讯录中归属甲机构、业务上被授权服务乙机构时，由管理员为其在乙机构增加手工兼岗，并为该任岗授予任职角色。用户权限按全部任岗聚合，乙机构数据范围按兼岗所在机构解释。

该方式不修改平台数据范围能力。代价是兼岗同时承载了“授权服务”语义；当跨机构授权大量出现，或汇报关系、组织图等能力开始依赖任岗事实时，再将“指定机构（及下级）”数据范围作为独立平台能力建设。

## 模块与扩展点

```text
muyun-iam（federation 包，muyun.iam.federation.enabled 默认关闭）
  身份源、租户接入策略、外部身份绑定、登录事务、加入申请、同步运行与映射
  登录事务编排、准入判定、开户与同步写入、会话签发
muyun-iam-web
  通用外部登录与绑定入口、管理端标准模块入口
muyun-iam-<vendor>（厂商插件，例如 muyun-iam-welink）
  实现身份源协议接口；HTTP 客户端、厂商字段解析与应用 Token 缓存只存在于插件内
```

厂商协议按能力拆为两个接口，身份源可以只实现其一：

| 接口         | 职责                                                                             |
| ------------ | -------------------------------------------------------------------------------- |
| 登录协议     | 生成授权跳转或受认可的二维码展示信息；用授权结果换取经后端校验的外部身份。       |
| 通讯录读取   | 查询员工详情与状态、部门详情、分页读取部门树和部门人员。                         |

插件只收到只读的身份源描述对象（`IdentityProviderDescriptor`）：身份源编码、外部企业标识、身份命名空间、Client ID、由平台按环境变量解析的密钥，以及协议配置。协议配置以字符串键值的 JSON 对象保存在身份源上，由协议在管理员保存时校验，用于承载端点、scope 等厂商参数。插件返回的外部身份至少包含外部企业标识、外部用户标识和认证时间；前端提交的用户标识、部门或手机号不构成可信身份。

state、浏览器绑定、防重放、准入、账号关联、开户、同步写入和会话签发都由平台完成，插件不创建账号、不写 IAM 数据、不签发会话。会话签发入口 `UserSessionService.loginWithVerifiedIdentity` 只允许 `federation` 包调用，由契约测试约束。插件以自身自动装配与开关接入，进入 BOM，不进入 Starter 默认依赖。

模拟身份源（协议类型 `mock`）需同时开启 `muyun.iam.federation.mock.enabled`，只在开发运行模式下可用，生产运行模式下启动即失败。它提供一个开发用授权页，由开发者填写外部用户 ID 后按真实流程回到工作台，前后端链路与真实身份源一致。

## 领域模型

| 对象         | 职责                                                                                                                       |
| ------------ | -------------------------------------------------------------------------------------------------------------------------- |
| 身份源       | 平台级配置，由系统管理员维护：类型、外部企业标识、身份命名空间、应用凭据引用、端点与启停。可被多个租户引用。               |
| 租户接入策略 | 租户级配置，由有权限的租户管理员维护：引用身份源，登录与绑定开关、开户策略、默认角色、准入范围、同步根映射与同步计划。     |
| 外部身份绑定 | 外部身份与本地账号的关联：身份命名空间、外部企业标识、外部用户标识、租户、账号、关联来源、来源状态与时间。                 |
| 登录事务     | 一次扫码的服务端状态：随机 state、PKCE 校验串、目的（登录或绑定）、目标租户与身份源、绑定发起账号与会话、浏览器关联、过期与消费状态。         |
| 加入申请     | 首次扫码、无本地账号且开户策略为审核时产生的待审事实；审批前不签发业务会话。                                               |
| 同步运行     | 一次同步的专题事实：范围版本、游标、统计、失败页与完成标记，以作业运行标识关联平台后台作业的执行状态与进度。               |
| 部门映射     | 外部部门与本地部门的对应关系、所属同步根与最近同步信息。                                                                   |

约束：

1. 外部身份绑定唯一键为身份命名空间、外部企业标识、外部用户标识与租户；同一租户内一个外部身份只能绑定一个账号，一个账号对同一身份源最多一个有效绑定。唯一性由数据库约束兜底，软删除不能绕过。
2. 身份命名空间表达外部用户标识的真实唯一范围。未确认外部用户标识跨应用稳定前，命名空间包含应用范围，不合并不同应用的同名标识。身份源已有绑定时，协议类型、Client ID、身份命名空间、外部企业标识以及协议声明的身份范围配置（如 issuer）均锁定；更换身份权威须新建身份源。
3. 外部用户标识是唯一的主关联键。姓名、手机号、邮箱不用于自动合并；工号只在企业范围明确、唯一且可信时作为辅助依据。用户名相同不构成接管已有账号的依据。
4. 应用凭据只保存安全引用，不在前端、URL、普通日志与接口回显中出现。

### 与现有模型的对应

| 外部事实           | 平台落点                                                                                       |
| ------------------ | ---------------------------------------------------------------------------------------------- |
| 外部员工           | `Employee`，主机构为同步根映射的机构，主部门为外部主部门对应的本地部门。                       |
| 外部多部门任职     | `EmployeePosition`：一个主岗加若干兼岗，不以最后遍历的部门覆盖全部归属。                       |
| 登录账号           | `UserAccount`，允许无本地密码；通过 `EmployeeAccount` 与职员一对一绑定。                       |
| 默认角色           | `EmploymentRoleGrant`，授给同步来源的主岗。                                                    |
| 业务数据归属       | 沿用标准权限字段 `authOrganizationId` 等，不新增业务专属归属字段。                             |

`EmployeePosition.positionId` 必填，而外部通讯录通常不提供岗位标准项，因此租户接入策略需指定同步任岗使用的默认岗位。`Employee.employeeNo` 只在机构内唯一，工号作为用户名前需校验其在租户内唯一。

### 来源状态与本地状态

`UserAccount.enabled`、`Employee.enabled` 和任岗启停是本地管理状态；外部在职、停用或离职状态记录为来源状态，存放于外部身份绑定与同步来源事实上。

1. 登录要求本地状态与来源状态同时允许。
2. 同步与开户只能更新来源状态，不能恢复管理员禁用的账号、职员或任岗。
3. 同步只维护自身来源的数据：来源职员资料、同步部门、同步任岗与默认角色授权；手工任岗、手工授权和本地角色不被覆盖或回收。

## 登录与绑定流程

### 登录事务

```text
浏览器建立事务 → 平台返回授权地址、state 与 browserProof；state 和 browserProof 只保存在发起浏览器
  → 浏览器打开身份源授权页
  → 身份源把浏览器送回工作台地址，并附带 state 与授权结果参数
  → 工作台用 state 匹配本浏览器保存的事务，带 state、browserProof 与全部回传参数提交平台
  → 平台核对 state 与 browserProof 后原子领取事务，由协议插件在服务端校验并解析外部身份
  → 校验身份源、外部企业、租户接入策略，在租户内解析绑定
  → 登录成功时直接签发平台会话，绑定成功时返回绑定摘要；结果只交给提交请求的浏览器
```

1. 目标租户来自锁定租户的登录入口；未确定身份源时不生成授权地址。
2. 身份源的回调地址登记为工作台地址（`muyun.iam.federation.workbench-url`），而不是平台 API。这样授权结果只会回到完成授权的浏览器，只有发起该事务、持有 browserProof 的浏览器才能完成它：把授权链接发给他人，对方完成授权后也无法让发起者拿到会话，对方的工作台会因找不到对应事务而丢弃回传参数。
3. state 与 browserProof 均为服务端随机生成的一次性值，库中只存哈希，比较采用常量时间；state 不以租户编码充当。回传参数中的 state 须与提交的 state 一致。事务过期、state 未知、凭证不符或重复提交均拒绝，失败后重新建立事务。平台不使用 Cookie，与 Bearer token 会话模型一致。
4. 每个事务另有只存于服务端的 PKCE 校验串（S256），经授权上下文交给协议：授权请求携带其摘要，兑换授权结果时携带原值，使授权结果只能由请求它的事务兑换，泄露的授权码不能移植到他人建立的事务。校验串在事务完成时清除。不支持 PKCE 的身份源，协议须以厂商提供的等价机制把授权结果绑定到事务，接入前单独评估。
5. 工作台在提交前从地址栏移除回传参数，地址中最多保留锁定租户标记；授权码、state、凭证与任何 Token 都不留在地址或浏览历史中。工作台页面声明不发送 Referer，回传地址不会经后续请求带出。
6. 外部 Token 不作为平台 Token。外部身份解析成功后经 IAM 内部会话签发入口登录，复用租户启用、账号启用、登录审计与会话生命周期；会话登录方式记为 `external:<身份源编码>`。
7. 强制改密只约束以密码建立的会话；密码登录锁定只防护本地密码，不阻止也不解除外部登录。
8. 完成结果状态为 `succeeded`、`denied`、`expired`，拒绝原因以稳定码表达（`identityNotBound`、`identityConflict`、`alreadyBound`、`enterpriseMismatch`、`policyDisabled`、`accountUnavailable`、`sessionEnded`、`providerRejected`、`providerUnavailable`，平台自身故障为 `internalError`）。需要绑定、开户确认、审核和选择租户的状态随对应能力加入。
9. 以 POST 把授权结果送回回调地址的身份源（如 OIDC `form_post`、SAML）以及“手机授权、桌面登录”的桥接流程不在本流程内：它们的结果不经过发起浏览器，需要单独设计浏览器绑定或手机端确认后再接入。
10. 厂商不提供扫码状态时，不展示虚构的“已扫码”中间状态。

### 主动绑定

已登录用户在个人设置中发起绑定：

1. 需要近期认证：当前会话须在 5 分钟内建立，否则提示重新登录后再操作。该规则对有无本地密码的账号一致。
2. 绑定事务在建立时固化账号、租户、身份源与发起会话，回调侧不能替换目标账号；完成时发起会话须仍然有效，注销、改密或管理员下线该会话后，未完成的绑定以 `sessionEnded` 拒绝。
3. 外部身份已绑定本租户其他账号时返回冲突，不自动解绑、合并或接管。
4. 绑定不产生其他租户的账号，也不增加数据范围。
5. 解绑需近期认证并保留可用的登录方式：没有本地密码，且解除后不再有身份源可用、租户策略允许登录的绑定时拒绝解绑。解绑物理删除绑定，不删除账号。同步会自动建立绑定时，解绑需记录禁止自动重绑的标记。
6. 管理员在“外部身份绑定”模块只读查看绑定，可通过标准删除动作解除；绑定只能由经过校验的联邦流程创建。

### 开户策略

| 策略       | 无本地账号时的行为                                                                       |
| ---------- | ---------------------------------------------------------------------------------------- |
| `DISABLED` | 拒绝登录并提示联系管理员或使用已有账号登录后绑定。默认值。                               |
| `AUTO`     | 校验准入后展示确认信息，原子建立职员、任岗、账号、绑定与默认角色，提交成功后签发会话。   |
| `REVIEW`   | 校验准入后建立加入申请，审批前不签发业务会话。                                           |

`AUTO` 与 `REVIEW` 均需查询权威员工资料：外部企业、在职状态与准入范围均满足才可开户或申请；取不到可信归属时不自动开户。用户选择的租户或机构只表达意图，不作为准入证据；企业、外部用户标识、工号与组织归属不可由用户编辑。

## 通讯录同步

### 范围与语义

1. 同步根可配置多个互不相邻的外部部门子树；重叠根合并去重。空范围或全企业根需要显式确认，不默认拉取整个企业。
2. 准入范围独立于同步范围。“已同步”不等于“可加入租户”。
3. 同步先提供无数据变更的预览，统计组织数、人员数、重复身份与冲突；预览与正式同步一样后台运行，返回运行标识与进度。
4. 逐页读取并幂等写入，不一次装载整个通讯录；遵守厂商限流，可安全重试的读取采用退避重试，授权码不重试。
5. 只有某一范围整轮拉取成功且范围版本一致时，才判定“本轮缺失”；接口失败、权限不足或范围缩小不能按离职批量处理。
6. 可信的停用或离职状态使对应来源状态失效并撤销相关会话，不影响其他租户中的合法账号。调岗回收旧的同步任岗及其派生授权，保留手工任岗与手工授权。
7. 同步根范围变更先产出影响报告，由有权限的管理员确认执行；清理只作用于本来源管理的数据，不物理删除历史账号。
8. 首期无变更事件订阅时，以定时同步为主，并定义来源状态最大年龄；超龄时登录前查询权威资料，查询失败按策略拒绝自动开户。

### 作业接入

通讯录同步是平台[后台作业](../../BACKGROUND_JOB_SCHEDULING.md)的首个租户级、专题托管业务作业，平台负责触发、租约、互斥、重试、运行记录与失败提醒，专题只负责读取通讯录与写入 IAM 事实：

| 事项       | 约定                                                                                                                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 作业类型   | 租户级类型，使用独立执行通道，外部拉取不占用平台维护作业线程。定时触发失败不自动重试、等待下一周期；允许管理员人工重试；采用标准失败提醒。                                                   |
| 计划       | 每个“租户 + 身份源”一条计划，专题键为租户接入策略。计划表达式与启停随租户接入策略维护，在策略保存事务中经 `JobService.registerManaged` 登记，策略删除时 `deleteManaged`；作业管理页只做运维。 |
| 执行身份   | 租户内系统执行主体（`SYSTEM` 模式），不以发起人身份执行。专题页的“立即同步”只记录触发人，不改变执行身份。                                                                                 |
| 互斥       | 同一租户与身份源的预览、正式同步共用同一互斥范围，串行执行；不同租户之间互不串行。                                                                                                           |
| 写入       | 外部读取在事务外进行；每页写入经 `JobContext.transaction(businessLocks, writes)` 提交，先取同步专题业务锁再校验租约，事务内不调用外部接口。分页边界检查取消请求；进入人员阶段与整轮处理结束时分别上报 50% 与 100%，接管不回退进度。                 |
| 专题事实   | 同步运行以作业运行标识关联，保存范围版本、游标、统计与失败页；`lockBusiness` 与 `stateChanged` 在平台运行状态变化的同一事务内镜像终态。作业运行不承载同步状态机。                          |
| 结果       | 返回稳定结果码与统计摘要：全部完成为成功；存在失败页为部分成功，不触发“本轮缺失”判定；缺失与离职处理只在整轮成功后的收尾事务中执行。                                                     |
| 幂等与续跑 | 执行语义为至少一次：写入以外部标识为键幂等；自动重试与接管复用原运行，按同步运行游标继续。                                                                                                   |
| 留存       | 每个租户与身份源保留最近一次整轮完成的正式同步及其后运行事实；更早且超过 30 天的终态运行、见到集合与部门事实由专题有界分批清理，不随作业运行清理一并删除。                                                                                                                                   |

过期登录事务已由 `iam.external-login-retention` 平台级作业清理，使用 `default` 通道，每小时 fixed-delay、首次延迟一分钟，每轮最多 10 批、每批 200 条，物理清理所有租户中已过期的已消费与未消费事务。结果码为 `LOGIN_TRANSACTIONS_CLEANED`，达到批次上限为 `BATCH_LIMIT_REACHED`。

### 阶段 A 接入契约

- 读取插件实现 `ExternalDirectoryProtocol`，仅消费 `IdentityProviderDescriptor`。部门分页为包含所选根的父先子后序列；部门详情返回权威祖先 ID，人员详情包含完整部门任职、主部门和来源状态。分页 token 不透明，单页最多 100 条；只读拉取发生暂时失败时最多读取三次，50／100 毫秒退避，插件须遵守厂商限流。身份源可以只实现登录或读取能力，两类协议声明的身份范围配置键共同受绑定后的权威锁定约束；每页提交前在数据库事务内复核身份源权威，读取期间发生权威变化时以 `DIRECTORY_CONFIGURATION_CHANGED` 失败，不提交该页。
- `mock` 读取与模拟登录使用相同开发模式及开关门禁。身份源协议配置的字符串键 `directory` 保存 JSON 字符串，其对象包含 `departments`、`people`、`failPages`。不增加第二套可编辑文件或服务，现有身份源管理页即可维护，fixture 可由测试直接构造。部门按父先子后排列，字段为 `id/parentId/title/ancestorIds`；人员字段为 `id/title/employeeNo/primaryDepartmentId/departmentIds/status/mobile/email`，状态为 `active/disabled/departed`。`failPages` 可填写 `departments:<root>:<offset>` 或 `people:<department>:<offset>`，用于模拟确定性失败。
- 策略的 `syncRoots` 是 `[{"externalDepartmentId":"部门 ID","organizationId":"本地机构 ID"}]`。保存前在持锁事务之外读取权威祖先、合并重复及被祖先覆盖的根；同一根映射多个机构拒绝。空范围或全企业根要求 `syncScopeConfirmed=true`。空范围表示不读取任何人员，不自动解释为全企业。范围、默认岗位或角色变化产生不可变 `DirectorySyncScope`，队列仅冻结其引用，不保存通讯录全文或凭据。`syncPositionId` 必填，`syncRoleId` 可选，仅接受非管理用途的普通任职角色。
- `syncExpression` 使用秒位为 0 的 cron，`syncZoneId` 指定合法 IANA 时区，为空时由平台默认时区解析，`syncEnabled` 与策略启停共同控制托管计划。关闭或删除策略时删除托管计划，保留执行历史。动作 `preview`、`synchronize` 按策略、模式与范围版本 `scopeId` 去重，同一未结束运行直接返回其 ID；终态后可再次发起。动作返回平台作业运行 ID，执行身份始终是租户内 SYSTEM。
- 租户类型为 `iam.directory-sync`，自动装配独立 `directory-sync` 通道；部署可通过 `muyun.platform.job.channels.directory-sync.threads/claim-interval` 调整资源，默认 2 个线程、1 秒领取间隔。同一租户和身份源的预览、正式同步共用互斥键，其他租户独立。运行租约五分钟、单次最长一小时、最多三次领取（支持失联执行者接管）；处理器失败不自动重试，保留标准失败提醒和人工重试。
- 游标分部门与人员两阶段：保存根序号及外部分页 token，再按本轮部门事实的稳定 ID 遍历人员分页。每页 IAM 写入、本轮见到的外部身份、统计与下一游标同事务提交。租约接管沿用原运行；人工重试按平台契约创建新的作业运行，但通过受租户与范围版本校验的引用沿用原同步专题运行和游标。`lockBusiness/stateChanged` 在同一事务镜像终态。
- 所选外部根及其子树形成映射机构下的部门树，根机构本身不被修改；保留根节点对应的部门，以承接直接任职在根节点的人员。`EmployeePosition.source=manual/directory`，`sourceProviderId` 定义维护方，手工与同步任岗可在同一位置共存。同步仅维护其来源任岗，确保同步主岗存在默认角色授权，不重新启用管理员停用的账号、职员、任岗或既有授权。用户名仅在工号通过租户内现存职员与账号唯一性检查时使用工号，否则由身份源与外部用户 ID 摘要派生；不自动合并已有账号。
- 预览只持久化专题统计和逐轮见到事实，不写部门映射、职员、任岗、账号、绑定或授权。全部完成为 `DIRECTORY_COMPLETED`；失败页或冲突为 `DIRECTORY_PARTIAL`，不标记整轮完成。失败页仅保存阶段、部门 ID 与游标，最多保留 100 条定位，失败总数独立统计，不保存厂商异常报文。
- 阶段 A 只保存观测到的来源状态，不据此使来源失效或改变登录准入。阶段 B 才处理本轮缺失、来源失效与会话撤销、旧任岗及派生授权回收、范围变更报告和来源状态新鲜度。A 保留范围版本、部门最近运行、人员及任岗最近见到运行；主部门变更和既有映射跨机构变更记录冲突，不在 A 隐式回收或迁移。`iam.directory-sync-retention` 使用平台级 `default` 通道，每小时 fixed-delay、首次延迟一分钟；保留每个租户与身份源最近一次整轮完成的正式同步及其后全部运行（跨范围版本），无完成轮时仅按 30 天留存。更早且最后更新超过 30 天的终态运行可清理，预览与部分成功不推进保留基线；未结束运行及排队中的人工续跑引用始终保留。每轮最多 10 批，每批最多删除 200 条人员见到事实、200 条部门事实，开始清理即拒绝该旧轮的人工续跑（`DIRECTORY_CONTINUATION_EXPIRED`），可重新发起完整同步；子事实删完才删除所属运行；先取专题业务锁再取清理作业运行锁，并在锁内复核。结果为 `DIRECTORY_FACTS_CLEANED`／`BATCH_LIMIT_REACHED`。部门映射与不可变范围版本独立保留，不参与此清理。

## 安全前置

以下内核能力是外部登录的前提，已先于联邦能力交付，现状见 [身份与权限专题概览](OVERVIEW.md) 的“登录与上下文”：

1. IAM 内部统一会话签发入口：写入 session 前以最新账号记录原子复核启用状态（密码登录另复核锁定），再统一写入登录状态、审计与生命周期事件。联邦通过 `UserSessionService.loginWithVerifiedIdentity` 进入同一入口；该方法标记为内部协作者（`@hidden`），不作为业务接入 API，也没有对应的 HTTP 入口。
2. 登录失败锁定，锁定期内不校验凭据。按 IP 的登录限流依赖可信代理策略，在此之前由网关承担。
3. 无本地密码的账号，密码登录对其直接拒绝。
4. 会话与登录审计记录登录方式。
5. 未声明平台动作的 HTTP 入口默认要求登录，匿名访问须显式声明（平台动作用 `ANONYMOUS_ALLOWED`，其他方法用 `@AnonymousEndpoint`）；外部登录的匿名入口同样遵循该规则。

## Web 入口

外部登录入口位于 `/iam.auth/external` 下，按身份源路由：匿名入口只有建立登录事务与由发起浏览器完成事务（开发模式另有模拟授权页），均以 `@AnonymousEndpoint` 显式声明；绑定、解绑与查询本人绑定要求登录。锁定租户的登录上下文（`/iam.auth/login-context`）返回该租户提供的外部登录方式。管理端的身份源、租户接入策略与外部身份绑定以标准静态模块交付，同步运行提供标准只读列表与详情，加入申请随后续能力加入。URL 明细见 [Web API](WEB_API.md)。

部署需配置 `muyun.iam.federation.workbench-url`（工作台对外地址，即向身份源登记的回调地址）与 `muyun.iam.federation.api-base-url`（平台 API 对外地址，供需要自带页面的协议使用，如模拟身份源），二者只接受不带查询参数的绝对 http(s) 地址；事务有效期由 `muyun.iam.federation.transaction-ttl` 配置，默认 3 分钟。身份源编码最长 48 个字符，以便写入会话登录方式。

身份源回到工作台的那次页面请求本身携带授权码与 state，这是授权跳转固有的；部署时须对工作台地址的访问日志做查询参数脱敏。

匿名错误提示只给出必要信息，不暴露他人账号是否存在。稳定业务错误码见 [错误码目录](ERROR_CODE_DIRECTORY.md)。匿名建立事务当前没有频率限制，由网关限流承担；过期事务由平台后台作业有界清理。

## 首期范围与验收

首期包含：安全前置改造；外部身份绑定与登录事务；已有账号扫码登录；已登录账号主动绑定与解绑；按同步根预同步开户，含预览、后台运行与离职、调岗回收；开户策略 `DISABLED`；WeLink 插件与模拟身份源。

验收以 contract 与 IT 覆盖以下边界，并区分模拟通过与真实联调通过：

1. 预同步员工扫码进入锁定租户，账号与绑定唯一。
2. 多同步根、重叠根与多部门员工不重复开户、不丢任岗、不扩大数据范围。
3. 已有账号绑定后扫码进入同一账号，已绑定他人的身份返回冲突。
4. 无本地账号且策略为 `DISABLED` 时拒绝，不创建任何数据。
5. 本地禁用、来源停用均无法登录，同步不恢复本地禁用。
6. 调岗、移出范围、部分拉取失败按规则回收或保持，不误判离职。
7. 重复回调与并发同步不产生重复账号或绑定。
8. 伪造 state、过期事务、串用目的或替换绑定账号均被拒绝，不产生会话。
9. 前端、URL 与平台日志不出现外部 Token、授权码、密钥或平台 Token；回调页面请求的访问日志按部署要求脱敏。
10. 泄露的授权码提交到他人建立的事务时被拒绝。

## 外部前置条件

真实联调前需由身份源管理方确认，在此之前只以模拟身份源推进：

1. 部署环境、授权与 API 主机及网络可达性。
2. 外部企业标识及其返回与校验方式。
3. 适用于普通员工的应用类型、应用凭据与可用人员范围。
4. 普通员工网页扫码协议：授权地址或组件、scope、回调参数、授权码有效期、换取 Token 与身份查询格式。
5. 回调白名单、可信域名与 IP 白名单。
6. 通讯录权限、字段语义（含员工状态取值）与限流规则。
7. 试点同步根部门编码。
8. 外部用户标识在企业与不同应用间的稳定性，用于确定身份命名空间。
9. 普通在职、范围外、停用或离职测试账号。
10. 是否提供部门与用户变更事件订阅。

## 不做事项

1. 不引入全局账号模型与租户成员表。
2. 不新增“指定机构”数据范围类型。
3. 不让厂商插件直接写 IAM 数据或签发会话。
4. 不按姓名、手机号、邮箱或用户名自动合并账号。
5. 不引入外部调度框架；同步建在平台后台作业之上，不另建专题调度。
6. 首期不实现 `AUTO`、`REVIEW` 开户、公共登录入口选租户、跨租户切换与 H5 免登桥接。
7. 不迁移外部消息、机器人或短信通道。
