# 业务内容多语言试用与运行评测

本指南用于质量异常单、设备分类两个样板的小范围试用。工程演练、实际业务人员审阅与生产容量评测分别记录；自动校验通过、模型生成成功或工程人员代操作，均不能代替业务人员对术语和业务含义的判断。能力范围见[业务内容多语言](BUSINESS_CONTENT.md)。

## 试用准备

试用负责人明确参与人员、授权租户与组织、原文及阅读语言、允许提交模型的数据范围，以及当前有效的模型连接。沿用正常账号和动作授权，不共用管理员身份完成团队试用；本指南不要求向工程人员提供密码或模型密钥。

至少包含一组同语言使用人员和一组跨语言协作人员。界面使用中英文，业务内容使用中英德；业务记录、字段和明细可以有不同来源语言。没有实际业务团队时可以完成工程演练，但业务质量审阅保持待完成。

| 使用方式 | 试用重点 |
| --- | --- |
| 同语言日常工作 | 正常填报与阅读是否顺畅；来源、历史和译文维护是否可按需找到；无关高级入口是否干扰主操作 |
| 跨国协作 | 阅读偏好是否易理解；原文核实、译文状态和人工维护是否清楚；切换语言是否保留输入 |
| 内容维护 | 保存人工草稿与质量确认是否易区分；原文变化后的待复核和并发冲突是否能正确处理 |

只使用获准的业务数据。可先用合成文本熟悉操作；反馈中优先提供受权记录定位和修订号，避免把敏感原文、用户凭据或供应商错误全文复制到公共问题单。

## 完整业务演练

1. 中国人员新建质量异常单，选择商品，填写中文说明和检测明细，登记实际来源语言。保存并重开，核对作者、数量、引用及原文。
2. 美国人员选择英文阅读，核实原文并按正常权限办理，填写英文意见；德国人员以德文阅读，填写德文调查或任务表单。核对数字、单位、设备编码、否定及条件，特别是暂勿发货与允许发货。
3. 修改真实业务原文并保留历史；另在译文维护中保存人工草稿，再由有确认资格的人员核对确认。检查两类操作没有混淆，未确认草稿不会替换普通阅读版本。
4. 通过外语关键词查询、多页排序和引用选择重新找到同一对象。检查缺失提示能解释可能遗漏的内容，同名译文不会合并不同记录。
5. 设备分类导出业务填写文件。分别尝试仅填写已确认译名、机器译名对象确认、分类改名后只改其他字段，以及主动修改分类。检查稳定身份与名称修改意图。
6. 准备有少量错误的独立记录文件，确认正确项先成功；下载实际失败文件，直接修正重传。检查成功项不重复写入、主子表上下文不重放，空白不修改而 `0` 和 `false` 正常保存。
7. 在隔离环境由运维安排无模型、暂时失败及原文变更场景。业务人员观察原文可用、状态可解释和明确重试；不由试用者修改供应商端点、任务状态或权限来恢复。

当前和归档流程分别核对。归档阅读不提供新轮次变更操作；译文质量确认不推进业务审批，也不作为日常办理门禁。语言切换期间至少保留一次尚未保存的主子表或译文输入，并分别验证取消与保存。

## 反馈与试用结论

每个问题使用以下模板，交给试用负责人汇总；发送给他人仍需遵守所属组织的信息共享要求。

| 项目 | 填写内容 |
| --- | --- |
| 场景与定位 | 页面、所属模块、受权记录定位、字段／明细及原文修订号 |
| 使用语言 | 界面语言、原文语言、阅读或导出语言 |
| 操作与结果 | 实际步骤、预期、实际表现；是否阻断保存／办理或造成身份混淆 |
| 质量分类 | 术语、数字／单位、编码、否定／条件、含义遗漏，或界面／交互问题 |
| 影响与建议 | 影响的业务决定、建议译法或操作改进；不要仅记“翻译不自然” |
| 审阅事实 | 实际审阅人、审阅日期、结论与复核状态；未审阅保持空白 |

业务负责人按场景给出通过、需修正或未执行结论；未执行、来源未知和原文回退不计作目标语言质量通过。发生错误放行含义、越权读取、原文被译文覆盖或文件重复写入时，暂停受影响范围试用，保留原文和定位证据，由平台修复并复核后恢复。

## 运行基线与容量评测

开始前明确目标记录量、峰值填报／阅读并发、主要协作语言、允许的译文等待与检索就绪时间，以及模型费用预算。尚无目标业务量时，仅执行有界工程基线，不声称生产达标。评测使用专属数据范围，记录代码版本、数据库和模型配置版本、实例资源及测量方法，避免把不同条件的结果直接比较。

| 测量项 | 方法与边界 |
| --- | --- |
| 原文保存 | 测量正常授权保存耗时与失败率，同时确认原文已提交；不把译文完成时间算作保存耗时 |
| 翻译等待 | 从原文提交到各目标语言有效阅读就绪，区分排队、执行、重试和终态失败；轮询只确定观测精度 |
| 查询与分页 | 原文及外语关键词、阅读排序、计数和多页去重；分别测量已有译文与缺失译文的受权范围 |
| Excel | 预览、导入、导出、错误文件及修正重传分别计时；保持既有文件限制和聚合事务语义 |
| 模型资源 | 记录成功、故障及重试的实际调用数；费用采用供应商实际账单或可核实用量，不能仅凭文本长度估算为实付成本 |
| 恢复 | 在隔离环境验证故障后明确重试与重启后的租约恢复，同时检查业务保存、已有阅读和身份范围 |

报告至少列出样本数、并发、成功／失败数、耗时分布和未完成项。小样本可报告最小、中位和最大值，不将少量请求的高分位数包装为稳定 SLA。负载评测与模型语义质量分别审阅；需要时先降低负载或缩小预生成语言范围，再决定是否调整实现。

`muyun.content.primary-languages` 仅控制提交后预生成范围，留空不关闭已有译文或按需阅读。模型网关的全局与用户并发限制继续约束生成，不通过增加工作线程扩大模型权限或绕过限制。历史补齐始终由受权人员选择有限范围明确启动；配置恢复不自动扫描历史。

## 同步文件批次

1000 行是协议上限，不是即时完成的承诺。千行同步导出仍较慢，受控试用先从约 50 行的小批次评测，保持主子表业务单元完整，再按当前实例、数据库、引用复杂度、实际等待和代理超时确定范围。不能把不同环境或少量请求的计时作为生产 SLA；超过可接受等待时缩小范围，进一步优化按明确容量需求另行安排。

导出继续经过正常查看入口与逐记录授权，详情展示使用导出场景，查看字段保护与最终导出保护分别保留；原文、来源及引用身份、版本和回执不因提速改变。导出文件原样重传应无新增或更新，失败文件仅重传失败单元，核对时同时检查版本与关联上下文。

## 专题执行并发

`muyun.content.generation-workers` 控制单实例自动翻译执行路数，默认 `1`，允许 `1` 至 `8`；每路按 `muyun.content.generation-delay-ms`（默认 1000 毫秒）在上次执行结束后再次扫描。首次扫描延迟使用 `muyun.content.generation-initial-delay-ms`（默认 60000 毫秒）。调整这些启动参数需重新启动宿主，不改变原任务、租约和修订身份。

默认单路保持轻量资源使用。出现实际排队且供应商、数据库与网关额度允许时，可先以 `2` 路做同环境对照；网关默认每用户在途并发为 `2`，增加执行路数不保证等比例提速。超出网关额度仍按现有限流与有限重试处理，不能靠放大工作线程解决供应商限流。多实例的路数需合并评估；现有网关额度是单实例限制，不是共享计费配额或全局公平调度。

每路直接复用同一持久化领取、当前身份与业务范围复核、模型路由和结果落库链路；不预取原文到内存队列，不新增翻译专用连接或通用任务中心。任务保留已授权触发者，不能为取得更多用户额度而轮换身份。
