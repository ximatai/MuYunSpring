# 业务内容多语言

状态：阶段 1—3 的工程交付已完成，质量异常单与设备分类两个样板具备受控小范围试用条件。界面交付中英文，业务内容验证中英德；德文内容可用不代表完整德文界面交付。工程人员的真实页面、接口与故障演练不代替实际业务人员的语义审阅，也不构成生产容量、SLA 或费用承诺。

本文是业务内容能力的稳定接入与运行入口。试用准备、业务反馈及容量评测见[试用与运行评测](BUSINESS_CONTENT_PILOT.md)；界面和配置文案见[国际化](../../INTERNATIONALIZATION_GOVERNANCE.md)，前端公共接入见[语言接入](../../../frontend/INTERNATIONALIZATION_INTEGRATION.md)。

## 交付范围

各团队可以用自己的语言填写同一业务的字段、明细和办理意见，再按独立阅读偏好互读、查询和办理。原文、作者、来源语言、修订与译文分开保存；普通业务通过字段声明复用平台的存储、权限、展示、异步生成和文件能力。

当前工程交付覆盖一个租户内的跨国组织协作。语言不增加访问资格，权限、租户、引用身份、公式、事务和生命周期沿用所属业务。跨租户协作和新的外部身份模型由所属业务另行建立契约。

| 能力 | 已交付范围 |
| --- | --- |
| 来源与填报 | 静态 Java、动态元数据、主子表来源语言、作者、原文历史、并发与原值编辑保护 |
| 阅读与维护 | 持久化机器译文、人工草稿与确认、共享阅读、独立阅读偏好、按需原文核实 |
| 查询与办理 | 原文与有效译文检索、服务端排序分页、缺失提示、引用与树、既有流程及历史 |
| 业务文件 | 数据填写与修改、阅读导出、译文草稿文件、名称解析、部分成功和失败文件直接重传 |
| 运行保障 | 无模型降级、可信异步身份、当前路由复核、持久化任务、有限重试、租约恢复与旧结果失效 |

## 字段策略与语言用途

| 策略 | 典型内容 | 行为 |
| --- | --- | --- |
| 保持原值 | 编码、型号、数量、日期及需原样保留的名称 | 不翻译业务值，格式本地化保持原契约 |
| 自动阅读翻译 | 异常、调查、处理意见 | 正常保存原文，按策略生成可复用阅读译文 |
| 人工维护多语言 | 分类、商品名称和标准说明 | 支持人工草稿、质量确认及受权机器起草；普通阅读优先当前有效确认版本 |

不默认翻译所有字符串，不遍历任意业务 JSON。字典和配置标签按配置来源处理，业务选项按目标记录身份处理；同名记录不合并。来源语言由填写者显式登记，不从界面、国家或阅读偏好推断；未知语言保持未知。

| 用途 | 含义 | 选择与约束 |
| --- | --- | --- |
| 界面语言 | 按钮、字段标签、固定提示等 | 沿用现有界面语言能力 |
| 来源语言 | 作者某次实际填写的文本语言 | 与原文及修订绑定，不能因阅读者变化而改写 |
| 阅读语言 | 用户希望理解业务内容的语言 | 可默认跟随界面语言，显式选择后独立保留 |
| 导出语言 | Excel 模板和阅读文件采用的语言 | 由导出操作明确选择，不改写文件中的来源语言 |

界面继续使用原有语言协议，业务阅读通过独立偏好及 `X-MuYun-Content-Language` 表达。切换语言不改写原文、不清空未保存的主子表或译文输入。

## 声明与原文来源

静态持久化文本字段使用 `@BusinessContent` 显式接入；继承的字段可在具体模型类声明，例如 `@BusinessContent(field = "title", key = "equipment-category-name", value = ContentPolicy.MANUAL_TRANSLATIONS)`，不必重复定义标准基类字段。模型声明统一编译并校验未知字段、遮蔽、重复声明和重复文本身份；平台审计、授权及树关联字段不作为业务文本。动态字段的 `contentPolicy` 编译为相同的 `ContentFieldDefinition`，以元数据字段 ID 保留字段身份。未声明的业务值保持原有行为。受保护字段、字典 code 和虚拟字段不支持本轮来源存储，不能通过旁路复制其明文。

动态字段语言策略纳入既有元数据变更集预检、指纹及发布，不通过直接修改主表字段绕过发布边界。新增字段未声明策略时保持原值；修改字段时省略或传空策略表示保留当前策略，明确传入 `KEEP_ORIGINAL` 才撤回语言能力。修改标签等其他字段属性不丢失已声明的语言策略及稳定字段身份。预检复用最终字段约束，拒绝非文本、受保护、字典及引用身份字段启用内容策略；共享字段的策略变更同时校验所属其他关系的配置。

原文修订与正常业务保存处于同一事务。来源语言通过绑定具体记录的 `ContentWriteContext` 随本次保存提交，不读取界面语言。未确定的语言保持空值；原文改变后未明确提交新语言时重新标记为未确定。只修改其他字段不新增原文修订；纠正来源语言校验审阅的文本修订，原文保存继续执行业务乐观锁。原文作者取自可信当前身份，不采信客户端审计字段；只纠正来源语言时保留原文作者和填写时间，另记修订人。首次跟踪存量文字或恢复跟踪后发现原值断档时，保留未追踪基线，作者和填写时间保持未知，基线采集人不冒充历史作者。

`BusinessContentService` 通过所属业务 Service 的动作授权、已声明的数据范围、活动记录和当前字段策略读取分页历史，不提供可独立读取的来源 ID 接口。软删后普通历史读取不可见，恢复后继续使用原历史；最终删除在同一事务内清理来源副本。

正常静态保存及动态记录信封接受独立的 `$contentLanguages` 写入元数据，例如 `{"description":{"languageTag":"zh-CN","expectedRevision":3}}`。它与实际原文同时提交，主子表每行分别携带，不放入 `values` 或任意业务 JSON。已有来源要求提交审阅的文本修订；省略表示未提交语言修改，不默认跟随界面语言。语言写入意图纳入可靠保存的请求指纹，写入后暂时消费，事务回滚恢复该次意图且不覆盖调用方后续决定；提交成功后清除；重开记录不会把上次意图当作新修改。静态标准模型无需业务另写协议适配。

标准主记录提供 `GET /{module}/view/{id}/content` 来源快照及 `GET /{module}/view/{id}/content/{field}/history?page=1&size=20` 分页历史。读取同时经过所属记录当前查看权限、租户与数据范围、页面范围及编译后的字段边界，不提供按来源哈希直接读取的公开接口。快照返回实际原值、文本策略和并发所需版本；无匹配来源时明确返回未追踪状态，不把旧修订当作当前原文。主子表来源通过 `GET /{module}/view/{parentId}/relations/{relationCode}/{childId}/content` 及其 `/{field}/history` 入口读取，复用父拥有的聚合范围和子表字段边界，不将主表数据筛选套到子表。共享表单、只读详情和明细表格已接入来源语言及历史控件；同一业务可登记中英德原文，来源语言与界面语言独立，切换界面语言保留未保存输入。

可选 `collaboration-demo` profile 提供 `quality.equipment_category`、`quality.product` 静态主数据及 `quality.exception` 动态异常单，检测明细和团队调查记录通过正常主子表接入。字段、引用、页面和菜单使用现有平台声明及发布流程；样板只安装业务配置，不预置真实人员或冒充业务作者。明细来源的 Web 字段边界采用所属关系的已发布列表投影；无关系投影的既有静态声明沿用编译读取模型。

## 既有流程与办理意见

既有流程的真实办理意见从已持久化事件登记原文，保留实际操作者、发生时间和显式提交的 `reasonSourceLanguage`；技术审计消息不作为办理意见翻译。当前流程及归档历史通过所属实例、业务记录和事件身份读取，复用来源、阅读、人工维护与持久化生成契约。维护译文要求所属业务的内容修改或确认权限，不推进任务；异步执行重新核对原操作者、租户及业务查看范围。归档保留内容历史，最终删除所属流程历史同时清理副本，延迟结果不能恢复已清理内容。

流程任务表单的原文修改仍走所属静态或动态业务的标准保存、字段白名单、状态检查和事务；来源语言及审阅版本通过独立 `contentLanguages` 意图提交，不混入业务 `values`，也不以办理意见语言代替字段语言。工作台业务摘要在已有查看授权和列表字段保护后附加公共阅读投影，原始标题与业务身份保持独立，缺少有效译文时展示原文。工作台标题查询同时匹配已暴露的原文和本次阅读投影中的有效译文，过滤后统一计算服务端总数及分页，不以客户端当前页过滤代替查询。

已发布的流程动作贡献进入同一 `WORKFLOW` 能力目录，静态和动态业务详情均提供受权的当前流程分页及归档轮次选择；普通工作流不会因此启用 `APPROVAL`、增加审批状态字段或改变业务保存门禁。流程目录先固定所属业务、租户及查看资格，再在数据库分页，仅返回选择所需摘要，不重复输出执行快照。详情以原文配合实时阅读控件展示，列表的暂存译文投影不覆盖或重复显示为原文。

样板内部记录通过既有元数据字段保护配置全量脱敏，并声明保持原值；普通页面不展示该字段，普通详情及保存结果不返回明文，来源修订及业务译文不复制该字段。样板升级保留字段身份、已有业务值和用户页面草稿，并修正旧版未保护的内部记录声明。

## 译文事实与独立授权

业务译文存储按所属文本、不可复用的原文修订身份和目标语言保留追加式修订，分别记录机器结果、人工草稿、确认和明确删除。人工草稿不替换当前阅读版本；确认记录审阅的原文和草稿修订，保留草稿作者与确认人各自的事实。当前原文下优先采用已确认版本，其次采用机器结果；机器刷新保留人工草稿及确认版本。删除某语言使用带版本的独立意图，不清空其他语言，旧生成结果不能越过删除修订恢复该语言。原文修订、译文写入和最终清理共享记录事务锁，延迟旧结果不能写入新原文版本；即使最终清理后复用业务记录 ID、显示修订号重新从 1 开始，旧原文修订身份也不能匹配新记录；最终删除同时清理原文及译文副本。回收站的最终清理通过既有删除观察者通知副本清理，沿用所属清理事务；回收站协调器继续独立管理恢复与清理流水。

业务文本声明同时形成 `BUSINESS_CONTENT` 能力，发布独立的 `contentEdit`（维护）及 `contentConfirm`（质量确认）动作，不继承普通业务编辑资格；聚合子表由父记录的动作及数据范围治理。未声明文本的模块不发布这两个动作。普通保存继续只处理业务原值。

## 检索、排序、分页与引用

静态样板通过既有标准模块适配器与 `QueryAbility` 声明查询字段，动态样板消费已发布查询契约，均不逐页面处理翻译。普通查询中已声明业务文本字段的相等、包含式文本匹配及集合条件，可匹配原文和各语言当前有效阅读译文；排除条件同时排除对应原文和有效译文。人工草稿不参与检索；确认优先于机器结果，明确删除、原文修订身份改变、当前原值与最新来源不一致时，旧译文不参与匹配。源语言已是目标语时，该语言仍以原文为准。`NULL`、空值及区间条件保持原字段语义。条件在既有数据库查询内执行，筛选、去重、总数、分页、汇总及已接入的动态导出复用同一条件；业务字段及返回值不被译文替换。用户文本条件在合并租户、权限、菜单与导航范围前扩展，固定范围仍按原始业务值执行。标准静态受管明细的筛选使用相同的用户条件扩展，子服务外部范围及父记录约束保持原值语义。

标准分页列表通过 `X-MuYun-Content-Language` 表达独立阅读意图；已声明并允许查询排序的业务内容字段，以当前有效目标语言译文排序，缺失时回退原文，使用数据库的小写文本比较及稳定记录 ID 收尾，在数据库完成筛选、总数与分页后，仍通过所属 Service 读取业务记录。动态内容字段的查询排序资格由内容及查询声明推导，不改变整数拖拽排序字段的语义。标准静态受管分页明细采用相同排序入口，父范围与子动作资格保持原有语义。

分页响应的 `businessContent` 独立返回当前页已暴露业务字段的有效译文，以及当前授权业务范围内缺少该语言阅读内容的记录数。译文采用批量读取，仅为当前输出中仍与原文一致的字段提供展示；不替换记录字段，不为列表逐行追加查看请求或生成任务。缺失统计在用户业务文本条件之前保留潜在遗漏范围，同时保留非文本条件及固定租户、权限、导航、菜单和父记录约束；空白业务文字不计为缺失，来源已是目标语言的当前原文视为就绪。提示不承诺缺失记录能命中用户输入的外语文字。标准业务文件导出复用相同查询、阅读语言及服务端排序。

## 阅读与人工维护接口

标准来源路径的 `/reading?language=en` 返回原值、有效阅读文本、实际语言及回退事实，不返回人工草稿，也不触发写入或模型调用。相同原文版本的确认译文优先，其次为机器译文；来源已为目标语言时保留原文。`/{field}/translations/{language}/prepare` 与 `/review` 分别以维护及确认资格打开当前原文；存量未追踪文字只建立未知历史作者的基线。`/draft`、`/confirm`、`/remove` 独立提交，必须携带审阅的不可复用原文 `sourceRevisionId`、显示修订号及目标语言的 `expectedRevision`，确认还需 `reviewedDraftRevision`。历史按原文身份分页读取，维护人员与确认人员使用各自动作入口。所有入口保留所属页面、字段、租户、活动记录和聚合范围；读取投影不替换业务字段。

## 持久化异步生成

自动阅读生成使用同一主记录或明细来源路径下的 `POST /{field}/translations/{language}/generation`；`retry=true` 表达对终态任务的明确重试，`GET` 同一路径只读取状态。入口要求所属记录查看资格、已发布的字段暴露及 `AUTO_TRANSLATE` 策略，当前允许 `zh-CN`、`en`、`de` 目标语言，来源语言须已登记，单字段原文上限为 16,000 字符。已有有效译文直接复用，当前原文下的明确删除阻止自动恢复该语言；人工维护策略只允许维护者明确申请机器起草，不因普通阅读或保存自动生成。无有效模型配置或无法保留可信身份时，不创建可执行任务。接口不接收客户端提供的执行身份、模型连接或权限范围。

生成任务在请求事务中持久化，网络调用在事务外执行；并发请求按原文身份、目标语言及已审阅译文头去重。执行和完成分别恢复真实身份并核验当前动作、业务记录、原文、策略及译文头，原文修订与明确删除均能阻止延迟结果写入。标准 Web 适配器保留稳定的编译读取契约指纹、菜单身份及参数指纹、原页面范围指纹和不透明选择引用；进程内缓存编号变化不使相同读取契约失效，读取字段、关系、动作或范围契约变化仍会撤回任务。执行时重新读取可见菜单与业务入口策略并重新解析选择；取得记录内容锁后再次核验完整入口范围，记录移出原页面范围后不随新范围执行，也不伪造 HTTP 请求。未进入编译计划的请求特有范围不能静默丢弃。

当前每次执行使用五分钟租约，过期执行不能追加结果；可重试的模型超时、暂时不可用及并发限制最多执行三次，等待期间可继续阅读原文及已有有效译文。配置撤回不持续重试，恢复配置不自动重放历史任务。格式、截断及数字、单位、设备编码校验失败不发布机器译文。任务只保存身份与范围引用及非敏感问题码，不复制原文、供应商错误全文或凭据；终态运行记录保留 30 天并有界清理，原文及译文事实不随运行记录到期删除。业务最终删除在所属事务内同时清理该记录的任务。

## 提交预生成与自定义入口

标准动静保存由原文生命周期产生变更事实，在原事务提交前按最终原文身份登记主要协作语言的持久化任务，网络调用仍由原异步执行器处理。同一事务内多次修改同一文本只处理最终版本，回滚同时撤回任务；未改变原文及来源语言的普通保存不补翻历史。默认主要语言为 `zh-CN,en,de`，部署可通过 `muyun.content.primary-languages` 在这三种语言内收窄，留空关闭提交后预生成，按需阅读入口继续独立可用。

提交预生成复用实际保存入口的编译计划、父子归属、字段暴露、页面与菜单范围，以及真实填报者的查看资格和模型路由，不赋予额外身份或读取权限。标准主子表从所属关系的真实外键确定父记录，静态子服务可保留自己的模块别名。来源、历史、阅读、人工维护及生成执行均保留生产者当前的字段读取策略：字段策略收到生产者模块、当前文本记录 ID 及 VIEW 治理策略，聚合读取资格继续由所属父记录建立。已发布页面隐藏或移除的字段不能从实体存储字段目录重新取得生成资格。

标准 CRUD 入口已声明 `CompiledRecordScope`，普通业务无需额外接线。覆盖查看、保存或执行范围方法时，不继承原方法对可重放范围的承诺；只有全部约束已由编译计划、菜单及正常 Service 策略表达的覆盖实现，才可显式声明相应边界。依赖请求头等请求特有约束的自定义入口需提供可信延后执行适配，否则不启动自动生成。

无有效模型、来源语言未知或不满足自动策略时不登记任务。模型可用性读取、范围解析及任务登记整体使用原事务内保存点；可用性查询失败或登记失败均不阻断原文保存，也不留下部分语言任务。失败只产生不含文本和凭据的安全诊断；缺失项继续通过查询覆盖提示及受控补齐恢复，不承诺模型恢复自动扫描全库。

## 受控补齐与复核参考

受控补齐以当前分页内明确选择的业务记录及一种目标语言为范围，每次最多选择 50 条，可包含当前已发布、同模块的所属明细；整个范围最多 200 条记录及 200 项文字。范围完整预检后才登记任务，超限时不部分启动。标准主记录使用 `POST /{module}/content/generation/status` 只读预览及 `/content/generation` 显式生成；所属明细使用对应父记录、关系下的批量入口。分页响应提供服务端确定的来源地址，客户端不把明细 ID 当作主记录 ID 使用。每项仍重新核验当前记录、字段、页面及租户资格，不接收客户端身份或模型路由。

明细选择在数据库分页前固定真实父外键及所属租户，最多读取剩余限额加一条，单项读取同时约束明细身份。编译读取授权复用业务原值、页面范围及菜单策略，不为补齐装配整份详情。已有静态自定义明细读取需同时实现有界读取契约；仅覆盖旧全量读取时，新补齐入口保持不可用，原来源、历史及人工维护入口继续使用原读取规则。无自动字段或不可读取的诊断行不占文字限额。

共享补齐窗口只处理自动阅读字段，人工维护字段继续使用译文维护。预览及有界状态轮询不创建任务，生成与失败重试均由用户明确操作；关闭窗口不撤回已持久化任务。关闭或处于后台缓存的阅读面板停止读取、生成请求及状态轮询，重新打开后按当前记录和阅读语言恢复；未保存的业务草稿保持原有内容。已有有效译文、人工草稿及确认记录保持原有事实，明确删除不自动恢复，来源语言未知时提示登记。模型配置恢复不自动补齐历史，也不自动重放因配置不可用而停止的旧任务；用户核实后可在相同入口明确重试。

原文变更后，维护入口提供最近旧原文的人工译文及其原文、作者和历史作为复核参考，明确删除的版本不重新作为参考。删除当前语言同时截断更旧参考及其待复核提示；在当前原文下重新保存草稿不会恢复已舍弃的旧建议，受权修订历史仍可读取。该参考不参与当前阅读，也不继承旧确认状态；维护人员核对当前原文后保存新草稿，再由具备确认资格的人员核对。复制参考只改变维护输入，不提交原文或译文。普通阅读仅依据旧确认版本提示待复核，不暴露旧人工草稿是否存在。当前译文状态按同一修订上界分别读取最新事实，查询和返回行数不随修订历史增长。

## 模型门面与身份路由

自动翻译同时要求字段声明允许自动翻译、当前业务范围有符合处理策略的文本，以及按现有模型路由存在有效模型配置。无有效模型配置时不启动自动翻译，不创建可执行的生成任务、不调用模型，也不将其视为需要持续重试的业务失败。页面说明“自动翻译未启用”，仍可保存原文、维护人工译文，并展示来源版本及权限仍有效的已有译文；界面语言和配置译文能力不受影响。

满足条件时，原文成功提交后可靠地产生待处理事实，异步预生成主要协作语言，阅读时按需补齐其他允许语言。提供有界重试、幂等、超时、失败定位和人工重试；业务提交不等待翻译完成，翻译不可用不导致原文保存失败。可靠交接需要覆盖进程重启，不能只用内存回调充当任务持久化。

执行任务时重新按既有路由核验当前配置和处理资格；当前已无有效配置或不再满足处理策略时停止调用，不自行扩大兜底资格。停用租户专属连接后，若已有明确授权的平台共享兜底仍有效，则继续按正常路由解析。配置缺失与已配置模型的超时、限流等运行故障分别表达。后续配置模型不自动触发全库历史补齐，已有原文通过受控批量补齐处理；新提交和正常阅读按既定策略触发。

任务、重试和进度属于本专题，遵守[后台任务与异步批次边界](../../BACKGROUND_JOB_AND_BATCH_BOUNDARY.md)，不为本专题建设通用任务中心。原文修订、译文版本及生成证据属于必要的专题事实；运行审计仅记录动作线索，按[审计与专题流水边界](../../AUDIT_AND_PROCESS_LOG_BOUNDARY.md)关联，不承载文本全文。

翻译复用现有[模型连接配置](../configuration/AI_MODEL_INTEGRATION.md)，统一通过 `AiModelGateway` 的文本生成能力调用当前有效 LLM，不另建翻译专用供应商目录、凭据、模型配置或独立 chat agent 接入链。部署需要使用内网模型时，由现有模型连接配置承接。

平台身份、租户身份及平台共享兜底完全服从既有模型路由；租户没有专属配置但有明确允许的共享兜底时仍属于有有效配置，不能自行扩大兜底资格。异步任务保留可信触发身份及业务执行范围，不把租户任务改为平台系统身份来取得平台凭据。业务翻译只依赖稳定门面，不直接查询模型配置表；无调用的可用性判断通过 `AiModelGateway.isTextGenerationAvailable()` 门面，复核同一路由、供应商启用及凭据可解析性，不以配置行存在或 `apiKeyConfigured` 代替，也不在业务模块复制配置解析。

可信延后执行身份通过 `TrustedExecutionIdentityResolver` 交接真实账号引用，不保存会话、凭据或权限快照。IAM 在捕获和恢复时检查账号实际租户、创建身份、启停、删除及密码限制，并重新解析当前组织和时区；原有代办还须重新验证同一授权及委托双方任职，不切换成其他授权或操作人身份。该门面仅恢复身份事实，不替代业务执行时的动作、记录及页面范围授权；业务所属租户与模型路由租户由调用链分别保留。此身份契约本身不启动翻译任务。

调用只提交本次翻译所需的文本、语言及允许上下文，不复用跨用户聊天历史，不提供工具或赋予模型业务操作权限。结果仅作为待校验的译文，不能执行其返回的指令。连接、凭据、路由和模型调用并发限制复用现有网关，翻译专题负责自身任务调度与输出校验，不叠加失控重试。模型已配置不代表翻译质量或语言支持已经通过验收，仍需验证术语、返回格式、耗时及容量。

## Excel 填写与回导

可回导的数据文件保留稳定技术表头及身份，明确区分可写业务内容与只读阅读译文。填写业务、修改已有业务、维护译文及阅读导出分别具有明确用途；不把阅读译文通过普通保存写回业务原字段。开启 `EXCHANGE` 的静态 Java 与动态元数据模块通过同一公共文件引擎和“业务文件”入口执行以下契约。

Excel 的本地化填写分为列标题、字典选项和业务引用名称三个层次。展示表头可按导出语言呈现，技术表头和 sheet 身份继续稳定；字典项反查为稳定 code，业务引用名称反查为目标记录 ID，用户自由输入的文本仍是新原文。导入名称的解析语言应由文件或显式导入选项确定，不能在处理中随操作者界面语言变化。

| 场景 | 业务边界 |
| --- | --- |
| 只填写名称 | 允许仅填写原名或当前有效的已确认译名，不强制填写 ID／编码；在有效业务范围内唯一匹配就关联，重名时要求补充编码或限定条件，不选择首个结果 |
| 名称不存在 | 报告未找到并引导修正或由有权限人员先维护基础资料，不自动创建分类等引用对象 |
| 手填机器译名 | 未经人工核对的机器译名只提供候选，用户明确确认对应业务对象后才导入；确认绑定身份，不自动将机器译文转为已确认译文 |
| 导出后分类改名 | 系统导出文件可核实原有稳定身份且用户未修改引用选择时，继续使用同一关联，不因译名变化阻断其他字段更新；无法确认身份时重新匹配 |
| 跨语言修改原说明 | 仅在页面同样允许修改的权限和业务状态下，明确作为业务内容修改，按新输入语言形成原文修订，保留旧内容和作者历史，并更新其他语言译文 |
| 部分记录有误 | 互相独立的记录先导入正确项，错误文件只包含失败的待修正项及必要上下文；100 条中 90 条成功、10 条失败时，用户只修改并重传这 10 条 |
| 已有字段留空 | 修改已有数据时，空白及未提交字段默认不修改；清空必须明确表达，并执行字段约束和权限校验，不用普通业务文本中的某个关键词隐式清空 |

待更新记录的身份和引用目标身份分别解析；业务编码只有在声明的范围内具有唯一性时才作为稳定匹配键。对重名、过期、缺失或不可访问的名称提供允许披露的诊断，不使用机器语义猜测。不因填报名称失败而创建新基础资料。

系统生成的编辑文件携带稳定身份及可核实的导出基线。用户未改分类时保留原关联；主动改分类名称时重新解析并确认新的目标，不能悄悄沿用旧 ID。稳定身份与用户实际填写意图冲突时明确诊断；仅含旧名称的手工文件不享有自动识别改名前对象的保证。隐藏列不是可信凭据，导入仍校验真实归属、权限、记录版本及引用有效性。

业务说明的阅读译文不作为默认可写值。需要修改原说明时，导出模板及导入预览明确显示当前内容与本次业务修改；只想纠正翻译时使用译文维护用途。原记录已冻结、已审批或发生并发修改时，沿用正常业务限制，Excel 不获得额外修改资格。

新增记录的空白继续接受正常默认值和必填校验，不能用更新的“不修改”语义跳过创建要求；数字 `0` 和布尔 `false` 是实际填写值。明确清空在 `__clearFields` 中列出技术字段名，并在导入预览说明动作。

错误文件保留失败项的可编辑业务值、定位和关联身份、版本、解析语言及可读错误原因，支持原文件直接修正重传；不要求用户重新准备成功项。主子表以业务完整性要求确定失败和重试单元，必要的父级定位或已成功关联仅作明确的上下文，不重新列为待写业务项。重传仍执行当前权限、版本和重复提交保护，不能重复创建已经成功的记录。业务写入成功而阅读翻译尚未完成，不计为业务导入失败。

文件身份、原文修订及引用基线在服务器持久化，回执有效期为 30 天；回执不复制业务原文，不授予额外权限。同一已提交文件行重传只跳过，继续修改应重新导出。当前一层主子表按完整业务聚合提交及回滚，错误文件中的只读上下文不重放业务值。错误文件保留已选择的填写语言与名称解析语言，修正后可直接重传。可收集的数据错误允许其他独立单元成功；未识别的基础设施异常传播并回滚当前单元。

### 译文文件与其他交付

译文维护文件通过明确的业务身份、字段、原文版本及目标语言定位，执行权限、版本和歧义校验。局部维护不清空其他语言，原文过期时要求复核，不把导入修订自动等同于人工确认。`TRANSLATIONS` 文件以业务行身份、字段、不可复用原文修订身份、显示修订号及译文维护版本定位；导入仅保存人工草稿。

供阅读的多语言导出明确导出语言、译文来源和状态。数据文件与阅读导出具有可辨别的用途，不能把阅读导出中的显示译文直接回导为原字段。首轮复用 Excel 导出交付，不新增报告制作、客户发送、签发、审阅证明或强制人工确认的业务流程。

通知、人工页面、API 消费者及助手使用同一标准业务读取能力。若助手消费译文，应保留其来源与状态，执行仍基于原始身份、规则及授权；本专题不建设新的助手对话或业务执行机制。

## 默认交互与运行边界

默认交互采用渐进展开：正常阅读呈现一份有效正文，原文、来源和维护按需打开；同语言原文不显示无意义的翻译操作。查询可能遗漏未译内容时保留简短风险提示，具体范围及补齐操作再展开。单一国家使用不要求逐条维护多语种，也不按国家隐藏真实来源或绕过授权。界面语言目录与业务阅读、来源语言独立；收窄 `muyun.content.primary-languages` 仅改变提交后预生成范围，不能作为关闭业务内容能力或删除已有译文的开关。

宿主完成平台启动协调后才能接入业务请求，端口已经监听不代表动态元数据已安装。开发态可在应用就绪后核对端点目录；部署使用宿主自身的就绪策略。模型故障时保留原文和有效已有译文，终态失败由受权用户核实后明确重试；进程中断通过持久化任务及租约恢复，执行仍重新核对真实身份、业务范围及当前模型路由。模型配置恢复不自动扫描历史。

已完成的工程文件操作与受控故障验收不构成生产容量或 SLA 承诺。投产前按实际记录量、并发、模型延迟与业务术语检查等待时间、失败恢复和翻译质量；数字、单位、编码、否定及放行条件须由业务核对。扩大语种、业务覆盖或外部消费者时重新验收相应范围。


同步文件导出保留逐记录授权、字段保护、来源与引用基线及回执事务；主记录的详情结果与来源组合读取，避免重复详情展示。1000 行是文件协议上限，不是交互延迟承诺。千行导出仍较慢，小范围试用先从约 50 行的完整业务单元批次评测，再按实际等待和代理超时决定范围；拆批不破坏主子表完整性，不以旁路读取换取速度。

运行参数、单实例有界执行路数及网关限流的关系见[试用与运行评测](BUSINESS_CONTENT_PILOT.md)。默认翻译单路执行；收窄主要协作语言或关闭预生成不删除已有译文，也不关闭原文及人工维护。增加工作线程不扩大模型权限或共享额度。

## 工程交付与后续启用

工程验收覆盖两个样板的填写互读、语言切换保留草稿、保存重开、主子表、查询分页、引用、人工维护、当前及归档流程、Excel 部分成功与失败文件修正重传，以及权限隔离、无模型、模型故障、原文变更、迟到任务和进程中断恢复。真实 PostgreSQL 合同测试支撑持久化与事务边界；自动测试不能替代页面操作或业务语义审阅。

实际业务团队启用前，由业务负责人核对术语、数字、单位、编码、否定及放行条件，并按部署规模确认等待时间、失败恢复和模型费用。没有实际团队时，结论保持工程验收通过、业务质量审阅待开展；不把工程人员构造的确认状态当作真实业务审校通过。

广泛业务与语种推广、独立维护工作区、配置译文跨环境交付、其他消费者宿主及生产规模容量另行推进，不阻塞阶段 1—3 的工程收口。新增业务与消费者仍需验证自己的权限、状态、字段暴露及语言范围。业务数据及其译文不随应用配置包复制。

不建设翻译专用模型配置、跨租户共享模型、新助手对话、通用任务中心、整套 PIM、报告签发或译文审批驱动的业务门禁。附件正文、OCR、音视频及任意语言语义搜索不属于当前交付范围。
