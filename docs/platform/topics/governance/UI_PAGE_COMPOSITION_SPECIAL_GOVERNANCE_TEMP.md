# UI 页面编排专项治理（临时）

> 状态：临时专项记录。本文用于约束动态模块页面编排的首期交付，并在模型、运行态和正式专题文档稳定后删除；不作为长期并行架构说明。

## 目标与边界

动态模块的页面编排不是字段表格配置，而是受模板约束的页面组合：元数据提供可用字段事实，设计器维护 UI Tree，运行态将**已发布**的页面方案编译为统一 UI descriptor 与执行计划。

```text
已发布主元数据与能力
    -> 页面定义 / 界面方案 / 修订
    -> 已发布的页面 UI Tree
    -> ModuleUiDefinition / ResolvedModuleUiDescriptor / ModuleExecutionPlan
    -> 动态记录页面与读写运行态
```

静态声明和动态页面编排仍须归一到同一 Web 运行时模型。页面配置不得绕过元数据字段事实、数据权限、租户范围、动作授权或后端读写计划；动态页面不再读取旧“UI 配置集 / UI 配置”。

## 规范模型

页面编排以三类业务对象表达；修订是界面方案的版本与发布实现细节，不额外形成第四种用户心智对象。

### 页面定义

`页面定义`是模块内稳定的页面身份，包含页面 alias、页面契约类型及主元数据关系锚点。菜单、动作和外部入口应指向页面定义，而不直接绑定某个客户端、模板、租户或组织差异。

首期动态运行态只识别每个模块的 `management` 页面定义。

### 界面方案

`界面方案`（presentation variant）是某个页面定义在特定客户端与作用范围下的一份完整 UI 声明。它归属页面定义，声明目标客户端、作用范围和后续修订来源；不采用字段级继承或 patch 合并。

完整方案使草稿、预览、发布和回滚的结果可确定。租户或组织差异若后续需要，应复制为完整方案后独立维护、独立发布。

### UI 模板与修订

UI 模板是平台维护、版本化的页面语法：固定根节点、插槽、允许的组件节点、属性 schema、校验规则和预览出口。业务方案只能在合法插槽内新增、投放、移动或配置节点，不能删除模板根节点或必备插槽。

`修订`保存某个界面方案的完整 UI Tree、状态和版本。编辑只改草稿；发布通过校验后切换已发布修订，并由发布协调器在事务提交后刷新动态模块的运行态。

## 当前基线实现

首期已经交付并仅承诺以下路径。它是页面编排工作台的能力基线，尚不等同于产品级 UI 配置体验：

1. 页面定义、界面方案、草稿修订和发布修订已具备持久化与发布领域模型。
2. 页面编排工作台可为动态模块初始化 `management` 页面，维护 Web 全局方案的草稿，保存并发布；发布后自动保留一份后续草稿，支持继续编辑。
3. 当前编排模板为 `management v4`，按树、列表、微列表呈现方式提供不同导航骨架，共享详情 / 表单、分组及直接子实体关联区域。页面结构树承载配置入口：标题、辅助信息和快速查询都是固定骨架节点，字段拖入后以子节点表示绑定；标题和辅助信息各容纳一个字段，重复拖入时替换，快速查询容纳多个去重文本字段。列表模式保留可排序的展示列。`management v1`、`v2`、`v3` 继续支持已有发布快照。
4. 字段放入页面后成为页面组件节点。组件属性随草稿和修订持久化，并在发布时由模板 schema 校验：列表节点支持展示标题、列宽与对齐；表单节点支持展示标题、列宽度与只读展示。分组标题、子实体展示字段和快速查询占位提示也由模板规则约束。它们编译为统一页面定义与字段展示契约，不修改元数据字段或字段控件属性。
5. 动态运行态只解析 `management` 的**全局 WEB 已发布修订**，编译为统一的 `ModuleUiDefinition`、descriptor 与执行计划；没有已发布修订时，不产生供业务页面执行的动态页面 descriptor 或执行计划；草稿预览可通过独立只读入口编译。
6. 动态记录查询已可消费上述页面编排执行计划，不再要求旧 `uiConfigId`。服务启动时会恢复已发布且拥有主元数据的动态模块运行态。
7. 草稿预览通过服务端 `PresentationRevisionPreviewService` 校验模板并编译 descriptor，与已发布页面复用 `PageRevisionModuleUiDefinitionAdapter` 和完整的 `DynamicPageCompilationContext`。主字段标题、必填约束、直接子关系与模块概览模式由同一份编译输入提供；预览不选择或安装已发布修订。前端预览使用标准字段、列表单元格及关联表格渲染组件；预览失败时标明上次成功结果已过期并允许重试。
8. 页面修订发布在事务内预编译并校验候选执行计划，编译失败保留原修订和原计划；提交后安装候选计划。草稿保存、放弃未保存修改、发布前确认及后续草稿创建已有独立交互。提交后的安装失败恢复仍需与运行态发布恢复一起治理。

主子字段投放、草稿保存、发布、租户业务页新增与修改、详情重读、清空子表及业务记录版本冲突已完成浏览器验收；页面草稿版本冲突已完成双会话验收，编排工作台的长树和长表单已覆盖 1440px 与 980px Chromium 布局验收。

因此，首期有效的运行时选择可以明确写为：

```text
动态模块 + management 页面定义 + WEB + GLOBAL
    -> 已发布修订
    -> 统一页面 descriptor 与执行计划
```

## 元数据 Tree 的既定边界

左侧元数据 Tree 只提供字段和关系来源，不是 UI 配置本身。投放到 UI Tree 时应绑定稳定的模块元数据字段及其页面角色，不复制字段定义、数据库列或 SQL。

当前工作台已展示主元数据、直接子元数据关系及其字段；直接子实体可加入表单关联区域并选择展示字段。运行态保留系统字段不会作为普通页面字段来源，元数据治理中的展示/排序能力不等于页面可编排能力。下列目标**尚未交付**：

- 单值引用字段（当前记录仅保存一个目标 ID，例如一对一、多对一）按需懒加载目标元数据；
- 单值引用的递归展开、权限与可达性校验、循环检测及最大深度限制。

集合关系、一对多和多对多不作为字段 Tree 的递归展开入口。

## 元数据变化与页面依赖

页面定义的主实体绑定是稳定引用，删除对应关系前必须先处理页面定义。草稿与已发布修订的导航标题、辅助信息、快速查询、列表、表单、分组字段和直接子实体关联参与统一配置删除检查；拒绝信息包含页面、修订状态和版本。修改草稿不会释放旧已发布修订的引用，必须发布修正后的草稿。历史归档保留不可变快照，不永久阻止元数据演进，重新使用时仍须通过当前来源校验。

可用字段刷新保留已加载的树和本地编排，完整目录就绪后统一更新。草稿遇到不存在、已停用或不再可编排的来源时保留标记节点和原有页面属性；用户显式移除节点或恢复来源后才能发布，不静默过滤配置。失效节点标记只属于编辑状态，不进入持久化 UI Tree。解析失败的草稿不能由空白本地树覆盖。

## 编辑、预览与发布契约

页面方案遵循以下生命周期：

1. 初始化页面与全局 Web 方案，生成模板根节点和默认插槽。
2. 用户从元数据 Tree 投放字段，或在模板允许的插槽内新增、移动、配置组件节点。
3. 保存仅保存草稿；预览和 UI Tree 使用同一份草稿状态。
4. 发布校验模板规则、插槽、字段可用性、版本冲突和作用范围唯一性。
5. 发布在事务内编译校验候选计划，提交后安装运行态计划；提交前校验或编译失败不得切换已发布修订。提交后的激活/安装失败恢复仍属于待补治理，不能以 HTTP 成功或失败替代发布状态。

工作台采用统一的页面级保存、放弃与发布入口；可用字段和页面结构两栏可分别折叠。字段来源通过节点“添加到…”菜单或拖拽选择目标；页面节点就地配置、移除或添加分组，拖拽与键盘排序直接更新本地草稿，不另设排序保存或固定底部操作区。

可用字段（A）可以拖入页面结构（B）或描述符预览（C）。预览在拖动期间渲染临时布局：列表列、表单字段和子表列直接显示落下后的字段位置，已有字段复用正式 renderer 并以布局动效滑入候选顺序；动作锚点同样按临时顺序重排。临时布局不修改草稿，只有左键在合法落点释放时才复用本地草稿命令提交。主表字段可在表单分组间移动，子表字段只能进入所属子表；非法位置不接受放置。字段拖拽在指针完全离开已进入的预览区域时取消。动作入口离开操作区时清除该区临时布局，允许继续移动到其他区域；在非法位置释放不提交。右键或 Esc 取消临时布局和本次拖动。预览解析期间保留最近成功画面并暂时禁止预览拖放，避免使用过期位置。所有调整遵循页面保存与发布链路，不改变数据库表结构。

表单根节点的字段和分组共用一份 `order` 顺序声明，条目为 `{field: 字段名}` 或 `{group: 分组编码}`；字段属性和组内字段仍由各自节点持有。显式顺序必须完整、去重且只引用根字段与已声明分组；旧修订省略顺序时按根字段、分组读取。结构树直接展示这一层混排，分组可整体移动，字段可在根层和分组间移动；关联子表继续位于主表单之后。后端按该顺序展开标准表单描述符，预览复用标准字段、分组标题、表单网格和子表展示组件，仅叠加编排操作及空组占位。示例值保存在预览本地，不进入页面声明。

属性输入即时更新本地草稿，关闭属性面板不回滚修改；仍须显式保存或发布。非法列宽在更换选择后仍阻止保存与发布，并提供对应字段的修正入口。节点移除只改变页面声明，不删除元数据；最近一次移除可连同分组、子表内部字段和属性撤销，后续内容编辑、保存或重新加载会结束该次撤销机会。

预览使用服务端解析的 descriptor 和本地示例记录，编辑预览中的改动不直接修改真实业务记录。若后续接入真实数据预览，必须复用运行态权限、数据范围与脱敏策略。

草稿保存发生版本冲突时保留本地修改并持续提示，暂停保存与发布；用户确认加载最新草稿后才替换工作副本。刷新读取失败保留当前编排，避免丢失本地调整。页面结构刷新复用同一入口。发布成功后先退出旧修订的编辑态；后续草稿创建成功即接纳其回执，重新加载失败不回退到已发布修订。

## 模式骨架与字段绑定契约

平台模板目录提供三种模式的骨架定义。`management v4` 的根包含 `mode`、`quickSearchFields`、`actions` 与 `nodes`；列表使用 `list` 插槽，树和微列表使用 `explorer` 插槽，后者通过 `titleField` 与可选 `secondaryField` 绑定导航展示字段。三种模式复用 `form` 插槽。`actions` 只允许投放到平台拥有的 `page`、`detail`、`form` 三个锚点，分别对应页面操作区、详情操作区和表单操作区；不开放导航行、字段单元格、子表或任意自定义容器。入口以区域与动作编码共同标识，同一动作可在不同区域配置独立标题和顺序。同一区域重复投放保留已有属性。受管入口替代模板内置的新建、刷新、编辑、删除、启停和保存按钮；移除入口后不再通过隐含按钮执行同一操作。取消、查看与导航工具仍由模板提供，查看态启停由标题旁的开关承载，不再重复显示启用／停用按钮；开关按当前状态对应的已编排入口及记录权限决定是否可操作，入口隐藏或缺失时保持只读，树模板不再隐含提供“新建子项”。

动作表示业务能力，入口表示交互意图：页面 `create` 打开新建表单，详情 `update` 打开编辑表单，表单 `create` / `update` 分别校验并提交新建 / 修改；`query` 刷新列表，详情删除经过确认，启停使用已有标准流程。编译描述符下发明确 operation，动静链路均校验动作来源及作用范围，执行继续遵循平台授权与数据范围。尚无交互契约的动作不可投放，失效入口阻止保存和发布，不猜测 HTTP 或脚本执行方式。设计时的动作目录独立于当前操作者的执行权限。

新建草稿与旧版草稿编辑时依据动作目录补齐默认入口，保存为 v4；v1–v3 已发布快照保留旧行为，重新发布后才切换为受管入口。已发布启停入口保护 ENABLE 能力，移除入口并发布后才释放依赖。快速查询占位提示继续保存于 `props.list.searchPlaceholder`，由快速查询骨架节点双击编辑；该兼容路径适用于所有导航模式。

`quickSearchFields` 是显式查询范围，空数组表示关闭查询；导航展示字段与查询字段相互独立，不要求加入列表或表单。服务端根据字段规格提供文本查询资格，发布与预览再次校验。列表查询复用标准 QuerySchema 和 OR LIKE 契约，树和微列表在已加载记录中按同一字段集合筛选。导航、查询字段进入读取投影与元数据引用保护，不扩大可编辑字段范围。

静态 Java 页面 DSL 通过 `quickSearch(...)` 声明同一查询范围，树和微列表通过 `explorer(...)` 声明导航展示。静态页面的查询字段必须属于模块既有查询能力。未声明页面查询范围时保留模块默认行为。

树模式预览仅展示共享详情 / 表单，不提供树导航预览；列表模式的页面预览保留导航区，微列表与树模式不再模拟导航。动作预览复用运行态入口标题与新建 / 编辑状态规则，按钮仅用于选择、双击配置与拖动，不执行真实业务动作。表单预览可切换新建和编辑状态，取消固定入口同时可见；实际执行权限与记录状态仍由运行态判断。标题、辅助信息与查询字段的绑定均在骨架树完成，不另设常驻字段选择器。

v2 修订固定自身呈现模式，概览变更不会重新解释已发布页面。旧 v1 页面须先在页面配置中保存、发布新版骨架，再切换概览模式。概览切换后，由用户显式采用新草稿骨架；共享表单保留，导航重建，发布后才替换运行页。已发布 v2/v3 页面仍依赖的树和排序能力在概览变更时保留，并显示依赖说明。

## 未交付能力（不得对外宣称完成）

- 多层子实体编排、单值引用懒加载递归及其循环/深度治理尚未实现；已有直接子实体来源与表单关联区域不覆盖这些范围。
- 更丰富的组件属性、组件类型扩展与条件化属性尚未进入首期；属性 schema 必须继续由模板拥有，不能退回到无约束 JSON 或复用字段控件属性表。
- `MOBILE` 方案、租户方案、组织方案虽然已有领域模型基础，但动态执行计划目前不按请求上下文解析它们；运行态只消费全局 Web 管理页。
- 组织 > 租户 > 全局的多作用范围解析，以及任何字段级 patch 合并，均未进入首期运行时。

## 页面治理质量门槛

在继续扩大动态业务页面或多端运行器之前，页面编排工作台须先通过以下门槛：

1. 管理员无需阅读实现提示，即可识别正在编辑的页面定义、呈现目标、模板、草稿及最近已发布修订。
2. 草稿保存、放弃本地修改、发布确认和发布后的后续草稿具有明确且不可混淆的状态表达；发布始终指向唯一的页面与呈现目标。
3. 预览和运行态使用同一份受模板校验的编译语义；草稿预览与已发布运行态必须明确区分。
4. 模板插槽、允许组件与组件属性由平台模板契约拥有；页面工作台不得继续增长为无约束 JSON 编辑器。
5. 元数据来源、字段能力贡献和页面可配置范围可被解释；关系递归只在单值引用、权限和循环治理完备后开放。
6. Web、移动端和作用范围变体是同一页面定义下的完整方案，页面工作台必须显式表达其目标与回退语义，不能通过字段级 patch 拼接。

当前优先级是完成以上页面治理门槛，而非扩展配置完成后的动态业务页面功能。动态业务页只作为同源预览和已发布 descriptor 的验证消费者，不承载补齐工作台体验的职责。

## 后续推进顺序

1. 在已验证的主子编排、草稿冲突及桌面/窄屏滚动基础上，推进发布提交后的运行态激活状态、失败诊断与受控重试；复用现有发布协调边界。
2. 在真实主子页面验收中核对已有的来源刷新和引用保护：刷新可用字段会原位更新目录并重新核验本地草稿，保留本地更改与合法选择；失效字段和关系保留在树中，显式修正后才能发布。
3. 在现有预览编译出口和模板 schema 上，完善字段来源、能力解释及错误定位；单值引用递归按真实场景补权限、可达性、循环和深度治理。
4. 在上述体验与编译链路稳定后，治理 MOBILE、租户和组织的完整方案选择与固定优先级；不引入 patch 合并。
5. 页面治理质量门槛稳定后，才恢复动态业务页的扩展验收；届时将正式契约沉淀到 configuration/page 专题并删除本文。

## 明确不做

- 不支持任意自定义模板、任意 UI JSON 或业务端自由定义节点语法。
- 不支持租户/组织方案对全局方案的字段级 patch 合并。
- UI Tree 不直接绑定原始数据库列或 SQL。
- 预览、配置和发布不绕过元数据发布、运行态刷新、权限或数据范围治理。

详情与表单均按视图的分组信息及字段顺序展示分组标题、说明和普通字段，页面预览复用标准只读详情组件。显式详情展示视图只使用自身分组，不继承编辑视图的分组；未声明展示视图时沿用编辑视图。运行态不为无可见字段的分组渲染空标题，设计预览保留空分组标题以便定位和配置。

### 业务预览

模块治理的业务预览复用标准 `ModulePageHost`，通过模块运行态上下文读取已发布页面，并使用同一业务查询、权限、动作和读写链路。它不使用草稿编译预览或示例数据；未发布页面时不开放通用 CRUD 回退。页面配置中的设计预览仍用于检查未发布草稿。

业务预览中的操作直接保存真实业务数据。返回业务预览时检查运行态是否变化，保留正在编辑的表单；有变化时提示用户完成当前操作后重新加载已发布页面。编辑或保存期间禁止重载；关闭工作台页签时复用平台未保存状态提醒。
