# 模型连接配置

## 能力定位

首期模型能力只解决受治理的模型连接与文本调用：平台维护一条平台级 OpenAI-compatible 模型连接，每个租户至多维护一条租户级连接；业务代码通过 `AiModelGateway` 使用当前有效连接。它不包含智能体身份、工具调用、菜单代办、单据修改、元数据编排、会话记忆或按业务场景选择多个模型。面向终端用户的助手在该门面之上分层建设，目标场景、前端能力接入和阶段边界见[智能助手能力融合专项治理](../../AI_ASSISTANT_GOVERNANCE.md)。

静态与动态业务未来都只能通过来源无关的 `AiModelGateway` 访问模型；不得在 Controller、动态执行器或业务 Service 中直接持有供应商 SDK、API Key 或供应商 URL。

`AiModelGateway` 是业务侧唯一稳定门面。每次调用都会在执行时请求 `AiModelRouteResolver` 解析当前路由，
不会在 Bean 初始化或业务对象中固化配置。路由解析器把配置记录与供应商目录合成为内部
`ResolvedAiModelRoute` 快照，传输适配器只消费协议、端点、模型和凭据，不依赖配置持久化实体。
这些内部类型不作为业务接入 API 暴露。

## 供应商目录

`AiModelProvider` 是平台级供应商目录，仅平台超级管理员可维护。供应商定义稳定编码、名称、启停状态、协议和 API 基础地址；首期预置 DeepSeek、阿里云百炼和 LM Studio。租户只能从启用的供应商中选择，不能新增供应商或修改其地址。

首期协议固定为 `OPENAI_COMPATIBLE`。基础地址只接受 HTTPS；本机回环地址允许 HTTP 以支持 LM Studio。地址不接受账号信息、查询参数或片段，HTTP 客户端不跟随重定向。供应商配置是受治理的端点目录，不是任意 HTTP 请求或供应商脚本机制；供应商特有参数、模型自动发现、协议插件和降级策略不属于当前契约。

## 配置、可见范围与优先级

`AiModelConfiguration` 只有两种归属，并且每种归属最多一条记录：

1. `平台级`：`tenantId` 为空，仅系统管理员可创建和维护。默认仅平台使用；开启
   `tenantFallbackEnabled` 后，才允许没有专属配置的租户作为兜底使用。
2. `租户级`：`tenantId` 为目标租户。系统管理员可代建并绑定任意租户；租户管理员创建时服务端强制绑定当前租户，不能伪造其他租户。

`configurationLevel` 是由 `tenantId` 锁定的归属级别：`tenantId` 为空时固定为 `PLATFORM`，
否则固定为 `TENANT`。租户级配置的 `tenantFallbackEnabled` 始终归一为 `false`，避免归属和使用策略漂移。

平台管理员与目标租户拥有相应权限的管理员编辑同一条租户级记录，不存在管理员配置与租户自建配置并列或互相覆盖。当前租户优先使用自己的租户级配置；不存在时，仅回退到开启 `tenantFallbackEnabled` 的平台级配置。没有可用配置时返回 `CONFIG_MISSING`。

运行时路由要求调用链已经建立明确的认证身份和执行上下文。认证为平台系统用户时始终使用平台级配置；系统用户为管理业务数据而选择的租户作用域，不会把其身份改写为租户用户。真实租户身份按租户专属配置和平台共享兜底的顺序解析。缺失上下文不会被视为系统身份，也不能静默使用平台凭据。业务调用方不得传入配置 ID、供应商或租户 ID 来绕过这一推断。

当前每个归属最多一条配置，因此首期路由维度只有身份与租户作用域。模块、动作或其他业务场景尚不参与模型选择；出现同一作用域按业务场景选择不同模型的明确需求时，应给网关增加稳定的业务用途标识，并由路由层结合执行上下文解析。不得把配置 ID 塞入 `AiTextRequest`，也不得让业务代码直接查询配置服务。

不支持“指定租户”子表或多租户授权语义。配置归属只由 `tenantId` 表达，运行时和页面均不解析或展示其他租户范围模型。

## 凭据保护

`credentialSource` 切换两种凭据来源，旧记录默认 `direct`：

- `direct`：通过 `apiKeyInput` 写入 API Key，沿用加密存储；更新留空保留原值。
- `environment`：通过 `apiKeyEnvironmentVariable` 保存服务器环境变量名，不限制前缀，例如 `DASHSCOPE_API_KEY`；变量名区分大小写，以字母或下划线开头，仅包含字母、数字和下划线，最长 128 个字符。只有平台管理员可以保存或测试该模式，租户可按既有路由规则使用管理员配置的连接。

切换到环境变量模式会清除原有 Key 密文与签名；切回直接填写时必须重新提供 Key。`apiKeyConfigured` 表示已配置凭据或变量引用，不保证部署环境中的变量存在。保存环境变量引用不要求当前进程已经设置该变量；测试连接和实际调用在路由解析时共用同一凭据解析器，变量缺失或为空时返回 `CONFIG_MISSING`，不回退到旧 Key。变量值只进入本次内部传输快照，不写入配置实体、数据库、缓存或读取响应。读取的是后端进程环境；部署修改环境变量后需重启后端进程。

直接填写的 API Key 是写入专用字段：读取 API、模块描述符、OpenAPI 和运行审计都不返回其值，凭据仅返回非敏感的 `apiKeyConfigured` 状态。更新时不传 Key 保留原值，传入非空值替换原值。保留凭据通过字段保护能力从 RAW 更新快照中解密并验签，普通编辑和启停仍走同一持久化保护链，不能把存储密文当作业务明文再次加密。

凭据持久化复用平台字段保护能力：写入时以 AES-GCM 加密并以 HMAC-SHA-256 生成完整性签名，读取时先解密再校验签名。生产环境必须通过部署密钥提供 Base64 编码的 16、24 或 32 字节主密钥：

```yaml
muyun:
  security:
    field-protection:
      key-base64: ${MUYUN_SECURITY_FIELD_PROTECTION_KEY_BASE64}
```

缺少该配置时，平台不允许持久化直接填写的受保护模型凭据；环境变量模式不依赖该字段保护密钥。密钥本身不进入数据库、日志、审计或配置导出。后续如迁移到 Vault/KMS，应替换密钥提供器，不改变模型配置或调用门面。

## 调用与诊断

`AiModelGateway` 当前提供普通文本生成和 SSE 流式文本输出。适配器使用 OpenAI chat-completions 协议，统一映射消息、温度和最大输出 token；服务端不保存对话内容。SSE 以 `[DONE]` 表示正常完成，供应商错误事件、非法事件和提前断流均抛出平台异常，不暴露供应商错误报文；已交付的部分文本不代表调用成功。

网关在单个后端实例内统一限制普通/结构化、流式/非流式调用的在途并发：`muyun.ai.max-concurrent` 默认 `16`，`muyun.ai.max-concurrent-per-user` 默认 `2`，均须为正整数。用户额度按认证用户 ID 计算，不随页面租户切换重置；总额度涵盖所有路由，保护平台共享模型及实例资源。超限立即返回 `AI_CONCURRENCY_LIMIT`（HTTP 429），不排队、不自动重试；流式响应已建立时通过错误事件交付。额度覆盖路由解析至同步调用/流消费结束，失败或取消退出后释放，不保存消息或凭据。此限制不是按时间窗口计费或跨实例配额；多实例部署需要另行配置共享限流设施。

平台不提供接收任意提示词的通用公网代理接口。具体业务能力应在自身 Controller 或动作入口完成权限、数据范围、输入约束和审计，再调用 `AiModelGateway`；否则通用代理会绕过业务语义并扩大模型凭据的使用面。

`POST /platform.ai_model_configuration/{id}/test` 是持有配置更新权限的已保存配置连通性诊断；标准表单动作也可验证尚未保存的当前输入，并在编辑时复用留空的已存凭据。两条路径都发送固定的最小探测请求，只返回连通状态与耗时，不返回模型文本、完整供应商响应或凭据。

本地 LM Studio 可用于集成验证，使用 `LM_STUDIO_KEY` 作为请求凭据；测试或运行日志不得输出该环境变量。

## 旧库结构升级

旧版模型的 `availability_scope` 已由 `configuration_level`、`tenant_id` 和 `tenant_fallback_enabled` 替代。自动 schema ensure 不会删除模型外的历史列；旧库若保留该列的非空约束，新建配置会因未写入已废弃字段而失败。升级此类旧库时执行以下 SQL，保留历史列及其数据，仅解除已废弃的非空约束；无此列的新库无需执行：

```sql
ALTER TABLE public.platform_ai_model_configuration
    ALTER COLUMN availability_scope DROP NOT NULL;
```

该约束与凭据来源无关，直接填写和环境变量模式均应通过标准保存入口写入。不要通过恢复废弃模型字段或给业务保存补写旧值来维持旧约束。
