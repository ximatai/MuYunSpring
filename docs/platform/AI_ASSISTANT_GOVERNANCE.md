# 智能助手能力融合专项治理

## 定位与文档边界

本文维护智能助手的稳定分层、接入和运行契约。统一建设方案、主干与分支、当前代码进度和下一步工作均见[平台与智能助手协作建设方案](AI_COLLABORATION_ROADMAP.md)，只使用该方案的 **平台治理 → 智能体治理 → 交付演练** 顺序，不另设阶段编号。

助手服务于发现业务、查询数据、准备业务草稿和协作配置应用。它组合平台已有能力，不拥有 CRUD、配置发布、业务规则或权限的第二套实现。新增操作先在所属平台能力中形成可独立使用的正式契约，再向助手开放。平台已有能力、助手已接入、真实用户已完成目标是三个不同事实。

## 分层与事实归属

```text
用户 ↔ 对话面板 / 会话控制器
             ↓
      Assistant Runtime ↔ 后端助手回合服务 → AiModelGateway → 供应商适配
             ↓                                  （仅模型协议与路由）
       当前 Surface / 能力适配
             ↓
  标准页面运行器 / 所属治理编辑会话
             ↓
  正式领域命令 → 权限、范围、版本、事务、校验、审计与运行态
```

| 职责 | 所属边界 | 不承担的职责 |
| --- | --- | --- |
| 模型连接、凭据、路由、并发、协议归一 | `muyun-platform` 的 `AiModelGateway` 与内部 adapter | 不持有页面、候选或业务执行权限 |
| 平台指导、结构化模型回合及服务端限制 | `muyun-platform` assistant；HTTP/SSE 由 `muyun-platform-web` 交付 | 不根据客户端工具描述调用任意 Service、URL 或 Controller |
| 公共消息、Surface、能力和确认契约 | 前端 `web-contracts`、`web-core` | 不依赖具体 Vue 组件、Workbench 业务或供应商 SDK |
| 会话控制、历史、活动页组合、用户交互 | `platform-workbench` | 不复制领域进度、编辑会话或配置发布 |
| 标准查询、表单、引用、主子草稿适配 | `dynamic-page-runtime` | 不建立静态/动态两套助手，不拼旁路业务请求 |
| 配置候选、差异、预检、提交及生效核实 | 元数据、规则、页面等所属平台能力 | 不以助手确认类型作为长期公共编辑内核 |

公共编辑与提交已使用入口无关的 `OperationProposal`、确认状态机与领域编辑契约；`metadataEditorSession`、`businessRuleSession` 不反向依赖助手确认类型。会话内部分局部方法仍沿用 assistant 命名，不代表另一套候选或执行权限。页面、规则和元数据各自拥有候选格式及提交边界，不强行合并为同一执行引擎。

认证用户、登录租户与权限由后端取得。页面业务执行租户沿已受控的 HTTP client 和 Web 过滤链传递，模型不能指定或覆盖；Workbench 通过不透明请求入口发起回合，不自行拼接租户请求头。可见菜单来自已剪枝目录，字段和动作来自 resolved descriptor 与当前会话，配置状态来自现行治理对象，业务完成来自正式结果及验收。聊天历史、方案建议、前端能力描述均不是授权事实。

静态 Java 与动态元数据是定义来源，人工页面与助手是操作入口。模型网关与助手不新增业务定义来源；未来服务端工具由服务端可信目录解析并重新授权，不能把客户端 Surface 原样升级为服务端执行目录。

## Surface 与能力契约

### 注册与执行

Surface 通过 `web-core` 按稳定页签实例注册，贡献裁剪后的 `describe()`、动态能力目录、上下文修订、用户交互修订、可选稳定入口及不透明回合请求入口。注册中心分配代次；Workbench 只激活当前页签，不以最后挂载的组件判断活动页。

一次调用遵守以下顺序：

1. 等待当前 Surface 的后台加载稳定，读取新鲜事实、能力目录和调用令牌。
2. 后端用这些受限数据组织模型决策，返回文本、澄清或结构化能力意图。
3. 前端复核能力仍存在，按可信实现的 `parseInput` 校验参数，拒绝重复或保留编码覆盖。
4. 异步准备不改变页面；产生效果前再次核验页面实例、代次、上下文与用户交互修订。
5. 同步提交进入受保护的 `applyEffect`，后续等待通过 `settle` 表达；下一步重新发现能力。

Surface 撤销、页签切换或显式取消会中断关联调用；记录、草稿、范围和版本变化使旧调用失效。后台数据加载只改变事实修订，不伪装成用户操作。稳定入口不能等待缺失的用户输入，也不能自行产生页面效果。助手导航仅等待自己打开的目标页与正式 Surface，不通过临时 fallback 向错误作用域发送原任务。

能力声明使用当前代码契约中的 `descriptor`、`effect`、`parseInput`、`execute` 和可选结果呈现适配；不在文档复制易漂移的完整 TypeScript 接口。参数描述与执行解析应一致，但当前并非全部由单一类型生成；主干一致性治理见统一方案。领域校验和后端授权不会因 schema 校验通过而省略。

### 效果与结果

可信能力声明 `read`、`page`、`draft`、`configuration-draft` 效果；模型不能修改其类别。`read` 不得调用 `applyEffect`。内部候选缓存通过受保护的内部状态提交，不算业务效果；菜单、查询和草稿修改调用正式运行器入口，不写 Router、组件内部状态或任意 HTTP URL。

同步执行事实区分 `read`、`effect-applied`、`not-applied`、`unknown`；回合终止区分 `stopped`、`waiting-for-user`、`repeated-call`、`step-limit` 以及取消、上下文失效、执行中断或模型失败。模型停止不代表业务完成。

`applyEffect` 只接受同步提交。误传 Promise/thenable、效果函数执行中抛错时保守标记未知并停止；效果已提交后发生等待失败、取消或过期，保留已发生事实，丢弃过期业务输出，不自动撤销或重试。异步持久化另走确认与正式提交契约，不能塞进同步效果回调。

结果通过有限的标题、文本行、差异、候选和回执呈现。面板不按具体 capability code 解析业务结果。草稿摘要来自真实前后差异，区分直接修改与联动并注明未保存；配置摘要先显示错误与警告，再显示影响，截断明确标记。后续模型总结失败不能抹去已发生效果。

## 字段、候选与上下文投影

静态 Web DSL 的 `assistantPolicy` 与动态字段 `props.assistantPolicy` 编译为同一 resolved 契约：

| 策略 | 字段描述 | 当前值与选项值 | 修改草稿 |
| --- | --- | --- | --- |
| `HIDDEN` | 不提供 | 不提供 | 不允许 |
| `DESCRIBE` | 提供名称、类型、约束 | 不提供 | 不允许 |
| `READ` | 提供 | 有界且受保护的投影 | 不允许 |
| `READ_WRITE` | 提供 | 有界且受保护的投影 | 仍受页面可写性、标准类型和业务限制约束 |

普通字段默认 `READ_WRITE`；密码强制 `HIDDEN`；模型声明存储或输出保护的字段上限为 `DESCRIBE`。列表只投影当前显示列，表单和明细遵循同一策略。凭据、密文、隐藏字段及组件内部状态不进入模型；列表查询中的引用路径值当前保守关闭；引用标题和 `subtitle` 按各自授权契约投影，不开放任意路径值、原始记录或 projection map。

该策略约束平台自动组织的上下文，不是后端授权或任意文本防泄漏网关。用户主动输入的文本不按字段名猜测重写。人工确认内容与模型安全摘要独立，不能从人工卡片标题、正文或详情自动回填模型上下文。

字段类型、必填、长度、精度与选项来自标准表单事实。批量补丁先完整校验，再一次提交，继续触发引用依赖清理、公式和脏状态；拒绝未知、重复、只读或未支持字段。字符容量按 Unicode 字符计数；金额及长整型沿用正式字符串 wire 协议，不把 JavaScript 浮点转换作为保存契约。客户端检查不能替代服务端精度、唯一性、引用与业务校验。

引用通过正式候选提供者读取，唯一精确匹配才可按名称确定性回填；同名、截断或不可用候选不能猜选。检索不是选择授权；搜索结果向模型只交付标题、可选说明和本次检索的不透明 `selectionKey`，选择后走标准草稿管线并应用授权回填。候选键绑定字段、当前上下文及本次检索，换行、换字段、换范围或再次检索使旧键失效。模型不得直接提交内部记录 ID。

候选 `subtitle` 由来源字段声明，静态/动态复用公共引用读取，说明与选择投影及持久化回填分离。受保护字段、不可见关联、拒绝读取或非标量结果不披露说明，文本最多 500 字符。下拉、弹窗、回显和助手共用此事实；详细边界见[模块引用与前端组件治理](topics/page/REFERENCE_COMPONENT_GOVERNANCE.md)。

远端字典候选当前由表单组件持有，助手只读取内联选项。这是共享表单事实的缺口，不能用助手专用缓存或请求补偿；是否进入本轮由主干所需字段决定。

## 已接入的标准页面范围

| 范围 | 当前契约与限制 |
| --- | --- |
| 菜单与范围 | 仅从正式可见目录查找、打开；租户/导航候选有界，唯一名称或一次性候选键选择；不构造任意 route |
| 列表与树查询 | 复用标准查询端口、声明字段/操作符及排序；`query.apply-standard` 为受限 AND 条件；LIKE 明确 SQL 模式语义，字面快捷搜索由平台转义 |
| 主记录新建与编辑 | 仅在权限、页面、租户、导航范围和会话就绪时开放；编辑接受当前正常列表/详情记录并核实更新动作；回收站不开放 |
| 导航表单 | `navigator.start-create` 打开来源模块标准编辑器；助手共享字段/引用/公式，用户在该编辑器保存；不复用主记录保存提议 |
| 主表草稿 | `form.describe`、批量普通字段补丁、单值引用候选与选择；JSON 结构、文件和未接入的选择语义不开放写入 |
| 聚合明细 | 一层可编辑聚合的读取/分页、选行、增删和字段/单值引用操作；只修改父草稿，通过标准父保存提交整单 |
| 保存审阅 | `form.prepare-save` 为支持的普通业务主记录产生人工确认；`platform`、`iam` 管理域及切换子资源的树页面不开放该通用助手保存 |

当前支持的单值树引用复用来源的标准分页候选、依赖绑定和授权；需要额外多轴导航或多值选择的情况仍保持限制。目标模块查询事实不足时由目标公共查询能力补齐，不为助手造旁路。

导航编辑器在加载中和加载失败时仍保留来源归属，未就绪不开放写能力；主表、导航、局部编辑与关联编辑遵守会话互斥。已有编辑会话或操作进行中不能另开草稿或切换范围。主记录新建/编辑在准备与实际提交时都复核范围，拒绝异步旧结果覆盖新会话。

明细的读取、修改与从零建设关系分别描述。未挂载或不可编辑明细不能据此认定业务不存在；完整子集合不可用时不开放写入。人工改行使旧确认失效，后台候选标题加载不算用户交互。确认审阅覆盖实际整单与引用名称，不只展示主字段。独立关系写入、多层嵌套、批量粘贴及回收站恢复未开放助手命令。

## 共同基础的执行与消息契约

`AiChatMessage` 表达文本、助手工具调用与关联调用 ID 的结果，`AiTurnRequest` 校验配对并拒绝缺失、重复或孤立结果；纯文本请求不接受工具消息。供应商 adapter 用稳定能力身份映射工具名，目录重排或历史能力退出不能改变身份。后端组织原生工具消息，最新页面事实与历史结果分开；仅已执行调用形成工具对，未执行的同批调用不伪造回执。

能力目录与完整工具定义分离：当前可用能力不超过 12 项时直接交付全部定义；超过时交付名称、说明目录，使用 `assistant.load-capabilities` 按需选择最多 8 项完整定义。近期已使用能力可复用定义选择，但每轮都从当前权限过滤后的目录重新生成 Schema，不缓存权限、候选或可执行命令。发现能力仅返回定义选择，不能执行被选择工具。定义选择允许切回先前已加载但被移出的能力，重复选择仍受无进展与总步数边界约束。服务端领域指引按当前有界能力代码目录选取固定文本，不随完整 Schema 的加载集合消失，也不采纳目录描述作为指令。只读回合的目录与加载器均排除写能力；总结回合不声明任何工具。元数据关系列表通过显式分页读取，不在每轮工作区事实中重复附带。

供应商报告的输入、输出和总 token 经回合结果及运行诊断传递；流式请求显式请求 usage。缺失计数保持未知，失败请求不能按零用量补齐。字符/字节只用于上下文大小边界，不能作为实测 token。对比应同时记录任务完成、模型调用、人工介入及用量覆盖，不能仅用单轮输入下降证明整体效率。

同一有效基线内保留有界近期成功读取，按能力与输入去重；被预算移出的结果可再次索取并复用，不将缓存命中一律当作无进展。页面或配置基线变化清理旧读取，效果保留独立精简回执。该缓存不跨用户轮次持久化，不提供持久化幂等或恢复执行权。

当前运行器默认 8 轮模型决策，有新事实/效果可延长至绝对上限 12 轮，每轮最多 8 次工具调用；连续两轮无进展或全部重复且证据已在上下文中时停止。达到边界至多追加一次无工具总结，不能执行操作或生成确认。总结失败保留已核实事实，取消与作用域失效仍拒绝迟到输出。不得以盲目提高预算治理反复查询。

能力目录当前最多 64 项，上下文和工具结果各有受控体积边界。详细目录按需分页，截断必须显式，正式预检消费完整权威数据。字符预算用于载荷保护，不冒充实际 token。稳定平台范式指导由后端按 Surface 与能力组合提供，不包含演示业务步骤，也不另维护一份能力支持矩阵。

错误区分可修正参数、候选不唯一/过期、前置条件、权限/业务拒绝、暂不可用与未知结果。能力 adapter 只返回受控原因，未知内部异常不暴露原文。循环去重只保护当前前端调用，不替代服务端事务幂等。

会话控制器负责历史、选择、运行、取消与反馈；registry 负责令牌与效果提交；runtime 负责有界模型回合；面板负责显示与用户操作。新增能力贡献自己的受控结果呈现，不修改通用面板或主循环中的业务分支。

## 人工确认与持久化结果

### 统一纪律

只读发现与用户已要求的可逆页面/草稿操作可由受控能力执行。持久化能力只有在已接入正式提交和结果契约时开放；模型工具只准备提议，不持有确认句柄。删除、批量写入、自动授权和审批不由普通保存契约扩张获得。

可信提议绑定对象、参数快照、身份、执行范围、候选/页面基线、有效期和结果核实方式。用户点击确认直接提交已审阅内容，不再让模型生成参数；聊天中的肯定词、模型的 selection 选项或范围确认不能代替执行凭据。解释性追问不必使有效提议失效，实际候选或作用域变化必须失效。

确认状态区分待确认、执行、核实、成功、明确拒绝、未知、取消和过期。双击共享同一次提交；明确拒绝可由用户显式重试原提议，重新检查有效性；传输中断或核实失败保持未知，未找到回执不授予自动重试权。取消未提交提议保留草稿，关闭面板或模型失败不撤销事务。

人工呈现与模型摘要分开。模型摘要仅来自能力显式的安全投影，缺省使用无业务值说明，不读取人工卡片补全。确认后的续接只允许重新读取事实及准备下一候选，不能自动执行下一次写入，不恢复旧确认授权。

### 当前写入保证

| 写入类型 | 已有机制 | 必须保留的限制 |
| --- | --- | --- |
| 普通标准记录 insert/update | `X-Muyun-Save-Request`、事务内回执、内容与身份约束、`save-receipts/{requestId}` 授权查询 | 通用助手保存限已接入模块；覆盖标准保存的自定义入口须显式接入，普通无请求身份保存不自动幂等 |
| 元数据字段 change-set | 不可变候选、权威 preview、指纹/版本、元数据及 DDL 事务、激活反馈 | 不具备与普通保存相同的通用持久请求回执；未知时不因刷新或字段同名推定原提交结果 |
| 直接子表创建 | 原请求身份、元数据/父关系/表与回执同事务、原请求查询 | 创建成功不证明字段/规则/页面已完成，激活另行核实 |
| 规则应用 | 完整规则预检、配置基线、事务应用及激活 | 请求不确定时核实当前配置并保持原操作未知，不自动重新应用 |
| 标准页面发布 | 共享发布命令、正式修订与发布校验、原修订/组合结果核实 | 以对应发布命令的精确结果为准，不凭当前页面相似判断本次成功；准备后续草稿失败不抹去发布事实 |
| 建设方案及历史建设节点 | 各自版本、请求身份、领域回执与所有权 | 方案确认不等于配置发布，历史节点不成为新标准治理的前置条件 |

普通保存回执与业务写入在同一事务中形成，相同身份并发串行化；相同内容返回原结果的当前授权投影，不重复生命周期，不同内容拒绝。回执查询重新检查记录访问权限，权限拒绝不证明写入未发生。恢复页面仅在原草稿仍未变化时进行。

标准记录保存、直接子表创建和标准页面修订发布在发送写请求前将最小查询引用存入个人会话。刷新后仅恢复“查询操作结果”，不恢复确认、写入参数或自动续接；查询前后核对原身份与业务范围，并由当前服务端权限重新授权。标准记录查询引用包含必要的租户、菜单、导航记录标识或 `{kind,key}` 选择引用；这些只读范围标识仍须由服务端重新解析与授权，不保存任意请求头或业务写入内容。记录/子表按原请求读取回执，页面按修订身份及模板、版本、UI 内容摘要匹配已发布或归档的不可变修订；后续发布不抹去原发布事实。归档修订禁止改写内容与伪造初始归档状态。引用不进入模型历史，保存引用失败时不发送该次写入。

字段/规则等尚无精确结果入口时只恢复未决提示，读取现行配置不能证明原操作已提交；组合新建字段/明细的页面保存仍使用活跃命令的组合回执，不持久化其完整命令。配置草稿跨刷新恢复仍为独立延期能力。

## 配置协作接入

### 元数据候选协作与人工生效

元数据编辑会话由工作区按模块持有，页面与助手共用候选；选模块、打开治理页、关闭后接续和放弃整份候选复用标准入口。不要求先保存建设方案；未结束候选禁止换节点或刷新基线。身份变化销毁会话，刷新浏览器不恢复本地候选或授权。

普通字段、引用、字典与批量新增沿标准编辑逻辑。多字段方案每批 1–12 项，同一节点完整解析目录、名称与列冲突后一次加入；任一失败不留部分候选。修改普通字段保留未指定的人工内容，引用/字典绑定修订能力按正式编辑器现有范围开放。差异由当前可见编辑与持久基线计算，未保留到树节点的修改也纳入预检，新增字段改名不能产生重复 ADD。

页面与对话共用 change-set 提交准备器，冻结完整候选与权威影响。预检与确认返回后再次核对模块、关系、加载基线和候选；字段、节点或范围变化使旧确认失效。指纹不交给模型，正式 apply 不注册为模型工具。提交后读取/激活反馈失败保留已提交事实，不重放写入。

主实体候选通过标准编辑器保存；模块保存与主实体建立是独立操作。直接子表候选复用正式创建入口和原请求结果查询；创建完成后读取真实关系继续配置，不凭同名节点猜测结果。多层关系未开放。

### 规则候选

规则会话按模块隔离，页面与助手读取同一字段/函数目录，修订同一规则集，复用预检、样例试算与应用。单条候选修订保留其他手工规则和只读规则；人工编辑器正在操作时不允许助手并发覆盖。确认覆盖整组当前更改，模块/候选/基线变化使旧确认失效。

规则应用区分写前拒绝、已提交后的界面同步失败和写入结果未知。收到成功应用响应后，即使界面控制读取失败或编辑上下文变化，也保留已提交结论；旧基线停止编辑与重提，重新加载成功后才恢复。写前预检失败不会标记为未知；写请求响应丢失仍保持未知，不自动重新应用。

计算、保存校验、界面控制分别遵守[公式专题](topics/formula/OVERVIEW.md)。支持已有直接子表逐行计算与主表汇总，试算使用类型化主表和明细样例；涉及真实引用数据须明确试算租户。服务端保存重新计算，试算不写业务数据、规则应用不回算历史记录。浏览器明细即时计算尚未开放，不伪造实时结果。关系结构由元数据治理建立，规则工具不能越界创建。

### 受模板约束的页面候选协作

页面编排读取正式模板、字段与关系目录，助手直接适配当前标准工作区候选。指定区域根字段按完整顺序替换，未指定区域/属性及已有分组保留；平台只读不可降级，快速查询只能使用合法字段。主表字段不能冒充子字段，省略关系布局保持不变，空布局只移除显示，不删元数据或记录。

当前每区域最多 40 个根字段，直接明细布局最多 16 组、每组 1–40 个字段。分组、动作与查询统计不由该修订能力改写；模板切换、布局拆分和新建数据项仍由正式治理入口处理。属性编辑、冲突或待创建字段未完成时暂停助手修订。所有解析成功才一次修改候选，不提交任意 UI JSON、脚本或组件类型。

### 页面编排的确认与生效衔接

导航通过正式模块身份定位治理页，等待编辑数据就绪。准备编辑只创建/恢复草稿，不发布；发布确认覆盖同一候选差异，页面按钮与对话共用预检及发布命令。字段生效后才进入页面可用目录，字段保存与页面发布是两个提交点，后者失败不撤销前者。

返回治理页刷新字段与查询资格时保留本地编排；加载失败暂停修订和保存，不能以旧目录提交。候选、目标或修订变化使旧确认失效；断流只核实原发布，后续草稿准备失败不抹去已发布事实。

页面发布在事务提交后产生模块变更事实，由 Web adapter 经已有实时通道通知。空闲业务页重建会话，编辑或执行期间保留输入并提示，结束后加载新配置；只广播失效事实，在线尽力交付，不承诺离线补发。完整加载以已发布服务端配置为准。

标准页面候选由工作区按身份与模块持有，`configuration.select-page-module` 可在未打开组件时读取和准备同一候选；打开或关闭可视编辑不替换候选。身份变化销毁会话，页面卸载仅解除呈现绑定。公共 `OperationProposal` 和确认状态机归平台，助手摘要与续接由 adapter 装饰。

`construction.prepare-page` 及其服务端页面生成/发布分支已退役；旧 PAGE 命令明确拒绝，历史回执查询保留。纯对话与可视入口均通过标准页面会话准备、预检和确认发布，不依赖建设计划。查看目录和打开编辑器不要求先建立协作任务；协作偏好只约束候选编辑方式，不作为只读访问的前置流程。

## 建设目标、进度与历史

### 建设方案的边界

方案归 application 领域，按认证用户与登录租户归属；页面执行租户不改变所有权。内容表达目标、范围、对象、关系、规则、问题、假设和验收例子，不承载可执行 schema 或模型声明的完成状态。原请求、预期版本及内容一致才可复用确认回执；无变化不造新版本，恢复不能覆盖有修改的候选。

一个建设对话最多绑定一个目标；同一目标的模块拆分不算换目标。新对话可发现现有模块并读取现行配置，不依赖原方案或建设者。方案未落地部分可修订，已交付对象及其绑定需求按历史验收语义冻结；后续业务改进进入标准治理。当前 `NOT_STARTED`、`INITIALIZED`、`PARTIALLY_DELIVERED`、`DELIVERED` 表达建设历史，不代替当前可用性。

未确认修改只属于当前工作区。未知方案确认保留原方案/请求身份、内容和版本供核实，不能换参数后重试；允许重新审阅原操作不意味着恢复旧授权。普通字段和页面配置是否允许执行由标准治理决定，历史方案全局版本的保守重检不得被自然语言相似度绕过。

### 多模块发现与单值引用建设

发现使用正式模块目录和标准字段契约，模型不猜内部 ID。动态引用目标须具备标准名称字段，静态目标须有引用能力；不可引用不等于对象不存在。引用只建立来源关系，不接管目标字段、页面、数据或权限。当前建设映射按真实直接子关系及保存计算核对证据，不证明自然语言表达式的业务含义正确。

新应用、模块沿标准管理页分别建立；主实体、字段、规则、页面和菜单各有独立治理入口。历史 `construction.initialization-status` 只核实已有回执与激活，不重新提供合并创建。`construction.describe-fields` 读取标准 `MetadataField` 与当前关系/规则，不将新增工具参数当作完整读取模型。所有新字段候选进入共享元数据会话，不能恢复独立字段发布实现。

### 建设进度与普通用户反馈

进度核实当前字段/约束/引用/子关系/计算、运行态、正式页面和用户可见菜单，标准治理形成的配置同样有效，无需补造建设回执。任务返回证据、条件和可选事项，不指定固定业务顺序；暂缓事项不得因自动续办重新启动。

`FIELD` 只证明字段存在，不能证明精度、价格快照或完整业务规则；`CHILD`、`REFERENCE`、`CALCULATION` 分别有结构性证据，但仍需试算和业务验证。`MANUAL_RESPONSIBILITY` 表达人承担业务步骤，不能冒充自动化功能；未决问题与已约定人工责任分开。

进度明确 `businessDataStatus=NOT_QUERIED`，配置齐备不能推定有/无业务记录。字段已满足时不重复创建；基线变化先查现状，不默认重建或发布。历史验收不证明当前基线，当前发布也不证明普通租户用户已获权限。

`construction.prepare-entry` 仅创建系统配置工作台入口，不授权租户或角色。`construction.prepare-acceptance` 记录用户基于当时需求和配置的判断，必须先实际验证标准保存、查询和详情，不能当作自动验收。目标用户可用性与交付门槛以统一方案为准。

## 会话连续性与历史记录

个人聊天按认证用户及认证租户持久化，页面选择的执行租户不切分聊天与建设目标。同身份换执行范围保留展示记录、方案绑定和协作偏好，清除旧模型观察、读取缓存、待续请求及执行授权；身份变化清理当前会话并隔离迟到结果。只有经过令牌校验的助手跨页面跳转可在重读目标事实后继续本轮明确请求，同页租户切换或人工换范围不能借此自动续接。

历史恢复仅恢复展示、有界模型历史及已保存方案关联；模型历史仅在执行范围一致时恢复。历史选择与确认成为不可执行文本，本地未保存候选、调用令牌、确认句柄和权限均不恢复。恢复后“继续处理/核实”先按只读策略核对当前业务，目录与执行端同时限制写入；取消不自动续做，正常后续请求不永久继承只读限制。

首次模型请求前保存用户输入，回合结束与确认状态变化后保存记录；失败保留内容供重试，版本冲突不覆盖，允许另存会话。关联方案读取失败不阻断聊天保存，但未读取成功不能修改该方案；不可访问时保留关联并如实提示，不自动另造替代方案。已建业务仍可直接治理。

当前每会话最多 1000 条展示消息、正文最多 512000 字符，达到限制明确拒绝保存；送给模型的历史仍有 12 条、单条 4000 字符、总计 16000 字符的边界。保存全部展示不代表无限记忆。目标与内部续接指令分离，自动回执不能伪装成用户授权；长期摘要和持久未保存草稿未交付。

标准记录、直接子表与标准页面发布已有最小查询引用恢复；字段和规则等尚无精确结果入口的限制见前述写入保证。“聊天已恢复”不能作为“执行结果已恢复”的证据。

## 交互、模型与诊断

澄清交互与执行确认分开。受控 `selection` 提供 2–8 个不透明选项，支持自由补充；选择交回模型澄清，不触发持久写入。同一模型响应混合选择与工具调用时只展示有效单个选择，不执行调用或展示可能误报成功的说明。非法或多个选择拒绝，输入恢复可用。

消息以受限 Markdown 呈现，不接受原始 HTML、危险链接或远程 Markdown 图片；用户输入与状态按纯文本。运行、取消、拒绝提议和关闭对话各自表达；状态提示不进模型历史。面板继续与业务区分屏，业务抽屉使用业务区边界；窄屏切换不销毁草稿，不引入模块专用避让逻辑。

模型连接、凭据、容量、并发及供应商错误的权威契约见[模型连接配置](topics/configuration/AI_MODEL_INTEGRATION.md)。网关保留文本及结构化、流式及非流式协议；助手不直连供应商。请求与响应体读取均有期限，并限制响应体、事件和参数大小，半截文本不等于成功。

输出预算与上下文容量由当前模型配置决定，未知容量不等于无限；输入容量采用保守估算，不是精确 tokenizer，业务层负责必要事实与分页，网关不截断业务内容。服务商 token 缺失时为未知，日志字符数不伪装成费用指标。

HTTP 成功响应内的结构化供应商错误只记录实际状态、允许列表中的 code/type、合法声明状态和结构类别，不记录 message。明确 `upstream_unavailable` 归为服务暂不可用，其他原因不按自然语言、type 或声明状态猜测。适配器的有限连接重试仅按模型专题约定发生在成功响应交付前，不重放业务工具、已收到的错误事件或整个助手回合。

诊断复用现有日志与观察端口，只记录 trace、数量、能力编码、效果/终止类别、耗时及可得用量，不默认记录用户正文、业务参数或供应商内容。观察失败不影响执行。模型语言偏差、反复读取和理解误差以真实场景归因；优先删重复描述和无效发现，不为可自然澄清的问题添加业务词典、语义门禁或专用流程。

## 验证与扩展纪律

主干的实现进度与 P/A/D 门槛只在统一方案维护。确定性测试锁住授权、字段保护、草稿互斥、候选失效、参数一致性、工具配对、效果后失败、确认与未知结果；数据库/HTTP 测试验证事务和真实配置/业务路径；真实模型与非技术用户演练验证目标完成及交接，三者不能互相替代。

新增能力先确定权威事实和正式入口，再做窄 adapter；新增特殊业务无需改主循环。Capability、Context、平台指导分别承担执行、观察和理解辅助，Skill 只在稳定复用出现时按需提炼，不能成为权限或脚本执行渠道。

后台持续执行、外部协议、通用服务端工具平台、长期自动记忆、多智能体、任意布局或脚本、自动授权、跨模块事务与万能回滚均不在本轮范围。工作流办理权、审批和任务完成判定继续归所属领域；后续进入这些目标时再按真实场景设计，不从聊天持久化推导后台执行能力。
