# 身份组织对象选择专项治理

状态：阶段一至阶段三的首批闭环已交付；后续按来源业务迁移。本文规定用户、职员、机构、部门和租户选择的目标、边界与阶段验收。当前已交付日志操作用户的事件时范围导航、固定范围机构部门懒树、角色归属范围导航和职员绑定账号候选；用户、职员封装已共享候选面板与类型契约。

## 问题与目标

本专题继续规定身份组织对象和历史日志的候选资格、范围及领域交互。跨业务的引用数据内核、通用组件与多宿主接入由 [模块引用与前端组件专项治理](topics/page/REFERENCE_COMPONENT_GOVERNANCE.md) 承接；本专题既有交付不等同于通用引用组件已完成，领域包装后续按该专项收敛公共实现。

标准列表查询、业务表单和授权等场景需要选择身份组织对象。现有记录选择器、引用解析、树导航与列表能力已有基础，但候选来源、租户范围和交互方式尚未形成完整的统一交付。

代表性问题是：平台管理员可无租户查看跨租户日志，操作用户选择却调用要求租户上下文的用户引用接口，导致候选加载失败。仅切换为 REFERENCE 权限入口不能解决业务范围不匹配。

治理目标：

1. 大量用户使用服务端搜索、分页和导航选择，支持单选、多选及已选回显。
2. 机构和部门按当前业务的有效范围自动选择下拉树或导航弹窗，简单场景保持轻量。
3. 前端统一交互，服务端负责候选资格、授权范围、字段投影和提交校验；业务不重复实现租户判断。
4. 静态声明和动态元数据进入来源无关的已编译选择契约，复用现有平台能力。
5. 三个日志作为首批验收场景，随后迁移其他用户选择入口，回收重复实现。

## 对象与业务边界

| 对象 | 选择结果    | 说明                                                           |
| ---- | ----------- | -------------------------------------------------------------- |
| 用户 | 用户账号 ID | 登录主体，可没有职员绑定、机构或部门；包含受场景允许的平台账号 |
| 职员 | 职员 ID     | 人员主数据，不以是否拥有登录账号作为存在条件                   |
| 机构 | 机构 ID     | 租户内组织主体，可形成层级                                     |
| 部门 | 部门 ID     | 归属一个机构，可形成机构内部门树                               |
| 租户 | 租户 ID     | 独立选择对象，也是跨租户场景的导航范围                         |

对外提供语义明确的用户、职员、机构、部门和租户选择封装，内部共享选择面板与状态管理。不通过一个包含大量互相冲突开关的万能组件向业务暴露底层细节。

选择父机构或父部门默认只选择该节点，不自动选中子节点或展开为全部人员。“选择对象”与“选择该对象及下级范围”是不同业务契约；后者必须显式表达范围规则，不隐藏在树勾选联动中。本专项不建设任意对象混选、授权范围表达式或流程参与人规则引擎。

## 默认交互

### 按有效范围选择展示方式

| 选择对象   | 当前业务有效范围 | 默认交互                                         |
| ---------- | ---------------- | ------------------------------------------------ |
| 部门       | 固定一个机构     | 下拉部门树                                       |
| 部门       | 允许跨机构       | 弹窗：机构导航与部门树；需要跨租户时追加租户导航 |
| 机构       | 固定一个租户     | 下拉机构树                                       |
| 机构       | 允许跨租户       | 弹窗：租户导航与机构树                           |
| 用户、职员 | 单一或跨范围     | 文本框入口与选择弹窗，服务端搜索分页             |
| 租户       | 授权租户范围     | 搜索与分页选择，复用共同面板能力                 |

判断依据是服务端解析的业务有效范围，不是前端判断管理员身份，也不是某次搜索恰好只返回一个结果。系统管理员编辑已固定租户的业务字段时，同样使用该租户内的下拉机构树。

单一范围内的树也可能很大，应支持按需加载和服务端搜索，并提供“展开选择”入口，在弹窗中延续相同范围与选择状态；不得为下拉展示一次加载整棵大型树。

### 用户与职员选择

入口外观为文本框，支持关键词输入，右侧有搜索按钮。按 Enter 或点击搜索按钮打开弹窗并带入关键词；输入文字只是搜索草稿，选中记录后才形成有效 ID。

弹窗复用标准列表导航：按需要展示租户、机构、部门导航，主区域展示分页候选列表。允许直接在授权范围内搜索，不强制逐级选完导航。无机构、无部门或平台账号须保留可达的搜索路径。

单选显示对象名称与必要的身份摘要；多选显示少量标签和已选数量，弹窗提供完整已选区。跨页、搜索及导航切换保留仍在有效业务范围内的已选项；不得将切换浏览导航误当作修改业务约束。取消关闭不改变外部值，确认后一次性交付选择结果。

全选默认仅作用于当前页的可选记录，不隐含选中全部查询结果；首期不交付“全量结果选择”。多选上限由业务契约限制，客户端提示与服务端校验一致。

### 机构与部门选择

固定范围时，树本身就是选择主体，不增加内容重复的列表。跨范围弹窗中，上级对象用于导航，目标对象树用于选择。按名称或编码搜索时返回可理解的路径摘要，同名对象以机构路径或租户信息区分。

租户内用户包括租户管理员，在固定租户范围下隐藏租户导航。平台管理员有跨租户选择资格时展示租户导航，可在契约允许时选择“全部授权范围”。未来若引入明确的多租户授权，导航仅展示授权集合，不因支持该交互而新增跨租户权限模型。

表单所属机构改变属于业务约束变化，应使旧候选请求失效，并清除或重新校验已选部门。与此不同，弹窗内为寻找其他部门而切换机构导航，不自动删除已选部门；是否允许跨机构、多租户组合由后端契约决定。

### 状态与错误

加载中、空候选、无选择权限、缺少必需上级条件和加载失败分别表达。缺少业务必填范围时展示操作引导，不发出注定失败的请求；可跨范围场景不得强迫填写一个虚构租户。

输入区域使用紧凑错误提示与重试，弹窗内使用局部错误态，避免告警撑坏查询栏。搜索和导航切换使过期响应失效。已选对象停用、删除或不可用时，不静默丢失原值；只回显当前允许披露的摘要或明确的不可用状态，是否允许保留与提交由业务决定。

## 服务端候选契约

### 责任划分

有效候选范围是当前身份授权、来源业务规则与已校验上下文的交集。租户、机构、部门导航和关键词只能继续收窄该范围，客户端不得通过传入 ID 或展示参数扩大范围。

普通引用使用来源模块和来源字段定位已有引用声明；日志等专用场景通过服务端注册的业务候选适配接入共同交付契约。组件不能自行拼接目标模块 CRUD 请求，也不能由客户端选择任意候选提供者获得访问资格。

候选资格必须绑定具体用途。普通表单引用沿用引用权限和来源字段约束；日志筛选依附日志查询权限及管理范围，不额外要求用户管理菜单或普通查询权限。候选查询不等于授予目标对象的管理权限。

### 共同交付能力

| 能力     | 约束                                                                                   |
| -------- | -------------------------------------------------------------------------------------- |
| 选择描述 | 返回对象类型、单多选与数量限制、有效范围、允许的导航、业务依赖和受控展示事实           |
| 候选搜索 | 服务端分页，搜索字段白名单，限制页大小，稳定排序；不在浏览器过滤前若干条冒充完整搜索   |
| 树读取   | 在相同范围内读取子节点与搜索路径；路径节点是否可展示、是否可选择分别判断               |
| 批量回显 | 按 ID 有界解析，仅返回允许披露的标题、路径与状态，不能成为绕过授权的读取入口           |
| 选择校验 | 确认或业务提交时重新校验对象资格、上级归属、数量与组合限制，处理选择期间权限和状态变化 |

描述、导航、候选、回显与最终业务校验使用同一范围规则。缓存必须区分来源业务、身份授权和范围，不能跨范围复用候选。具体接口路径、DTO 和扩展点在实施时结合现有引用交付确定，不在本专项预建第二套通用查询协议。

前端可注入单多选、外部值和来源业务上下文；有效限制以服务端契约为准。持久化仍保存字段契约规定的 ID 或 ID 集合，展示摘要不作为身份或授权依据。

## 三类日志的候选语义

登录、活动与异常日志共用用户选择交互，通过各自日志读取权限解析平台、租户或组织管理范围。候选从授权可见日志中的操作人产生，再复用身份摘要解析能力补充允许展示的账号、姓名和租户信息。该策略仅用于历史日志检索，不推广为普通业务分配人员的候选规则。

1. 平台管理员无租户时可以检索其可见范围中的平台和租户操作人，不补任意租户 ID，也不放宽普通用户管理接口的租户保护。
2. 历史人员停用、删除或调岗不能改变已有日志的授权事实。组织可见性仍依据事件记录的历史机构快照，不以人员当前机构替代。
3. 新写入的运行时日志保存事件时部门快照，部门导航仅根据该快照过滤，不以人员当前部门替代。旧日志及当前登录审计写入链路尚无部门快照时不归入任何部门，仍可经租户、机构、关键词和用户 ID 检索。
4. 缺失身份摘要时保留已授权日志中的操作人 ID 作为兜底，避免历史记录失去检索入口。
5. 登录失败可能没有确认用户，保留独立的登录账号文本条件，不能强行映射为用户引用。
6. 候选需面向授权结果集进行有界查询或专用索引读取，不从日志当前页提取候选，也不全量扫描后在内存去重。时间等条件是否联动候选须明确，不能使已选值因候选刷新而静默消失。

## 复用与实现边界

复用现有来源字段引用解析、引用读投影、机构部门树、列表分页、导航上下文绑定及单租户导航隐藏规则。共同面板拥有搜索、选择草稿、分页、已选区和响应失效管理；对象封装拥有用户、职员、机构、部门各自的展示语义。

IAM 领域负责身份组织关系和相关候选规则，日志领域负责历史事件的可见范围与候选来源，Web 层只做协议与投影适配。普通业务通过轻量声明接入，动态配置编译到相同描述；请求期不重新解释页面配置。

统一用户选择入口不等于把所有引用替换为身份组织选择器。字典、小型普通记录引用和其他领域对象不在本次迁移范围内；不新增 Gradle 子项目，不复制用户管理整页，也不为每个业务重新开发候选弹窗。

| 一：契约与共享用户选择闭环 | 已交付           | 日志候选从授权事件流读取并完成账号快照、搜索、分页和回显；共享用户选择弹窗支持单多选与单选双击完成；三个日志接入                       | 无租户平台管理员正常选操作用户；仅有日志业务权限的身份可用；候选与事件范围一致；搜索分页与历史回显正确       |
| 二：机构部门自适应选择     | 已交付代表性范围 | 来源字段 `TREE_CHILDREN`、固定机构内部门和固定租户内机构的下拉加展开选择；角色范围的专用跨租户机构导航                                 | 上级依赖缺失不请求；伪造父节点无法扩大范围；角色范围只消费服务端描述的导航键；父子选择语义明确               |
| 三：入口迁移与收口         | 首批已交付       | 职员绑定已有账号迁移到专用候选；用户、职员共享候选面板与独立语义包装；三个日志在共享用户面板接入受事件时范围约束的租户、机构、部门导航 | 表单、常驻查询、高级查询及业务授权入口遵守各自候选资格；不存在绕回普通 CRUD 的兜底路径；用户与职员 ID 不混用 |

各阶段先建立代表性完整业务闭环，再扩大迁移。后续预留任意结果集批量选择、混合对象选择、流程选人规则和新的多租户授权模型；这些不属于本专项首轮实现目标。

### 阶段一实现说明

三个日志分别提供与其查询权限绑定的操作用户候选入口。候选不再调用普通 `iam.user` 引用查询，而是从当前身份可读取的对应日志事实中去重、搜索和分页；返回的用户账号 ID 可直接作为日志 `operatorId` 条件。新写入事件保存操作账号快照，历史事件缺失快照时仍可通过受控身份投影或用户 ID 回显。旧事件的账号模糊搜索只覆盖已保存快照，迁移前数据可按用户 ID 检索。

前端通过 `ReferencePicker` 交付搜索、批量回显、分页、单选双击完成、多选草稿、取消和确认；`UserPicker` 保留为身份领域包装，不拼接 IAM CRUD 路径。日志宿主直接注入通用引用配置，身份适配负责账号列及租户、机构、部门三列导航：任意层级的选择立刻收窄右侧人员页，不强迫逐级完成；跨租户时才显示租户列。浏览导航保留未确认的多选草稿，来源业务依赖变化则重置并重验。

### 阶段一补充：日志操作用户的事件时导航

三个日志候选端点在既有搜索、分页和回显字段外，可接收独立的 `tenantId`、`organizationId`、`departmentId` 收窄参数，并返回同一授权日志事实导出的导航项。服务端先用日志读取权限收敛事件集，再校验每一个导航 ID 的可见性和父子归属；伪造范围直接拒绝。导航标题由 IAM 的能力级查找补齐，但 IAM 不参与候选范围或授权判定。

运行时活动、访问与请求错误日志保存操作人的机构、部门快照，部门移动不会改写历史导航。登录审计继续保留其已有机构快照；在其写入链路具备部门快照前，不展示为某一历史部门。

### 阶段二首个交付：固定范围的机构、部门展开选择

来源字段引用解析新增 `TREE_CHILDREN` 模式：它在同一候选规则、`REFERENCE` 数据范围和来源字段依赖下分页读取一个父节点的直接子节点；请求的父节点也先在同一范围中验证，不能以树展开作为扩大候选范围的通道。关键词搜索继续使用既有 `QUERY`，已选回显继续使用 `TRANSLATE`，三者共享来源上下文和表单值。

职员所属部门在所属机构已经确定时保留既有的紧凑下拉树，并额外提供“展开选择”入口，以同一来源字段契约按需读取部门树并在确认后回填原字段；机构尚未确定时入口禁用并给出引导，且不发候选请求。菜单方案的适用机构在租户已经确定时遵循同一规则。`TREE_CHILDREN` 返回当前候选范围内的子节点可见性，前端据此不向叶子节点发起无效展开请求。该交付只解决固定范围下大树的浏览成本，不把常用下拉交互替换为弹窗。

普通字段的跨机构部门、跨租户机构导航仍需由该字段的服务端选择描述明确允许后才可交付，不能通过客户端传入机构或租户 ID 直接开启。

### 阶段二第二个交付：角色归属范围的跨租户机构导航

角色归属范围不是普通业务字段引用，它继续使用页面选择上下文保存 `platform`、`tenant:<id>` 和 `organization:<id>` 选择键，并由角色领域在列表、创建和更新时作最终解析与校验。角色模块新增专用选择描述和候选门面：描述只下发当前身份可进入的直接范围与导航层级；候选请求只接收门面下发的导航键、层级、关键词、父节点和分页，服务端重新验证角色查询动作上下文、租户有效性、身份可见性及机构归属。

系统身份可从租户导航按需展开机构树；租户身份只收到当前租户范围。前端不再根据 `currentUser.system` 决定是否读取租户，也不直接调用租户和机构 CRUD 接口。角色候选树与普通来源字段引用保持两条语义独立的链路，不能据此放宽普通引用的跨租户限制。

### 阶段三首个交付：职员绑定已有账号

职员账号绑定是记录级动作，不复用用户管理页的普通选择器查询。候选接口先校验目标职员及其动作授权，再以该职员所属租户为边界，只返回启用且尚未绑定其他职员的账号；关键词、分页和按 ID 回显均在这一候选范围内执行。已绑定排除在服务端数据查询中完成，不能依赖浏览器先读取一页账号后自行过滤。

前端 `UserPicker` 与 `EmployeePicker` 组合平台 `ReferencePicker`，分别暴露用户账号 ID 与职员 ID 类型、提供者名称和展示语义。共享 UI 不是通用 IAM 查询权限：每个接入点仍须注入自己的服务端候选搜索和回显函数。当前职员账号绑定使用 `UserPicker`；`EmployeePicker` 作为职员主数据的同构封装，待出现具备明确业务候选规则的实际入口后接入。

## 验证与完成标准

- 权限：平台管理员无租户、固定租户业务上下文、租户管理员、组织管理员、只有来源业务权限的账号、无权限账号；导航、搜索和回显均不能扩大范围。
- 语义：用户与职员 ID 不混用；平台账号、无职员绑定账号可达；父节点不自动包含下级；停用、删除、调岗和同名对象正确表达。
- 交互：关键词带入、下拉与弹窗选择一致、取消不生效、跨页多选、当前页全选、清除、重开回显及上级依赖变化。
- 大数据：使用万级用户及大型树验证搜索、分页、按需加载和有界回显；检查实际请求与真实数据路径，不以少量 mock 数据作为完成依据。
- 并发：快速搜索、导航切换、外部范围变化及关闭重开时，过期响应不能覆盖当前候选或恢复失效选择。
- 浏览器：对三类日志、机构部门代表性表单、角色范围和职员绑定账号实际验证真实候选加载、选择和最终查询或提交；不能仅凭 CI 或请求路径断言宣布完成。

后端运行 `./gradlew verifyAll`，前端运行 `npm run check --prefix muyun-web`。关键数据范围与引用投影采用真实路径 contract 测试，范围拒绝和状态变化补回归测试。阶段完成后同步更新本专项状态和关联接口文档，清理过渡入口。
