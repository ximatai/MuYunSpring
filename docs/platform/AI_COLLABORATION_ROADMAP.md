# 平台与智能助手协作建设方案

## 定位与唯一建设顺序

本方案是平台与智能助手协作的统一建设入口，拥有主干范围、推进顺序、代码进度、分支取舍和验收门槛。[智能助手能力融合专项治理](AI_ASSISTANT_GOVERNANCE.md) 只维护助手接入与运行契约；元数据、公式、页面、权限等业务契约继续归所属专题，不在助手文档中复制实现规范。

建设顺序统一为 **P：平台治理 → A：智能体治理 → D：交付演练**。三者是同一业务目标的依赖门槛，不是三次重建，也不要求先治理整个平台。已有助手能力保留并维护安全边界；本轮新增投入先解决选定平台主干的公共问题，平台门槛通过后再扩充助手接入，最后用真实用户任务验证交付。

长期目标是业务声明一次，静态 Java 与动态元数据共享能力、数据访问、约束、权限、事务、生命周期和结果；人工与助手可以理解、审阅和操作同一份业务事实。业务接入仍保持模型、Ability、标准 Web 声明和少量领域扩展的轻量形态。

## 架构判断与取舍

### 两个维度，一套业务内核

定义来源与操作入口分别建模：

| 维度 | 当前形态 | 边界 |
| --- | --- | --- |
| 业务定义来源 | 静态 Java、动态元数据 | 声明方式不同，编译后复用平台能力；静态代码仍经代码审查和构建，不能被在线元数据编辑替代 |
| 操作入口 | 人工页面、智能助手 | 读取同一权威事实，复用所属领域和前端运行器的正式命令；助手不是第三套业务模型 |
| 后续入口 | 后台任务、外部调用 | 真实需求触发后接入领域门面，不借用浏览器状态或信任客户端工具目录 |

保留“动静一体”和“模型理解、平台执行”的方向。当前浏览器协作保留后端模型网关与回合服务、前端 Surface 和标准编辑会话；不把页面操作全部迁到后端，也不预建通用 Agent 引擎。未来服务端执行需要的窄契约由领域拥有，不反向依赖页面 descriptor。

模型负责理解目标、提出拆分、比较复用方案和校准歧义。平台确定性负责能力与数据事实、参数、权限、依赖、版本、事务和执行结果。不用提示词代替这些约束，也不把自然语言需求映射发展为通用业务证明系统。

### 平台拥有编辑与提交，入口只做适配

每类治理对象保留自己的候选、基线、预检和正式提交语义。元数据、规则和页面无需共用一个万能编辑器，但人工页面与助手操作同一对象时必须共享候选和命令：

```text
人工页面 ─┐
          ├→ 所属治理编辑会话 → 候选与差异 → 预检 → 人工审阅 → 正式领域提交
助手适配 ─┘                                              ↓
                                   提交事实 → 运行态核实 → 页面和入口 → 业务验证
```

公共编辑会话不应依赖助手专用异常、确认状态机或模型摘要。已被两种入口复用的候选有效性、提交、结果核实可提炼为小型入口无关契约；模型安全摘要、工具参数和对话续接留在助手适配层。目标是修正依赖归属，不是复制实现、机械改名或另造执行引擎。

页面显示、对话显示是呈现偏好，不应决定采用哪套配置发布路径。默认展示可接手的工作区；纯对话可以保留，但必须最终复用同一编辑会话、预检与发布。独立纯对话页面建设写路径已退役，历史回执仅保留只读查询。

### 设计记录与现行配置分离

建设方案保存业务目标、范围、决定、依赖和验收例子；方案版本与回执可解释历史，不能成为创建、发现、维护或使用已有模块的前提。简单配置可直接走标准治理；复杂多模块建设按需使用方案组织讨论，不强制先完成全量技术映射。

已落地业务以现行元数据、关系、规则、页面和权限为准。进度由这些事实与领域回执推导，不能在聊天、方案和工作台分别维护“完成状态”。历史人工验收证明当时基线的交付判断，不证明之后的配置仍正确，也不能代替业务试用。

### 分步提交，分别证明结果

以下事实必须分别表达：未保存候选、配置已提交、运行态已安装、页面已发布、菜单可见、目标用户有权使用、业务行为通过。统一的是解释与核实纪律，不是跨专题事务。

正式提交保留各领域的版本、指纹、事务与迁移策略。网络断流不等于未提交；后续刷新失败不抹去已提交事实。可重复写入需要稳定请求身份与幂等；以不可变修订或领域基线核实结果时必须能精确关联本次操作，不能按同名对象或相似内容推定成功。无法核实时保持未知并交接，不自动重放。

不为本轮建设跨模块原子发布、万能回滚或持久 Agent 工作流。配置包归档和版本指针也不能冒充实际发布、运行态切换或数据回滚。

### 长期改进范围

按公共根因决定修复范围，允许同步收敛调用方和测试，不以最小 diff 保留坏边界。仓库已有 BOM、Starter 和公开消费面；“当前业务未上线”不能推导为所有公共 API 都无需兼容。涉及公开契约时评估消费者、配置和迁移影响，不为内部过渡接口无限保留兼容层。

## 主干链路

本轮主干是 **标准治理从空白或已有业务出发，形成可实际使用的动态应用；助手等价接入这条链路**。静态业务用于验证平台公共契约，在线生成 Java 工程不在本轮范围。

| 节点 | 平台必须独立完成的能力 | 成功证据 |
| --- | --- | --- |
| M1 对象与归属 | 发现、复用或建立应用、模块和主元数据，说明当前选择及未完成项 | 正式对象身份、绑定、标准字段与运行态诊断；新模块不冒称已有主实体 |
| M2 数据结构 | 字段、约束、字典、单值引用及一层直接子表；候选可人工修改、放弃 | 标准目录、候选差异、真实预检、正式提交与元数据查询 |
| M3 业务规则 | 主表和直接子表计算、汇总、保存校验，必要的界面控制 | 规则集预检、带类型样例试算、服务端保存复算；不只检查规则存在 |
| M4 页面交付 | 用实际目录编排列表、表单、明细和查询，审阅并发布页面 | 同一候选、已发布修订及标准运行页面；显示字段不创造实体或关系 |
| M5 可访问入口 | 菜单挂载、目标租户应用开通、角色与动作授权 | 系统配置身份与普通目标用户分别核实；管理员可见不等于租户可用 |
| M6 实际业务 | 保存、重开、查询、详情，主子聚合修改与约束 | 真实持久化及业务断言，失败不丢已提交事实，不出现跨租户访问 |

M2、M3 的变更可能要求重新核实 M4；它们不是永久单向流水线。对象之间按真实依赖推进，复用现有对象无需补造建设回执。M5 授权继续走 IAM 人工治理，不因助手建设应用自动授予权限。

平台阶段可以用技术性小场景和自动化测试定位问题，助手阶段可以用替身与有限真实模型做接入验证；完整非技术用户交付演练在两道门槛通过后进行。演练发现公共缺口时回到对应层修复，不能以临时助手流程绕过。

不按文件数、工具数或旧阶段编号计算完成百分比。当前总体状态是：**四个提交单元的代码已合并，但 P/A/D 业务门槛尚未全部通过。公共链路、助手操作和上下文机制已有实现；引用回填的删除依赖、赋值类型与规格变更校验，以及规则提交结果边界已补齐，建设与配置专属指引已按实际目标和场景收窄。管理员人工业务样例已通过；普通租户应用开通、角色绑定及业务菜单已核实，普通身份人工业务及助手两行订单协作（含人工接手、确认保存和刷新重开）已通过，完整助手应用建设、新会话接管及任务效率仍待验收。** 旧文档中的局部浏览器样本不抹去，也不能提升为当前组合目标的通过结论。

## 分支链路与处理顺序

“分支”表示相对于本轮业务目标的优先级，不表示其领域价值低。权限、数据正确性、未知结果和并发保护虽横跨节点，仍是主干的必要条件。

| 分支 / 问题 | 决定 | 原因、所属阶段与完成边界 |
| --- | --- | --- |
| 标准编辑会话依赖 Assistant 异常与确认 | 已落地，维护回归 | 公共候选、提交和确认类型已归平台；工具摘要与续接归助手。规则结果分类已补齐，不重复抽取契约 |
| 页面会话挂载依赖、独立纯对话发布 | 已落地，维护回归 | 模块级会话由人工与助手共享，组件卸载不丢候选；独立写路径已退役。持续覆盖慢加载、失活与身份切换，历史回执只读查询 |
| 主实体建立、字段到页面与入口的衔接 | 当前处理，P3 | 直接决定人工主干是否完整；缺失状态和进入下一治理区的方式必须明确 |
| 字段精度、价格快照及保存计算 | 当前核实并修复阻断，P3 | 金额字段存在或公式存在不证明业务正确；须证明成交价是订单事实、改价不回写历史。使用现有引用回填/保存规则，不预建定价引擎 |
| 配置提交、激活、页面发布与刷新失败 | 当前处理，P1–P3 | 建立逐操作结果核实矩阵；已提交与刷新失败分开。缺少精确核实的入口保持未知，不新增盲重试 |
| Schema 与 parseInput 不一致 | 当前处理主干能力，A1 | 现有描述与解析并非全部同源。复用领域校验和事实，补主干参数契约测试；不为此先建通用 Schema 框架 |

### 上下文效率的实测边界

2026-10-02 在相同本地客户页面、空白会话、同一 `gpt-6.1-sol` 配置下，以“打开商品页面配置，查看列表和表单布局，不修改或保存”为只读任务，仅切换全量或按需工具定义。全量方案首轮返回空内容并报告 length；按需方案前两轮成功，供应商报告输入 5,922、输出 92、总计 6,014 token，第三轮供应商不可用，人工点击继续一次仍不可用。后两次失败没有用量，6,014 仅为已报告部分，两组任务均未完成。该样本证明用量可观测和失败可区分，不能证明节省比例或交付成功；该样本早于按需加载保留完整领域指引的修正，最终版本须在可用服务下重新完成同任务对照。页面就绪链路修正后的全量目录复测仍在首轮收到空内容（供应商报告 0 token）；失败样本不作为成本优势，临时全量配置已还原。

2026-10-02 冻结版本下的普通订单基线：已完成的只读查询为 2 次模型调用，供应商报告输入 8,093、输出 189、合计 8,282 token。随后两行新单草稿及人工继续、补充需求合计 31 次调用，其中 29 次返回用量，输入 123,265、输出 1,954、合计 125,219 token；另 2 次供应商失败未报告用量，任务仍未完成。该样本直接表明简单任务存在明显交互成本，不能作为节省比例或完整交付证据；后续改进应在相同目标与模型配置下比较任务完成率、调用次数和完整已报告用量，而非只比较单轮上下文大小。

`f51fba07a` 冻结版本、相同普通身份与模型配置的复测：旧单只读查询 2 次调用，输入 8,117、输出 285、合计 8,402 token；两行新单填报、一次预算继续、人工改数量后的助手审阅合计 23 次调用，输入 101,232、输出 1,399、合计 102,631 token。两段合计 25 次调用，全部返回用量，合计 111,033 token，无供应商失败，正式确认保存及刷新重开通过。其中新单完整草稿为 20 次调用、89,347 token，人工接手后的审阅为 3 次调用、13,284 token。旧基线未完成而本轮已完成，不能把两者直接换算为等价任务的节省比例；23 次调用仍偏多，单次成功也不能证明普遍稳定性。

晴川新会话续建失败样本共 9 次模型调用，7 次完成、2 次空响应失败；供应商报告输入 29,649、输出 419、合计 30,068 token，其中两次失败均报告 0。该数值为上游报告值，不证明失败请求没有实际计算或计费。未形成新的正式配置；只读连接诊断单独统计，不计入建设成果或上述任务用量。客户单模块复测（`aac9d6b36`）另计 13 次调用、11 次完成、2 次空输出失败，13 次均报告用量，输入 48,038、输出 707、合计 48,745 token；失败仍各报告 0，隔离诊断不混入任务统计。能力目录现已去除已加载定义的重复说明，发现 Schema 明确未知应用别名时省略精确范围；隔离复测中模型仍可能推测应用别名，Schema 说明不构成来源验证；这些契约修正尚不证明整任务节省、范围误判消除或模型空输出已解决。成本回传同时补齐 Web 响应遗漏，通过 JSON／SSE 边界测试区分完整、部分、零值和缺失用量；不将这一修正宣称为上游空响应故障已解决。

最新五轮用户验收中，空存储设置被误判为必填的一轮没有供应商失败，仍用了 32 次模型调用、131,153 token 且没有正式保存。这说明停滞与成本不能全部归因于供应商故障。普通客户登记、补充及失败恢复一轮共 12 次调用，10 次报告用量，合计 41,359 token，另 2 次失败没有用量；只有登记保存完成。两者身份、任务和代码版本不同，不能推导节省比例，默认值语义修复后的完整任务成本仍待复测。
