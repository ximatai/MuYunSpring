# 平台与智能助手协作建设方案

## 定位与唯一建设顺序

本方案是平台与智能助手协作的统一建设入口，拥有主干范围、推进顺序、代码进度、分支取舍和验收门槛。[智能助手能力融合专项治理](AI_ASSISTANT_GOVERNANCE.md) 只维护助手接入与运行契约；元数据、公式、页面、权限等业务契约继续归所属专题，不在助手文档中复制实现规范。

建设顺序统一为 **P：平台治理 → A：智能体治理 → D：交付演练**。三者是同一业务目标的依赖门槛，不是三次重建，也不要求先治理整个平台。已有助手能力保留并维护安全边界；本轮新增投入先解决选定平台主干的公共问题，平台门槛通过后再扩充助手接入，最后用真实用户任务验证交付。

长期目标是业务声明一次，静态 Java 与动态元数据共享能力、数据访问、约束、权限、事务、生命周期和结果；人工与助手可以理解、审阅和操作同一份业务事实。业务接入仍保持模型、Ability、标准 Web 声明和少量领域扩展的轻量形态。

## 架构判断与取舍

### 两个维度，一套业务内核

定义来源与操作入口分别建模：

| 维度 | 当前形态 | 边界 |
| --- | --- | --- |
| 业务定义来源 | 静态 Java、动态元数据 | 声明方式不同，编译后复用平台能力；静态代码仍经代码审查和构建，不能被在线元数据编辑替代 |
| 操作入口 | 人工页面、智能助手 | 读取同一权威事实，复用所属领域和前端运行器的正式命令；助手不是第三套业务模型 |
| 后续入口 | 后台任务、外部调用 | 真实需求触发后接入领域门面，不借用浏览器状态或信任客户端工具目录 |

保留“动静一体”和“模型理解、平台执行”的方向。当前浏览器协作保留后端模型网关与回合服务、前端 Surface 和标准编辑会话；不把页面操作全部迁到后端，也不预建通用 Agent 引擎。未来服务端执行需要的窄契约由领域拥有，不反向依赖页面 descriptor。

模型负责理解目标、提出拆分、比较复用方案和校准歧义。平台确定性负责能力与数据事实、参数、权限、依赖、版本、事务和执行结果。不用提示词代替这些约束，也不把自然语言需求映射发展为通用业务证明系统。

### 平台拥有编辑与提交，入口只做适配

每类治理对象保留自己的候选、基线、预检和正式提交语义。元数据、规则和页面无需共用一个万能编辑器，但人工页面与助手操作同一对象时必须共享候选和命令：

```text
人工页面 ─┐
          ├→ 所属治理编辑会话 → 候选与差异 → 预检 → 人工审阅 → 正式领域提交
助手适配 ─┘                                              ↓
                                   提交事实 → 运行态核实 → 页面和入口 → 业务验证
```

公共编辑会话不应依赖助手专用异常、确认状态机或模型摘要。已被两种入口复用的候选有效性、提交、结果核实可提炼为小型入口无关契约；模型安全摘要、工具参数和对话续接留在助手适配层。目标是修正依赖归属，不是复制实现、机械改名或另造执行引擎。

页面显示、对话显示是呈现偏好，不应决定采用哪套配置发布路径。默认展示可接手的工作区；纯对话可以保留，但必须最终复用同一编辑会话、预检与发布。独立纯对话页面建设写路径已退役，历史回执仅保留只读查询。

### 设计记录与现行配置分离

建设方案保存业务目标、范围、决定、依赖和验收例子；方案版本与回执可解释历史，不能成为创建、发现、维护或使用已有模块的前提。简单配置可直接走标准治理；复杂多模块建设按需使用方案组织讨论，不强制先完成全量技术映射。

方案对象可在既有方案审阅中显式关联已发现的标准模块；关联不创建配置，也不补造初始化回执。进度、字段和交付检查通过该关联解析当前主关系与元数据。旧方案的初始化回执仅提供历史关联线索，显式关联优先；缺失或失效的配置仍须通过标准治理补齐。建设专属初始化和字段写实现已退役，创建与发布复用标准治理服务；历史回执仅保留只读查询，不回写当前方案状态。

已落地业务以现行元数据、关系、规则、页面和权限为准。进度由这些事实与领域回执推导，不能在聊天、方案和工作台分别维护“完成状态”。历史人工验收证明当时基线的交付判断，不证明之后的配置仍正确，也不能代替业务试用。

### 分步提交，分别证明结果

以下事实必须分别表达：未保存候选、配置已提交、运行态已安装、页面已发布、菜单可见、目标用户有权使用、业务行为通过。统一的是解释与核实纪律，不是跨专题事务。

正式提交保留各领域的版本、指纹、事务与迁移策略。网络断流不等于未提交；后续刷新失败不抹去已提交事实。可重复写入需要稳定请求身份与幂等；以不可变修订或领域基线核实结果时必须能精确关联本次操作，不能按同名对象或相似内容推定成功。无法核实时保持未知并交接，不自动重放。

不为本轮建设跨模块原子发布、万能回滚或持久 Agent 工作流。配置包归档和版本指针也不能冒充实际发布、运行态切换或数据回滚。

### 长期改进范围

按公共根因决定修复范围，允许同步收敛调用方和测试，不以最小 diff 保留坏边界。仓库已有 BOM、Starter 和公开消费面；“当前业务未上线”不能推导为所有公共 API 都无需兼容。涉及公开契约时评估消费者、配置和迁移影响，不为内部过渡接口无限保留兼容层。

## 主干链路

本轮主干是 **标准治理从空白或已有业务出发，形成可实际使用的动态应用；助手等价接入这条链路**。静态业务用于验证平台公共契约，在线生成 Java 工程不在本轮范围。

| 节点 | 平台必须独立完成的能力 | 成功证据 |
| --- | --- | --- |
| M1 对象与归属 | 发现、复用或建立应用、模块和主元数据，说明当前选择及未完成项 | 正式对象身份、绑定、标准字段与运行态诊断；新模块不冒称已有主实体 |
| M2 数据结构 | 字段、约束、字典、单值引用及一层直接子表；候选可人工修改、放弃 | 标准目录、候选差异、真实预检、正式提交与元数据查询 |
| M3 业务规则 | 主表和直接子表计算、汇总、保存校验，必要的界面控制 | 规则集预检、带类型样例试算、服务端保存复算；不只检查规则存在 |
| M4 页面交付 | 用实际目录编排列表、表单、明细和查询，审阅并发布页面 | 同一候选、已发布修订及标准运行页面；显示字段不创造实体或关系 |
| M5 可访问入口 | 菜单挂载、目标租户应用开通、角色与动作授权 | 系统配置身份与普通目标用户分别核实；管理员可见不等于租户可用 |
| M6 实际业务 | 保存、重开、查询、详情，主子聚合修改与约束 | 真实持久化及业务断言，失败不丢已提交事实，不出现跨租户访问 |

M2、M3 的变更可能要求重新核实 M4；它们不是永久单向流水线。对象之间按真实依赖推进，复用现有对象无需补造建设回执。M5 授权继续走 IAM 人工治理，不因助手建设应用自动授予权限。

平台阶段可以用技术性小场景和自动化测试定位问题，助手阶段可以用替身与有限真实模型做接入验证；完整非技术用户交付演练在两道门槛通过后进行。演练发现公共缺口时回到对应层修复，不能以临时助手流程绕过。

## 分支链路与处理顺序

“分支”表示相对于本轮业务目标的优先级，不表示其领域价值低。权限、数据正确性、未知结果和并发保护虽横跨节点，仍是主干的必要条件。

### P：平台治理

**P1：入口无关的治理编辑与提交边界，已落地并维护结果语义。**

元数据、规则和页面共享的公共提议、确认及错误契约已归平台；助手 adapter 负责模型安全摘要和对话呈现，后端权威预检与事务保持所属领域职责。规则应用已区分：写请求前的明确预检拒绝、已提交但界面同步失败、提交结果未知必须分别表达。成功响应后的读取失败保留提交事实，并要求重新加载后继续编辑。

完成条件：不开启助手也可准备、审阅、取消和提交；同一候选可由任一入口接手；人工修改/身份变化使旧确认失效；明确拒绝、提交成功后读取失败、结果未知分别有契约测试。元数据、规则不强制共享同一事务或同一候选格式。

**P2：统一页面候选生命周期，已落地并维护回归。**

页面编辑会话已与组件展示解耦，治理页与对话选择同一模块及同一候选，独立 construction 页面写路径已退役。持续覆盖不打开页面准备、打开后接手、关闭后继续、字段基线变化后重新预检，以及慢加载与失活后的迟到响应。

完成条件：两种呈现方式获得相同差异与发布结果；换模式不替换候选，放弃页面草稿不撤销已提交字段；断流能精确核实原发布，发布后刷新失败不重复发布。

**P3：打通平台人工主干并核对业务语义。**

在隔离数据中从标准入口建立/复用应用、模块、主实体、引用与直接子表，完成规则、页面、菜单及普通租户用户授权。逐个核对提交与未知结果读取契约，给助手阶段提供可用命令与明确限制。检查价格快照、数值类型、必填与计算字段交互、列表/详情一致性。不得通过直接写数据库或未交付接口补齐产品缺口。

平台门槛：M1–M6 可由人工独立完成，关键真实路径与失败路径有证据；公共编辑、提交和运行态不依赖助手；已发现的主干阻断已修复。只完成后端 Service 测试不能通过本门槛。

### D：交付演练

使用相同业务目标、可重建起点与明确角色做完整演练：先人工基线，再助手建设并中途人工接手，最后用目标用户验证真实业务。演练以非技术业务人员的语言提出目标，不喂模块别名、字段英文名、工具参数或源码知识；不能预建目标配置冒充建设成果。

独立模拟用户只接收业务背景、目标和操作边界，自主组织话术、追问和接手方式。话术多样性验收至少覆盖三种实际交流思路；同一会话的重试不另算一轮，角色名称不同不等于话术思路不同。每轮冻结代码，由主执行者结合页面证据、运行记录和轮后用户访谈定位问题，在正确层修正后再验证。模拟用户反馈与实际完成证据分别记录，不能把修复后的自动化检查或模型服务恢复当作用户验收通过。

首个组合样例采用客户、商品、订单及订单明细，仅验证平台公共能力，不成为内置业务模板。客户/商品可独立维护，订单引用客户，明细引用商品并保存数量和本次成交价，小计与总额服务端计算。新建、改数量、增删行、保存后重开和查询详情均须验证。商品改价后，旧单重开及修改非价格字段再保存均应保留原成交单价；修改数量按原成交单价重算金额，不能每次保存重新读取商品现价。成交价可按商定业务规则由人确认或调整。若现有能力不能兑现某项，回到 P 处理或明确重新确定范围，不能将已约定的自动回填或计算静默降级为人工操作，也不能擅自改成单行订单。

分别记录三类结论：配置事实正确、实际业务正确、真实模型协作可用。记录所用模型、初始配置、目标用户、必要补充和确认次数、失败/恢复、耗时及实际可得的 token；供应商故障单独归因，单次样例不推导普遍成功率，字符数不冒充 token。纯对话与可视方式的成本比较不是本轮交付前置项目。

交付门槛：上述三类结论均有可复现证据，未支持项如实交接；中途追问、人工修改、部分提交失败、刷新后只读核实不丢目标或重复写入。系统配置成功、测试通过、模型宣称完成或人工点击验收按钮，均不能单独替代交付结果。

### 已确认契约与剩余门槛

- **共享菜单治理：**标准编辑页、模块治理入口与助手 adapter 使用同一候选、审阅、提交回执和可见性核实契约。菜单挂载不授予权限；配置身份、目标租户和业务角色分别核实。一般模块入口不以建设方案或额外业务回执为前置条件。默认租户初始化只复制代码声明入口及必要目录，不复制人工系统业务入口；明确平台托管的旧副本可停用，人工维护入口及承载它们的目录保留。
- **正式值与草稿：**仅服务端保存时计算的字段，在编辑、助手草稿事实及审阅卡中显示“保存后计算”，详情显示正式保存值。准备审阅不写入，也不提前产生正式计算结果；助手算式仅作明确标记的参考。仅草稿请求不强迫进入提交。模型对旧正式值与当前草稿的文字解释仍需继续验证。
- **跨页读取：**同身份、同执行范围内，已授权显示观察可有界保留，页面失活不使读取事实自动变为未知。观察只表达读取时的值，不恢复候选、参数、权限或保存授权；用户要求最新值或后续修改时重新读取。列表未匹配只证明当前查询范围内未找到，不能推导对象不存在或擅自新建。
- **参数及模型兼容：**主干能力的 Schema、执行解析和领域校验应一致。当前已修正模块选择 Schema 的重复分组正则兼容问题，执行端仍严格校验模块路径。拒绝未声明工具可在原预算内重新规划一次，不能自动重试传输故障或未知写入。供应商超时及可用性故障单独归因，不能宣称整体稳定性已经解决。
- **进度与权限：**正式配置、建设方案、历史回执、页面打开和未保存候选分别表达。方案缺少关联或进度不证明正式模块不存在，也不按名称自动绑定。普通业务缺字段时如实说明未保存内容，配置改造需另有明确目标和权限；不能让员工承担技术存储选择。
- **下一步验收：**核实完整助手建设与新会话接管，继续覆盖不同业务背景、自主话术、人工接手、失败恢复及多对象目标。当前仍需收敛重复能力发现、技术用语、查询总结不一致及预算续办负担；以正式配置、已确认目标和实际回执辅助模型，不扩大预算或加入固定业务步骤。

效率以相同目标、可重建起点、相同模型配置和完整任务结果比较，同时记录人工补充、必要确认、调用次数、耗时及供应商报告的 token。缺失用量不记零，全零报告不证明未计费；任务未完成、人工动作不同或版本不同的样本，不能换算为等价节省比例。按需工具定义与有界观察已落地，但简单业务仍可能消耗多轮决策，不能由局部查询改善宣称整体效率达标。

## 验证与维护

平台行为改动运行 `./gradlew verifyAll`；前端依 `muyun-web/AGENTS.md` 执行相关单元、组件、完整检查与消费者验证。真实数据库、HTTP、组件/浏览器 fixture 和真实模型演练各自证明不同边界，汇报须区分实际执行、缓存命中与未执行。

本方案只记录稳定决策、证据入口、当前状态与下一步。每完成 P/A/D 中一个能力单元，更新进度及遗留边界，将细节归回领域专题和测试；不追加新的历史阶段或把执行日志堆入文档。后续任务协作及后台能力只保留触发条件，进入目标后再设计。
