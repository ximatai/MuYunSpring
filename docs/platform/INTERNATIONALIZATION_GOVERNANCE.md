# 国际化专项治理

状态：平台与填报界面的国际化基础能力已建立，默认交付中英文。代码资源、在线配置独立发布、专题展示与冻结历史共用文本契约；新增语种、并发作用域、长文案及真实消费者纳入持续验收。业务记录内容的多语言读写仍按后续独立专题推进。

国际化面向实施人员和终端用户，覆盖平台功能、业务填报界面与业务内容。建设顺序是先交付平台和填报界面的多语言能力，再按真实业务需求建设记录内容的多语言维护。静态 Java 声明、动态元数据、人工页面和智能助手复用同一套语言上下文、文本解析与回退规则，继续遵循[动静一体核心设计](../architecture/DYNAMIC_STATIC_UNIFIED_CORE.md)。

## 治理目标

1. 实施人员可以为模块、字段、页面、字典和业务提示维护翻译，并向终端用户交付多语言业务页面。
2. 终端用户可以选择界面语言，完成查询、主子表填报、校验、保存和任务办理；切换语言保留未保存草稿与业务上下文。
3. 支持随推广增加语种，新增语言主要增加资源与语言登记，不要求修改业务模型、字段结构或业务执行代码。
4. 静态与动态来源共用翻译契约，业务接入保持轻量，公开消费者获得与框架宿主一致的语言能力。
5. 翻译不改变业务身份、权限、租户隔离、校验、公式、事务、生命周期和历史事实。

## 翻译范围与维护归属

| 类型 | 范围 | 维护与交付方式 |
| --- | --- | --- |
| 代码声明文案 | 平台固定提示，以及静态 Java 页面 DSL 声明的标题、标签和说明等文本 | 通过稳定文案键与所属平台或业务应用的语言资源维护，随软件版本部署 |
| 在线配置文案 | 在线维护的模块与菜单名称、字段标签、页面分组、帮助说明、字典选项、规则提示、流程节点与办理指引 | 翻译绑定所属配置对象、文本属性及对应原文版本，在线维护并受控发布 |
| 业务记录内容 | 商品名称、服务介绍等显式需要多语言版本的业务字段 | 后续按字段声明接入，保留原文与语言版本，形成独立读写和查询契约 |

官方预置配置可以随部署交付初始译文，资源按模块、来源 ID 和精确原文版本绑定。平台在配置初始化及默认菜单复制完成后，通过正常翻译维护命令补种并发布；已有人工草稿、已发布译文和其他原文版本均不覆盖。此后译文修订仍通过独立发布治理，不因重启重新覆盖。新租户仅补齐自己的默认菜单副本，已被接管或改变原文的副本不套用默认译文。新增语种沿用资源与语言登记，不修改业务执行代码。租户菜单方案按默认副本身份、内置管理员角色按系统用途声明预置基线，目标仍绑定实际配置记录。补种在租户或机构预置创建完成后执行，仅处理原文版本一致且未维护过的目标，保留已有人工草稿及发布译文。

配置文案即使存储在数据库中，也属于首期界面国际化范围。业务记录内容的多语言能力不默认覆盖所有字符串字段，用户填写的人名、法定名称、备注等内容按所属业务规则处理。

译文维护归属按文本来源判断，不按静态或动态模块划分：代码声明的原文和译文随所属应用资源部署，在线配置的译文在线维护并独立发布。两种来源进入同一文本引用与解析契约，展示投影不修改共享业务执行计划。

## 建设边界

1. **公共译法统一。** 平台公共模块在每种语言下使用统一翻译，不提供租户个性化覆盖。业务自有配置的翻译跟随对象归属管理，沿用已有权限与租户边界。
2. **语言可以扩展。** 使用标准语言标签和可扩展语言目录，不写死双语枚举或为每种语言增加业务列。语言目录治理启用状态、默认语言和回退关系；缺失翻译时回退到可用默认文本，并提供缺失诊断。
3. **展示与业务语义分离。** 语言属于用户体验和展示上下文；时区、币种及业务日期保持各自契约。模块 alias、字段名、字典 code、动作码、接口参数和公式表达式保持稳定。
4. **原文与译文分离。** 配置维护明确编辑原文或目标语言版本，本地化展示不得写回普通业务字段。用户切换界面语言不改写已填写内容。
5. **保留文本来源。** 静态声明和动态编译保留稳定文案身份及来源，页面自定义标签与元数据字段名称分别翻译，继续服从已有覆盖关系。现有默认文本保留为回退，不以显示文本作为程序判断依据。
6. **在线配置译文独立发布。** 已生效在线配置的译文允许单独修正和发布，提交时校验对应原文版本，原文变化后标记待复核。原文版本与译文发布版本分别表达；译文发布只刷新相关展示资源，不触发 schema 变更、业务规则修改或工作流重新发布。
7. **代码声明资源随版本交付。** 平台及静态业务代码声明的语言资源随所属软件版本部署，首期不建设管理员在线导入代码语言包的机制。在线配置翻译继续受控发布，后续配置包迁移应携带对应翻译资源与来源关系。
8. **助手复用正式能力。** 助手使用同一语言上下文与配置、表单事实；机器翻译可产生候选，正式应用仍经过所属配置或业务的审阅与提交链路。
9. **实例与历史绑定冻结原文。** 工作流实例及历史展示按冻结的原文身份与版本解析译文，不套用当前配置的新原文；对应原文版本的译文更正不改写历史快照或办理事实。系统生成提示与审批意见等用户输入分别处理，用户输入保留原文。
10. **保留现有数据交换契约。** 首期导入导出本地化列标签、提示及配置文案，技术表头和业务记录原值保持现有语义。引用继续支持标题反推与歧义拒绝；跨语言业务标题、模板语言变化及译文更正后的文件往返，在业务内容多语言阶段形成单独契约。

项目尚未上线，现有环境与数据均为测试用途。当前建设按目标契约更新测试构造和演示数据，不承担旧测试数据迁移、旧文本格式兼容或过渡回填；新契约仍需验证流程版本变化、在途实例和历史记录的长期行为。

## 阶段计划

| 阶段 | 主要范围 | 阶段完成标准 |
| --- | --- | --- |
| 一 收口存量文案契约 | 文案参与行为判断改为稳定标识，补齐动作消息参数，明确原文与展示译文的边界 | 改变显示文字不改变程序行为，译文不通过普通保存写回原文 |
| 二 建立统一语言基础 | 语言目录、用户偏好、前后端上下文、资源加载、缺失回退、控件与公共消费者入口 | 中英文可选择并传递，语言与权限、租户、时区和币种各自独立 |
| 三 打通代码声明文案 | 平台固定操作、错误与成功提示、静态页面标签及应用语言资源 | 一个静态模块完成双语查询、填报、校验、保存与重开 |
| 四 打通在线配置翻译 | 在线配置文案维护、原文版本校验、译文独立发布、展示投影与缓存刷新 | 一个动态主子表模块完成双语闭环，切换语言保留草稿，译文更新不改变执行计划 |
| 五 扩大平台覆盖 | 实施治理、权限、流程、工作台、导入导出、提醒与助手 | 各入口语言一致，历史保持冻结原文，引用标题往返保持现有契约 |
| 六 验证扩展与整体交付 | 第三种语言、长文案布局、并发语言隔离、完整业务与真实消费者 | 新增语言主要增加资源和登记，完整链路验收并纳入持续验证 |

每步由主 agent 实现、自行复盘与验证后提交，再由独立 subagent review 对应提交；修复发现的问题并重新验证后才进入下一步。代码声明与在线配置的共同链路成立后再扩大覆盖，文字长度、字体、布局方向和控件适配按实际推广语言验收。

业务记录内容多语言在上述界面改造后单独推进。[业务内容多语言专项治理](BUSINESS_CONTENT_MULTILINGUAL_GOVERNANCE.md)按阶段 1—3 实施，以跨国团队共同填报和互读为场景，规定字段策略、原文与译文版本、自动阅读翻译、人工修订与确认、搜索排序、引用及数据交换的目标与验收；后端原文修订底座已接入，业务闭环尚未交付，不将底层测试视为业务验收。阶段 4 的推广及配置译文跨环境交付后续建设，当前业务必需的权限、质量、恢复和运行保障随阶段 1—3 落实。

## 当前语言交付

中英文覆盖平台固定操作与已安装静态声明目录；在线配置的正式译文由实施人员维护并独立发布。法语作为扩展验收语言，已登记目录、部分代码资源与控件资源，默认停用，缺失文本回退英文。部署通过 `muyun.i18n.enabled-languages` 启用已登记语言，不修改业务模型或执行代码。

推广语种的正式启用应完成对应术语、应用代码资源与在线配置译文的审校。当前法语资源用于验证扩展契约，不代表完整法语交付；其他布局方向与推广字体按实际目标语种另行验收。

## 验收重点

- 不同语言用户同时访问时，菜单、页面、选项和消息不串语言；缓存区分业务作用域、有效语言与翻译版本，过期响应不覆盖当前展示。
- 英文界面编辑配置或业务记录不会把译文写回原文；语言切换不丢失主表、明细、查询条件、记录身份和乐观锁版本。
- 浏览器即时校验与服务端最终校验消费同一提示来源，插值参数完整；规则判定和数据保存结果不随语言变化。
- 字典与枚举保存稳定编码，引用保持真实记录身份；导入导出技术表头保持稳定，引用标题反推与歧义拒绝沿用现有契约，不因翻译展示改变记录匹配。
- 代码声明文案随所属应用资源交付，在线配置译文独立发布并校验来源，原文变更可诊断；已发布页面、运行实例及历史回显保持各自版本和事实边界。
- 验证原文发布新版本后，旧版本在途实例仍使用冻结原文，并能解析对应版本的已发布译文；译文更正不改变节点身份、流程行为或审批意见。
- 实时提醒按接收侧语言展示，助手摘要与人工页面语言一致；公开消费者验证语言资源、公共入口及第三方控件接入。

验证沿用仓库现有测试与消费者链路。涉及真实配置持久化、发布、租户范围和数据保存时补充真实路径契约测试，布局与长文案通过浏览器验收；不以语言包存在或字符串替换数量作为交付完成依据。
