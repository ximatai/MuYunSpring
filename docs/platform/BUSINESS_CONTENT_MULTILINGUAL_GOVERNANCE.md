# 业务内容多语言专项治理

状态：实施中，阶段 1—3 为本轮交付范围；业务验收口径已确认。当前平台已具备中英文界面、代码资源和在线配置翻译能力。本专题已完成阶段一的来源与真实填报，接入原文及译文修订底座，并接通受权阅读、独立阅读语言偏好及共享人工维护界面；自动生成后端提供专题持久化任务及标准记录接口，共享界面已接通自动申请、有限轮询及明确重试；真实模型验收及跨语言检索尚未完成。

跨国团队需要使用各自熟悉的语言填写业务，也需要阅读、检索和办理其他团队产生的业务。推荐建设统一的业务内容多语言能力：保留真实原文，自动生成阅读译文，允许有权限的人员修订和确认译文。人工确认只表示某版译文经过核对，不表示业务审批、报告签发或对外发布；日常阅读和办理不以人工确认译文为前置条件。

本专题承接[国际化专项治理](INTERNATIONALIZATION_GOVERNANCE.md)中的业务记录内容范围，遵循[开发原则](../DEVELOPMENT_PRINCIPLES.md)和[动静一体核心设计](../architecture/DYNAMIC_STATIC_UNIFIED_CORE.md)。除下述已实现的来源与存储契约外，以下能力与阶段仍为目标，不代表业务验收通过。

## 已实现的来源与存储契约及接入限制

静态持久化文本字段使用 `@BusinessContent` 显式接入；继承的字段可在具体模型类声明，例如 `@BusinessContent(field = "title", key = "equipment-category-name", value = ContentPolicy.MANUAL_TRANSLATIONS)`，不必重复定义标准基类字段。模型声明统一编译并校验未知字段、遮蔽、重复声明和重复文本身份；平台审计、授权及树关联字段不作为业务文本。动态字段的 `contentPolicy` 编译为相同的 `ContentFieldDefinition`，以元数据字段 ID 保留字段身份。未声明的业务值保持原有行为。受保护字段、字典 code 和虚拟字段不支持本轮来源存储，不能通过旁路复制其明文。

动态字段语言策略纳入既有元数据变更集预检、指纹及发布，不通过直接修改主表字段绕过发布边界。新增字段未声明策略时保持原值；修改字段时省略或传空策略表示保留当前策略，明确传入 `KEEP_ORIGINAL` 才撤回语言能力。修改标签等其他字段属性不丢失已声明的语言策略及稳定字段身份。预检复用最终字段约束，拒绝非文本、受保护、字典及引用身份字段启用内容策略；共享字段的策略变更同时校验所属其他关系的配置。

原文修订与正常业务保存处于同一事务。来源语言通过绑定具体记录的 `ContentWriteContext` 随本次保存提交，不读取界面语言。未确定的语言保持空值；原文改变后未明确提交新语言时重新标记为未确定。只修改其他字段不新增原文修订；纠正来源语言校验审阅的文本修订，原文保存继续执行业务乐观锁。原文作者取自可信当前身份，不采信客户端审计字段；只纠正来源语言时保留原文作者和填写时间，另记修订人。首次跟踪存量文字或恢复跟踪后发现原值断档时，保留未追踪基线，作者和填写时间保持未知，基线采集人不冒充历史作者。

`BusinessContentService` 通过所属业务 Service 的动作授权、已声明的数据范围、活动记录和当前字段策略读取分页历史，不提供可独立读取的来源 ID 接口。软删后普通历史读取不可见，恢复后继续使用原历史；最终删除在同一事务内清理来源副本。

正常静态保存及动态记录信封接受独立的 `$contentLanguages` 写入元数据，例如 `{"description":{"languageTag":"zh-CN","expectedRevision":3}}`。它与实际原文同时提交，主子表每行分别携带，不放入 `values` 或任意业务 JSON。已有来源要求提交审阅的文本修订；省略表示未提交语言修改，不默认跟随界面语言。语言写入意图纳入可靠保存的请求指纹，写入后暂时消费，事务回滚恢复该次意图且不覆盖调用方后续决定；提交成功后清除；重开记录不会把上次意图当作新修改。静态标准模型无需业务另写协议适配。

标准主记录提供 `GET /{module}/view/{id}/content` 来源快照及 `GET /{module}/view/{id}/content/{field}/history?page=1&size=20` 分页历史。读取同时经过所属记录当前查看权限、租户与数据范围、页面范围及编译后的字段边界，不提供按来源哈希直接读取的公开接口。快照返回实际原值、文本策略和并发所需版本；无匹配来源时明确返回未追踪状态，不把旧修订当作当前原文。主子表来源通过 `GET /{module}/view/{parentId}/relations/{relationCode}/{childId}/content` 及其 `/{field}/history` 入口读取，复用父拥有的聚合范围和子表字段边界，不将主表数据筛选套到子表。共享表单、只读详情和明细表格已接入来源语言及历史控件；同一业务可登记中英德原文，来源语言与界面语言独立，切换界面语言保留未保存输入。

可选 `collaboration-demo` profile 提供 `quality.equipment_category`、`quality.product` 静态主数据及 `quality.exception` 动态异常单，检测明细和团队调查记录通过正常主子表接入。字段、引用、页面和菜单使用现有平台声明及发布流程；样板只安装业务配置，不预置真实人员或冒充业务作者。明细来源的 Web 字段边界采用所属关系的已发布列表投影；无关系投影的既有静态声明沿用编译读取模型。

样板内部记录通过既有元数据字段保护配置全量脱敏，并声明保持原值；普通页面不展示该字段，普通详情及保存结果不返回明文，来源修订及业务译文不复制该字段。样板升级保留字段身份、已有业务值和用户页面草稿，并修正旧版未保护的内部记录声明。

业务译文存储按所属文本、不可复用的原文修订身份和目标语言保留追加式修订，分别记录机器结果、人工草稿、确认和明确删除。人工草稿不替换当前阅读版本；确认记录审阅的原文和草稿修订，保留草稿作者与确认人各自的事实。当前原文下优先采用已确认版本，其次采用机器结果；机器刷新保留人工草稿及确认版本。删除某语言使用带版本的独立意图，不清空其他语言，旧生成结果不能越过删除修订恢复该语言。原文修订、译文写入和最终清理共享记录事务锁，延迟旧结果不能写入新原文版本；即使最终清理后复用业务记录 ID、显示修订号重新从 1 开始，旧原文修订身份也不能匹配新记录；最终删除同时清理原文及译文副本。回收站的最终清理通过既有删除观察者通知副本清理，沿用所属清理事务；回收站协调器继续独立管理恢复与清理流水。

业务文本声明同时形成 `BUSINESS_CONTENT` 能力，发布独立的 `contentEdit`（维护）及 `contentConfirm`（质量确认）动作，不继承普通业务编辑资格；聚合子表由父记录的动作及数据范围治理。未声明文本的模块不发布这两个动作。普通保存继续只处理业务原值。

标准来源路径的 `/reading?language=en` 返回原值、有效阅读文本、实际语言及回退事实，不返回人工草稿，也不触发写入或模型调用。相同原文版本的确认译文优先，其次为机器译文；来源已为目标语言时保留原文。`/{field}/translations/{language}/prepare` 与 `/review` 分别以维护及确认资格打开当前原文；存量未追踪文字只建立未知历史作者的基线。`/draft`、`/confirm`、`/remove` 独立提交，必须携带审阅的不可复用原文 `sourceRevisionId`、显示修订号及目标语言的 `expectedRevision`，确认还需 `reviewedDraftRevision`。历史按原文身份分页读取，维护人员与确认人员使用各自动作入口。所有入口保留所属页面、字段、租户、活动记录和聚合范围；读取投影不替换业务字段。

自动阅读生成使用同一主记录或明细来源路径下的 `POST /{field}/translations/{language}/generation`；`retry=true` 表达对终态任务的明确重试，`GET` 同一路径只读取状态。入口要求所属记录查看资格、已发布的字段暴露及 `AUTO_TRANSLATE` 策略，当前允许 `zh-CN`、`en`、`de` 目标语言，来源语言须已登记，单字段原文上限为 16,000 字符。已有有效译文直接复用，当前原文下的明确删除阻止自动恢复该语言；人工维护策略不触发机器生成。无有效模型配置或无法保留可信身份时，不创建可执行任务。接口不接收客户端提供的执行身份、模型连接或权限范围。

生成任务在请求事务中持久化，网络调用在事务外执行；并发请求按原文身份、目标语言及已审阅译文头去重。执行和完成分别恢复真实身份并核验当前动作、业务记录、原文、策略及译文头，原文修订与明确删除均能阻止延迟结果写入。标准 Web 适配器保留编译计划、菜单身份及参数指纹、原页面范围指纹和不透明选择引用，执行时重新读取可见菜单与业务入口策略并重新解析选择；取得记录内容锁后再次核验完整入口范围，记录移出原页面范围后不随新范围执行，也不伪造 HTTP 请求。未进入编译计划的请求特有范围不能静默丢弃。

当前每次执行使用五分钟租约，过期执行不能追加结果；可重试的模型超时、暂时不可用及并发限制最多执行三次，等待期间可继续阅读原文及已有有效译文。配置撤回不持续重试，恢复配置不自动重放历史任务。格式、截断及数字、单位、设备编码校验失败不发布机器译文。任务只保存身份与范围引用及非敏感问题码，不复制原文、供应商错误全文或凭据；终态运行记录保留 30 天并有界清理，原文及译文事实不随运行记录到期删除。业务最终删除在所属事务内同时清理该记录的任务。

原文变更后，维护入口提供最近旧原文的人工译文及其原文、作者和历史作为复核参考，明确删除的版本不重新作为参考。删除当前语言同时截断更旧参考及其待复核提示；在当前原文下重新保存草稿不会恢复已舍弃的旧建议，受权修订历史仍可读取。该参考不参与当前阅读，也不继承旧确认状态；维护人员核对当前原文后保存新草稿，再由具备确认资格的人员核对。复制参考只改变维护输入，不提交原文或译文。普通阅读仅依据旧确认版本提示待复核，不暴露旧人工草稿是否存在。当前译文状态按同一修订上界分别读取最新事实，查询和返回行数不随修订历史增长。

共享阅读、人工维护及自动生成状态界面已接通；真实模型验收、跨语言查询及引用候选、流程和 Excel 闭环仍待完成。主要协作语言的提交后预生成与受控补齐继续属于完整闭环目标。真实 PostgreSQL 合同测试证明来源、标准保存、主子表、来源读取、译文存储及任务恢复边界，不代替后续完整业务验收。

## 业务目标与范围

1. 各国团队可以使用自己的语言填写同一业务中的不同字段、明细和处理意见，不要求统一用中文或英文录入。
2. 阅读者可以选择业务内容的阅读语言，查看译文、原文、来源语言及译文状态。
3. 商品名称、标准说明支持人工维护多语言版本；异常说明、调查记录等持续产生的内容支持自动阅读翻译，人工修订与确认按需要使用。
4. 列表、详情、主子表、引用、流程、文本搜索及数据交换共同覆盖多语言内容，不能只在详情页增加翻译按钮。
5. 原文、译文、作者和版本可以追溯；权限、租户隔离、业务身份、规则、事务及历史事实保持稳定。
6. 静态 Java 与动态元数据通过同一能力接入，普通业务不重复实现翻译调度、权限、版本和展示流程。
7. 内容维护人员可以按授权查看语言覆盖、批量补齐和复核，实施人员可以交付配置及其译文；普通填报者不需要每次填写全部语种。

首轮以同一企业租户内的跨国组织协作为范围。参与人员可以是员工，也可以是在现有身份和业务授权范围内的客户、合作伙伴；语言不产生新的访问资格。跨租户业务协作及新的外部身份接入模型需要所属业务另行建立契约。

## 内容策略与语言上下文

### 字段显式声明

| 策略 | 典型内容 | 目标行为 |
| --- | --- | --- |
| 保持原值 | 编码、型号、数量、日期，以及业务要求保留的人名和法定名称 | 不自动翻译业务值；日期、数字等格式本地化保持各自契约 |
| 自动阅读翻译 | 异常描述、调查说明、处理意见、协作记录 | 原文正常保存，按阅读语言提供机器译文，允许核实原文 |
| 人工维护多语言 | 商品名称、标准操作说明 | 支持机器起草、人工修订和确认，优先展示当前有效的已确认译文，不新增业务审批或发布门禁 |

不默认翻译所有字符串或遍历任意业务 JSON。字典项仍按配置文案翻译，保存稳定 code；同一事实的语言表达属于本专题，不同国家的合规声明、渠道要求或法人业务差异由业务变体模型表达。

系统字典与业务记录提供的选项按真实来源接入：前者维护字典项的配置译文，后者解析目标业务记录的有效译文并保存其 ID。选择控件可以共享，但不能仅因一个字段显示为下拉选项就把其值视为配置词条。同名原文的不同记录各自维护译文，改名不改变记录身份；应用和业务语境不能依靠全局原文匹配区分。

同一记录允许字段和明细采用不同来源语言。来源语言跟随独立文本及其修订，不能只给整张业务单据标记一个语言。自动识别辅助确定来源语言；短文本、型号和混合语言无法可靠识别时，允许明确选择或纠正，不把界面语言当作已确认的来源语言。

### 四种语言用途

| 用途 | 含义 | 选择与约束 |
| --- | --- | --- |
| 界面语言 | 按钮、字段标签、固定提示等 | 沿用现有界面语言能力 |
| 来源语言 | 作者某次实际填写的文本语言 | 与原文及修订绑定，不能因阅读者变化而改写 |
| 阅读语言 | 用户希望理解业务内容的语言 | 可默认跟随界面语言，显式选择后独立保留 |
| 导出语言 | Excel 模板和阅读文件采用的语言 | 由导出操作明确选择，不改写文件中的来源语言 |

复用标准语言标签与目录元信息，分别治理界面交付状态、业务内容可用语言及有效模型的翻译能力。支持德文业务内容不代表平台已经交付完整德文界面。内容语言的启用、回退和个人偏好协议在实施前确定，不能直接修改现有 `Accept-Language` 的界面语义。

## 原文与译文契约

### 事实与展示分离

业务字段继续保存作者输入的原值。原文的新增和修改经过正常业务保存链路，执行权限、字段保护、校验、乐观锁、事务与生命周期。来源语言及文本版本与本次成功写入保持一致；事务回滚不产生可消费的文本修订或翻译任务。

译文表达同一原文的另一种语言，不参与普通业务字段回写，不改变唯一性、公式、数值计算或流程判定。若业务需要根据多语言文本执行专门校验，应显式声明该规则，不能隐式改变现有规则的输入。

新增处理意见保留该条意见的作者和原文；修改同一字段则是已有业务事实的修订，需要相应权限和并发校验。阅读译文、修改原文、修订译文分别提供明确操作入口，不能在普通编辑时悄悄把译文作为原文提交。

普通记录保存不附带替换整套译文的副作用。译文未加载、未编辑或只编辑一个目标语言时，其他语言保持原状；明确删除某一译文需要独立表达删除意图并校验版本与权限。不能把未提交、空列表和明确清空混为一谈，清除译文也不等于删除业务原文。

### 来源与版本

文本身份至少能够定位租户、所属模块和实体、主记录或明细记录、稳定字段身份。译文绑定该来源的原文修订及目标语言，不按中文内容匹配，也不按可变的展示路径或行号识别来源。

原文修订与译文修订分别表达。文本版本以该文本的有效来源事实判断，修改价格等无关字段不让名称译文失效；修改原文或纠正来源语言应重新判断译文有效性。人工确认必须核对其审阅的原文版本和译文版本。

机器译文保留对应的原文版本、目标语言、模型调用的非敏感溯源标识、可获得的模型或策略版本、术语与上下文版本及生成时间。服务未暴露模型版本时如实记录可追溯标识，不承诺完整重现模型；端点和凭据不进入业务展示或译文文件。已确认译文另行记录修订人、确认人和生效事实。

### 阅读与更新

普通阅读优先显示目标语言下匹配当前原文的已确认译文，其次显示匹配当前原文的机器译文，缺失时显示原文及处理状态。来源语言已经等于目标语言时直接显示原文。只能显示其他语言的回退文本时，应明确标记实际语言和回退，不计为目标语言翻译完成。

未确认的人工修订保存为维护草稿，不替换普通阅读中的有效译文；保存草稿也不清除之前的有效确认版本或机器译文。确认时校验其审阅的原文与译文版本。没有确认译文时，阅读与既有办理仍可继续，不新增业务门禁。

日常阅读可直接查看机器译文，清楚区分机器生成、人工确认、处理中、失败与待复核等事实；具体状态字段在实现中按职责拆分，不预设一个承载全部含义的大枚举。首轮不要求业务先配置“正式对外结论”或译文审批流程；未来具体业务若确有签发或受控发布要求，再由所属业务声明动作与门禁。

原文变化后，旧译文退出当前有效展示，人工译文保留为待复核参考，历史版本按权限可查。延迟到达的旧任务只能保留为对应版本结果或废弃，不能覆盖当前展示。机器刷新不能覆盖人工修订稿或已确认译文。

机器译文持久化并复用，避免每次阅读重新翻译。同一原文版本和目标语言的并发生成应去重；模型、术语或允许使用的上下文变化，通过受控再生成产生新译文修订。原则上从真实原文直接翻译，不默认以英文中转产生多次转译。

## 平台能力与运行边界

### 共享接入与存储方向

静态 Java 通过轻量字段和能力声明接入，动态元数据编译为相同的来源无关契约。共享能力负责来源定位、版本校验、译文维护、读取投影、任务及检索协同，标准页面和公开消费者不复制业务特判。

推荐由平台统一管理结构化的业务文本来源与译文，业务主表保留原值。通用译文存储适用于跨模块、字段、明细和意见的接入；类型、外键、查询索引及生命周期约束需要在真实路径设计中落实，不能把通用存储变成脱离业务归属的字符串仓库。不按语种增加 `name_en` 等列，不为语言变化复制整条业务记录。

复用现有语言标签、批量解析和原值与展示分离的基础；业务译文不进入现有系统配置译文维护作用域。现有 `$texts`、`titleText` 是需要评估的展示接入点，最终扩展必须携带业务来源、权限及译文状态，不在草案中预设已存在新的来源枚举、HTTP API 或保存协议。

### 权限与生命周期

1. 读取和生成均核验真实业务归属、有效租户及适用授权；客户端传入来源 ID 不能扩大范围。译文维护和确认还需各自动作资格，不赋予业务审批或对外发布资格。
2. 译文、搜索索引和缓存沿用原文的可见范围及字段保护；引用展示继续遵守既有引用投影契约，不借本专题新增目标记录读取资格。
3. 后台任务携带明确的租户、业务来源、触发身份或系统态原因，按受限执行范围工作；重试和完成时复核当前来源及适用策略。
4. 敏感字段及上下文仅在明确允许的处理策略下通过模型网关提交翻译。脱敏、加密、下载和保留期覆盖派生译文，原文删除或授权变化后不能从缓存或索引继续披露。
5. 软删除、恢复和最终清理跟随所属记录生命周期；历史保留与最终清理策略明确处理原文修订、译文、任务和索引，不能留下失去归属的可读副本。

### 异步翻译与服务治理

自动翻译同时要求字段声明允许自动翻译、当前业务范围有符合处理策略的文本，以及按现有模型路由存在有效模型配置。无有效模型配置时不启动自动翻译，不创建可执行的生成任务、不调用模型，也不将其视为需要持续重试的业务失败。页面说明“自动翻译未启用”，仍可保存原文、维护人工译文，并展示来源版本及权限仍有效的已有译文；界面语言和配置译文能力不受影响。

满足条件时，原文成功提交后可靠地产生待处理事实，异步预生成主要协作语言，阅读时按需补齐其他允许语言。提供有界重试、幂等、超时、失败定位和人工重试；业务提交不等待翻译完成，翻译不可用不导致原文保存失败。可靠交接需要覆盖进程重启，不能只用内存回调充当任务持久化。

执行任务时重新按既有路由核验当前配置和处理资格；当前已无有效配置或不再满足处理策略时停止调用，不自行扩大兜底资格。停用租户专属连接后，若已有明确授权的平台共享兜底仍有效，则继续按正常路由解析。配置缺失与已配置模型的超时、限流等运行故障分别表达。后续配置模型不自动触发全库历史补齐，已有原文通过受控批量补齐处理；新提交和正常阅读按既定策略触发。

任务、重试和进度属于本专题，遵守[后台任务与异步批次边界](BACKGROUND_JOB_AND_BATCH_BOUNDARY.md)，不为本专题建设通用任务中心。原文修订、译文版本及生成证据属于必要的专题事实；运行审计仅记录动作线索，按[审计与专题流水边界](AUDIT_AND_PROCESS_LOG_BOUNDARY.md)关联，不承载文本全文。

翻译复用现有[模型连接配置](topics/configuration/AI_MODEL_INTEGRATION.md)，统一通过 `AiModelGateway` 的文本生成能力调用当前有效 LLM，不另建翻译专用供应商目录、凭据、模型配置或独立 chat agent 接入链。部署需要使用内网模型时，由现有模型连接配置承接。业界产品只作为能力参照，不作为采购候选或直连要求。

平台身份、租户身份及平台共享兜底完全服从既有模型路由；租户没有专属配置但有明确允许的共享兜底时仍属于有有效配置，不能自行扩大兜底资格。异步任务保留可信触发身份及业务执行范围，不把租户任务改为平台系统身份来取得平台凭据。业务翻译只依赖稳定门面，不直接查询模型配置表；如需要无模型调用的可用性判断，由模型能力提供受同一路由约束的安全门面，包含供应商启用和凭据可解析性，不以配置行存在或 `apiKeyConfigured` 代替，也不在业务模块复制配置解析。

可信延后执行身份通过 `TrustedExecutionIdentityResolver` 交接真实账号引用，不保存会话、凭据或权限快照。IAM 在捕获和恢复时检查账号实际租户、创建身份、启停、删除及密码限制，并重新解析当前组织和时区；原有代办还须重新验证同一授权及委托双方任职，不切换成其他授权或操作人身份。该门面仅恢复身份事实，不替代业务执行时的动作、记录及页面范围授权；业务所属租户与模型路由租户由调用链分别保留。此身份契约本身不启动翻译任务。

调用只提交本次翻译所需的文本、语言及允许上下文，不复用跨用户聊天历史，不提供工具或赋予模型业务操作权限。结果仅作为待校验的译文，不能执行其返回的指令。连接、凭据、路由和模型调用并发限制复用现有网关，翻译专题负责自身任务调度与输出校验，不叠加失控重试。模型已配置不代表翻译质量或语言支持已经通过验收，仍需验证术语、返回格式、耗时及容量。

## 语言维护与应用交付

### 按来源分工

| 内容来源 | 维护与交付职责 | 与本专题的关系 |
| --- | --- | --- |
| 代码文案 | 所属应用维护模板及语言资源，随软件版本交付 | 复用现有国际化契约，不建设公共原文词条匹配或管理员在线改代码语言包 |
| 在线配置 | 实施或配置维护人员按来源、原文版本维护与发布译文；配置包携带相关译文关系 | 沿用配置治理边界，配置包携带译文仍需单独实现和验收 |
| 业务内容 | 所属业务授权人员维护原文及已确认译文，平台生成阅读译文 | 本专题统一承担；业务数据不因应用发布而跨环境复制 |

动态页面字段标题、查询条件标签和字典说明变化仍按配置来源处理；该字段内的业务文本按已声明内容策略处理。静态与动态共用编译后的能力声明，不为在线表单另设一套翻译服务或与其他入口冲突的总开关。

提示继续使用稳定模板和具名参数，翻译模板后填充业务值；编号、数量不同不产生新词条。参数中的业务名称若需要本地化，必须具有明确的业务来源及展示声明，不能对参数全文做通用翻译或改变用于业务判断的原值。

### 新增语言与批量维护

新增内容语言时，维护人员按模块、字段策略、来源版本、目标语言和授权范围查看缺失、失效、机器待生成及人工待复核情况。支持选择范围批量生成、导出待维护内容、导入修订及查看进度和失败项；针对业务内容，不要求逐条打开业务表单维护。

已有原文在新增语言或启用字段策略后进入受控补齐范围，日常新增或修改原文继续产生增量任务。补齐以当前来源版本为准，可重试并跳过有效结果；已有人工草稿和已确认译文不得被覆盖。来源或原文未确定、策略禁止外发以及无授权的项分别诊断，不能计作翻译完成。

代码资源、配置译文与业务内容的覆盖情况分别统计，缺失诊断保持相应来源归属；运行时遇到未知文本只报告来源缺失，不能自动把任意用户输入或抽象 key 注册为公共词条并发送翻译。新增语言的批量生成与人工核对译文是不同步骤，任务完成不等于语言正式交付。

### 配置交付与已有译文接入

应用配置跨环境交付时，配置治理负责携带相关配置译文、目标语言、来源关系、原文版本及生效状态，并校验语言依赖。来源身份在目标环境发生映射时，译文关联按同一映射校验，不能只复制数据库 ID 或按中文默认名称猜测归属。已安装的代码资源由软件版本提供，不混入在线配置覆盖。

配置包中译文的目标冲突、原文不一致及覆盖策略进入 dry-run 和受控应用流程，保留已有人工维护结果；没有相应译文的语言明确诊断。现有配置治理的归档、导出和 dry-run 不等同于真实配置及译文已安装，必须以目标环境实际页面、选项和版本关系验收。

业务记录及其语言版本通过业务数据交换交付，不随应用配置包复制。若后续需要接入其他系统的既有译文，先提供明确的来源映射、语言规范化、原文校验和冲突报告，再按受控导入处理；未明确数据范围前不建设旧系统迁移适配，不把按原文匹配作为迁移默认规则。

## 查询与业务消费者

### 搜索与排序

结构化筛选继续使用原始业务值。文本搜索明确区分按原文、按指定语言以及跨语言搜索，结果说明匹配语言和文本来源；查询不能因换了界面语言而悄悄改变已提交条件的含义。

首轮跨语言搜索覆盖声明字段的原文和当前有效译文，不承诺任意语言的同义词或语义召回。主要协作语言在提交后预生成并更新可查询投影，按目标语言和当前原文版本表达检索处理中、就绪或失败。不能把旧译文仍在索引中视为新版本就绪。

检索覆盖所有受权记录，筛选、计数、去重、排序和分页在服务端一致执行，不能在当前页翻译后筛选或排序。查询使用稳定记录身份去重；目标语言排序需明确语言规则、回退值与稳定 ID 次序，索引未就绪时说明结果可能不完整。

### 引用与流程

引用候选、已选回显和只读摘要展示有效译文，继续提交记录 ID；译文相同不合并记录，标题变化不改变引用身份。名称不能唯一定位时继续拒绝歧义，不因机器翻译增加新的隐式匹配路径。

流程办理使用稳定状态、动作和原始业务事实。机器译文中的“暂停发货”不自动设置状态或触发动作，人工确认译文也不触发业务审批、暂停或放行。办理意见的原文和作者保持不变，阅读翻译不改写审批事实，已有办理条件不因译文尚未确认而新增阻断。

现有工作流配置冻结规则保持独立。历史业务内容按照其原文修订解析译文，原文与译文修订可追溯，不用当前原文替换历史事实。首轮不新增“谁当时阅读了哪个译文”的证明模型或签发快照；具体业务出现此类需求时另行确定。

### Excel 填写与回导

可回导的数据文件保留稳定技术表头及身份，明确区分可写业务内容与只读阅读译文。填写业务、修改已有业务、维护译文及阅读导出分别具有明确用途；不把阅读译文通过普通保存写回业务原字段。以下为已确定的目标业务边界，尚需实现和验收，不代表当前导入导出已经支持。

Excel 的本地化填写分为列标题、字典选项和业务引用名称三个层次。展示表头可按导出语言呈现，技术表头和 sheet 身份继续稳定；字典项反查为稳定 code，业务引用名称反查为目标记录 ID，用户自由输入的文本仍是新原文。导入名称的解析语言应由文件或显式导入选项确定，不能在处理中随操作者界面语言变化。

| 场景 | 业务边界 |
| --- | --- |
| 只填写名称 | 允许仅填写原名或当前有效的已确认译名，不强制填写 ID／编码；在有效业务范围内唯一匹配就关联，重名时要求补充编码或限定条件，不选择首个结果 |
| 名称不存在 | 报告未找到并引导修正或由有权限人员先维护基础资料，不自动创建分类等引用对象 |
| 手填机器译名 | 未经人工核对的机器译名只提供候选，用户明确确认对应业务对象后才导入；确认绑定身份，不自动将机器译文转为已确认译文 |
| 导出后分类改名 | 系统导出文件可核实原有稳定身份且用户未修改引用选择时，继续使用同一关联，不因译名变化阻断其他字段更新；无法确认身份时重新匹配 |
| 跨语言修改原说明 | 仅在页面同样允许修改的权限和业务状态下，明确作为业务内容修改，按新输入语言形成原文修订，保留旧内容和作者历史，并更新其他语言译文 |
| 部分记录有误 | 互相独立的记录先导入正确项，错误文件只包含失败的待修正项及必要上下文；100 条中 90 条成功、10 条失败时，用户只修改并重传这 10 条 |
| 已有字段留空 | 修改已有数据时，空白及未提交字段默认不修改；清空必须明确表达，并执行字段约束和权限校验，不用普通业务文本中的某个关键词隐式清空 |

待更新记录的身份和引用目标身份分别解析；业务编码只有在声明的范围内具有唯一性时才作为稳定匹配键。对重名、过期、缺失或不可访问的名称提供允许披露的诊断，不使用机器语义猜测。不因填报名称失败而创建新基础资料。

系统生成的编辑文件携带稳定身份及可核实的导出基线。用户未改分类时保留原关联；主动改分类名称时重新解析并确认新的目标，不能悄悄沿用旧 ID。稳定身份与用户实际填写意图冲突时明确诊断；仅含旧名称的手工文件不享有自动识别改名前对象的保证。隐藏列不是可信凭据，导入仍校验真实归属、权限、记录版本及引用有效性。

业务说明的阅读译文不作为默认可写值。需要修改原说明时，导出模板及导入预览明确显示当前内容与本次业务修改；只想纠正翻译时使用译文维护用途。原记录已冻结、已审批或发生并发修改时，沿用正常业务限制，Excel 不获得额外修改资格。

新增记录的空白继续接受正常默认值和必填校验，不能用更新的“不修改”语义跳过创建要求；数字 `0` 和布尔 `false` 是实际填写值。明确清空的表达方式及模板结构在实施时确定，并在导入预览说明动作。

错误文件保留失败项的可编辑业务值、定位和关联身份、版本、解析语言及可读错误原因，支持原文件直接修正重传；不要求用户重新准备成功项。主子表以业务完整性要求确定失败和重试单元，必要的父级定位或已成功关联仅作明确的上下文，不重新列为待写业务项。重传仍执行当前权限、版本和重复提交保护，不能重复创建已经成功的记录。业务写入成功而阅读翻译尚未完成，不计为业务导入失败。

当前导入导出只承诺原文 title 反推，错误文件还可能携带出错组中已成功的记录。上述多语言匹配、编辑基线、明确清空及失败项文件属于待建设契约，需以真实文件往返和主子表路径验证；可收集的数据错误允许部分成功，不承诺基础设施异常下仍提交其他项。

### 译文文件与其他交付

译文维护文件通过明确的业务身份、字段、原文版本及目标语言定位，执行权限、版本和歧义校验。局部维护不清空其他语言，原文过期时要求复核，不把导入修订自动等同于人工确认。具体文件结构在实施前确定。

供阅读的多语言导出明确导出语言、译文来源和状态。数据文件与阅读导出具有可辨别的用途，不能把阅读导出中的显示译文直接回导为原字段。首轮复用 Excel 导出交付，不新增报告制作、客户发送、签发、审阅证明或强制人工确认的业务流程。

通知、人工页面、API 消费者及助手使用同一标准业务读取能力。若助手消费译文，应保留其来源与状态，执行仍基于原始身份、规则及授权；本专题不建设新的助手对话或业务执行机制。

## 业务验收样板

### 中美德团队共同处理质量异常单

同一企业租户内设置中国工厂、美国采购和德国质量团队，按明确授权共享异常单。静态商品目录提供商品编码与人工维护名称，动态质量异常单包含异常标题、说明、商品引用、检测明细、结构化处理状态及各团队调查记录。另设无权访问的字段、组织记录和另一租户的相似数据。

界面使用已交付的中英文；业务内容登记中、英、德三种语言。德国人员可以使用英文界面和德文阅读偏好，这不要求同期交付完整德文界面。

业务操作按以下顺序完成：

1. 中国工程师选择同一商品，填写中文异常说明：“温度达到 80°C 时，12 件样品中有 2 件密封失效；暂勿发货。”保存主表及检测明细。
2. 美国采购以英文阅读该单，核实中文原文，新增英文意见：“Please keep this batch on hold until the replacement seals pass the retest.”
3. 德国质量人员以德文阅读前两人的内容，再用德文新增调查记录。三国人员重新打开同一单据，分别读取自己的语言版本。
4. 中国工程师将原说明的 `80°C` 更正为 `60°C`，同时模拟旧翻译请求延迟返回，验证版本切换、人工译文待复核及检索更新。
5. 有权限的人员修订并确认译文，其他人员完成查询、引用、流程办理、数据文件往返和多语言阅读导出查看，再验证翻译服务故障与权限变化。

### 验收标准

| 范围 | 必须达到的结果 |
| --- | --- |
| 真实填写 | 主表、明细及意见保留实际输入、作者与来源语言；同一单据允许多种来源语言 |
| 双向协作 | 美国人员能阅读中文内容的英文译文，中国人员能阅读英文意见的中文译文，德国人员能阅读两者的德文译文 |
| 翻译质量 | 数字、单位、型号、否定、条件和业务含义准确；本样例保留 `80°C`、`12`、`2` 及暂勿发货含义，不以固定译文措辞验收 |
| 来源核实 | 列表和详情说明译文状态，可访问原文；来源语言不确定时允许纠正，纠正后重新校验译文 |
| 语言独立 | 英文界面可以采用德文阅读偏好，切换界面语言不重写来源语言或显式阅读偏好 |
| 草稿闭环 | 主子表填写、切换语言、取消草稿、保存和重新打开均保持其业务语义；译文不进入普通保存原字段 |
| 原文修订 | `60°C` 的新版本生效后，不再把 `80°C` 译文作为当前内容；旧任务、缓存和响应不能覆盖当前版本 |
| 并发维护 | 原文与译文维护分别校验版本；同时确认、原文变更及机器重试不会静默覆盖人工工作 |
| 人工确认译文 | 当前有效的人工确认版本优先；失效版本进入待复核，未确认的机器译文可正常阅读，不阻断既有办理 |
| 搜索与分页 | 指定语言检索就绪后，英文关键词能找到中文原文对应记录；多页数据无因本页翻译导致的漏项、重复或错误计数 |
| 引用身份 | 候选和摘要可显示译文，选中、回填、保存及重新打开仍引用同一商品和业务记录；同名译文不混淆身份 |
| 流程办理 | 状态、权限和动作按业务声明执行；阅读翻译不改变办理意见原文，不根据译文自动暂停或放行 |
| 故障恢复 | 超时、配额耗尽及进程重启时原文保存正常，处理状态可解释，允许恢复重试且不会重复生成当前有效结果 |
| 未配置模型 | 有效模型缺失时不生成可执行翻译任务、不发模型调用、不反复重试；原文填报、人工译文维护和有效已有译文展示正常，补配模型后不自动全库补齐 |
| 模型路由 | 复用平台、租户及明确允许的共享兜底，异步执行不改变身份以扩大资格；有效路由全部撤销后不调用，专属连接停用但授权共享兜底有效时仍按既有规则调用，供应商停用或凭据不可解析时不能误判可用 |
| 权限隔离 | 无权字段、组织记录和另一租户的数据不经原文、译文、索引、缓存、任务结果及外发上下文泄露 |
| 数据交换 | 数据文件回导保持原值、技术表头及引用身份；译文文件按稳定来源和版本维护；阅读导出不会误回导为业务原文 |
| 历史与清理 | 原文及译文修订可追溯，不混用当前与历史来源；软删、恢复、最终清理及授权收回后，派生数据遵守相同可见性和保留策略 |
| 布局与公共接入 | 长文本在列表、详情、明细和流程意见可操作；独立静态业务消费者与动态模块遵守相同接入契约 |

### 设备分类与语言推广验收

在业务样板中增加设备分类主数据：默认名称为“数控设备”，已确认的英文名称为“CNC Equipment”。中英文用户选择后保存同一分类 ID；另建一条默认名称相同、业务语境不同的记录，确认其译文独立维护，改名和相同显示文字都不改变身份。未启用内容翻译的备注在英文界面输入中文，保存及切换语言后仍保留原文。

| 范围 | 必须达到的结果 |
| --- | --- |
| 状态及选项 | 系统字典状态在两种语言下保存同一 code；来自业务记录的分类选项保存同一记录 ID，并消费该记录的译文 |
| 配置与业务分工 | 动态字段标题、查询标签和字典说明按配置原文版本更新；业务字段值及对应语言版本不被配置发布改写 |
| 参数化提示 | 不同设备编号、名称和数量复用同一提示模板，各语言语序正确，参数原值及业务判断保持稳定 |
| 局部维护与删除 | 译文未加载或只保存英文时不清空其他语言；明确删除某个语言经过授权和版本校验，不删除原文 |
| 新语言补齐 | 选定范围生成新语言的存量内容，查询进度与失败后重试；有效已确认译文及人工草稿不被覆盖，统计不将回退计作已翻译 |
| 人工维护文件 | 批量导出、修订和导入通过稳定来源及版本关联；过期原文、重名和目标冲突有明确报告 |
| 本地化名称填写 | 原名和已确认译名可以唯一反查 code／ID，重名要求补充条件，未找到不创建基础资料；不得以当前原文 title 往返代替本项验收 |
| 机器译名确认 | 手填机器译名先显示受权候选，确认具体记录后绑定身份，不能无确认导入或自动标记为已确认译文 |
| 改名后的回导 | 系统导出后分类改名，只改数量仍关联原分类；主动改分类必须重新解析，无法核实的旧名称不被猜测匹配 |
| 业务修改与译文修订 | 不改说明时不回写阅读译文；明确用英文修改中文原说明时产生新原文修订并保留历史，仅修订英文译文时不改原文；冻结和并发限制继续有效 |
| 失败文件与重传 | 100 条独立记录中 90 条成功、10 条失败，生成只含 10 条待修正记录的错误文件；直接修正重传后不重复创建成功项，主子表必要上下文不作为重复待写数据 |
| 空白与清空 | 更新时缺列或空白保持原值，明确清空才执行删除值且接受约束校验；`0` 和 `false` 正常写入，新建记录不能借空白跳过必填 |

阶段四推广时另行验收应用配置及所属译文的跨环境交付：目标环境关联正确，dry-run 暴露冲突且不覆盖人工维护，业务记录不随应用包复制。本项不作为本轮两个业务样板收口的前置条件。

机器翻译质量以业务人员对原文及译文的审阅为准，配合固定业务语料的回归对比。每个首轮语向均覆盖短文本、长文本、专业术语、混合编码和数字、条件及否定句。普通阅读可异步等待；延迟、失败率、主要语言检索就绪时间和成本预算应在真实容量评测后形成明确门槛。

| 事项 | 推荐方向与待确定内容 |

| 人工译文维护 | 落实修订、确认和并发权限；人工确认表达译文质量状态，不增加业务审批、签发或对外发布流程 |

| 数据与历史 | 落实已确定的名称填写、机器译名确认、改名回导、跨语言修改、失败文件重传及空白语义；确定模板协议、可靠身份与基线、版本、清空表达及原文译文的保留策略 |
| 语言推广与配置交付 | 明确各来源的覆盖统计、批量维护资格、配置包译文依赖和冲突策略，验证目标环境真实生效；旧系统译文接入按明确数据范围另行触发 |
